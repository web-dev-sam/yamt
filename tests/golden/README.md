# Golden conflicts

Ten real three-way merge conflicts from public open-source projects (plan §2 #26), used to
check that yamt's chunk boundaries match what PhpStorm shows for the same conflict.

Each `<case>/` holds:

- `base.<ext>`, `local.<ext>`, `remote.<ext>` — index stages 1, 2 and 3 of the conflicted file,
  byte for byte as git produced them (an add/add case has an empty `base.<ext>`);
- `README.md` — project, license, merge commit and parents, original path, how to compare;
- `expected.json` — yamt's chunks, generated by `just golden-update`, never edited by hand.

`scripts/golden-repo.sh <case> <dir>` rebuilds a case as a git repo stopped mid-merge, so
PhpStorm's own merge window can open it. It needs git ≥ 2.32 (`GIT_CONFIG_GLOBAL`) and ignores
the user's git config, attributes and ignore files.

## How the cases were selected

1. Bare clones of MIT-licensed TypeScript/Vue projects: `vuejs/core`, `vuejs/router`,
   `vuejs/pinia`, `vuejs/language-tools`, `vitejs/vite`, `nuxt/nuxt`, `TanStack/query`,
   `vueuse/vueuse`.
2. For every two-parent merge commit (`git rev-list --merges --parents --all`), re-run the merge
   with `git merge-tree --write-tree <parent1> <parent2>` (git 2.56, default `ort` strategy) and
   keep the conflicted `.ts`, `.tsx` and `.vue` files with their stage 1/2/3 blob ids.
3. Keep files with 40–1500 lines on each side (base excepted for add/add), at least two changed
   regions and at least one conflict; drop files that git matched through a rename, so all three
   stages share one path.
4. Pick ten by hand for a mix of shapes (identical changes on both sides, changes 1–3 lines
   apart, a large conflict beside small one-sided changes, a pure insertion at the same place,
   add/add, a missing final newline), at least three projects, at least one `.vue` and one `.tsx`,
   and few enough regions to compare by eye.
5. Write the three blobs with `git cat-file blob <id>`; ours is the merge's first parent
   (`local`), theirs its second (`remote`).

## Cases

| case | project | license | file | lines b/l/r | why |
| --- | --- | --- | --- | --- | --- |
| `vue-router-playground-app` | [vuejs/router](https://github.com/vuejs/router) | MIT | `packages/playground/src/App.vue` | 233/205/219 | A 49-line conflict (local deletes a block that remote rewrites) 2 unchanged lines below a 20-line local-only change, plus other one-sided changes on both sides. |
| `vue-core-playground-app` | [vuejs/core](https://github.com/vuejs/core) | MIT | `packages-private/sfc-playground/src/App.vue` | 204/219/207 | A pure insertion at the same place on both sides (one line each, different text) 1 unchanged line below a local-only one-line change, plus five more local-only regions and one remote-only insertion. |
| `vue-core-compiler-von` | [vuejs/core](https://github.com/vuejs/core) | MIT | `packages/compiler-core/src/transforms/vOn.ts` | 183/183/180 | A remote-only change 2 unchanged lines above a conflict (remote deletes 3 lines, local edits the first of them) and a far remote-only change. |
| `vue-core-script-context` | [vuejs/core](https://github.com/vuejs/core) | MIT | `packages/compiler-sfc/src/script/context.ts` | 208/206/201 | The same import inserted identically on both sides, a conflict whose remote side equals the tail of the local side, and a local-only change 2 unchanged lines below it. |
| `vite-modulepreload-polyfill` | [vitejs/vite](https://github.com/vitejs/vite) | MIT | `packages/vite/src/node/plugins/modulePreloadPolyfill.ts` | 107/121/106 | Three regions changed identically on both sides, a conflict in the import block where both sides add the same first line, and a local-only insertion. |
| `tanstack-query-persist-provider` | [TanStack/query](https://github.com/TanStack/query) | MIT | `packages/react-query-persist-client/src/PersistQueryClientProvider.tsx` | 55/58/56 | A TSX conflict where remote deletes 9 lines that local edits, framed by remote-only changes 1 unchanged line above and below it. |
| `tanstack-query-svelte-base-query` | [TanStack/query](https://github.com/TanStack/query) | MIT | `packages/svelte-query/src/createBaseQuery.ts` | 0/74/76 | An add/add file (absent at the merge base, so `base.ts` is empty) whose two versions differ in 4 small places. |
| `nuxt-island-test` | [nuxt/nuxt](https://github.com/nuxt/nuxt) | MIT | `test/nuxt/nuxt-island.test.ts` | 68/214/241 | The remote side has no final newline; both sides insert at the same places (imports, mocks, end of file), giving three conflicts, one of them 140 lines long. |
| `vueuse-use-magic-keys` | [vueuse/vueuse](https://github.com/vueuse/vueuse) | MIT | `packages/core/useMagicKeys/index.ts` | 170/168/186 | Local and remote changes interleaved 2-3 unchanged lines apart (base lines: local 103/105/107/115, remote 110/111) above one conflict. |
| `language-tools-script-setup` | [vuejs/language-tools](https://github.com/vuejs/language-tools) | MIT | `packages/language-core/lib/codegen/script/scriptSetup.ts` | 619/613/639 | Two conflicts separated by a single unchanged line (`}`), after four local-only changes earlier in the file. |

Line counts count a last line without a newline. Region descriptions come from
`git diff --histogram` of base against each side; yamt and PhpStorm may draw the boundaries
differently, which is what the comparison is for.
