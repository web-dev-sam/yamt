## Behaviour (what the user sees)

**Find (Ctrl+F on Linux, Cmd+F on macOS), any of the three panes.**

- Clicking a side pane focuses it (it stays read-only; text can be selected and copied). Ctrl/Cmd+F in a
  focused pane opens a find bar at the top of that pane only; the selected text, if any and on one
  line, fills the field.
- Typing finds plain text, case-insensitive. Every match in the pane is highlighted; the current one
  is selected, highlighted more strongly and scrolled into view.
- The bar shows "3 of 12" when the selection is on a match, "12 results" when it is not, "No results" when
  nothing matches (empty field: nothing shown). The count follows edits in the middle pane.
- Enter / F3 or the down button: next match; Shift+Enter / Shift+F3 or the up button: previous; both
  wrap around. Escape or the close button closes the bar and returns focus to the pane.
- Look: JetBrains New UI dark (plan §2 #24), colours only from the palette (`style.css` tokens), Lucide
  icons for up/down/close (plan §2 #34, `?raw` in editor/).

**Drag over the apply or ignore icons** (supersedes "acting on `pointerdown`" in cm6-rules CM10).

- Pressing an apply or ignore icon does nothing to the text yet: that change is "covered".
- Moving up or down while holding covers every open change of that side (the strip between that side's
  pane and the middle) whose icon row lies between the pressed icon and the pointer, inclusive. The
  pointer may leave the strip or the window; the wheel may scroll the panes meanwhile.
- Covered changes are highlighted while dragging: their icons of the pressed kind and their blocks in
  the side pane. Uncovering (moving back) removes the highlight.
- Releasing the button applies (or ignores) every covered change, top to bottom, with the outcome each
  would get if its icon were clicked in that order (plan §2 #33: append after an applied other side,
  replace otherwise; a side whose other side's lines are empty resolves the conflict). All of it is
  **one undo step**: one Ctrl+Z restores the text and every status, one redo re-applies them.
- Press and release without moving = today's click on that icon. A cancelled pointer (pointercancel)
  applies nothing. The middle pane keeps focus as today.

**Ctrl/Cmd+click on a highlighted block** in the left or right pane (a line of an open change of that
side: tinted lines, word marks included) does exactly what that change's apply icon does, focus
included. Plain clicks keep normal pane behaviour. A side that is already applied or ignored has no
tint and nothing happens.

**Read-only mode.** `new MergeController(data, hosts, { readOnly: true })`: the middle pane refuses user
edits (typing, paste, Tab, Enter, undo/redo keys); the strips draw bands but no icons; Ctrl/Cmd+click
and dragging do nothing; find works in all panes; `applyAllNonConflicting(side)` still works (the
window will use it to show the kept side after "Keep"). Default (`readOnly` omitted or false): today's
behaviour plus the above.

## Contract

- `MergeController` constructor: `(data: FileMergeData, hosts: MergeHosts, options?: MergeOptions)`;
  `export type MergeOptions = { readonly readOnly: boolean }` from `editor/index.ts`. No other public
  surface change.
- Bulk apply/ignore of a chosen list follows CM6/CM7: changes computed in original coordinates and
  passed together in one action transaction with one `setStatus` per change; undo restores statuses
  through the existing `invertedEffects`. Drag highlight state is not in history (a side-pane effect or
  a strip class, never the center's history).
- Strip buttons are repainted every frame (`paintGap` → `replaceChildren`): the drag must survive that
  (listen on the persistent `<svg>` strips / pointer capture there, not on the per-frame `<g>`).
- Every function ≤ 40 lines, every non-test file ≤ 300 lines; `editor/` stays framework-free (PM3).
  New files go in `editor/internal/`; name each in `deviations_from_brief` (the orchestrator updates the
  project map and architecture).

## Tests

Behaviour, not wiring (`skill://cm6-rules`, node project):

- bulk apply/ignore of a chosen list: result text and statuses equal clicking the same icons one by one
  top to bottom, including a conflict whose other side was applied (append) and one whose other side
  is empty; one `undo` restores text and every status; one `redo` re-applies.
- which changes a drag covers given press row and pointer row (both directions, rows outside every
  icon, closed sides skipped).
- Ctrl/Cmd+click mapping: a position inside an open block → that change; outside, or a handled side →
  nothing.
- find count: "3 of 12" / "12 results" / "No results" at the edges (no matches, selection off a match,
  last match wraps to the first).
- read-only: a user edit transaction is refused in the middle pane; `applyAllNonConflicting` still
  changes it.
