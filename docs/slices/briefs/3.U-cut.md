# Slice 3.U-cut — one Ctrl+X cuts once

Board "Unchanged lines" row 2b. Finding **#849** (found by the panes half's rework 2 smoke, pre-existing,
app-wide; `.omp/run/notes/UnchangedPanesR2.md` open_risks): "With nothing selected, one Ctrl+X makes
WebKitGTK send two trusted `cut` events and CodeMirror handles both (`@codemirror/view` handlers.cut): an
empty-cursor Ctrl+X cuts two lines instead of one (real app, vOn.ts: `cuts:[[true,184],[true,183]]`, 184 →
182 lines; with a 3-character selection one event). On a wave line the first cut is blocked by #848's
filter and shows the next step, then the second cut removes the line that step just revealed, so plan #63's
'a line cut on the wave line deletes nothing' is false in the app." Product rule: one key press is one cut
(every editor, WebStorm included); plan §2 #63 for the wave line.

## Target

Owned: `frontend/src/editor/internal/pane.ts`, `pane.test.ts`, and one new module if the rule deserves
its own file (e.g. `frontend/src/editor/internal/cutOnce.ts` + `cutOnce.test.ts`). Read-only: everything
else (a strips fix round edits `strips.ts`, `drag.ts` and `index.ts`'s import lines at the same time).
Non-goals: copy, paste, the clipboard contents' format, any other key.

## Change

1. Find out why two `cut` events arrive (WebKitGTK editing command and GTK's `cut-clipboard` binding, a
   native menu accelerator, or something else) and measure their gap (`event.timeStamp`, frames, tasks)
   in the real app with a real X key (`just app-session start-app … --x11`, `press … --x11`).
2. Handle one `cut` per key press in every pane: the duplicate is prevented and never reaches
   CodeMirror's handler. The rule must not depend on a `keydown` reaching the page (on macOS a menu
   accelerator can swallow it) and must let two separate presses cut twice. Choose the boring rule the
   measurement supports and say why.

## Acceptance

- Node test of the rule's decision (pure function or state), with a hand failing-path proof (`editor/`
  is not mutated).
- Real app on a private display (`just app-session start-app --name <n> --fresh-repo`, real X keys
  `--x11`; the debug binary built from this tree), `packages/compiler-core/src/transforms/vOn.ts`, middle
  pane — paste line counts and the clipboard (`xclip -o -selection clipboard` on the session display or
  a paste into the middle):
  1. Cursor on a visible line, no selection, one Ctrl+X: exactly one line gone, it is on the clipboard.
  2. Two separate Ctrl+X presses: two lines gone.
  3. A 3-character selection, Ctrl+X: those characters gone once.
  4. Cursor on a wave line (e.g. the top wave), Ctrl+X: no text gone, the run shows its next step in
     all three panes.
  5. Ctrl+Z after 1 restores the line.
- `pnpm -C frontend lint`, `typecheck`, `test`, `unused`, `fmt:check`: exit 0 (tails).
