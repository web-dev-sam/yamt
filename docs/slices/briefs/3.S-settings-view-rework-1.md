## Findings (verbatim from `.omp/run/findings.jsonl`)

1. **#702 should** (DR6, `KeymapList.vue:112`): "Add Keyboard Shortcut" opens the dialog empty, but
   WebStorm's `ShortcutDialog.showAndGet` (`ShortcutDialog.java:107-112`) fills it with the action's
   first key when no key is selected. → **Follow WebStorm** (orchestrator decision, DR6): Add opens
   with the action's first key shown (OK enabled; OK with a key the action already has changes
   nothing, `KeymapPanel.java:897-911`); an action with no keys opens empty with OK disabled. Add
   still adds (`from: null`).
2. **#703 should** (vision 2, `KeyRecorder.vue:34`): `owners` re-implements "which other action
   already holds this key", which `keymapEdit.ts` `placed` already decides for the clash question;
   a later change to the clash rule would update the question but not the live warning. → Export
   one `keyOwners(bindings, action, key)` from `keymapEdit.ts`, use it in `placed` and in
   KeyRecorder.
3. **#704 should** (`KeyRecorder.vue:108` / `KeymapList.vue:92-106`): `plusMenuKey` and `menuKey` are
   the same Escape/Tab-close plus wrap-around Up/Down handler with two identical step tables
   (`MENU_STEPS`, `ROW_STEPS`). → One step table and one pure `stepMenuItem(menu, event)` in a
   single ui module used by both.
4. **#705 should** (CP1, `MergeToolbar.vue:33`, `editor/internal/pane.ts:182`): "board item 662" /
   "board item 690" is a new reference form chosen to dodge the palette check; the house form for a
   decision is `plan §2 #NN`; #690 is a finding id, change history, not a source. → "(plan §2 #57)"
   in MergeToolbar; in pane.ts drop "board item 690", keep only the `@codemirror/commands`
   citation, and say "only yamt's undo commands undo" (the toolbar buttons are hidden).
5. **#706 should** (`keyText.ts:109`): `SET_KEYS` silently drops a text that does not parse
   (`flatMap → []`), while `ipc/keys.ts` throws on a bad constant (`defaultKeys`). → Throw on a null
   parse the same way.
6. **#708 nit** (VU13, `SettingsView.vue:46`): `useDefault` is a click handler with the composable
   prefix. → `moveToDefault`.
7. **#709 nit** (TS16, `keyText.ts:15`): `SetKeyEntry` exported, unused outside. → Drop `export`.
8. **#710 should** (`KeymapList.vue:47`): a click outside an open menu always moves focus back to the
   row, even onto a focusable control (clicking into the Settings file field while a menu is open
   puts focus back on the row; typed characters are lost; Space/Enter reopens the menu). → On a
   click outside, close the menu and refocus the row only when focus did not move elsewhere
   (`document.activeElement` is body or inside the menu); Escape and Tab keep today's refocus.
9. **#711 should** (`KeyRecorder.vue:70`): the dialog's key rules have no automated test (Shift+Tab
   recorded, Enter confirming an empty field, Escape with Shift cancelling, owners counting the
   action's own keys would all pass `pnpm test`). → Move the field's decision (cancel | confirm |
   leave | record key | ignore, given the event and the shown key) into a pure function in a ui
   `*.ts` module with a node test.
10. **#712 nit** (`keyText.ts:104`): the trailing-separator clause can never be false (no action's
    defaults are empty). → Drop it, keep the doubled-separator check.
