# Slice 1.P — palette test (VU17, approved at the last retro, due with the next window work)

The owner wants one place for colours: the `@theme` block in `frontend/src/style.css`
(plan §2 row 24). Today only reviewers guard it. This slice adds a test that reads the source
tree, so a colour typed anywhere else, or a reference to a colour token that does not exist,
fails `pnpm test`. Chunk colours arrive in the next editor work; this test must be in place first.

## Target

Owned: `frontend/scripts/palette.ts`, `frontend/scripts/palette.test.ts`.
Read-only: everything else, notably `frontend/src/**` (another agent is changing `src/ipc/**`,
`src/ui/**` and `src/main.ts` at the same time — do not depend on their content),
`frontend/scripts/fences.ts` (reuse its exports where they fit; do not edit it), `.omp/**`, `docs/**`.
Non-goals: Tailwind utility classes (`bg-editor`, `text-fg-muted` — telling colour utilities
from size utilities is out of scope; the stock-colour reset in `style.css` already makes
`text-white` produce nothing), CSS named colours (`white`, `red`), any `src/**` edit, any
config or package script change.

## Contract (fixed; you may add, never change)

```ts
// frontend/scripts/palette.ts
export type PaletteViolation = {
  readonly rule: "literal" | "unknown-token";
  readonly file: string; // relative to frontend/, e.g. "src/ui/FileList.vue"
  readonly line: number; // 1-based
  readonly match: string; // the offending text, e.g. "#1e1f22" or "--color-nope"
};
export function findPaletteViolations(files: readonly SourceFile[]): PaletteViolation[]; // pure
export function readPaletteSources(frontendRoot: string): SourceFile[]; // src/**/*.{ts,vue,css} except src/ipc/bindings.ts
```

`SourceFile` is the type `fences.ts` already exports (one definition).

Rules:

- **literal** — anywhere under `src/`, except inside the `@theme` block of `src/style.css`
  (`@theme`, optionally followed by `static`/`inline`, up to its matching `}`):
  a hex colour (`#` not preceded by a letter or digit, then 3, 4, 6 or 8 hex digits, not
  followed by a letter, digit or `-`), or a
  functional colour `rgb(`, `rgba(`, `hsl(`, `hsla(`, `hwb(`, `lab(`, `lch(`, `oklab(`, `oklch(`
  (case-insensitive, as a whole word). `color-mix(…)` built from `var(--color-…)` is allowed.
- **unknown-token** — a reference `var(--color-NAME)` anywhere under `src/`, or a
  `--color-NAME` used outside the `@theme` block, whose `NAME` is not defined in the `@theme`
  block. (`--color-*: initial;` is the reset, not a definition.)

## Change

1. `palette.ts`: `findPaletteViolations` is pure; `readPaletteSources` is the only disk access.
2. `palette.test.ts` (Vitest `node` project already includes `scripts/**/*.test.ts`):
   - the real tree: `findPaletteViolations(readPaletteSources(<frontend dir>))` is `[]`;
   - a temporary directory (`mkdtemp`, removed afterwards) with `src/style.css` (an `@theme`
     block defining `--color-editor`, plus `#ffffff` in an `@layer base` rule),
     `src/ui/Probe.vue` (`class="bg-[#123456]"`) and `src/ipc/bindings.ts` (containing
     `#abcdef`, must be skipped) gives exactly two `literal` violations, through the same
     `readPaletteSources` → `findPaletteViolations` path, with correct lines;
   - in-memory failing paths, one per shape, each asserting rule, file, line and match:
     `rgb(0 0 0)` in a `.ts` theme object; `OKLCH(` upper case; `#1e1f22cc` (8 digits);
     `var(--color-nope)` in a `.ts`; `--color-nope` in a `.vue` `<style>`;
   - in-memory allowed cases, asserting `[]`: hex inside `@theme`; `#app` selector;
     `var(--color-editor)` when defined; `color-mix(in srgb, var(--color-editor) 30%, transparent)`;
     `--color-*: initial;`; a reference like `issue#123` (the `#` follows a letter).
     After the wave, the verifier runs `just mutants` on your changed lines; a mutant that
     survives your tests comes back as a finding.
3. Run once at the end: `pnpm -C frontend lint && pnpm -C frontend typecheck && pnpm -C frontend test && pnpm -C frontend fmt:check && pnpm -C frontend unused`.
