## Findings (verbatim)

- **#565** (boundary, should) `frontend/src/ui/views.ts:24` — The `opened … deleted !== null` clause in takesASide still records `taken {by:"disk"}` for a deleted-side file only if it is open at the moment of the change. So the same Staged change leaves different `taken` state depending on what is shown, which #560 set out to remove. The deleted-side view now gets the same fact a second way, from `middle.kind !== "Stages"`. *Fix:* Drop the opened clause so takesASide is just 'the listed entry is unsupported' (choice files), and let deletedSideView take 'resolved on disk' from middle.kind alone. If a Stages middle can follow a Staged change, record the deviation for the orchestrator instead.
- **#566** (boundary, should) `docs/architecture.md:398` — Two docs still describe the old code: the ChunkSource block shows the positional `finishFile(path, text, diskVersion)` that #554 replaced, and project-map line 60 describes views.ts as 'shown views: fetch, put, reload, disk version', although shownVersion is gone and takesASide (which reads the file list) took its place. *Fix:* Curator: change architecture.md:398-402 to `finishFile(request: { path; text; diskVersion })`, and change the views.ts entry in project-map:60 to 'shown views: fetch, put, reload; takesASide (choice or deleted-side file)'.
- **#567** (boundary, nit) `frontend/src/ui/deletedSide.ts:25` — The new parameter `loaded` holds a middle kind (`"Stages" | "Disk" | "DiskNotText"`), while the same function returns `middle: "loaded"`. So `loaded !== "Stages"` reads as if it were about the view's 'loaded' middle. *Fix:* Rename the parameter (and the test's `loaded` argument) to `middleKind`.
- **#568** (correctness, should) `frontend/src/ui/MergeView.vue:88` — The read-only rule now lives only in an SFC function that no test runs. The rework removed the two tests that pinned it — useMergeController's 'a file deleted on one side gets a read-only editor' and apply.test's `open(notText).state.readOnly === true`. So a regression such as `||` for `&&`, or dropping the DiskNotText case, would make a deleted-side or not-text middle editable and let finish write an empty document, and every test would still pass. *Fix:* Move `isEditable(data: FileMergeData)` into a pure module (e.g. views.ts or deletedSide.ts), import it in MergeView, and add a table test: deleted side → false, DiskNotText → false, Stages and Disk → true.
- **#569** (correctness, should) `frontend/src/ui/store.test.ts:1511` — 'each write sends the disk version of the view it acts on' now passes the versions itself (`takeSide(…, seven)`, `reset(LOGO, LOGO_SIDES.diskVersion)`), so it only pins that the store forwards its argument. It would still pass if MergeView or ChoiceView sent a stale or wrong version, yet the title claims it proves the view's version is sent. *Fix:* Retitle it to 'finish, take and reset forward the disk version they are given', so the claim matches what it pins, and record in the open risks that the views' `data.diskVersion`/`sides.diskVersion` bindings are covered only by the desktop smoke.
