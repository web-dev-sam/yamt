## Findings to fix

### #946 (boundary, should; `frontend/src/lsp/internal/detect.ts:174`)

**Problem:** The new `root` parameter makes detection compute the project's workspace URI (`fileUri(root, folder)`) a second time, and oxlint needs it to match the URI `handshake.ts` `projectFolder(spec, root).uri` sends; `specOf(preset, detected, folder, root)` and `detectIn(lookups, folder, root)` also take two plain strings that can be swapped without a type error. Growth question: if the handshake ever changes how it builds that URI (separators, drive letter, trailing slash), oxlint quietly stops applying `run: "onType"`, and every caller of `detect` has to fetch `root` before it can call it.

**Fix:** Pass the preset's `initializationOptions` function (workspaceUri → options) through to the spec and call it in `initializeParams` with `folder.uri`, then drop `root` from `detect`, `detectIn` and `specOf`. This is the brief's 'build it at start' option and needs `handshake.ts`/`spec.ts` in a fix round. If the parameter stays, at least pass `{ folder, root }` as an object to `specOf`/`detectIn`.

**This round:** keep `detect`'s `root` parameter (the setup slice is written against it), but build the project folder's URI with the one function the handshake uses (`projectFolder`/`fileUri` — one function, called from both places, so they cannot drift), and pass `{ folder, root }` as one object to `specOf`/`detectIn`. Do not change `ServerSpec`.

### #947 (boundary, should; `frontend/src/lsp/internal/detect.ts:150`)

**Problem:** The native preview counts as installed when `node_modules/@typescript/native-preview/package.json` exists, so detection has a second test for 'the project has this program' next to `findProgram(...).place === "Project"`, which oxfmt and oxlint use and which starting `tsgo` also uses. A detected `tsgo` with `install: null` can therefore still fail to start with NotFound, against design §1 ('detected and can start never disagree'). Growth question: whoever adds the next preset has two rules to choose from, and the status area's 'not installed' versus 'not found' depends on which one was picked.

**Fix:** Decide the native preview with `findProgram(project, look.nativePreview.command.program)` and `found.kind === "Found" && found.place === "Project"`, the same way as `projectProgram`. Drop `nativePreview.package` from `presets.ts` and from `lookedFor`.

### #948 (boundary, should; `frontend/src/lsp/internal/presets.ts:33`)

**Problem:** `TS_FIRST` is the same eight extensions as `SCRIPTS` in a different order, and the order changes nothing because `serves` only uses `includes`. Growth question: adding a script extension now means editing two lists, and if one is missed TypeScript silently stops serving that file type.

**Fix:** Use `fileTypes: SCRIPTS` for TypeScript, delete `TS_FIRST`, and in `presets.test.ts` compare as a set or against `scripts`.

### #949 (boundary, should; `frontend/src/lsp/internal/detect.ts:224`)

**Problem:** `addedSpecs` (servers the user added by hand: file-name naming, '(2)' counters, root project) shares no helper or rule with detection, but sits in `detect.ts`, which therefore holds two concepts. Growth question: the Settings slice's changes to added servers will touch the detection file and push it toward the 300-line cap.

**Fix:** Move `addedSpecs` and `FIRST_REPEAT` into `lsp/internal/added.ts` with its own test file, and re-export it from `index.ts` from there (the orchestrator has to own the new file).

### #953 (correctness, should; `frontend/src/lsp/internal/detect.ts:53`)

**Problem:** Surviving mutant `typeof value === "string"` → true. Brief Behaviour 4 says a malformed package.json counts as "no field / no version", and no test checks that for a non-string value. With the mutant, `{"version": 7}` in node_modules/typescript/package.json detects `tsc`, a numeric 5 reaches `InstallHint.reason.version`, which is typed `string`, and `{"packageManager": ["pnpm@9"]}` becomes pnpm because the regex turns the array into a string. The test at detect.test.ts:397 (`{"packageManager":3}`) passes either way, because "3" never matches the regex. What gets harder: every later reader of `jsonField` can count on a string that no test protects.

**Fix:** In the "not detected … with no version" test (detect.test.ts:276), add a tree whose typescript package.json is `{"version":7}` and expect `[]`. In the field test, change the `3` case to `{"packageManager":["pnpm@9"]}` with an `app/yarn.lock` and expect "yarn".

### #954 (correctness, should; `frontend/src/lsp/internal/detect.ts:143`)

**Problem:** Surviving mutants `^\d+` → `^\d` and → `\d+`. Every test version has a one-digit major and starts with a digit, so nothing pins how the major is read. With `^\d`, a TypeScript 10.0.0 project reads as major 1 and is told to install typescript-language-server ("needs the separate package"). With the unanchored form, a version such as "x7.0.0" is detected as TS 7 even though Behaviour 4 says it has no version. What gets harder: the TS ≥ 7 split is the whole choice of TypeScript server, and its parse has no test.

**Fix:** Add two cases: `typescriptAt("", "10.0.0")` must give `TypeScript tsc --lsp --stdio @` (kills `^\d`), and a version of "x7.0.0" must give `[]` in the not-detected loop (kills `\d+`).

### #955 (correctness, should; `frontend/src/lsp/internal/detect.ts:230`)

**Problem:** The implementer's own rule ("an empty command is skipped: there is no program to name or start") only covers `[]`. A command of `[""]` (for example a Command field with a leading space split on spaces, design §8) or a program like `"bin/"` still gives a spec named "" (then " (2)") whose program cannot start. What gets harder: the Settings slice has to remember to trim before calling `addedSpecs`, which is a second copy of this rule.

**Fix:** Skip the entry when the program's file name `base` is "" (one condition replacing `program === undefined`), and add `{ command: [""] }` and `{ command: ["bin/"] }` to the "empty command is skipped" test.
