## Change

1. **Name the mapping after the architecture** (`src/compute.rs` ~61, ~94, vision 1). `SideDiff::map`
   reads as `Array.map` to a TS reader. Rename it `map_base_to_side` (architecture §3.1 step 4).
   Rename `starting_within` to `starting_at_or_before_end`, so the `<=` rule (an insertion at the
   region end belongs to the region) is in the name; name the start-side helper to match
   (`starting_before_start` or similar).
2. **Generate shared edits** (`tests/invariants.rs` ~84). `triple()` has no path that gives both
   sides the same edit, so `BothSame` comes almost only from both sides picking the same new last
   line — nearly always at EOF. Add a `shared` arm: one common edit list applied to base, then
   separate extra edit lists per side. Also run proptests 3 and 7 on `(base, local, local)`,
   where every chunk must be `BothSame`.
3. **Proptest 4 must notice missing chunks** (`tests/invariants.rs` ~217). `.iter().all(..)`
   passes on an empty list. In each leg also assert the list is empty exactly when the changed
   side equals base, e.g. `prop_assert_eq!(kinds(base, base, remote).is_empty(), remote == base)`.
4. (nit) **One slicing idiom in `apply_non_conflicting`** (`src/apply.rs` ~16–28). The arms rebuild
   `Range<u32>` from `LineRange` and the tail slices a second way. Use one private helper (or
   `lines_in`) for the arms and the tail alike.
5. (nit) **`Options` next to its consumer** (`src/chunk.rs` ~43). Move `Options`, its `Default`
   impl and `DEFAULT_GAP` into `compute.rs` beside `compute_chunks`; `lib.rs` re-exports from there.
