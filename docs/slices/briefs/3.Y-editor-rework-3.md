# Slice 3.Y-editor, fix round 3 (approved beyond the two-round limit)

Board "Language servers and saving" row 5. Original brief `docs/slices/briefs/3.Y-editor.md`; rounds 1 and 2
`3.Y-editor-rework-1.md`, `3.Y-editor-rework-2.md` (committed `6186288`, `b29f88c`; notes `LspEditorR1.md`,
`LspEditorR2.md`). The re-check of round 2 raised #951 (below, verbatim). The orchestrator, deciding as product owner
(#952, plan §2 #71), approved a third round with a **product rule** that makes the whole class of bug impossible
instead of a better heuristic:

> **Formatting never changes the lines of a change that still waits on a side, nor the line just before or just
> after it. A format edit that would touch them is left out; the rest of the formatter's answer is applied.**

Why this is the right rule: Save does not write the shown text of a change whose sides all wait (it writes git's
markers or the side's lines, plan #69), so formatting there buys nothing; a half-decided change is decided by the user
first and formatted on a later Save; and an edit that never reaches an open change's lines or its edges cannot move
text across them or empty them (CM1, CM8).

## Block

### #951 (correctness, block; `frontend/src/editor/internal/format.ts:61`)

**Problem:** #945 is fixed only when the block's edge line changes in whitespace alone. If the formatter also changes
a token on that line, a split or join next to the block still leaves the whole edit unmatched; `lineChanges` pairs it
by position and the symptoms of #945 come back: (B) `line 198`/`line 199`/one-line block `block 1` formatted to
`line 198 line 199`/`  block 1;` deletes line 200 (the whole block), which becomes `ignored ignored` with no arrows;
(A) `foo(x, y)`/`B1` formatted to `foo(x,`/`  y)`/`  B1;` puts `  y)` inside the block; (C) a reindented last line
that gains a `;` plus a blank line after it inserts the blank inside the block.

**Fix (the rule above):** before dispatch, drop every line edit (as `lineDiff` groups them, after the round-2
pairing) whose old line range overlaps an open change's lines or touches the line just before or after it (an open
change: any side still pending, per `chunkField`); dispatch the rest as one `yamt.format` transaction. The outcome is
still `formatted` when some edits were applied, `unchanged` when none were left (the Save goes on either way). Keep
the round-2 pairing for the edits that remain.

## Acceptance

1. Format tests, each failing before the change (paste the failing runs): #951's (A), (B), (B2) and (C) with a
   token change (`;`, quotes) on the edge line → the block `pending pending`, its own text unchanged, `replace`
   arrows, one undo step, and the lines away from the block formatted; a formatter that reformats lines _inside_ an
   open block leaves them as they were; a half-decided conflict is not touched either; a decided change (both sides
   applied or ignored) is formatted; an answer that only touches an open change → `unchanged`, nothing dispatched.
2. The round-1 and round-2 tests keep passing except where they asserted formatting _inside_ an open block (update

3. A failing-path proof for the rule (`editor/` is not mutated).
4. `pnpm -C frontend lint`, `typecheck`, `test`, `fmt:check`: exit 0 (tails).
