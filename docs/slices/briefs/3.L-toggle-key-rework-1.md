## Blocks

1. **#809 — one rule for "is this press one of these keys".** `store.ts` `fileListKey` (lines 280-293) and
   `editor/internal/historyKey.ts` `historyCommand` (lines 24-34) both run `keyOfEvent(event, platform)` and then
   `.some((key) => sameKey(key, pressed))` over an action's keys. Export one function from `ipc/keys.ts` (vision 2:
   `ipc/keys.ts` is the one source of what keys mean, #57):

   ```ts
   export function pressesKey(event: Pressed, keys: readonly Key[], platform: string): boolean;
   ```

   `Pressed` is the existing module type (`keys.ts`, the `Pick<KeyboardEvent, …>` that `keyOfEvent` takes): true
   when `keyOfEvent(event, platform)` is not null and equals one of `keys` by `sameKey`. Re-export it from
   `ipc/index.ts` only if that file is how `ui/` and `editor/` import `ipc` today (it is: add it there — this one
   line in `frontend/src/ipc/index.ts` is granted to you). `fileListKey` and `historyCommand` both call it; neither
   calls `keyOfEvent`/`sameKey` for this any more. Their other guards (`defaultPrevented`, the waiting question,
   `inTextField`) stay where they are and in the same order of effect.

2. **#811 — test the match at its boundaries.** In `keys.test.ts`: `pressesKey` with an empty list (false, for
   Ctrl+B and a plain `b`), with two keys (`Mod-b`, `Mod-Shift-l`: each press true, Ctrl+Shift+B false), and macOS ⌘B
   vs ⌃B against `Mod-b`. In `store.test.ts`: `{"toggle-file-list": []}` → Ctrl+B and a plain `b` neither flip nor
   call `preventDefault`; `{"toggle-file-list": ["Mod-b", "Mod-Shift-l"]}` → each key flips. `historyKey.test.ts`
   keeps passing unchanged (it pins undo/redo through the new function).
