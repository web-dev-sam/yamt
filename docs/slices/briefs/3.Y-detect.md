## Contract (fixed; you may add, never change)

```ts
// lsp/index.ts
export type ProjectLookups = Pick<ServerHost, "findProgram" | "projectFiles">;
export function detect(
  paths: readonly string[],
  lookups: ProjectLookups,
): Promise<readonly ServerSpec[]>;
//   paths: the repository's conflicted files (repo-relative, "/" separators)
//   one spec per detected tool per project folder, in a stable order (project folder, then oxfmt, oxlint,
//   TypeScript, eslint — the formatter first, since the first formatting spec formats); names unique
//   ("oxlint", or "oxlint (frontend)" when two projects use it)
//   a tool whose server program is missing gets `install` (InstallHint with the project's package manager)
export function addedSpecs(
  added: readonly AddedServer[],
  taken: readonly string[],
): readonly ServerSpec[];
//   name = the program's file name, "(2)" … when it repeats or is in `taken`; project "" (the repository root);
//   formats true (it formats only if the server also offers formatting); settings and initializationOptions null
```

## Behaviour (plan #70 and the design, settled)

1. **Project folders:** for each path, the nearest folder with a `package.json` walking up to the repository root
   (the file's own folder first); each distinct project is checked once; files with no project are served by no
   preset.
2. **Presets** (`presets.ts`, one table, the design's §1):
   - **oxlint**: `oxlint` found in the project (`findProgram(...).place === "Project"`); `oxlint --lsp`;
     `initializationOptions` `[{ workspaceUri, options: { run: "onType" } }]` (`workspaceUri` = the project folder's
     `file://` URI — reuse `lsp/internal/uri.ts`; the root comes from the host context, so take it as a parameter or
     build it at start — decide and report); file types js jsx mjs cjs ts tsx mts cts vue; formats false.
   - **oxfmt**: `oxfmt` found in the project; `oxfmt --lsp`; js jsx mjs cjs ts tsx mts cts json jsonc json5 css scss
     less html vue md yaml yml toml graphql; formats true.
   - **TypeScript**: a `tsconfig.json` or `jsconfig.json` in the project, and the project's `typescript` package
     (`node_modules/typescript/package.json` up to the root): major ≥ 7 → `tsc --lsp --stdio`; else
     `@typescript/native-preview` installed → `tsgo --lsp --stdio`; else (5.x/6.x) `typescript-language-server
     --stdio`, found in the project or on PATH, else `install` with reason `{ kind: "typescript", version }`; file
     types ts tsx mts cts js jsx mjs cjs; formats false.
   - **eslint**: a config (`eslint.config.{js,mjs,cjs,ts,mts,cts}` or `.eslintrc{,.js,.cjs,.json,.yaml,.yml}`) and
     the project's `node_modules/eslint/package.json`; `vscode-eslint-language-server --stdio` found in the project
     or on PATH, else `install` with reason `{ kind: "eslint" }`; settings `{ validate: "on", run: "onType" }`; file
     types js jsx mjs cjs ts tsx mts cts vue; formats false.
   - Global installs do not count for oxlint, oxfmt or TypeScript itself (detection means "this project uses it").
3. **Package manager** (`packageManager.ts`, for `InstallHint.manager`): the `packageManager` field of the project's
   `package.json` (`npm@…`, `pnpm@…`, `yarn@1…` → `yarn`, `yarn@2+` → `yarnBerry`, `bun@…`), else the lock file
   nearest the project folder up to the repository root (`pnpm-lock.yaml`, `yarn.lock` → `yarn`, `bun.lock` /
   `bun.lockb`, `package-lock.json`; `Text`, `TooLarge` and `NotText` all mean "exists"), else `null`.
   `InstallHint.folder` = the project folder, `package` and `program` per tool.
4. **Lookups:** batch `projectFiles` calls (one per project for its candidate files is fine); a malformed
   `package.json` counts as no field / no version; nothing throws — a lookup that rejects means "not found".

## Acceptance

1. Node tests with a fake `ProjectLookups` over an in-memory tree, each naming its rule: project folders (nested, at
   the root, none, two files in one project checked once); each preset detected and not detected (a global oxlint
   does not count; TypeScript 7 → `tsc`, native preview → `tsgo`, 5.9 with `typescript-language-server` in the
   project, on PATH, and missing → `install` with version "5.9.3"; eslint with and without its server, without a
   config, without the package); names unique across two projects; the package manager from every field form
   (`pnpm@12.0.0`, `yarn@1.22.0`, `yarn@4.1.0`, `npm@10`, `bun@1.1`), every lock file, nearest wins, a field beats a
   lock file, none → null; `addedSpecs` names, "(2)", a name already taken by a detected spec; a rejecting lookup.
2. Run `detect` once against this repository through a throwaway node script with a `child_process`/`fs` fake of the
   two lookups (same rules as the Rust host: `node_modules/.bin` up to the root, then PATH; repo-relative paths) for
   the paths `frontend/src/main.ts` and `crates/session/src/lib.rs`: paste the specs (expected: oxfmt, oxlint,
   TypeScript not installed with manager `pnpm` and folder `frontend`, eslint only if its server is found; nothing
   for the Rust file). Delete the script.
3. `pnpm -C frontend lint`, `typecheck`, `test`, `unused`, `fmt:check`: exit 0 (tails). `unused` may flag the new
   exports until the setup slice imports them: report it, add no artificial importer.
