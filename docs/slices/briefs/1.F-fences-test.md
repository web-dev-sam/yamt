# Slice 1.F — import-rule test (PM2 / PM3 / PM5 as a test, owed since retro 0.0)

Retro 0.0 approved moving the frontend import rules from "linter only" to "linter + test":
`frontend/scripts/fences.test.ts` lands with the next web slice. This is it. The test must
catch a violation even if someone edits the linter config, so it reads the source tree itself.

## Target

Owned: `frontend/scripts/fences.ts`, `frontend/scripts/fences.test.ts`.
Read-only: everything else, notably `frontend/src/**` (another agent is adding
`src/editor/**` and `src/ui/**` files at the same time — do not depend on their content),
`frontend/.oxlintrc.json` (the linter's version of the same rules), `.omp/**`, `docs/**`.
Non-goals: changing the linter config, the `bindings.ts` visibility rule (IPC2), a CLI entry or
package script, any `src/**` edit.

## Contract (fixed; you may add, never change)

```ts
// frontend/scripts/fences.ts
export type SourceFile = { readonly path: string; readonly text: string }; // path relative to frontend/, e.g. "src/ui/App.vue"
export type FenceViolation = { readonly rule: "PM2" | "PM3" | "PM5"; readonly file: string; readonly specifier: string; readonly reason: string };
export function findFenceViolations(files: readonly SourceFile[]): FenceViolation[];
export function readSourceTree(frontendRoot: string): SourceFile[]; // every src/**/*.{ts,vue} except src/ipc/bindings.ts
```

Rules (from `skill://project-map`; module = first directory under `src/`):

- **PM2** — a file under `src/ui/**` imports `@codemirror/*`, anything resolving into
  `src/editor/internal/**`, or anything resolving into `src/model/**`.
- **PM3** — a file under `src/editor/**`, `src/model/**` or `src/connectors/**` imports
  `vue`, `vue/*`, `@vue/*`, `@vueuse/*`, or `@tauri-apps/*`.
- **PM5** — (a) a file imports something resolving into another module's `internal/` directory
  (bare `…/internal` and `…/internal/x` both count; a module's own `internal/` is fine);
  (b) an import cycle among `src/**` files (report each cycle once, any member as `file`).

Imports to see: static `import`/`export … from`, `import type`, side-effect `import "x"`, and
dynamic `import("x")` with a string literal — in `.ts` files and in both `<script>` blocks of
`.vue` files. Relative specifiers resolve against the importing file, with or without extension
(`.ts`, `.vue`, `/index.ts`). Query suffixes (`?raw`, `?url`) are stripped before resolving.
Use the `typescript` compiler API (`ts.preProcessFile` or the AST) and `@vue/compiler-sfc`, both
already installed; no new dependency.

## Change

1. `fences.ts`: `findFenceViolations` is pure (no file-system access); `readSourceTree` is the
   only function that touches the disk.
2. `fences.test.ts` (Vitest `node` project, already includes `scripts/**/*.test.ts`):
   - one test runs `findFenceViolations(readSourceTree(<frontend dir>))` and expects `[]` — this
     is the guard on the real tree;
   - one test builds a temporary directory (`node:os` `tmpdir` + `mkdtemp`, removed afterwards)
     with `src/ui/probe.ts` (`import "@codemirror/state";`), `src/ui/Probe.vue` (`<script setup
     lang="ts">` importing `@codemirror/view`) and `src/ipc/bindings.ts` containing
     `import "./bindings";` (a self-cycle that must not be reported, because the file is skipped), and
     expects exactly two PM2 violations, one per probe file, through the same `readSourceTree` →
     `findFenceViolations` path;
   - failing-path tests with in-memory `SourceFile`s, one per rule shape: ui → `@codemirror/view`;
     ui → `../editor/internal/pane`; ui → `../model`; editor → `vue`; connectors → `@vueuse/core`;
     ui `.vue` file whose `<script setup>` imports `../editor/internal`; editor → `../ipc/internal/x`;
     a two-file cycle; a type-only import that violates PM2; a `?raw` import that does not violate
     anything; a module importing its own `./internal/x` (allowed). Each asserts the exact rule and file.
3. Run once at the end: `pnpm -C frontend lint && pnpm -C frontend typecheck && pnpm -C frontend test && pnpm -C frontend fmt:check`.
