# Slice 3.Q-switch-web — fix round 2 (`ServerSwitchWebR2`), the last round for this slice

Board "Servers and panes" row 5. Round 1 `e62d468`, fix round 1 `3bbb89b` (notes `.omp/run/notes/ServerSwitchWebR1.md`).
Row 7's WebKit run (`.omp/run/notes/ServerGroupHeader.md`, open risk 1) found that fix round 1's switch shows the wrong
state when the reply is fast:

> **#1288** (block) `frontend/src/ui/LanguageServerSettings.vue:84` — With `@click.prevent` on the native checkbox, a
> reply that resolves in a microtask (fixture mode's in-memory settings) lets Vue set `checked` before the browser undoes
> the cancelled click (microtasks run after each listener, before the dispatch ends and the canceled activation restores
> the old state), so the box shows "on" while the server is off (row muted, server gone from the header). The real app is
> right only because its IPC reply arrives in a later task. The shown state depends on reply timing.
> Fix: a `<button type="button" role="switch" :aria-checked="…">` in place of the native checkbox — nothing toggles
> natively, so `aria-checked` bound to `off` is the only writer, after a reply and after a failed write; a click calls
> `switchServer(spec.key, off.has(spec.key))`; Space and Enter work as on any button. Its accessible name stays the
> server's shown name (`aria-labelledby` the name, or the name inside the button); its look: a small box in the existing
> tokens, a lucide `check` while on (the same size and place as today's checkbox), the row muted while off as today.
