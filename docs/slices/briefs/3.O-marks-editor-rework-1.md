- **#1204** (`editor/internal/frame.ts:30`) — "Frame never uses its new `focus: SideFocus` part. It only passes it to

  its listed jobs (the per-frame paint and the rows/waves/anchors cache)." Fix: replace `focus` in `FrameParts` with

  Frame's lane callback calls `parts.jump(pane, target, this.layout().rows)` then `this.#scroll.follow(pane)`; Frame
  drops its `SideFocus` and `markJump` imports. Keep `editor/index.ts` ≤ 300 lines.
- **#1205** (`editor/theme.css:323`) — "The 4 px pick distance lives in two places: `PICK_DISTANCE_PX = 4` in
  `marks.ts:46`, which `tickAt` uses, and the literal `inset: -4px 0` of `.change-mark::before`." Fix: export the
  constant, set a custom property on each lane from it (as `strips.ts:101–103` does with `--strip-wave-hit`), CSS
  `inset: calc(-1 * var(--mark-pick)) 0`.
- **#1210** (`editor/internal/markJump.ts:59`) — "A problem tick whose problem starts exactly at the end of the last
  collapsed line (a zero-length diagnostic at a line end, e.g. a missing semicolon) leaves those lines collapsed and
  parks the cursor on the wave. The fold's hidden range ends at that line's end (`foldRuns.ts:37`). `foldSelection.ts`
  `holds` only reveals a cursor strictly inside the range." Fix: the first dispatch selects the whole line
  (`{ anchor: line.from, head: line.to }`: a non-empty selection inside a hidden range reveals), then the cursor at the
  place's start. Add a node test that fails before (a zero-length problem at the end of the last hidden line → the lines
  show), at the level where the rule can be tested without a DOM if one exists (`foldSelection`/`folds` state); else a
  WebKit step and say why.
- **#1211** (`editor/internal/markLanes.ts:97`) — "While Alt is held, a mouse-wheel gesture that starts with the pointer
  on a tick … scrolls nothing. The lane is a child of `view.dom` and a sibling of `scrollDOM`, so the browser finds no
  scrollable ancestor of the tick to scroll." Fix: a passive `wheel` listener on each lane (same abort signal) that
  forwards the deltas to that pane's `scrollDOM` (`scrollBy`, scaled by `deltaMode`: lines × `LINE_HEIGHT_PX`, pages ×
  `clientHeight`). Observe it in WebKit: Alt held, a wheel over a tick scrolls that pane and the others follow.
