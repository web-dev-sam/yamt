## Contract changes (approved by the orchestrator)

- `StoredSettings`: drop both `#[serde(default)]` attributes, so the generated TS fields are
  required in both directions. The file parser keeps defaulting a missing `theme`/`keys` itself.
- `Theme` gains `pub fn name(self) -> &'static str` ("dark" / "light"), with a unit test that it
  equals `serde_json::to_value(theme)`; `file.rs` and `start_script` use it (one spelling).

## Findings to fix (verbatim from the reviews, `.omp/run/findings.jsonl`)

1. **#666 / #667** (correctness + boundary, should): `#[serde(default)]` on `StoredSettings`'
   fields has no Rust user (`file.rs:106-118` defaults missing file entries itself); the generated
   TS reads `theme?: Theme; keys?: {…}` on a reply Rust always fills, and a `current` that leaves
   out `keys` would silently create a file from the defaults. → Contract change above.
2. **#668** (correctness, should): when the settings path is a dangling symlink (a dotfiles link
   whose target does not exist yet), `canonicalize` fails and the code falls back to the link path,
   `load` reads it as missing, and a read or change then renames a regular file over the link —
   against rule 6. → In `write_text`, when `fs::symlink_metadata(path)` says symlink, resolve it
   with `fs::read_link` (a relative target joined onto `path.parent()`) instead of
   `canonicalize`; test `a_dangling_settings_symlink_creates_its_target_and_stays_a_link`.
3. **#669** (correctness, nit): the `start_script` test uses `contains`, which would pass for the
   wrong element. → `assert_eq!` on the whole script for Light and Dark.
4. **#670** (boundary, should): `Loaded` keeps theme and keys twice (`entries["theme"/"keys"]` and
   `stored`), so the setters must keep both in step. → `parsed` removes `theme`/`keys` from the
   map with `from_value`; `Loaded { others: Map<String, Value>, stored: StoredSettings }` with one
   `fn entries(self) -> Map` used by `write_entries`; the setters change only `stored`; `put_keys`
   and the pairing comment go away.
5. **#671** (boundary, should): "dark"/"light" spelled in three places (serde's `rename_all`,
   `theme_name`, `start_script`). → `Theme::name` above.
6. **#672** (boundary, should): `start_theme<R: Runtime>` is generic but only built for
   `tauri::Wry`. → `&PathResolver<tauri::Wry>`, no type parameter.
