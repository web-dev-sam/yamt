# Slice 2.K — each file keeps its work while the app is open; nothing is lost without asking

Board v0 wave 2'. Owner decisions (plan §2 #37, #14): after the last file the app stays open; every
file of the merge stays in the list with its mark; clicking a resolved file shows its three panes
with the result as it was finished; the top bar says everything is resolved; each file's editor
state lives for the app's lifetime, so leaving an unfinished file and coming back keeps its work.
Today (`ui/store.ts` after 2.1) every `open` rebuilds the editor, so switching files throws the
middle pane's work away. WebStorm parity for the two confirmations (rule DR6; WebStorm 2026.2
`DiffBundle.properties`, quoted below).

Non-goals: keeping work across app restarts (#14); buttons for files the editor cannot show (#36,
wave 3); changing what "Mark resolved" writes.

## Behaviour (what the user sees)

1. **Switching files keeps the work.** Open file A, apply or type, scroll; open B; back to A: A's
   three panes are exactly as left — middle text, applied/ignored marks, scroll position, cursor,
   and Ctrl+Z still undoes the last action in A. Clicking the file that is already shown does
   nothing. Each file is loaded from the app once per session (until it is reset).
2. **Resolved files reopen as finished.** After "Mark resolved" the file stays shown and keeps its
   state; reopening it later shows the result as it was finished, with its undo history. Editing it
   again and pressing "Mark resolved" again writes the new text.
3. **Reset starts over.** "Reset file" throws away that file's panes and history and reloads it from
   git (as in 2.1); other files keep theirs.
4. **"Mark resolved" with work left asks first** (WebStorm `iterative.merge.dialog.*`): when the
   toolbar's summary still counts unprocessed changes or unresolved conflicts, a dialog titled
   "Unprocessed Changes" says "{N} unresolved conflict(s) and {M} unprocessed change(s) still remain.
   The file will be saved exactly as shown in the Result pane." (only the non-zero parts, singular /
   plural right), buttons "Save Current Result" and "Back to Resolving". Save → as today; Back →
   nothing written. With nothing left it saves without asking.
5. **Quitting with unsaved work asks first** (WebStorm `merge.dialog.exit.without.applying.changes.
   confirmation.message`, title `cancel.visual.merge.dialog.title`): closing the app window while any
   file's middle pane differs from what was loaded or last marked resolved opens "Cancel File
   Merge": "Are you sure you want to exit without applying changes?" plus the list of those files,
   buttons "Exit" and "Cancel". Exit → the app closes (exit status as 2.0 decides); Cancel → the
   window stays. No unsaved work → it closes at once (untouched unresolved files lose nothing: git
   keeps their conflicts). In a browser (fixtures) there is no close handling.
6. **Everything resolved.** When every file in the list is resolved, a bar at the top of the
   right-hand area (same place as the problem bar; the problem bar wins while it is shown) says
   "All files are resolved. Close the window to finish the merge." in the JetBrains New UI dark
   success-banner colours (Green1 `#253627` background, Green3 `#375239` border).
7. Dialogs look like JetBrains New UI dark dialogs (window background, separator border, title in
   the normal text colour, primary button `--color-primary`), are modal, Enter = the first button,
   Esc = the safe one ("Back to Resolving", "Cancel").
8. Findings from the 2.1 reviews, fixed here (quoted, with the decision):
   - #305 (correctness, should): "A non-Error invoke rejection (Tauri IPC-layer strings: invalid
     args, command not found, ACL denial) comes back from the generated typedError as
     {status:'error', error:<string>} and toResult passes it on as a SourceFailure; the bar shows only
     the raw string and logFailure spreads it into one field per character." **Decision:** in
     `ipc/tauri.ts` a non-object error becomes a thrown `Error`, so the store reports it as
     `Unexpected`; one `tauri.test.ts` case.
   - #306 (correctness, should): re-clicking the active row rebuilds the editor and drops edits.
     **Decision:** behaviour 1 above (re-clicking the shown file does nothing).
   - #308 (boundary, nit): narrow the `list` problem variant's cause to `Unexpected` only.

## Contract

- One mounted merge view (and its `MergeController`) per opened file; only the active one visible.
  Inactive views must keep their scroll position: not `display: none` (a hidden scroller loses
  `scrollTop` in WebKit) — prove it in the smoke. `editor/` stays unchanged (its public surface is
  enough: `resultText`, `summary`, `undo`, …).
- The store owns which files are opened and which is active (state ownership, architecture §5.1);
  views own their controllers. "Unsaved work" per file = the middle pane's `resultText()` differs
  from the text it had when loaded or last marked resolved; the store can ask every opened file at
  quit time without the views knowing about quitting.
- The pure decisions live in plain `.ts` files with tests: whether "Mark resolved" must ask (from
  `MergeSummary`), the "Unprocessed Changes" sentence (counts, singular/plural), whether quitting must
  ask (from the unsaved list).
- `ipc/window.ts` is the only file that touches `@tauri-apps/api/window`: it exports a function to
  run an async "may the window close?" check on the app's close request (the app keeps the window
  open when it answers no) — used only when `VITE_CHUNK_SOURCE === "tauri"`. The capability file
  grants exactly what that needs (e.g. `core:window:allow-destroy`, `core:event:allow-listen` for the
  app's one window label in `src-tauri/src/window.rs`); state the list.
- `createAppStore` and `useMergeController` get under the 40-line function limit, and the override
  in `.oxlintrc.json` is deleted (rules review P12); `pnpm lint` proves it.
- New colour tokens in `style.css` `@theme` (VU17): `--color-success` `#253627`,
  `--color-success-border` `#375239`.

## Tests

Behaviour, not wiring (`store.test.ts`'s fake source; new `.test.ts` next to the pure decisions):

- opening A, B, then A again loads each once and keeps both opened; re-clicking the active file
  loads nothing; reset of A reloads only A (new data object) and keeps B opened.
- after a successful "Mark resolved" the file stays opened and its saved text is the finished
  text; a failed one (2.1's problem bar) keeps the old saved text.
- the unsaved list names exactly the files whose text differs from loaded / last finished.
- "Mark resolved" asks iff the summary counts anything; the sentence carries the counts with the
  right singular/plural (compare by `toContain`, never whole strings).
- quitting asks iff the unsaved list is non-empty.

`editor/` is not touched, so its hand proofs do not apply; `just mutants` covers `ui/` and `ipc/`.
