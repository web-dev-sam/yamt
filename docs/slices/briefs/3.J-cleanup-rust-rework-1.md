## Facts (given)

- `MergeSession::abort_operation`/`continue_operation` re-read the stop first; another stop → `Err(StopMovedOn)`
  (`crates/session/src/operation.rs:149`, pinned by `crates/session/tests/operations.rs:110`).
- `on_worker` (`src-tauri/src/merge.rs` ~:150-172): `Ok((session, Err(error)))` puts `Merge::Held(session)` back;
  a panic sets `after_a_panic` (`moved_on(&session)`) and answers `StopMovedOn` (#1435).
- The window now takes every `StopMovedOn` to `nextStop`, which lists once and expects that list to open git's
  current stop. With the old session `Held`, `list_stop` answers `Listing::MovedOn` and the window ends the stop a
  second time, losing the moved-on notice (#1440).

## Change

1. In `on_worker`'s error arm: an `Err(yamt_session::Error::StopMovedOn)` from the worker sets `moved_on(&session)`
   (the same constructor the panic arm and Continue's `Stopped` use) and answers `StopMovedOn`; every other error keeps
   `Held(session)` as today. One match, no second copy of the `MovedOn` construction.
2. A `merge/tests.rs` case (or two): git moves on outside (`git rebase --continue` in the repository after resolving
   step 1 by hand, as the existing outside-move tests do), then `abort_operation` answers `StopMovedOn`, the state is
   `MovedOn` at the same root, and the next `list_stop` answers `Files` for the new stop; the same for
   `continue_operation`. Seen failing on `d4fa963` (state `Held`, `list_stop` answering `MovedOn`), then passing.
3. `src-tauri/AGENTS.md`: the worker sentence names this rule.
