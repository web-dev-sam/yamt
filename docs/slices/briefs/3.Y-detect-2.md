## Behaviour

1. **Ecosystems** (`lsp/internal/ecosystems.ts`, new, the one table; plan #72 "Projects per ecosystem", "Where
   programs are looked for"): node, python, rust, go, php, clang — each with its project rule (manifests tried in order;
   rust: the nearest `Cargo.toml` whose text has a `[workspace]` table line, else the nearest `Cargo.toml`; go:
   `go.work`, else `go.mod`; clang: `compile_commands.json`, `build/compile_commands.json` (project = the folder holding
   `build/`), `compile_flags.txt`, `.clangd`) and its `ProgramFolders` (project: node `node_modules/.bin`; python
   `.venv/bin`, `.venv/Scripts`, `venv/bin`, `venv/Scripts`; php `vendor/bin`. home: python `.local/bin`; rust
   `.cargo/bin`; go `go/bin`; php `.config/composer/vendor/bin`, `.composer/vendor/bin`, `.local/bin`). Folder walking
   exists once (today's `foldersUp`/`projectFolders` generalised), not per language.
2. **Which projects a path joins:** a path joins an ecosystem only when some preset of that ecosystem serves its file
   type (a `.ts` file under a Cargo workspace never brings rust-analyzer); its project there is that ecosystem's rule
   applied from the path's folder up to the root. Node keeps today's result for every path it handles today.
3. **Presets** (`presets.ts`, one table, spec order = table order, formatters first): plan #72's list without Vue,
   Deno and bash-language-server — oxfmt, Biome, oxlint, TypeScript, eslint, rust-analyzer, gopls, ruff, ty,
   basedpyright, pyright, PHP (Phpactor, else Intelephense), clangd — each with the command, sign, file types,
   formats rule, settings and `initializationOptions` of the design's table P (rust-analyzer `checkOnSave: false` in
   both; Phpactor `{ "language_server.enable_trust_check": false }` [INFERENCE that the dotted key is accepted at the
   top level of `initializationOptions`: check Phpactor's source or docs, report]). Specs carry their ecosystem's
   folders and are found with them.
4. **Counts as used** (plan #72): a config file, a config section (a line matching e.g. `^\[tool\.ruff` in
   `pyproject.toml`) or, for rust-analyzer, gopls, clangd and PHP, the ecosystem's manifest alone → the server counts
   wherever `findProgram` finds it (place `Project`, `Path` or `Home`), else the spec carries its install hint; a preset
   whose only sign is the program in the project (oxfmt, oxlint, Biome; ruff, ty, basedpyright when the project has no
   config for them) → only `place: "Project"` counts and nothing is shown otherwise. TypeScript and eslint keep their
   rules. PHP: the first of Phpactor, Intelephense that is found; neither → Phpactor's hint.
5. **Formats** (plan #72): Intelephense never; clangd only with `.clang-format` or `_clang-format` in the project
   folder or a parent up to the root; Phpactor never in this row (row 5 adds its fixer/phpcs rule); the rest as table P.
6. **Install hints:** python's manager from the lock file nearest the project folder up to the root (`uv.lock`,
   `poetry.lock`, `pdm.lock`), else null; rust-analyzer `{ kind: "rustup", component: "rust-analyzer" }`; gopls
   `{ kind: "go", module: "golang.org/x/tools/gopls@latest" }`; Phpactor `download` with the PHAR command from the
   design's install table and `needs: "PHP 8.2 or later"`; clangd `system`; ruff, ty, basedpyright, pyright `python`
   with their PyPI package names.
7. **Language ids** (`languageIds.ts`): php → php; pyi → python; c, h → c; cc, cpp, cxx, hh, hpp, hxx → cpp; bash →
   shellscript.
8. **Words** (`ui/serverText.ts`; every word stays there): `installText(hint)` per kind — node as today, plus the vue
   sentence "This project uses Vue; its .vue files need the package @vue/typescript-plugin in this project." with no
   PATH line; python: project command by manager (`uv add --dev`, `poetry add --group dev`, `pdm add -d`, none →
   `python -m pip install` with "In the project's virtual environment" and "Or the same with your package manager."),
   all-projects `uv tool install` for uv, else `pipx install`; rustup: one step `rustup component add <component>`;
   go: one step `go install <module>` and the line "It goes to Go's bin folder (usually ~/go/bin), where yamt looks too.";
   download: one step `command`, the `needs` line when not null; system: the line "Install <program> with your
   system's package manager." and no step. Every kind keeps "Or install it any other way that puts <program> on your
   PATH." (not vue) and the come-back line. Non-node kinds have no reason sentence. `InstallText`'s steps become a list.
9. **`ServerMenu.vue`:** renders a variable number of steps and the optional lines; nothing else changes.
