## Findings to fix (quoted, with the decision)

- #316 (correctness, **block**) + #319 (boundary, should): "The store can reach `active` = A while
  A has no view, and then clicking A does nothing. Two ways: (1) reset A, then quickly click B and A
  again while the reset IPC is in flight; the overtaken reset drops A's view … without reloading it.
  (2) A reset whose reload fails … the `path === active` early return makes clicking A a no-op."
  — "`active` and `opened` are two facts that can disagree … `load`'s replace branch is unreachable
  because reset always filters first." **Decision:** reset keeps the file in `opened` until its
  fresh data arrives and then replaces it in place (the existing replace branch becomes the live
  path; its comment becomes true); a failed or overtaken reload leaves the old view in place and the
  problem bar explains; the re-click early return applies only when the active path is also in
  `opened`. Store tests: reset A → open B → open A → resolve the reset → A shows (a view exists and
  `open('a.ts')` is a no-op only then); a failed reset reload keeps A's old view.
- #317 (correctness, should): "The 're-clicking the shown file loads nothing' assertion still passes
  with the `path === active` guard deleted … The guard's only observable effects (not clearing the
  problem bar, not superseding an in-flight load) are untested." **Decision:** add the test that
  re-clicks the shown file while another file's load is pending and asserts the pending load still
  wins (or while a problem shows and asserts it stays) — whichever the guard after #316 guarantees.
- #320 (boundary, should): "One file's 'saved baseline' lives in two places: `loaded` in
  useMergeController.ts and `state.finished` in the store … The store also keeps result text now."
  **Decision:** one baseline per file, held in `useMergeController` (non-reactive): set at load,
  replaced through `markSaved(text)` that the store calls on the tracked work after a successful
  finish; the tracked work exposes `unsaved(): boolean`; `State.finished` and its bookkeeping are
  deleted. The store never stores document text.
- #318 (correctness, nit): non-object errors (null, numbers) from the IPC layer also become a thrown
  `Error` in `ipc/tauri.ts`, not only strings; test case.
- #322 (boundary, should): the `ipc/tauri.ts` comment cites its source (`bindings.ts` `typedError`
  re-throws only `Error`s; Tauri rejects invalid arguments / unknown commands / ACL denials with a
  plain value).
- #323 (boundary, nit): `MergeView` takes `finish` and `reset` from `useAppStore()`; the two emits
  and `App.vue`'s forwarding go.
- #324 (boundary, nit): a detector for "only `ipc/window.ts` imports `@tauri-apps/api/window`":
  add `@tauri-apps/*` to the `src/ui/**` restricted-import patterns in `.oxlintrc.json` and to the
  fences in `frontend/scripts/fences.ts` (+ a `fences.test.ts` case).
