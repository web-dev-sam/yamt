## Blocks

1. **#815 (block) — tests the mutation run can see.** Stryker's vitest runner filters a mutant's tests by
   "describe test" while Vitest matches "describe > test", so every `describe()`/`it()` test is skipped during
   `just mutants` (fileTree.ts, folderIcon.ts, fileIcon.ts scored 0 kills; also the old #402). Rewrite
   `fileTree.test.ts`, `folderIcon.test.ts` and `fileIcon.test.ts` as top-level `test("…")` calls, the style of every
   other test in `src/` (prefix the old describe name into the test name where it helps, e.g. `"treeRows: …"`). Same
   assertions or stronger; none dropped.
2. **#813 — one module for the icon-table helpers.** Move `IconTable`, `IconRow`, `iconTable`, `lookup` out of
   `fileIcon.ts` into new `ui/iconTable.ts`; `fileIcon.ts` (file table + `fileIcon`) and `folderIcon.ts` (folder table +
   `folderIcon`) both import it. `fileIcon`, `ICON_ROWS`, `FOLDER_ICON_ROWS` keep their names. Test the lookup rules
   once in `iconTable.test.ts` if they are not already pinned through `fileIcon`/`folderIcon` (lower-case match,
   `Object.hasOwn`: `constructor`, `__proto__` miss).
3. **#812 — no formatter or lint pragma; one table layout.** Remove the `// oxfmt-ignore` above `FOLDER_ICON_ROWS`.
   Both icon tables use one layout that `oxfmt` formats and that keeps each file ≤ 300 lines without any
   `oxfmt-ignore`/`oxlint-disable`: e.g. each row's names as one space-separated string (`[Cargo, "cargo.lock
   cargo.toml"]`, split once inside `iconTable` when the table is built), applied to **both** `ICON_ROWS` and
   `FOLDER_ICON_ROWS` so there is one way to write a row (vision 2). Another layout is fine if it meets the same three
   conditions (formatted, one layout for both, under the cap); say which and why. Every name in both tables stays.
4. **#817 — one "last segment" rule for icons.** Contract change (orchestrator's decision): `folderIcon(path: string,
   open: boolean): Component` takes the folder's path ("packages/core/src") and matches its last segment itself, as
   `fileIcon(path)` does for files; FileTree.vue passes `row.path` and no longer slices. Share the last-segment step
   between the two lookups if it is the same code (in `iconTable.ts`). Test `folderIcon("packages/core/src", …)` →
   the src pair, `folderIcon("SRC", …)`, an unknown chain → the generic pair.
5. **#816 — reveal as a pure, tested rule.** Add to `fileTree.ts`: `export function revealed(closed:
   ReadonlySet<string>, path: string): ReadonlySet<string>` — `closed` without every folder in `folderPaths(path)`;
   returns the **same set object** when none of them was closed (so FileList writes nothing then). `FileList.vue`'s
   watch on `active` calls it and assigns only when the result differs. Tests: a closed chained row holding the file
   opens (key = the row's last folder, e.g. `packages/core/src` for `packages/core/src/a.ts`), an outer closed folder
   opens, unrelated closed folders stay, same object returned when nothing changes, a top-level file changes nothing.
6. **#814 — the indent numbers in one place.** The row padding and the guide offset come from one set of constants
   in `FileTree.vue`'s script (e.g. `rowPadding(depth)` beside `guideLeft(level)`, both from the same 8 px indent,
   8 px row padding and 16 px twistie); the template computes no px.
