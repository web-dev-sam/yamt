## Findings (verbatim) and what to do

1. **#636 (correctness, should, CM7)** `editor/internal/chunkField.ts:56` — "A Ctrl/Cmd drag ends
   with different spans than clicking each change. When an applied span's `to` touches a later
   zero-line span that the same action also applies, the composed one-shot mapping moves the earlier
   `to` past the later insertion. Ctrl/Cmd+ignore dragged over [conflict, touching zero-line
   conflict] gives spans [2,8),[8,8) where clicking each gives [2,5),[5,8). This path is new in this
   slice. The apply-drag variant over [LocalOnly, touching zero-line conflict] has the same problem
   and already existed before it." Fix: the action transaction carries the spans the chained
   throwaway state ends with (`chainedChanges` already builds that state), and the field takes them
   as given, as it takes `restoreSpans` on undo — one effect for both if the name reads right for
   both (e.g. `placeSpans`), not two. This covers bulk apply too (same `chainedChanges`). Keep the
   `setStatus` effects in the transaction (undo inversion and the side panes' status push stay as
   they are). Then `newlyApplied` has no case left (each throwaway update in the chain carries one
   change's `setStatus` with its own text change): revert `updateSpans`/`mapSpans` to the rule
   before this slice unless a test shows it is still needed — say which. Tests: keep the 'touching'
   case and add the two variants above, each asserting spans **and** text equal clicking one by one;
   show each fails without the fix. List in `deviations_from_brief` the CM1/CM2/CM7 wording that no
   longer matches (the orchestrator updates the rules).
2. **#632 (boundary, should, vision 2)** `editor/internal/gap.ts:35` — "Two modules state separately
   when a Ctrl/Cmd click also decides the other side: the hint uses `chunk.kind === "Conflict" &&
   isSideOpen(other)` here, the action uses `chunk.kind === "Conflict"` in sideDecisions
   (apply.ts:104) plus chainedChanges' isSideOpen guard, so a later change to one (e.g. including
   BothSame) silently makes the hint promise something the click does not do." Fix: one predicate
   next to the status rules (e.g. `decidesOtherSide(chunk, status, side)` in `status.ts`), used by
   both `otherWaits` and the reach-"conflict" branch of `sideDecisions`. The chained `isSideOpen`
   guard stays (the first half can close the other side, e.g. a zero-line other side).
3. **#633 (boundary, should, vision 2)** `editor/internal/sideFocus.ts:222` — "#pressed decides on
   its own whether modClicks will consume this press (`changeAt` hit && !readOnly && isModHeld).
   That is the rule duplication behind #606: only the hit test was unified, the consume condition
   still lives in two places and can drift again." Fix: in `#pressed`, skip when
   `!readOnly && modClickAction(...) !== null` — ask the same function `modClicks` acts on.
4. **#634 (boundary, should)** `editor/internal/strips.ts:147` + **#637 (correctness, should)**
   `editor/internal/gap.test.ts:166` — "The row-rebuild check compares derived title strings, so
   `titles` is threaded through PlacedArrow and ArrowRow and a titles object plus template strings
   is built for every visible arrow on every frame, when the input fact is the boolean
   `arrow.otherWaits`" / "The hint test checks only `arrowTitles`, so it still passes with today's
   `sameShape`: removing the title comparison at strips.ts:147-148 brings back the stale two-line
   title after the other side is ignored, and no node test fails." Fix: store `otherWaits` in the
   row, compare it in the reuse check, build titles only when a row is (re)built; make the reuse
   decision a pure exported function over plain data (mode, otherWaits, layout) and test that a row
   built while the other side waited is not reused once that side is ignored (fails if the
   `otherWaits` comparison is dropped).
5. **#635 (boundary, nit, CP1)** `editor/internal/modClick.ts:19` — "The comment's second clause
   ('on macOS Ctrl+click is the system's secondary click') now sits above isMac, but it justifies
   isModHeld's `metaKey && !ctrlKey` rule two functions below." Fix: keep the `browser.mac`
   reference above `isMac`, move the secondary-click clause back above `isModHeld`'s return.
6. **#638 (correctness, nit)** `editor/internal/historyKey.ts:10` — "`\p{M}` matches every combining
   mark … the name understates what falls back to the physical key." Fix: rename to
   `LETTER_OR_MARK`.
