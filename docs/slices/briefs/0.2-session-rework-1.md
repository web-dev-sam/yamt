## Contract change (orchestrator decision)

`UnsupportedReason` gains two variants: `Symlink` and `Submodule`. Today a submodule conflict
(mode `160000`, its stages hold commit oids) makes `open` fail for the **whole merge**, and a
symlink conflict (mode `120000`) is decoded as text and would be written back as a regular file.
Both become unsupported files the window lists with a reason, so the rest of the merge stays
usable (vision 4: the state is named, not inferred). Architecture §3.3/§4 already show the new
variants.

## Change

1. **Non-regular files** (`src/session.rs` decode path). Decide by the captured stages' `mode`
   before reading any blob: any stage with mode `0o160000` → `Submodule`; any with `0o120000` →
   `Symlink` (named `const`s, RS13). No `cat-file` read for those files. Tests: a merge with a
   submodule conflict and a symlink conflict next to a normal modify/modify file → `open`
   succeeds, `files()` reports `Submodule` / `Symlink`, `load`/`finish` return `Unsupported`, the
   normal file still loads. If the conflict-repo fixture cannot script a submodule conflict
   with plain git commands, extend it (it is yours).
2. **Status follows the index on reset** (`src/session.rs` ~145). Set `Unresolved` right after
   `restore_stages` succeeds, before `checkout_merge`; a failing `checkout -m` must not leave the
   file `Resolved` while git lists it as unmerged.
3. **Decode order across sides** (`src/session.rs` ~257). Today the checks stop at the first
   failing side and run per side, so a Latin-1 base plus a NUL-containing local reports `NonUtf8`.
   Run each check across all three sides in this order: NUL in the first 8000 bytes of any side →
   `Binary`; then any side over 8 MiB → `TooLarge`; then any side not UTF-8 → `NonUtf8`. Unit test
   with sides that fail differently (e.g. non-UTF-8 base, binary local → `Binary`).
4. **EOL from local when base is empty** (`src/session.rs` ~103, RK5). No test exercises it.
   Add a CRLF add/add file and assert `eol == CrLf`.
5. **Reset coverage** (`tests/finish_and_reset.rs` ~95). Also prove reset (a) of an add/add file
   after finish and (b) of a modify/modify file that was never finished; each asserts
   `ls-files -u` identical to before and `<<<<<<<` in the worktree (resolve-undo cleared where
   finish ran, as in test 8).
6. **One path lookup per call, no allocation** (`src/session.rs` ~126, ~139, ~160). Replace the
   `file()` / `file_mut()` pair with one free fn `find_file(files: &mut [FileState], path: &str)
   -> Result<&mut FileState>` (and an immutable twin only if `load` needs it), called once per
   method. Compare with `file.path.to_string_lossy() == path` (no `String` built per comparison);
   `display_path()` stays only for the DTOs.
7. **Cite the git fact** (`src/session.rs` ~141, CP1). The comment that `checkout -m` refuses
   one-sided paths gets its source on the same line (git's `builtin/checkout.c`, observed on git 2.56).
8. **`hash_object` reports failure** (`crates/conflict-repo/src/lib.rs` ~77). Missing stdin →
   error; non-zero exit → `Error::GitFailed` with stderr, as `git_ok` does. No silent `Ok("")`.
9. (nit) **Size boundary pinned** (`src/decode.rs` tests): exactly `MAX_TEXT_BYTES` decodes;
   `MAX_TEXT_BYTES + 1` is `TooLarge`.
10. (nit) **Guard reads as a guard** (`src/session.rs` ~127): rename `texts()` to `require_text()`.
11. (nit) **Plain grouping** (`src/session.rs` ~219): an edition-2024 let-chain
    (`if let Some((path, stages)) = groups.last_mut() && *path == entry.path { … } else { … }`)
    instead of the guarded `match` with a `Some(_) | None` arm.
