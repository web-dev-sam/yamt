# Slice 3.Y-folders — where a server's program is looked for: folder lists from the window, home folders after PATH

Board "Language server presets" row 2. Product rules: `docs/plan.md` §2 **#72** ("Where programs are looked for") and
**#70** (the host, program lookup). Design: `.omp/run/notes/PresetsDesign.md` option A, build "H". Facts with a source
are given; re-check only [INFERENCE].

Today `crates/lsp-host/src/program.rs` looks for a server's program in `node_modules/.bin` of the project and each
parent up to the repository root (place `Project`), then each PATH entry (place `Path`). Python virtualenvs
(`.venv/bin`), Composer's `vendor/bin` and the usual per-user install folders (`~/go/bin`, `~/.cargo/bin`,
`~/.local/bin`) are never searched, so a later build cannot detect ruff in a project's `.venv` or a `go install`ed
gopls. This slice makes the folder lists an argument the window passes (Rust learns folder names, never a server or a
language) and adds home folders after PATH. **No behaviour change for today's four presets**: the window passes
`node_modules/.bin` exactly where Rust used it before.

## Contract (fixed; you may add, never change)

```rust
// crates/lsp-host (re-exported from lib.rs)
/// Folders a server's program is looked for in besides PATH (plan §2 #72). Each entry is a relative path of plain
/// names separated by `/` ("node_modules/.bin", ".venv/Scripts", "go/bin"); an entry that is empty, absolute or
/// holds `..` or `.` is skipped.
#[derive(Clone, Debug, Default, PartialEq, Eq, Deserialize, specta::Type)]
pub struct ProgramFolders {
    /// Tried in the project folder, then each parent up to the repository root; within one folder in list order.
    pub project: Vec<String>,
    /// Tried after every PATH entry, relative to the user's home folder.
    pub home: Vec<String>,
}

pub struct ServerCommand { pub program: String, pub args: Vec<String>, pub project: String, pub folders: ProgramFolders }

pub enum ProgramPlace { Project, Path, Home }

impl Host {
    pub fn find_program(&self, program: &str, project: &str, folders: &ProgramFolders) -> ProgramFound;
}
// `start` looks the program up with `command.folders`. `NotFound.searched` lists every folder tried, in order.
// A program containing a path separator keeps today's rule (taken relative to the project, place Project).
// Unknown home folder: home entries are skipped.
```

```ts
// frontend/src/ipc/domain.ts (+ index.ts export)
export type ProgramFolders = { readonly project: readonly string[]; readonly home: readonly string[] };
// ServerCommand gains `folders: ProgramFolders` (readonly arrays, as `args` today)
// frontend/src/ipc/ServerHost.ts
findProgram(program: string, project: string, folders: ProgramFolders): Promise<ProgramFound>;
// frontend/src/lsp/internal/spec.ts
ServerSpec.folders: ProgramFolders;   // the start command carries it
// one constant for today's lookup, in one place inside lsp/internal/:
//   { project: ["node_modules/.bin"], home: [] }
// used by detection's findProgram calls, by every detected spec and by every added spec (addedSpecs)
```

## Change

1. `program.rs`: the fixed `BIN_FOLDER` goes; `folders(...)` builds the list from `ProgramFolders` (project entries per
   folder from the project up to the root, then PATH, then home entries joined to the home folder with place `Home`).
   Entry validation reuses or mirrors `files.rs`'s rule for repository paths (plain names only). The home folder comes
   from the standard library (no new crate); tests inject it the way `find_with_path` injects PATH.
2. `lib.rs`: `ProgramFolders`, `ServerCommand.folders`, `ProgramPlace::Home`, `find_program`'s new argument; `start`
   passes `command.folders`.
3. `src-tauri/src/servers.rs`: the `find_program` command takes `folders`; its tests follow.
4. Window: `ipc/` types and `tauri.ts`; `lsp/` passes the constant above everywhere `findProgram` is called and puts
   it on every spec; the start command sends `spec.folders`. Fake hosts and spec literals in tests follow.
5. `crates/lsp-host/AGENTS.md` and `frontend/src/lsp/AGENTS.md`: the lookup sentence.
