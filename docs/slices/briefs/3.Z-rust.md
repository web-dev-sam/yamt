// crates/session/src/waiting.rs (new), exported from lib.rs
/// What Save writes for this change while a side of it still waits (plan §2 #69).
#[derive(Clone, Debug, PartialEq, Eq, Serialize, specta::Type)]
#[serde(tag = "kind")]
pub enum Waiting {
    /// One side changed these lines, or both the same way: written applied, as git wrote it.
    SideLines,
    /// A conflict: `open`, the local section, `between` (base section if any, then the separator),
    /// the remote section, `close`. Lines without line breaks.
    Markers { open: String, between: Vec<String>, close: String },
    /// A region yamt could not place: written as the Result shows it.
    AsShown,
}
pub struct MarkerStyle { /* open, base: Option<_>, separator, close — the design's shape */ }
//   MarkerStyle::found_in(disk: &[u8], marker_size) -> first block git wrote at open, else fallback
//   MarkerStyle::fallback(marker_size)               -> labels ours/theirs, merge style

// merge_data.rs
pub struct MergeChunk { pub chunk: Chunk, pub middle: LineRange<MiddleLine>, pub words: WordChanges, pub waiting: Waiting }

## Change (the design's "Rust behaviour"; order is a suggestion)

1. `waiting.rs`: `Waiting`, `MarkerStyle` (`found_in` reads the first marker block of the at-open bytes with the
   file's `conflict-marker-size`, copying the open line, the diff3/zdiff3 base marker line if present, the separator
   and the close line exactly; `fallback` uses `ours`/`theirs` like `start.rs`'s `merge_file`).
2. `merge_data.rs` / `seed.rs`: every chunk gets `waiting`: one-sided and same-on-both chunks `SideLines`; a stages-view
   conflict `Markers` from the file's `MarkerStyle` (diff3 style: `between` holds the base marker line, the chunk's
   base lines, then the separator); a disk-view conflict at an exactly located block `Markers` copied from that
   block's own lines (`Block { whole, ours, theirs }`); an inexact block or raw region `AsShown`.
3. `disk.rs` / `open.rs` / `session.rs`: `AtOpen = Untouched(OnDisk) | Changed(OnDisk) | Unread`, set once in
   `open.rs` into `FileState.at_open`, never written again; `Seen::after_own_write(written)` (`ViewFromDisk` stays,
   `ViewFromStages`/`GitOutput` → `ViewFromStages`).
4. `writes.rs`: `save` = `finish` without `git add`: `require_text`, `changed_on_disk` (a disk change stops it and
   replies `ChangedOnDisk`, foreign bytes kept), `file_bytes_before_write` (`NotAFile` for a link or folder), skip the
   write when the bytes equal what yamt last saw, else `fs::write` with the best-effort put-back `finish` does, then
   `seen = seen.after_own_write(..)`; `settled` and `DiskVersion` unchanged; reply `Written { files }`; the write must
   never come back as a `DiskChange`. `finish` = the shared write + `git add` + its rollback (behaviour unchanged).
5. `reset` per the design's table: disk look first, `IndexBefore`, `restore_stages`, then the file from `at_open`
   (regular bytes written back, removing a link that now sits there; `Missing` removes the file; a folder is
   `NotAFile`, checked before touching the index; link, submodule, other entry or `Unread` → today's `checkout -m`
   when `can_rebuild_markers`, then `read_back`); a failed file write restores the index and the bytes from before
   (all or nothing); `seen` = `ViewFromStages(bytes)` for `Untouched`, `ViewFromDisk(bytes)` for `Changed`; status
   `Unresolved`.
6. `commands.rs`: `save_file` registered next to `finish_file`, plus a mock-runtime test (`tauri::test`, the pattern
   already in that file) that a save leaves the file listed conflicted.
7. `crates/cli/src/fixture.rs`: build merge data with `MarkerStyle::fallback` (fixtures have no git output on disk).
8. `crates/session/AGENTS.md`: the new module and the save/reset rules in its file list.

## Acceptance

1. `cargo nextest run -p yamt-session -p yamt-cli -p yamt-app` green, including the design's tests (real repositories
   from `conflict-repo`):
   - **S1** every golden case: save with everything waiting (a test-only splice that mirrors the window's builder:
     `SideLines` → the changed side's lines, `Markers` → open, local, between, remote, close; ~15 lines), then a new
     session's `open` + `refresh` + `load` finds the file untouched, or every `Conflict` back with the same local and
     remote ranges;
   - **S2** a half-decided conflict not edited comes back exactly placed; edited or ignored → one raw conflict with
     both sections in the file;
   - **S3** after `save`: `refresh().disk_changes == []`, `ls-files -u` unchanged, status `Unresolved`; a foreign
     write before `save` → `ChangedOnDisk`, foreign bytes kept; a stale version writes nothing; link or folder →
     `NotAFile`; identical bytes → the file's modification time unchanged;
   - **S4** reset after a save: bytes = at-open bytes, stages back, a later refresh shows no change;
   - **S5** run 1 saves S, run 2 saves S2 and resets → the file is S;
   - **S6** a file changed by hand before start resets to the hand-edited bytes, not git's conflict;
   - **S7** all or nothing: an `index.lock` leaves the file untouched; a failed file write restores the index;
   - **S8** unit: `MarkerStyle` from `tests/markers/style-{merge,diff3,zdiff3}.txt`, `marker-size-12.txt`, `crlf.txt`
     (add the samples you need); a seeded exact block's `Markers` plus its section lines rebuild `Block.whole`
     exactly.
     If S1/S2 show the [INFERENCE] about exact placement is wrong, say so with the failing case — do not weaken them.
2. `cargo clippy --workspace --all-targets -- -D warnings` and `cargo fmt --check` clean; `just arch-check` passes.
3. `just bindings` run locally shows `saveFile` and `waiting` in `bindings.ts` (report the diff lines; do not keep the
   generated file in your patch if your workspace cannot avoid it — say which).
