## Contract

Fixed (exists; you may add, never change): `MergeController`'s public members and types
(`frontend/src/editor/index.ts:36-43`, `:231-294`), `MergeHosts`, `MergeOptions`; `Pane`, `PaneViews`
(`internal/geometry.ts:10-11`); `ChunkState`/`isSideOpen` (`internal/status.ts`); CM1–CM14.

New, fixed for the next slice (names may be refined; report any change):

1. `connectors/index.ts` — the one source of the wave's numbers (WebStorm `DiffLineSeparatorRenderer`):
   `WAVE_STEP_PX = 5`, `WAVE_HALF_HEIGHT_PX = 3`, `WAVE_GAP_PX = 1` (period 4 steps = 20 px),
   `waveTile(): string` (the 20×8 tile path `M0 1 Q2.5 1 5 4 Q7.5 7 10 7 Q12.5 7 15 4 Q17.5 1 20 1`
   built from the constants) and `waveCenterY(lineHeight: number): number` (`(lineHeight − 2·3 − 2·1)/2
   - 3 + 1`= 10 for 20 px). The next slice adds`waveJoinPath` beside them.
2. `editor/internal/foldRuns.ts` — `Hidden = { from: DocPos; to: DocPos }` (whole lines: start of the
   first hidden line … end of the last), `FoldLevel = Readonly<Record<Pane, Hidden | null>>`,
   `Fold = { hidden: readonly FoldLevel[] }` (levels still hidden, outermost first; showing one drops
   it from the front), `foldRuns(chunks, docs): Fold[]` (chunks.length + 1 runs; run k sits before
   chunk k), and `displayed(fold, pane): Hidden | null` (the first non-null level of that pane).
   `DocPos`/`toDocPos` move from `chunkField.ts` to `internal/docPos.ts`.
3. `editor/internal/folds.ts` — the middle pane's `foldField(initial)` owns the runs (centre ranges
   mapped, sides' ranges fixed references), with `showFolds` (`{ run, keep }`, only ever shows);
   the sides mirror per-run hidden counts. The controller holds the field instance next to its chunk
   field; the frame code reads it through a getter `folds: () => readonly Fold[]`.
4. DOM: every wave element in a pane carries `data-fold-run="<run>"`; one hover owner
   (`editor/internal/folding.ts`) listens on all five hosts (`hosts.left/center/right` and both
   `hosts.strips`) by `closest("[data-fold-run]")`, toggles `fold-wave-hover` on every
   `[data-fold-run="<run>"]` in the five hosts on a hover change, exposes the hovered run for nodes
   created later, and turns a primary click on any such element into "show the next step of that run".
   So any strip node the next slice gives `data-fold-run` gets hover and click with no new listener.
5. The layout cache (`rowsChanged` or its successor) is dropped when the fold field's value changes.
6. The once-per-frame paint moves out of `index.ts` into `editor/internal/frame.ts` (design §Q9:
   `#frameId`, `#layoutCache`, `#repaint`, `#layout`, `#requestFrame`, the cancel in `destroy`) — a
   move, no new logic — so `index.ts` stays under oxlint's 300 lines.

## Change

1. `docPos.ts` (move), `foldRuns.ts` (WebStorm's builder line for line, design §Q1; constant
   `CONTEXT_LINES = 4`; the equal-level drop; ±∞ run ends at the file edges; `end − start ≥ 2`).
2. `folds.ts`: the field and effect, `mapHidden` (from `+1`, to `−1`, snapped inward to whole lines,
   fewer than 2 lines → null, nesting kept), the side count mirror and its push guard (as
   `pushCovered`), `revealKeep(levels, selection)` (an end of the main selection strictly inside
   `(from, to)`, or a non-empty selection within `[from, to]`). Field update order: map, then
   `showFolds`, then reveal on the transaction's selection. Never in history (only `placeSpans` is
   snapshotted, `chunkField.ts:120-125`): a click followed by `undo()` returns false.
3. `foldView.ts`: per run and pane, `Decoration.replace({ block: true, widget })` over the displayed
   range, from state (`EditorView.decorations.compute`); widget `estimatedHeight` = one exported
   `LINE_HEIGHT_PX` that also feeds `pane.ts:80`; `lineNumberWidgetMarker` → a gutter marker whose
   element is the wave overlay (`data-fold-run`, `role="button"`, an `aria-label` such as "Show
   unchanged lines"), absolutely placed across the gutter and the visible text area, not moving with
   horizontal scroll; the wave by a CSS mask of `waveTile()` (also the `-webkit-` form) over
   `background-color: var(--color-diff-wave)`, 1 px stroke, 2 px under `fold-wave-hover`,
   `cursor: pointer`; `EditorView.atomicRanges` over `[from, start of the next line)`. Verify the
   overlay in WebKit early (`100cqi` in a sticky gutter is [INFERENCE]); if it misbehaves, use the
   design's fallback (the wave in the content widget, `position: sticky` with the measured gutter
   offset) and say so.
4. `folding.ts`: the hover owner and the delegated pointer handling (design §Q5): `pointerover` /
   `pointerleave` set the hovered run; a primary `mousedown` on a wave calls `preventDefault`; a
   primary `click` dispatches `showFolds` to the middle (effects only, `addToHistory` false) and clears
   the hover; one `AbortController`, aborted in `destroy`. `sideFocus.ts` skips presses on a wave
   (next to its scrollbar test) so no side mark is set and no focus moves.
5. Reveal: the middle reveals inside its own field; a side's listener on a selection change computes
   `revealKeep` with that side's fixed ranges and sends one `showFolds` to the middle; the middle's
   push back carries no selection, so no loop. After a reveal from a side's find, the match is
   scrolled into view in that side.
6. `viewport.ts`: `visibleLines` skips widget blocks, so bulk apply never puts the cursor on hidden
   lines (design §Q8).
7. Wiring in `index.ts` (+ `frame.ts`), `pane.ts` (`LINE_HEIGHT_PX`, the three `Text`s built once
   before the views — `createPane` may take a `Text` —, gutter overflow, container); `style.css`:
   `--color-diff-wave` #555555 in `@theme static`, #d0d0d0 in `:root[data-theme="light"]` (VU17).
8. `editor/AGENTS.md` and the module list it keeps, if it lists internals.
