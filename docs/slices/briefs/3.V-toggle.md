## Behaviour (plan #68, settled)

1. Button "Collapse unchanged fragments", Lucide `chevrons-down-up`, after "Next change" and before the
   apply-all buttons; pressed look and `aria-pressed="true"` while on, distinct from hover, palette
   tokens only; leaves the keyboard where it was (`keepsKeyboard`, as the arrows); disabled when the other
   icon buttons are.
2. On by default. Off: every hidden line of every opened file shows in all three panes; no wave in any
   pane or strip. On: every run of every opened file collapses back to its start (all steps hidden),
   whatever clicks had shown; the runs are the ones the file has now (mapped through the middle's edits,
   never recomputed; lines typed inside a run hide with it). Files opened or rebuilt later follow the
   current state; a file opened while off still has its runs.
3. Stored in the window's storage under its own key; anything but a stored "off" means on; one choice for
   every file.
4. The right-click menu lists it third of seven, shown at first (a stored hidden list from before shows
   it); hiding it leaves collapsing as it is.
5. A cursor inside lines that get hidden moves to the start of the wave line hiding them; a selection with
   either end inside is dropped, leaving that cursor (IntelliJ `onFoldProcessingEnd`); in all three panes;
   #63's reveal rule must not reopen the run.
6. The middle pane's top line stays where it is on screen (the wave line takes its place when it gets
   hidden); the sides line up with the middle at once.
7. Not in the undo history: undo/redo after a toggle undo the earlier edit and leave the folds alone.
8. #63's rules keep working after any toggle: clicks show 4, 8, then all; find reveal; the delete filter at
   the wave; hover; joins in the strips.

## Contract (from the design, B1)

- `folds.ts`: the middle's field value `FoldState = { runs: readonly Fold[]; hiding: readonly number[] }`
  — every level of every run, never sliced, all mapped through each document change (the cascade that
  blanks levels inside one shrunk below 2 lines stays), plus per run how many innermost levels still
  hide. `setHiding: StateEffect<readonly number[]>` (replaces `showSideFolds`; the middle and the sides
  use it). `foldFields(runs, collapsed: boolean)`. `paneFolds` reads `innermost(levels, hiding[run])` for
  every pane. `showFolds{run, keep}` → `hiding[run] = min(hiding[run], keep)`. Off → all 0; on → each
  run's level count. `pushFolds` sends `setHiding` to the sides whenever `hiding` changes identity, and
  moves a side's cursor out of newly hidden lines when its counts grow.
- `foldSelection.ts` (pure): `leaveHidden(range, hidden)` (head strictly inside → the range's `from`;
  either end strictly inside → the selection is dropped, leaving that cursor); `holds` and `revealKeep`
  move here from `folds.ts`.
- The toggle's middle transaction: `{ effects: [setHiding, center.scrollSnapshot()], selection?,
  annotations: addToHistory.of(false) }`; `Folds.setCollapsed(on)`; `Frame.realign()` →
  `ScrollSync.follow("center")` so the next sync writes both sides even though the middle did not scroll.
- `ui/collapsing.ts`: `createCollapsing(storage?)` with `useStorage<boolean>("yamt.collapse.unchanged",
  true, …)`, `flush: "sync"`, `writeDefaults: false`, read rule `raw !== "false"`, `onError` →
  `log.warn("collapse.storage_failed", …)`; returns `{ collapsing, toggleCollapsing }`, spread into the
  store as `settingsActions` is.
- `useMergeController(data, hosts, { readOnly, preferences, collapsed })` (an options object, TS7);
  `MergeOptions.collapsed`; a `watch` calls `controller.setCollapsed(on)` on every live controller. Not
  through `Preferences` (re-applying preferences must never reset shown runs).
- `TOOLBAR_BUTTONS = ["previous", "next", "collapse", "applyLeft", "applyRight", "undo", "redo"]`, not in
  `HIDDEN_AT_FIRST`; `IconButton.pressed: Readonly<Ref<boolean>> | null` → `aria-pressed` (no attribute
  when null); the pressed classes follow `ChoiceButtons.vue`'s `aria-pressed:` variant.

## Acceptance

1. Node tests (the design's Part B table): off → no displayed range in any pane and zeros pushed to the
   sides; on after one or two clicks → every run equals a fresh open; lines typed above a run while off,
   then on → the shifted range hides; a level shrunk below 2 lines stays shown after on; a field built off
   has zero counts and on hides all; toggle then undo → the edit is undone, folds and `undoDepth`
   unchanged; clicks still go 4 → 8 → all after on; the delete filter still works at the wave;
   `leaveHidden` cases and a property test that `revealKeep` of its result is null for every selection in a
   small document; a side cursor moves when counts grow, not when they shrink; `follow("center")` writes
   both sides with the middle's `scrollTop` unchanged; storage: missing → on, `"false"` → off, `"true"`,
   `""`, `"no"`, `"[]"` → on, `getItem` throws → on and logged, toggling writes `"false"` then `"true"`, the
   default is not written; toolbar order and an old stored `["undo","redo"]` list showing the toggle;
   `toggleCollapsing` flips and persists; built off → the controller gets `collapsed: false`, flipping
   calls `setCollapsed` once per live controller, a preferences change never calls it. `editor/` is not
   mutated: hand a failing-path proof per rule (break it, paste the failing test, restore); `ui/` is
   mutated (`just mutants`), so its survivors on your lines are findings.
2. WebKit (fixture page, `pnpm -C frontend dev --port <own port>` + `just webdriver <own port>`,
   MiniBrowser, real pointer clicks and keys; `skill://verification`), on `vue-core-compiler-von` and a
   second file:
   1. Fresh: the toggle shows pressed, waves where #63 puts them.
   2. Click a wave twice in one file, open the second file, toggle off: no `.fold-wave` and no strip
      `[data-fold-run]` in either file; gutters number without gaps.
   3. Toggle on: wave counts and the line numbers around each wave equal those at a fresh open (vOn.ts:
      25|83 and 22|80 around the long run, `UnchangedVerify` step 3).
   4. While off, put the middle's cursor inside a run, toggle on: the cursor sits at the start of the wave
      line; a selection with one end inside collapses to that cursor; the wave does not reopen.
   5. The middle's first visible line number is the same before and after a toggle, and the sides' matching
      lines share its row at once.
   6. Toggle, then Ctrl+Z: the last edit is undone and the waves do not change.
   7. Right-click the toolbar: seven items, the third checked; hide the toggle: it is gone and the waves
      stay; show it again.
   8. Toggle off, reload the page: it stays off (and the stored value reads "false").
   9. After a toggle, clicks, find reveal and Delete at a wave behave as #63 says.
3. `pnpm -C frontend lint`, `typecheck`, `test`, `unused`, `fmt:check`, `sfc-order`: exit 0 (tails).
