  `<FileList>` — `v-show`, never `v-if`: the list stays mounted, so its width and (from the other slice) its
  view and open folders survive a hide.

## Behaviour (what the user sees)

1. Ctrl+B (Linux, Windows) or ⌘B (macOS) hides the file list; the merge area (or the settings view) takes the
   whole width at once; the 5 px gap beside the list goes with it. The same key shows it again, at the width it had
   (also after a drag of its edge).
2. It acts with the focus anywhere: a side pane, the Result pane, a pane's find box, the settings view (its path
   field too), nothing focused; with a choice file or the deleted-side view shown; with the settings view open.
3. It does nothing while a question waits (Mark resolved's or the close question), while the key dialog
   records a key (`KeyRecorder.vue:60-61` stops the event at its field — confirm in the run), or when another
   handler already took the key.
4. The press does nothing else: in the Result pane no text or format change and no undo entry; Ctrl+Z afterwards
   undoes what it undid before.
5. The keyboard stays where it was: a side pane that has the keyboard (outline shown) still has it after a hide and
   after a show; Up/Down then step as before.
6. Re-binding in the settings view's Keymap works at once (#57): the row "Toggle file list" under "Window" offers
   the usual menu; after changing it to another key, that key toggles and Ctrl/⌘B does nothing; giving Ctrl/⌘B to
   another action asks the clash question naming "Toggle file list"; Reset Shortcuts brings Ctrl/⌘B back. On macOS
   ⌃B (`MacCtrl-b`) is a different key from ⌘B.
7. Every start shows the list (nothing stored).
