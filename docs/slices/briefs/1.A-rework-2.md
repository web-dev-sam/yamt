## Findings (verbatim) and decisions

### #235 block (correctness) — a wordless closer pairs with short unrelated lines

> With words plus symbols on Dice ≥ 50, a wordless closer still pairs with short unrelated lines
> that share only closing punctuation. Hand-traced: `});`/`bar();` 2 of 3+4 = 57, `});`/`foo(a);`
> 50, `},`/`foo,` 50, `);`/`return;` 50. A gap holding base `});` and a new `bar();` therefore
> renders `[bar(]);` instead of the whole-line mark that N4 ('call sharing only closing symbols is
> new') prescribes. N4 passes only because `foo(a, b);` has 7 visible tokens.
>
> Fix: When exactly one line is wordless, pair it only if its whitespace-free text also occurs
> inside the other line's whitespace-free text (C31 `}`⊂`}else{`, C32 `});`⊂`},{passive});` still
> pair; `bar();`, `foo(a);`, `foo,`, `return;` do not), and add N-cases `});`→`bar();` and
> `},`→`foo,` to word_catalogue.rs and the demo.

**Decision:** as proposed.

- When exactly one line is wordless, it pairs only if its whitespace-free text occurs inside the
  other line's whitespace-free text. Keep the visible-token Dice as the score used to choose among
  candidates.
- Two wordless lines compare as before.
- New cases, each tested on both sides like the others and added to the demo:

| #   | base  | side     | expected side          |
| --- | ----- | -------- | ---------------------- |
| N5  | `});` | `bar();` | not paired: `[bar();]` |
| N6  | `},`  | `foo,`   | not paired: `[foo,]`   |
