This slice builds the protocol side only: the window speaks the language-server protocol to programs that a host
starts. The Rust host, the editor's underline and formatting, the status area and detection are later slices; they
build on the contract below, so keep it exactly.

```ts
// ipc/ServerHost.ts — what the Rust host will serve (its serde shapes, fixed now for the Rust slice too).
export type RunId = number & { readonly __brand: "RunId" };
export type ServerCommand = {
  readonly program: string;
  readonly args: readonly string[];
  readonly project: string;
};
//   project: repo-relative folder, "" = the repository root; the server's working directory.
export type HostEvent =
  | { readonly kind: "Message"; readonly text: string } // one JSON-RPC message body
  | { readonly kind: "Log"; readonly line: string } // one stderr line
  | { readonly kind: "Exited"; readonly code: number | null };
export type StartReply =
  | { readonly kind: "Started"; readonly run: RunId }
  | { readonly kind: "NotFound"; readonly program: string; readonly searched: readonly string[] }
  | { readonly kind: "SpawnFailed"; readonly program: string; readonly message: string }
  | { readonly kind: "OutsideRepository"; readonly project: string };
export type ServerContext = { readonly root: string | null; readonly process_id: number };
export type ProgramFound =
  | { readonly kind: "Found"; readonly path: string; readonly place: "Project" | "Path" }
  | { readonly kind: "NotFound"; readonly searched: readonly string[] };
export type ProjectFile =
  | { readonly kind: "Missing" }
  | { readonly kind: "Folder" }
  | { readonly kind: "Text"; readonly text: string }
  | { readonly kind: "TooLarge" }
  | { readonly kind: "NotText" };
export interface ServerHost {
  context(): Promise<ServerContext>;
  start(command: ServerCommand, onEvent: (event: HostEvent) => void): Promise<StartReply>;
  send(run: RunId, message: string): void; // fire and forget, framing is the host's
  stop(run: RunId): Promise<void>; // the host waits 2 s, then kills
  findProgram(program: string, project: string): Promise<ProgramFound>; // used by detection later
  projectFiles(paths: readonly string[]): Promise<readonly ProjectFile[]>; // used by detection later
}
```

```ts
}

export type FormatRefusal =
  | { readonly kind: "noFormatter" }
  | { readonly kind: "notRunning"; readonly server: string; readonly state: ServerState }
  | { readonly kind: "failed"; readonly server: string; readonly message: string }
  | { readonly kind: "timedOut"; readonly server: string };

  | { readonly kind: "formatted"; readonly server: string; readonly sent: string; readonly result: string }

  changed(): void;                             // the text changed: sync SYNC_DELAY_MS (300) after the last call

  constructor(host: ServerHost | null, timers?: /* injectable clock + setTimeout for tests */);

  open(doc: ResultDocument): OpenDocument;
  destroy(): Promise<void>;                    // stops every server (shutdown, exit, host.stop)
```

## Behaviour (plan #70 and the design, settled)

1. **Serving:** a spec serves a document when the path's extension is in `fileTypes` and the path lies under
   `project`. Every opened document is open on every spec that serves it (`didOpen` once the server is running), with
   `uri` = `file://` of `context().root` + path (percent-encoded per segment; Windows drive paths as
   `file:///C:/…`); URIs coming back are compared after decoding. `languageId` from the extension (a table in
   `internal/languageIds.ts`; unknown → the extension).
2. **Starting:** `startOnOpen` true → a stopped spec starts when the first document it serves is opened (or is already
   open at `setSpecs`); false → it stays stopped until `start(name)`. A spec with `install` is `notInstalled` and never
   started. `stop(name)` keeps it stopped until `start`/`restart`, even with `startOnOpen`. No host → every spec is
   `failed{noHost}`, `format` → `noFormatter`.
3. **`setSpecs` reconciles:** a spec equal (deep) to a running one keeps its connection; a changed or removed one is
   stopped (and its problems cleared); a new one follows rule 2. So re-running detection later never restarts
   unchanged servers, and a server installed since (its `install` now null) starts without Restart.
4. **Handshake:** `initialize` with `processId` from `context()`, `clientInfo` yamt, `rootUri` and one
   `workspaceFolders` entry for the project folder, `positionEncodings: ["utf-16"]`, `textDocument.synchronization`
   (`didSave: false`), `publishDiagnostics` (`versionSupport: true`), `textDocument.diagnostic`,
   `textDocument.formatting`, `workspace.configuration`, `workspace.workspaceFolders`,
   `workspace.diagnostics.refreshSupport`, and `spec.initializationOptions`; then `initialized`, then
   `workspace/didChangeConfiguration { settings }`. No reply within 30 s → `failed{timedOut}` and the run is stopped;
   an error reply → `failed{initializeFailed}`. Start replies map to `failed{notFound|spawnFailed|outsideRepository}`.
5. **Sync:** full text (`take(version)`, one version counter per document) `SYNC_DELAY_MS` after the last
   `changed()`; `didClose` on `close()` and before a server stops.
6. **Problems:** pushed `publishDiagnostics` and pulled `textDocument/diagnostic` (when the server advertises
   `diagnosticProvider`: after every sync of any document on that server, for every open document on it; one pull in
   flight per document per server; `previousResultId` sent; "unchanged" keeps the last items; a reply for an older
   version triggers a new pull; `workspace/diagnostic/refresh` → `null`, then pull again) land in one call,
   `showProblems(server, version, …)`. A push without a version counts as the latest version sent. A stopped,
   crashed or removed server's problems are cleared (`[]`).
7. **Requests from servers** (`internal/answers.ts`, pure, the design's table): `workspace/configuration` per item
   from `spec.settings` by section (`""`/absent = the whole value, dotted sections walk into it, missing → `null`);
   `client/registerCapability`, `client/unregisterCapability`, `window/workDoneProgress/create`, `*/refresh` → `null`;
   `workspace/workspaceFolders` → the project folder; `window/showMessageRequest` → `null` and logged;
   `workspace/applyEdit` → `{ applied: false }` and logged; anything else → error -32601 and logged.
   Notifications: `window/logMessage`, `window/showMessage` → the log; `$/progress`, `telemetry/event` dropped.
8. **Formatting:** the formatter for a document is the first spec in list order with `formats: true` that serves it
   and whose server advertised `documentFormattingProvider`; one still starting is waited for; none → `noFormatter`;
   one whose spec formats but is stopped, crashed or failed → `notRunning`. Sync now, send `textDocument/formatting`
   with the options, apply the returned edits to the text sent (`internal/edits.ts`, pure: UTF-16 positions, edits
   in reverse order, overlapping edits rejected as `failed`) → `formatted { sent, result }`, or `unchanged` when the
   result equals the text sent (or no edits). Error reply → `failed{message}`; 5 s in total (including the wait for a
   starting server) → `timedOut` (and `$/cancelRequest`).
9. **Stopping:** `shutdown` (2 s), `exit`, `host.stop(run)`; `stopping` → `stopped`. An `Exited` the client did not
   ask for → `crashed{code}`; pending requests fail; it stays crashed until `start`/`restart`.
10. **Log** per server name: `yamt` lines (start with the full command and project, exit code, unanswered requests,
    failures, time-outs), `stderr` lines, `server` lines (log/show messages). Not the protocol traffic. Kept across
    restarts, last 2,000 lines.
11. **Parsing:** every message from a server is external data: parsed once with valibot at `internal/messages.ts`
    (schemas for the subset read). A malformed message is logged and dropped, never thrown into the app.

## Change

1. `ipc/ServerHost.ts`, exported from `ipc/index.ts` (types only).
2. `lsp/internal/*.ts` — suggested split (one concern each, all ≤ 300 lines): `messages` (valibot + JSON-RPC
   framing of ids/requests), `connection` (requests with ids and time-outs, notifications, answering server
   requests), `answers`, `server` (one spec's lifecycle and documents), `documents`/`sync`, `problems` (push + pull
   into one slot), `edits`, `uri`, `languageIds`, `log`, `state`. `lsp/index.ts` = `LanguageServers` + the types.
3. `lsp/AGENTS.md`: what the module owns, its fence, the reading path of one message.
4. Fence: `lsp` is framework-free (`FRAMEWORK_FREE_MODULES`), and `lsp/` never imports `editor/`, `ui/`,
   `model/` or `connectors/` (may import `../ipc`); a failing-path test in `fences.test.ts` for each new rule.

## Acceptance

1. Node tests with a fake `ServerHost` that plays a scripted server (in-memory JSON-RPC peer, fake timers), each
   naming the rule it pins: serving by extension and folder; lazy start, `startOnOpen: false`, `install` → never
   started, user stop survives `setSpecs`; reconcile keeps an unchanged spec's run and starts a newly installed one;
   handshake contents; sync after 300 ms with the full text and rising versions (CRLF text arrives unchanged); push
   and pull into one slot, versioned and unversioned pushes, stale pull re-pulled, refresh; problems cleared on stop,
   crash and removal; the answers table row by row; formatting choice order, wait for a starting formatter,
   `noFormatter`, `notRunning`, `failed`, `timedOut` at 5 s total, `unchanged`, edits applied with UTF-16 positions
   (an emoji before the edit) and a multi-line edit; crash → `crashed{code}`, pending requests failed; log cap at
   2,000 and kept across restart; no host → `failed{noHost}`; a malformed message logged and dropped; URIs with
   spaces, `#`, non-ASCII and a Windows drive round-trip.
2. Smoke against real servers (throwaway script, not committed; paste its output): a node-side `ServerHost` built on
   `child_process` with `Content-Length` framing, driving `LanguageServers` with `frontend/node_modules/.bin/oxlint
   --lsp` (`initializationOptions` `[{ workspaceUri, options: { run: "onType" } }]`) and `oxfmt --lsp` on a temp
   project copied from `frontend/` config (`.oxlintrc.json`, `.oxfmtrc.json`): a file with `debugger;` shows an oxlint
   problem with its range; a badly formatted file comes back `formatted` with the expected `result`; stop ends both
   processes (no child left: `pgrep -f "oxlint --lsp"` empty).
3. `pnpm -C frontend lint`, `typecheck`, `test`, `unused`, `fmt:check`: exit 0 (tails).
