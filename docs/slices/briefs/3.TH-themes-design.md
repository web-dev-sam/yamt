## What each option must answer

1. **The theme list's one source** (vision 2): each theme's settings-file name (= `data-theme`), label, group,
   kind (dark/light), native background, shape. Where each fact lives (Rust enum and its generated union, a TS table
   exhaustive over that union, CSS blocks), and the check that proves them in step (the palette check extended: every
   theme has a block, no block without a theme, each background equals its block's `--color-window`). Today's
   `"dark"`/`"light"` keep their meaning (rule 1); what an unknown name in the file does today and after.
2. **Palettes**: where ten blocks live (one file or one per theme, imported how), how each value's source (rule 2)
   sits next to it (`skill://comment-policy`), the check that every block defines exactly the same tokens.
3. **Kind** in one place: `color-scheme`, CodeMirror's dark flag, the minimap's softening.
4. **Code colours** (rule 3): the token list — the fewest tokens that keep every distinction the four editors make
   (research table B's groups), the new `SYNTAX_COLOURS` (tag precedence: CodeMirror picks the most specific tag
   match — name the order that gives e.g. a function call its colour and not the variable's), the minimap on the same
   table, and how yamt Dark and Light stay exactly as today (their new tokens take the colour the tag gets now).
5. **Shapes** (rule 4): the shape values per theme (radius, gaps, outer padding) and how flat themes draw their thin
   lines (which element, which token, the editor's border colour from table D) without moving any layout: the file
   list's width handle, the pane dividers and their dots (plan §2 #84), the toolbar and banners on the frame.
6. **Change colours** (rule 5): table C's mappings onto `--color-chunk-*`/`--color-mark-*`, each gap settled or a
   question; a new token only if a kind cannot be expressed today.
7. **Picker**: the Theme section with five groups × Dark/Light (rule 1): the component(s), the control (today's
   `ChoiceButtons` or a radio group), the accessible names, the words.
8. **Start and switch** (rule 6): `main.ts`'s start parse for every name (an unknown attribute → yamt Dark), the
   native background on start and switch, fixture mode.
9. **Tests**: for each node unit test the plausible bug it catches (Rust: names, old names, backgrounds; the palette
   check's failing paths; the TS table's exhaustiveness by type). `ui/`, `editor/`, `scripts/` are mutated by
   `just mutants` (VF7). WebKit steps (fixture page, `just webdriver 4447`) proving computed colours equal the record
   per theme, and real-app steps (`just app-session`) for the start without a flash and the switch.
10. **Builds**: files per build, changed-line estimate (guide ≤ ~1,500 per build), disjoint ownership, the contract
    between them (the theme names and the token list fixed in this design, so builds can run side by side).
11. **Plan §2 #102**: a draft row (rule text, rejected alternatives, visions cited).
