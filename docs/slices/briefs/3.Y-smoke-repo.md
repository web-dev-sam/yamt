# Slice 3.Y-smoke-repo — the language-server smoke repository grows a project per language

Board "Language server presets" row 3. Product rules: `docs/plan.md` §2 **#72** (read it whole: the preset table, "counts
as used", projects per ecosystem, where programs are looked for, who formats, Vue, Phpactor). Design:
`.omp/run/notes/PresetsDesign.md` (table P, "Real-app check on this machine"), build "D". Facts with a source are given;
re-check only [INFERENCE].

`scripts/lsp-repo.sh [--servers] <dir>` builds a git repository left mid-merge for the real-app check of yamt's language
servers (today: `web/` with oxlint, oxfmt, TypeScript; ruff at the root as a server added by hand into the user's
settings file). Other builds now make yamt detect many more tools (plan #72); this slice gives the final real-app check
one repository that exercises every preset this machine can run. **yamt itself installs nothing** (#70): installing
servers here is a developer convenience into a cache folder, never into the user's own tool folders.

## Target

Owned: `scripts/lsp-repo.sh`, `scripts/lsp-servers.sh` (new), `.vscode/tasks.json`.

Read-only: everything else; `scripts/git-sandbox.sh` (use its helpers), `frontend/node_modules` (links as today).

Non-goals: any product code; changing the user's settings file, toolchains or PATH (`rustup component add`, `~/go/bin`,
`~/.local/bin` are off limits); a project per Settings-only preset (Deno, bash-language-server); a TypeScript 7 project.

## Change

1. **`scripts/lsp-servers.sh`** (sourced by `lsp-repo.sh --servers`, or runnable alone): installs pinned versions (pick
   the current release of each, write the versions as variables at the top, report them) into
   `${XDG_CACHE_HOME:-$HOME/.cache}/yamt/<tool>-<version>`, once (skip when present; the network is needed the first
   time), and fills one folder `<cache>/yamt/servers-path/` with links to the programs that are found on PATH in real
   use: typescript-language-server (as today), Intelephense (npm), pyright (npm), gopls (`GOBIN=… go install
   golang.org/x/tools/gopls@<v>`), rust-analyzer (the release binary `rust-analyzer-x86_64-unknown-linux-gnu.gz` from
   its GitHub releases; not rustup's proxy, which on this machine has no component), and — best effort — PHP: a static
   PHP CLI build plus the Phpactor PHAR (needs PHP 8.2; static-php-cli's prebuilt binaries [INFERENCE that they run
   here]) and `composer.phar`. If PHP cannot be made to run, print one line saying so and leave Phpactor out: the
   `php/` project then shows "Phpactor (not installed)" with its hint, which the check uses. Print the PATH line to
   launch yamt with (`PATH=<servers-path>:$PATH`).
2. **`scripts/lsp-repo.sh`** builds these projects, each with **one conflicted file**, and outside the conflict **one
   seeded problem** per server that serves it and **one badly formatted line** where a formatter runs. Pick seeds the
   server reports while you type, without saving (rust-analyzer runs without `cargo check`: e.g. a call with the wrong
   number of arguments; gopls: a type error; clangd: `int x = "s";`; Intelephense: an undefined function).
   - `web/` (today's, unchanged) plus a conflicted `src/App.vue` (`<script setup lang="ts">` with a type error), `vue`
     and `@vue/typescript-plugin` in `web/node_modules` (`package.json` files as copies, like `typescript`'s today:
     yamt reads nothing whose real path is outside the repository, `crates/lsp-host/src/files.rs`).
   - `biome/`: `package.json`, `biome.json`, `node_modules/.bin/biome` (npm into the cache, linked); a lint problem
     and a formatting fix.
   - `py/`: `pyproject.toml` with `[tool.ruff…]`, `[tool.ty]` and `[tool.basedpyright]`; `py/.venv` made with `uv`
     holding ruff, ty and basedpyright (pinned; `.venv` is git-ignored as today); ruff's lint and format, a type error
     both checkers report. The root `pyproject.toml` and `api/stats.py` move here.
   - `rs/`: a Cargo workspace (`[workspace]`, two member crates); the conflicted file in one member; no `target/`
     committed.
   - `go/`: `go.mod` and one package.
   - `php/`: `composer.json`, `phpstan.neon` and a phpcs config (`phpcs.xml`); with PHP available, PHPStan and phpcs
     installed into `php/vendor` through `composer.phar` (or linked from the cache).
   - `c/`: `compile_commands.json` (generated with absolute paths at build time) and `.clang-format`.
     `--servers` no longer writes the user's settings file (ruff is a preset now); drop `add_ruff_to_settings` and the jq
     need. Keep `expected_conflicts` exact, the script's header comment current (what each project holds and why), and
     no user or system git config (risk RK19, `git-sandbox.sh`).
3. **`.vscode/tasks.json`**: the language-server tasks launch the app with the servers-path line prepended to PATH.

## Acceptance

1. `scripts/lsp-repo.sh /tmp/yamt-test-presets-a` (no servers) and `scripts/lsp-repo.sh --servers
   /tmp/yamt-test-presets-b`: both exit 0; paste the printed conflicted paths (one per project as listed) and
   `git -C … ls-files -u | cut -f2 | sort -u`.
2. Each installed program answers `--version` (or its own version flag) from `servers-path` or the project's bin folder:
   paste one line each; PHP's line or the "PHP could not run" line.
3. Each seed is real, shown with the tool's own command line where one exists (not yamt): `ruff check` and
   `ruff format --diff` in `py/`, `biome lint`/`biome format` in `biome/`, `gofmt -l` and `go vet` in `go/`, `rustfmt
   --check` in `rs/`, `clang-format --dry-run` and `clangd --check=<file>` in `c/`, `tsc --noEmit -p web` for the `.ts`
   seed; paste the relevant lines. For servers with no command line (Intelephense, Vue's plugin) say which seed the final
   real-app check must see.
4. `shellcheck scripts/lsp-repo.sh scripts/lsp-servers.sh` clean if shellcheck is installed, else `bash -n` on both.
5. The user's settings file and `~/go/bin`, `~/.cargo/bin`, `~/.local/bin` are untouched (list them before/after).
