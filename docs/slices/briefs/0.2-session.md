# Slice 0.2 — session: open, list, load, finish, reset

The engine's state machine (architecture §3.3, plan §6 risks 1, 2, 4, 5). The only crate that
knows both `merge-core` and `gitio`. It captures every conflicted file's three index stages at
open, decodes blobs into text (or says why it can't), computes chunks, writes the result and
marks it resolved, and puts a conflict back on reset — even after `git add`.

## Contract (fixed; you may add private items, never change these)

```rust
// crates/session/src/lib.rs re-exports exactly these public items (RS10)
pub struct MergeSession { /* private: repo, files, blobs */ }

#[derive(Clone, Copy, Debug, PartialEq, Eq, serde::Serialize, specta::Type)]
pub enum Eol { Lf, CrLf, Mixed }

#[derive(Clone, Copy, Debug, PartialEq, Eq, serde::Serialize, specta::Type)]
pub enum FileStatus { Unresolved, Resolved }

#[derive(Clone, Copy, Debug, PartialEq, Eq, serde::Serialize, specta::Type)]
pub enum UnsupportedReason { Binary, NonUtf8, TooLarge, LocalDeleted, RemoteDeleted }

#[derive(Clone, Debug, PartialEq, Eq, serde::Serialize, specta::Type)]
pub struct FileEntry {
    pub path: String,
    pub status: FileStatus,
    pub unsupported: Option<UnsupportedReason>,   // None ⇔ the window can show it
}

#[derive(Clone, Debug, PartialEq, Eq, serde::Serialize, specta::Type)]
pub struct FileMergeData {
    pub path: String,
    pub base: String,               // "" when the file has no base (add/add)
    pub local: String,
    pub remote: String,
    pub eol: Eol,
    pub language: Option<String>,   // "typescript" for .ts/.tsx/.mts/.cts, else None
    pub chunks: Vec<merge_core::Chunk>,
}

impl MergeSession {
    pub fn open(cwd: &Path) -> Result<MergeSession>;                 // discover + capture all stages
    pub fn files(&self) -> Vec<FileEntry>;                           // git's path order
    pub fn load(&mut self, path: &str) -> Result<FileMergeData>;
    pub fn finish(&mut self, path: &str, result: &str) -> Result<()>; // write worktree bytes as given, git add, Resolved
    pub fn reset(&mut self, path: &str) -> Result<()>;               // restore captured stages, checkout -m, Unresolved
    pub fn remaining(&self) -> usize;                                // Unresolved count
}

#[derive(Debug, thiserror::Error)]
pub enum Error {
    Git(#[from] yamt_gitio::Error),
    UnknownPath { path: String },
    Unsupported { path: String, reason: UnsupportedReason },
    WriteFailed { path: String, source: std::io::Error },
}
pub type Result<T, E = Error> = std::result::Result<T, E>;
```

Decided here (the architecture doc is updated to match):

- `FileEntry.unsupported: Option<UnsupportedReason>` replaces the `supported: bool` + `reason?:
  string` pair in architecture §4: a "supported but with a reason" entry cannot be built
  (vision 4), and the window can switch over the reason exhaustively.
- `files()` returns owned `FileEntry` DTOs; the captured stages stay private (vision 5, RS1).
- `base` is a plain `String`, `""` for add/add (plan §6 risk 2; RK2): no `Option` to unwrap later.
- The chunk types are `merge-core`'s, reused (plan §2 #25).

## Change

1. **open**: `Repo::discover`, `unmerged()`, group entries by path into one private record per
   file holding `[Option<StageEntry>; 3]` for Base/Local/Remote **as captured now** (plan §6
   risk 1), status `Unresolved`, and its `UnsupportedReason` if one applies without reading
   content (Local or Remote stage missing → `LocalDeleted` / `RemoteDeleted`). Keep one
   `BlobReader` for the session.
2. **Decode** (on `open` for the list, cached or recomputed on `load` — your call, state it):
   any side with a NUL byte in its first 8000 bytes → `Binary` (git's own heuristic and
   length); any side not valid UTF-8 → `NonUtf8`; any side over 8 MiB → `TooLarge`. Module
   `const`s with those values (RS13). A non-UTF-8 path → `NonUtf8` (displayed lossily).
3. **Eol**: from base, or from local when base is empty: only `\r\n` line breaks → `CrLf`; only
   bare `\n` (or none) → `Lf`; both → `Mixed`. Text is never converted (RK5, RK16).
4. **load**: unknown path → `UnknownPath`; unsupported → `Unsupported`; else the three texts,
   `eol`, `language`, `compute_chunks(base, local, remote, &Options::default())`.
5. **finish**: write `result` bytes unchanged to `<root>/<path>` (`WriteFailed` on error),
   `Repo::add`, status `Resolved`.
6. **reset**: `restore_stages` with the stages captured at open, then `checkout_merge`, status
   `Unresolved` (RK1, RK17). Works whether or not the file was finished.
7. **Shared fixture crate** `crates/conflict-repo`: lift `crates/gitio/tests/fixtures/mod.rs`
   into its `lib.rs` (same isolation of the user's git config) and generalise it to several
   files in one merge: `conflict_repo(files: &[ConflictFile]) -> TempDir` with
   `ConflictFile { path, base: Option<&[u8]>, local: Option<&[u8]>, remote: Option<&[u8]> }`,
   plus the existing `git`, `git_ok`, `hash_object`. gitio's tests use it; delete their copy.
   One source for the scripted conflict (vision 2). Test-only crate: `unwrap`/`expect` are fine
   in it only if clippy's test allowances cover them — otherwise return `Result` or document why.
8. **Tests** in `crates/session/tests/` (RS11), each named by behaviour, oracle = git's own
   index and the worktree bytes:
   1. open on a merge with modify/modify, add/add, delete/modify, binary, non-UTF-8 and CRLF
      files lists each once, in git's order, all `Unresolved`, with the right `unsupported`;
      `remaining()` counts them.
   2. load modify/modify `.ts`: texts equal the three sides, `language == Some("typescript")`,
      `eol == Lf`, chunks equal `compute_chunks` on the same texts.
   3. load add/add: `base == ""`, exactly one `Conflict` chunk (RK2).
   4. load delete/modify → `Unsupported { reason: LocalDeleted | RemoteDeleted }` (RK3);
      binary → `Binary`, non-UTF-8 → `NonUtf8` (RK6); > 8 MiB → `TooLarge`.
   5. CRLF file: `eol == CrLf`; `finish` with the loaded local text → worktree bytes identical
      to that text, `\r\n` intact (RK5).
   6. mixed-EOL file: `eol == Mixed`; finish round-trips byte-identical (RK16).
   7. finish → `git ls-files -u` no longer lists the path, worktree == result, status
      `Resolved`, `remaining()` one lower.
   8. reset after finish → `git ls-files -u` output identical to before finish (RK1) and the
      worktree contains `<<<<<<<` (RK17); status `Unresolved`.
   9. unknown path → `UnknownPath` for load, finish and reset.

## Acceptance

- `cargo nextest run -p yamt-session -p yamt-gitio -p yamt-conflict-repo`,
  `cargo clippy -p yamt-session -p yamt-gitio -p yamt-conflict-repo --all-targets -- -D warnings`,
  `cargo fmt --all --check`, `bash scripts/arch-check.sh` exit 0 — paste tails.
- Failing-path proof for tests 8 and 5: the one-line change that breaks each (e.g. capture
  stages lazily at reset; normalise `\r\n` on finish), the failure line, then revert.
- **Smoke**: in a scratch repo under `/tmp` (your own `git -C /tmp/…` commands) with three
  conflicted files incl. one CRLF and one add/add, a throwaway example prints `files()`, then
  finishes one file and resets it; paste `git -C /tmp/… ls-files -u` before finish, after
  finish and after reset, and `head -c 200` of the worktree file after reset. Delete the
  throwaway afterwards.
