# Slice 2.C' — the window offers a two-button choice for files the editor cannot show

Board v0 wave 3, web half. Owner decision plan §2 #36 (suggestion approved 2026-10-10): files the
editor cannot show get a choice in the middle pane — two buttons, one sentence per side: binary or
non-UTF-8 → take left / take right; deleted on one side → take the kept side / delete; symlinks →
each side's link target shown as text, take left / take right (a link deleted on one side: keep /
delete); a file on one side and a link on the other → "a file, N lines" / "a link to …"; submodules
→ each side's commit id, take left / take right. The choice is written and staged like "Mark
resolved" and can be reset. Slice 2.C gave the app `describe_file(path) -> FileSides` and
`take_side(path, side) -> Vec<FileEntry>` (generated in `frontend/src/ipc/bindings.ts`). Today such
a file shows only the problem bar ("… cannot be shown in the editor: …").

## Target

Owned: `frontend/src/ui/**` (the icon files `FileList.vue`, `fileIcon.ts`, `fileIcon.test.ts` only for
the three icon leftovers below); `frontend/src/ipc/**` except `bindings.ts` (GENERATED);
`frontend/src/style.css` (tokens only, if any).
Read-only: `editor/**`, `connectors/**`, `model/**`, Rust, configs, `docs/**`, `.omp/**`.
Non-goals: choosing a side for text files (the editor does that); showing file contents for binary
files; rename conflicts.

## Behaviour (what the user sees)

- Clicking a file the editor cannot show (its list entry has an `unsupported` reason) shows, where
  the three panes are, a choice view with the same column headers as the panes ("Local (yours)" |
  "Remote (theirs)"; no middle column needed), and under each header one sentence for that side
  and one button:
  - sentences by what the side holds: "Deleted in this branch." / "A text file, 120 lines." / "A
    binary file, 12.4 KB." / "Not UTF-8 text, 3.1 KB." / "A text file too large to show, 9.2 MB." /
    "A symbolic link to `../shared/config.json`." / "Submodule at commit `1a2b3c4`." (short id, full
    id in the tooltip);
  - buttons: "Delete" on a deleted side; "Keep" on the other side when one side is deleted;
    otherwise "Take left" / "Take right".
- Pressing a button resolves the file at once (no extra question: the choice is the question): the
  list row gets its resolved mark; the view says which side was taken ("Resolved with the left
  version." / "Resolved by deleting the file.") and offers "Reset file", which brings the conflict
  back (the two buttons again). Failures show in the problem bar as today (2.1's `problemText`
  covers `Git`, `UnknownPath`, `WriteFailed`).
- At start-up the first file shown stays the first one the editor can show (2.1); when there is
  none, the first file's choice view.
- Once these files are resolved, the "All files are resolved" bar (2.K) appears as for text files.
- In the browser (fixtures) there are no such files; the fixture source answers `describeFile` for
  its text files and `takeSide` by marking the file resolved, so the store code paths run in tests.

## Contract

- `ChunkSource` gains `describeFile(path): Promise<SourceResult<FileSides>>` and
  `takeSide(path, side: Side): Promise<SourceResult<FileEntry[]>>`; `FileSides`, `SideContent` and
  `Side` reach `ui/` through `ipc/index.ts` (IPC2), the generated types re-exported as domain types
  (no brands needed). `createTauriSource` maps the two generated commands like the others (#305's
  string-error rule included).
- The words come from one pure function per concern in `ui/` (sentence for a `SideContent`, button
  label for a side given both sides, the "Resolved with …" line), exhaustive over `SideContent.kind`
  (TS3), with tests; the size formatting (B / KB / MB, one decimal) is part of it.
- The store knows per opened unsupported file its `FileSides` and, after a choice, which side was
  taken (for the "Resolved with …" line); a reset forgets both and describes again.
- Every function ≤ 40 lines, every non-test file ≤ 300 (oxlint).

## Leftovers from the previous review (quoted, with the decision)

- #344 (correctness, should): "The one real saved baseline (`saved` set when the editor is built,
  `unsaved()`, `markSaved`) has no automated test. store.test.ts's `fakeView` re-implements the same
  logic, so mutants … survive … `createController` only null-checks the hosts." **Decision:** add
  `ui/useMergeController.test.ts` (`vi.mock("../editor")` with a fake controller whose
  `resultText()` is settable, stub host refs, `effectScope()` + `nextTick`): unsaved false at build,
  true after an edit, false after `markSaved(current)`, false again after the data ref gets a new
  object.
- #345 (correctness, should): "When `resetFile` succeeds but the reload fails, the problem bar says
  'Could not reset a.ts'. Git has in fact reset the file …" **Decision:** report that reload failure
  as an `open` problem for the path ("Could not open a.ts: …"); update its test.
- #347 (correctness, nit): a reset landing in the background clears another file's problem.
  **Decision:** clear the problem in `load`; `reset` clears only a problem about its own path.
- #342 (boundary, should): `frontend/src/ui/AGENTS.md` line 1 lists `@tauri-apps/*` among ui/'s
  forbidden imports (it is enforced since the last round).
- #348 (icons, correctness, should): `meson.build` gets the Bazel icon through the lowercased
  `build` extension; the set has `file-type-meson`. **Decision:** a name row `meson.build` → Meson,
  and a test that it is not Bazel.
- #350 (icons, boundary, should): the icon tables are built from `[icon, keys]` rows, which loses
  the duplicate-key error a record literal gave. **Decision:** keep the rows; a test asserts every
  key appears exactly once across the name rows and across the extension rows.
- #349 (icons, nit): move the `BUILD` / `Jenkinsfile` assertions into their own case for literal
  file names.

## Tests

Behaviour, not wiring:

- sentence and label functions: every `SideContent` kind; "Keep"/"Delete" when one side is
  `Missing`; size formatting at the unit borders (1023 B, 1 KB, 1.5 MB).

  the list and records the side; failure → problem bar, list unchanged; reset → describes again.
- fixture source: `takeSide` marks resolved, unknown path → `UnknownPath`.
