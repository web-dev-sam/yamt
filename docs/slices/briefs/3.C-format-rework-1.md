## Blocks

1. **#1472** — `formatResult.ts:35`: valid input nested ~32k levels deep (2·d² indent characters from ~64 KiB of input)
   makes `Layout.toString` throw a `RangeError` out of `formatWith` (`:56`) after building gigabytes of indent; the
   contract says a `FormatResult` always comes back. Keep a running output length in `Layout` from piece lengths and
   `2 * depth` per line, without building the strings; past a `MAX_FORMATTED_CHARS` constant next to it, throw
   `FormatFailure("The formatted text is too long", at)` so `formatWith` answers `failed` and the module never throws.
2. **#1473 (TS15)** — `NUMBER`, `ESCAPE` (`formatJson.ts:5-6`) and `NAME` (`formatXml.ts:17`) are module-level sticky
   regexes whose `lastIndex` each use mutates (`formatJson.ts:105,133`, `formatXml.ts:236`). Make each a field of its
   scanner instance (`readonly #number = /…/y;` in the JSON scan, `readonly #name = /…/y;` in the XML scan), so its
   `lastIndex` belongs to one scan.
3. **#1477** — `formatXml.ts:112`: inside an element a CDATA section is not counted as text, so `<a><b/><![CDATA[x]]></a>`
   is re-laid out with whitespace added to the element's character data. XML 1.0 §2.7: CDATA sections are character
   data, so this is mixed content, which Behaviour 3 keeps verbatim; the scanner already treats CDATA as text outside
   the root (`this.#open.length === 0` → `#holdText`). Count every CDATA as the parent's text; an element whose content
   is only CDATA and text stays on one line as before. Fix the DOCTYPE test's `<note>` expectation to verbatim and add a
   test for `<a><b/><![CDATA[x]]></a>` unchanged.
4. **#1478** — `formatXml.ts:140` `#doctypeEnd` skips comments inside the internal subset but not processing
   instructions, which the grammar allows there: `<!DOCTYPE a [<?p ]?>]><a/>` ends the DOCTYPE at the PI's `?>`, and
   `<!DOCTYPE a [<?p it's?>]><a/>` reads the apostrophe as a quote ("Unterminated DOCTYPE"). Skip a PI inside the subset
   as a comment is skipped. Test both documents.
5. **#1479** — `detectLanguage` skips a leading U+FEFF and answers JSON/XML, but both formatters then fail at line 1 on
   the same text ("Expected a value", "Text outside the root element"); once row 8 wires Auto and Format, text Auto
   just classified fails to format. In `formatWith`, a leading U+FEFF is kept as the output's first character and the
   scan starts after it; test JSON and XML with a BOM (formatted and `unchanged`).
