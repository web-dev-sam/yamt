# Slice 3.Y-settings-ipc — the window carries the `languageServers` settings entry

Board "Language servers and saving" row 6b. Product rules: `docs/plan.md` §2 **#67**, **#70** (the answer per
repository and servers added by hand live in the per-user settings file). The Rust half is committed (`99f7c07`,
notes `.omp/run/notes/LspHost.md`): `ipc/bindings.ts` now has `StoredSettings.languageServers:
LanguageServerSettings { repositories: { [root]: RepositoryAnswer }, added: AddedServer[] }`,
`RepositoryAnswer = "start" | "dontStart"`, `AddedServer = { command: string[], fileTypes: string[] }`, and the
commands `setServerAnswer(current, answer | null)` (keyed by the host's repository root; `null` forgets) and
`setAddedServers(current, added)`, both answering `SettingsRead`. Since then `pnpm -C frontend typecheck` fails
wherever the window builds a `StoredSettings` (`ui/settings.ts`, `ipc/fixtureSettings.ts`, tests). This slice
carries the entry through the window's settings, so the tree is green and the setup build later only calls two
actions.

## Target

Owned: `frontend/src/ipc/ChunkSource.ts`, `tauri.ts`, `tauri.test.ts`, `fixtureSettings.ts`,
`fixtureSettings.test.ts`, `index.ts` (exports only); `frontend/src/ui/settings.ts`, `settings.test.ts`,
`store.test.ts` (test data only).

Read-only: everything else — `editor/**` and `ui/MergeView.vue`, `ui/useMergeController.ts` (another build owns them
now), `lsp/**`, `ipc/bindings.ts` (generated), `ipc/ServerHost.ts`.

Non-goals: the start question, the Settings section, detection, any use of the answer; the server commands
(`startServer` …; a later build maps them).

## Contract (fixed)

```ts
// ipc/ChunkSource.ts — SettingsSource gains
setServerAnswer(current: StoredSettings, answer: RepositoryAnswer | null): Promise<SourceResult<SettingsRead>>;
setAddedServers(current: StoredSettings, added: readonly AddedServer[]): Promise<SourceResult<SettingsRead>>;
// ipc/index.ts exports the domain types RepositoryAnswer, AddedServer, LanguageServerSettings
// ui/settings.ts — SettingsInUse carries `languageServers: LanguageServerSettings` (from the file; empty
//   `{ repositories: {}, added: [] }` when the file has none), sent back in every `current`; SettingsActions gains
setServerAnswer(answer: RepositoryAnswer | null): Promise<void>;
setAddedServers(added: readonly AddedServer[]): Promise<void>;
```

## Change

1. `ChunkSource.ts`, `tauri.ts`: the two methods mapped onto `commands.setServerAnswer` / `setAddedServers` like
   `setKeys`; `index.ts` exports the three types.
2. `fixtureSettings.ts`: `copied` copies `languageServers` deeply; `setServerAnswer` stores under the fixture's
   repository key `"/fixture/repository"` (or removes it for `null`); `setAddedServers` replaces the list.
3. `ui/settings.ts`: the entry in `SettingsInUse`, in `storedSettings(...)`, in what a load reads; the two actions on
   the existing `send` pattern (errors reported as the other settings actions report them).
4. Test data in `tauri.test.ts`, `fixtureSettings.test.ts`, `store.test.ts` gains the entry.

## Acceptance

1. Node tests, each naming its rule: an answer set, replaced and forgotten round-trips through the fixture source
   and comes back in `SettingsRead.stored`; added servers replace the list; a load of a file without the entry gives
   the empty entry; the entry survives a theme change (sent back in `current`); `tauri.test.ts`: both methods pass
   their arguments and return the reply or the app's error.
2. `pnpm -C frontend typecheck`, `lint`, `test`, `unused`, `fmt:check`: exit 0 (tails). `ipc/*.ts` and `ui/*.ts`
   are mutation-tested.
