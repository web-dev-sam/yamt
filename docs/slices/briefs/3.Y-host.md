The window already speaks the protocol (`frontend/src/lsp/`, row 4) through the interface
`frontend/src/ipc/ServerHost.ts`. This slice serves that interface from Rust: it starts programs, frames bytes, and
stops them. Rust never parses a server message and never learns a server's name.

## Contract (fixed; the window's `ipc/ServerHost.ts` already uses these shapes)

```rust
// crates/lsp-host (serde + specta; tag = "kind" on enums with data)
pub struct RunId(u32);                                   // TS: number (branded in the window)
pub struct ServerCommand { pub program: String, pub args: Vec<String>, pub project: String }
//   project: repo-relative folder ("" = root, "/" separators); the program's working directory
pub enum HostEvent { Message { text: String }, Log { line: String }, Exited { code: Option<i32> } }
pub enum StartReply {
    Started { run: RunId },
    NotFound { program: String, searched: Vec<String> },
    SpawnFailed { program: String, message: String },
    OutsideRepository { project: String },
}
pub struct ServerContext { pub root: Option<String>, pub process_id: u32 }   // root None: not UTF-8
pub enum ProgramPlace { Project, Path }                   // TS: "Project" | "Path"
pub enum ProgramFound { Found { path: String, place: ProgramPlace }, NotFound { searched: Vec<String> } }
pub enum ProjectFile { Missing, Folder, Text { text: String }, TooLarge, NotText }
```

```
servers_context()                                        -> ServerContext
start_server(command: ServerCommand, events: Channel<HostEvent>) -> StartReply
send_to_server(run: RunId, message: String)              -> ()     queues one message; never blocks; unknown run ignored
stop_server(run: RunId)                                  -> ()     signals and returns at once; `Exited` follows on the channel
find_program(program: String, project: String)           -> ProgramFound
project_files(paths: Vec<String>)                        -> Vec<ProjectFile>   one per path, same order
set_server_answer(current: StoredSettings, answer: Option<RepositoryAnswer>) -> Result<SettingsRead, IpcError>
set_added_servers(current: StoredSettings, added: Vec<AddedServer>)          -> Result<SettingsRead, IpcError>
```

```rust
// crates/settings — StoredSettings gains one entry; file key "languageServers"
pub struct LanguageServerSettings { pub repositories: BTreeMap<String, RepositoryAnswer>, pub added: Vec<AddedServer> }
pub enum RepositoryAnswer { Start, DontStart }            // file and IPC: "start" | "dontStart"
pub struct AddedServer { pub command: Vec<String>, pub file_types: Vec<String> }   // file and IPC: "fileTypes"
```

The settings types serialize the same way to the file and over IPC (they are one serde): `languageServers`,
`fileTypes`, `"start"`/`"dontStart"`. `set_server_answer` keys the answer by the host's repository root — the exact
string `servers_context().root` gives; `None` forgets it (the question comes back). A malformed entry is a broken
file, exactly as a wrong `theme` is today.

## Behaviour (the design's §2 item 2, settled)

1. **Threads per run, std only:** a run thread owns the `Child` and waits on a control channel for `Stop` or
   "output closed", then waits up to 2 s for the child to exit, kills, reaps and sends `Exited`; a writer thread owns
   stdin and writes queued messages as `Content-Length: N\r\n\r\n` frames (a blocked write never blocks a stop: the
   kill breaks the pipe); a stdout reader parses frames (headers case-insensitive, other headers ignored) and sends
   `Message`, stopping the run with a log line above 64 MiB; a stderr reader sends `Log` lines, each cut at 8 KiB.
   No `Arc`, no async. `Exited` is sent exactly once per run, also after `stop_server`.
2. **The app:** `src-tauri` manages a `Mutex<Host>` beside `Mutex<MergeSession>`; the two are never locked together
   (architecture §7's one-`Mutex` rule becomes two, never nested — say so in `src-tauri/AGENTS.md`). `start_server`
   forwards the run's std channel into the Tauri `Channel` on a small thread; when a send fails (the page is gone or
   reloaded), the run stops itself. After `run_return`, `stop_all()` signals every run and joins each, so no child
   outlives a normal close. Commands stay thin (IPC5).
3. **Program lookup** (`program.rs`, shared by `start_server` and `find_program`, so "found" and "can start" never
   disagree): a program with a path separator is taken relative to the project folder; otherwise
   `<project>/node_modules/.bin`, then each parent's `node_modules/.bin` up to the repository root (`place: Project`),
   then each `PATH` entry (`place: Path`). Windows: try `PATHEXT` extensions, skip files without one; spawn with
   `CREATE_NO_WINDOW` (`std::os::windows::process::CommandExt::creation_flags`, no `unsafe`) so no console flashes.
   `NotFound` lists every folder searched, in order. A project outside the repository → `OutsideRepository`.
4. **Spawn:** working directory = the project folder; the environment passes through unchanged; stdin, stdout,
   stderr piped. Start failures are replies, never `IpcError`s.
5. **`project_files`:** repo-relative paths; a path outside the repository (after `..` or a link) answers `Missing`;
   text up to 64 KiB (`TooLarge` above, `NotText` when not UTF-8).
6. **`servers_context`:** the repository root as a string (`None` when not UTF-8) and `std::process::id()`.

## Acceptance

1. `cargo nextest run -p yamt-lsp-host -p yamt-settings -p yamt-app` green, with tests against `lsp-echo` (a real
   child process): framing round trip incl. a message split across reads, several messages in one read, a
   multi-byte UTF-8 body; stderr lines arrive as `Log`, a long line cut at 8 KiB; `stop` → `Exited` within 2 s for a
   cooperative server and by kill for one that ignores it, exactly one `Exited`; the server exiting by itself →
   `Exited { code }`; a dropped event receiver stops the run; `stop_all` leaves no child (check the pid is gone);
   program lookup order project → parents → PATH with `searched` in order, a path-separator program relative to the
   project, a project outside the repository; Windows-only `PATHEXT` cases gated `#[cfg(windows)]`;
   `project_files` cases (missing, folder, text, 64 KiB edge, not UTF-8, outside via `..`); settings: answer set,
   replaced, forgotten, added servers set, a malformed `languageServers` → broken file, an old file without the
   entry reads as empty; a mock-runtime command test (the `tauri::test` pattern in `commands.rs`) for `find_program`
   and `project_files`.
2. `cargo clippy --workspace --all-targets --features yamt-app/bindings -- -D warnings`, `cargo fmt --all --check`,
   `just arch-check` (and a failing-path check of each new arch rule: break it, paste the failure, restore).
3. `just bindings` run locally: report the new types and commands as they appear in `bindings.ts`; they must match
   `frontend/src/ipc/ServerHost.ts`'s shapes field for field (`process_id`, `kind` tags, `"Project" | "Path"`).
