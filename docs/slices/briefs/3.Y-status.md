## Contract (fixed; you may add, never change)

```ts
// ipc: the window's ServerHost served by the app; null in fixture mode
createTauriServerHost(): ServerHost            // exported from ipc/index.ts; Channel per start, RunId branded by guard in domain.ts
// ServerHost.ts's data types become re-exports of the generated ones (one source of truth; shapes are identical)
// ui
type Screen = { readonly kind: "files" } | { readonly kind: "settings" } | { readonly kind: "serverLog"; readonly name: string };
store.screen: Readonly<ShallowRef<Screen>>     // replaces settingsOpen (clean cutover: App.vue, SettingsButton, tests)

```

## Behaviour (decided by the orchestrator as owner, #876: a clean experience; recorded in plan #70)

1. **Placement:** `ServerStatus.vue` directly left of `SettingsButton` in all three header rows (`MergeToolbar.vue`,
   `ChoiceView.vue`, `MergeView.vue`'s read-only header); the gear's `ml-auto` moves onto the status area so the pair
   sits at the right end. Hidden entirely when there are no specs.
2. **What it shows**, compact, muted text, palette tokens only:
   - only in `MergeToolbar.vue` (an editable shown file): the shown file's problem counts — error icon and count,
     warning icon and count (Lucide icons, the counts from `MergeHandle.problems`); shown when some running server
     serves the file, zeros included; hidden otherwise;
   - only in `MergeToolbar.vue`: after a Save of the shown file whose format outcome is `notRunning`, `failed`,
     `timedOut` or `changedMeanwhile`, one warning line ("Not formatted: oxfmt is not running", "Not formatted: oxfmt
     failed: <message>", "Not formatted: oxfmt did not answer in time", "Not formatted: the Result changed while
     oxfmt was formatting") until the next Save of that file; `formatted`, `unchanged` and `noFormatter` show nothing;
   - one button per server: a small state dot and the name; `title` = the state words. Dot: running → success
     colour; starting/stopping → muted; stopped → hollow muted; crashed or failed → problem colour; not installed →
     warning colour.
3. **Server menu** (click a server button; `ServerMenu.vue`, teleported, `menuPosition.ts`/`menuKeys.ts` as
   `ToolbarMenu.vue` uses them; Escape and a press elsewhere close it): the name, the state line ("Running",
   "Starting…", "Stopping…", "Stopped", "Stopped: exited with code N" / "Stopped: exited" for a crash, "Not found:
   looked in" + the folders, "Could not start: <message>", "Did not answer in time", "Could not start: <message>" for
   initialize failures, "Runs only in the app" for no host, "Its folder is outside the repository"), then the actions
   that apply — Start (stopped, crashed, failed), Stop (starting, running), Restart (running, crashed, failed), Show
   log (always).
4. **Not installed** (`state.kind === "notInstalled"`, plan #70): instead of Start/Stop/Restart, the hint built from
   `InstallHint` in `serverText.ts`:
   - TypeScript: "This project uses TypeScript <version>, which needs the separate package
     typescript-language-server." eslint: "eslint's language server is the separate package
     vscode-langservers-extracted."
   - "In <folder>/:" (the repository root when `folder` is "") then the project command, and "Or for all projects:"
     then the all-projects command, each in a monospace box with a Copy button (`navigator.clipboard.writeText`;
     a failed copy leaves the text selected and selectable). Commands per manager: npm `npm install -D <p>` /
     `npm install -g <p>`; pnpm `pnpm add -D <p>` / `pnpm add -g <p>`; yarn `yarn add -D <p>` / `yarn global add
     <p>`; yarnBerry `yarn add -D <p>` / npm's global command; bun `bun add --dev <p>` / `bun add -g <p>`; unknown
     (`manager: null`) → npm's commands plus "Or the same with your package manager."
   - "Or install it any other way that puts <program> on your PATH." and "yamt finds it when you come back to this
     window."; then Show log.
5. **Log view** (`ServerLogView.vue`): `screen = serverLog{name}` shows it in the files grid cell instead of the
   merge views (as Settings does); a header "<name> log" with a Back button (Escape too); the lines in the editor
   font, each with its time (HH:MM:SS) and its source (stderr lines muted, yamt's own lines marked); it follows new
   lines while scrolled to the end and stays put when the user scrolled up; empty → "Nothing logged yet."
6. **Wiring:** `main.ts` builds `new LanguageServers(host)` (`createTauriServerHost()` in the app, `null` in fixture
   mode) and gives it to the store; `MergeView.vue` passes `store.servers` to `useMergeController` (a plain value, not
   a deep ref: `LanguageServers` has `#private` fields); `serverViews` follows `onChange`. Words in `serverText.ts`
   only.
