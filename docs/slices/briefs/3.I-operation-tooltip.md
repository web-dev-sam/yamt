# Slice 3.I-tooltip — the operation tag's details in yamt's own tooltip, open at once

Board "Operation tag tooltip" row 1. Product rule: `docs/plan.md` §2 **#100** (read it whole; it amends #92's hover,
#92's words and place stay). Owner's words (#1579): "I want an actual tooltip on the merge status on the bottom left
that opens immediately on hover". Today the tag's details sit in the browser's `title`, which WebKitGTK opens late and
in GTK's look.

## Target

Owned: `frontend/src/ui/{OperationLabel.vue,FileList.vue,AGENTS.md}`; new, only if a placement rule is worth a pure
function: `frontend/src/ui/operationTooltip.ts` + `operationTooltip.test.ts`.
Read-only: everything else (`operationText.ts`, `ipc/`, `editor/` incl. `theme.css`, `style.css`, the `use*`/menu
modules, Rust, `docs/**`, `.omp/**`).

keyboard focus on the tag.

## Contract

- `OperationLabel` props `{ operation: OperationView }` and `FileList` props unchanged.
- The tooltip's text is `operationLine(operation).tooltip`, from the same `line` the tag already computes (so a step
  change while open shows at once); `operationText.ts` unchanged.

## Change

1. `OperationLabel.vue`: no `title` anywhere on the tag. Pointer enters the tag → the tooltip shows in that frame: no
   timer, no transition or animation. Pointer leaves → it goes, same frame.
2. Text as given, line breaks and blank lines kept, long lines wrapped (`white-space: pre-wrap`); width fits the text
   up to 480 px (a one-line merge tooltip is no 480 px box).
3. Place (#100): above the tag with a 4 px gap, its left edge on the tag's text (the tag's left padding), free to reach
   past the file list over the panes, painted on top of panes, strips, minimap and the divider handle; never outside
   the window (narrower than 480 px of room → narrower tooltip); taller than the room above the tag → its height is
   that room, the first lines stay and the end is cut.
4. It closes when the tag goes (operation ends) or hides with the file list (Ctrl/Cmd+B); after the list shows again
   it stays closed until the pointer enters the tag again.
5. The pointer passes through it (`pointer-events: none`), its text cannot be selected.
6. Screen reader: the tag's name stays the line; its description stays the tooltip text whether or not the tooltip is
   open (e.g. `aria-describedby` to an element that always exists); nothing is read twice.
7. `ui/AGENTS.md`: where it says the tag's hover is the line's tooltip, say it is yamt's own tooltip, open at once (#100).
