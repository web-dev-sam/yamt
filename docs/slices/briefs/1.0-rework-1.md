## Change (findings verbatim, then what to do)

1. [should, boundary, TS13] `frontend/src/main.ts:10` — "`void store.loadFiles()` has no stated
   reason. loadFiles passes a listFiles rejection on, so a failed list (TauriChunkSource in M2)
   becomes an unstructured unhandledrejection that skips the one logger (IPC8). The window then
   shows an empty list with no `store.*` event." Fix: `loadFiles` catches like `open` does and
   logs `store.list_failed` with `reason`; it never rejects, so the `void` in `main.ts` is safe by
   construction. Add a store test: a rejecting `listFiles` logs exactly one
   `[error] store.list_failed {reason: …}` line, opens nothing, and `loadFiles()` resolves.
2. [should, boundary, TS11] `frontend/src/ipc/fixture.ts:68` — "createFixtureSource is 45 lines
   (68-112), over the 40-line limit. Its inner `function listFiles()` (line 85) has the same name
   as the returned method, so `async listFiles() { return listFiles(); }` (94-95) reads like
   recursion." Fix: rename the inner closure (e.g. `entries()`), and move parse + sort + `Map`
   construction into a top-level function (e.g. `parseFixtures(files)`).
3. [should, boundary, TS4] `frontend/src/ipc/fixture.test.ts:6` — "Annotating the eager
   `import.meta.glob` result as `Record<string, { path: string; chunks: unknown[] }>` makes Vite's
   `<M>` overload infer M from the annotation. That is an unchecked cast the
   consistent-type-assertions lint cannot see." Fix: type it `Readonly<Record<string, unknown>>`
   and read `path` and the chunk count through a small valibot parse inside the test.
4. [nit, boundary] `frontend/src/ipc/domain.ts:53` — `toRange` names its argument bag `dto`,
   which elsewhere in the file means a generated DTO. Fix: destructure in the signature.
5. [nit, correctness, RK7] `frontend/src/ui/store.test.ts:86,116` — the store tests hard-code
   `chunks: 9` from the real vueuse golden, so regenerating the goldens after tuning the engine
   would break tests that are not about chunk counts. Fix: derive the expected count from the
   data (`a.chunks.length`) or use an inline in-memory record.
