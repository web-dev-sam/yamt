## Blocks

- #433 (correctness) / #424 (boundary): "An open find bar … shrinks and pushes down only that pane's
  scroller … that pane's lines move about 29px below the other panes … closing the bar shifts them …
  The owner sees misaligned unchanged lines across panes." **Decision:** the bar floats over the top
  right of its pane, like VS Code's find widget, and never changes the pane's scroller size or
  position; the current match is scrolled so it is not hidden under the bar. Scroll sync stays as it
  is. Acceptance: with the bar open in one pane, opening it, scrolling any pane, and closing it leave
  the three panes' unchanged lines on the same screen rows (smoke screenshot with the bar open after a
  scroll).
- #434 (correctness): "ctrlKey is accepted on macOS, where Ctrl+click is the system secondary click … a
  macOS user who Ctrl+clicks to copy changes the merge result … On Linux, metaKey (Super) is accepted
  as well." **Decision:** only the platform modifier counts (Cmd on macOS, Ctrl elsewhere, the same
  platform test CodeMirror uses for `Mod`), in a small pure predicate with node tests for both platforms.

## Shoulds and nits (all in this round)

- #435 (correctness): "When covered spans touch … and the later span is a deletion at an unterminated
  document end … the composed ChangeSet drops the overlap. A drag then leaves a final line break that
  clicking one by one removes. Reproduced … composed 'a\nB\n', sequential 'a\nB'." **Decision:** build
  the action's changes so the result equals clicking one by one (e.g. each span's change computed on
  the document after the previous ones, composed into one ChangeSet, still one transaction and one undo
  step); a `sides.test.ts` case with touching spans, the last deleting an unterminated final line,
  compared with clicks. Reword CM7 in `deviations_from_brief` if its "original coordinates" no longer
  holds (the orchestrator edits the skill).
- #436 (correctness): "'the count follows edits' only calls the pure findLabel … Deleting
  `update.docChanged ||` from FindPanel.update keeps every test green." **Decision:** the recount
  decision becomes a pure function tested with real transactions (doc change, selection change, query
  change, none).
- #437 (correctness): "modClick.test.ts passes 0-based line numbers straight to openBlockAt. The
  1-based→0-based conversion is untested." **Decision:** `openBlockAt` takes a document position and
  converts inside; tests at a block's first character, the end of its last line, and the start of the
  line after it.
- #425 (boundary): "`#covered` keeps a second copy of the value both side panes already hold in
  `coveredField`." **Decision:** read it from the side pane's field; delete `#covered`.
- #426 (boundary): "`StripPaint` is exported but no file imports it … `Icons` repeats the same shape."
  **Decision:** unexport; `type Icons = StripPaint & { readonly onPress: OnPress }`.
- #427 (boundary): "`iconButton(markup, title, run)` takes two positional strings." **Decision:** object
  parameter `{ icon, title, run }`.
- #429 (boundary): "The search-match background reuses `--color-success-border` …" **Decision:** a new
  `--color-search-match` token in `style.css` (JetBrains New UI dark search-result tint; the palette
  test must still pass), used by the match highlight.
- #431 (nit): `search({ top: true, … })` does nothing with our own panel — drop it (moot if the
  overlay no longer uses the top panel slot).
- #432 (nit): the `main-field` attribute is @codemirror/search's refocus hook (`getSearchInput`) — one
  CP1 comment, if the attribute stays.
