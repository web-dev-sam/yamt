## Blocks

1. **#1480** (mutation survivor `index.rs:128`, guard `NotFound` → `true`) — no test covers a `tabs.json` that exists
   but cannot be read. Read as missing, `open` would write a fresh index over it and remove every other tab's column
   files as orphans. Test (in `tests/opening.rs`): a directory named `tabs.json` in `dir` (portable, passes as root) →
   `Err(Error::ReadFailed { path })` with `path == dir/tabs.json`; the folder's entries unchanged (no `lock` created, an
   existing `7-left.txt` kept).
2. **#1481** (survivor `files.rs:59`, same guard in `read_column`) — no test covers a column file that exists but
   cannot be read; read as empty, the next `set_column` would overwrite the user's text. Test (in `tests/columns.rs`):
   a directory at `<id>-left.txt` → `load_tab` gives `ReadFailed` with that path; `set_column` on either column gives
   `ReadFailed`; the directory is still there afterwards (as the non-UTF-8 test at `columns.rs:248`).
3. **#1482** (survivors `lib.rs:110`, `*` → `+`) — every limit test derives its boundary from `MAX_COLUMN_BYTES`, so the
   decided 8 MiB (plan §2 #97) could change unnoticed. Pin the value as a literal in the tests:
   `assert_eq!(start.column_limit, 8 * 1024 * 1024)` and `8 * 1024 * 1024` (not the constant) in
   `a_column_exactly_at_the_limit_is_stored` and the over-the-limit test.
4. **#1483** — `close_tab` writes the index before deleting the files (correct), but no test fails if the order is
   swapped. Test: a non-empty directory `tabs.json.tmp` in `dir` makes the index write fail while file removal still
   works → `close_tab` gives `WriteFailed`, both column files keep their bytes, `start().list` still lists the tab.
5. **#1484** — a hand-edited `tabs.json` with `nextId` or a tab's `number` at `u32::MAX` passes `problem()`; then
   `add_tab`'s `+ 1` panics (debug, under row 6's `Mutex`) or wraps to a repeated id (release). Refuse such an index at
   open as `Broken` (the file named, nothing written), with a unit test per field.
6. **#1487** (boundary, a decision copied) — `files.rs:109` `column_file_tab` parses the id with `u32::from_str`, which
   accepts `+7` and `007`, so foreign files such as `03-left.txt` or `+7-right.txt.tmp` are removed as orphans although
   `column_path` never writes those names: the file-name rule is written twice and the copies disagree. Keep an id only
   when it reads back exactly as `column_path` writes it (one rule: derive the reading from the writing, e.g.
   `(TabId(id).0.to_string() == digits)`); add `03-left.txt` and `+3-left.txt` to `other_names_are_no_column_files`.
