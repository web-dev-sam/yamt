Facts (given):

- Owner answers #1462: Format covers JSON and XML only, built in, no dependency; JSON keys keep their order.
- `JSON.parse`/`JSON.stringify` cannot be used: they put integer-like keys first (ECMA-262 OrdinaryOwnPropertyKeys) and
  round numbers past 2^53. `DOMParser` cannot be used: it resolves character references (`&#233;` → `é`) and the
  `node` test project has no DOM (`frontend/vite.config.ts`, `environment: "node"`).
- CodeMirror turns every line break in pasted text into `\n` (no `lineSeparator` set), so the formatters never see `\r`.
- `@codemirror/language-data` 6.5.2 `languages` (151 `LanguageDescription`s); `LanguageDescription.matchLanguageName(
  languages, name, true)` matches names and aliases (`editor/internal/language.ts` uses the same package).
- `editor/` is not mutated (VF7): each node test must name the plausible bug it catches and the one-line hand mutation
  that makes it fail; you apply each mutation once, see the test fail, revert, and report it.

## Contract (fixed; you may add, never change)

```ts
// editor/internal/formatResult.ts
export type FormatResult =
  | { readonly kind: "formatted"; readonly text: string } // differs from the input
  | { readonly kind: "unchanged" } // already formatted, or empty / whitespace only
  | { readonly kind: "failed"; readonly message: string; readonly line: number }; // 1-based line of the input

// editor/internal/formatJson.ts
export function formatJson(text: string): FormatResult;
// editor/internal/formatXml.ts
export function formatXml(text: string): FormatResult;

// editor/internal/detectLanguage.ts — a `languages` entry's `name` ("JSON", "XML", "HTML", "PHP", "Python", …) or null = plain text
export function detectLanguage(left: string, right: string): string | null;
```

## Behaviour

1. **Both formatters** keep every token exactly as written and change only the whitespace between tokens: two-space
   indent, leading and trailing whitespace dropped, and the output ends with `\n` exactly when the input's trailing
   whitespace held a line break. Output equal to the input → `unchanged`. A scan, not a recursive descent that can
   overflow the stack on deep nesting; linear in the input (columns hold up to 8 MiB).
2. **JSON** (RFC 8259, strict): `{`/`[` open a block, one member or element per line, `": "` after a key, `,` at line
   end; `{}` and `[]` stay compact (also with whitespace inside); strings kept verbatim with their escapes (a `\"` does
   not end a string; control characters inside a string fail); numbers kept verbatim (grammar checked:
   `-?(0|[1-9]\d*)(\.\d+)?([eE][+-]?\d+)?`); `true`/`false`/`null`; one root value, any text after it fails. Failures
   name what was expected where ("Expected ',' or '}'", "Unterminated string", "Unexpected text after the JSON value")
   with the input line of the offending token.
3. **XML**: one root element; start, end and self-closing tags kept verbatim (attributes, their order, quotes and
   entities as written, also a tag spanning lines); end tags must match their start tag (else fail, naming both names
   and the end tag's line); declaration `<?xml …?>`, processing instructions, comments, CDATA and `<!DOCTYPE …>` with an
   internal subset `[…]` kept verbatim, each on its own line at its depth. An element whose content holds no child
   element stays on one line, its content verbatim (`<a>text &amp; more</a>`, `<a><![CDATA[x]]></a>`, `<a></a>`). An
   element with child elements and only whitespace text puts each child on its own line, one indent deeper. An element
   with child elements and non-whitespace text (mixed content), and any element with `xml:space="preserve"`, is kept
   verbatim from its start tag to its end tag. Fails: unterminated tag, comment, CDATA, PI or DOCTYPE; an unclosed
   element at the end; a second root; non-whitespace text outside the root; a `<` that starts no valid construct.
4. **Auto** (`detectLanguage`): reads the left text, then the right only if the left finds nothing; per text, the first
   4,096 characters after leading whitespace (and a BOM). Rules in this order, first match wins:
   1. `#!` → the interpreter: the first word's last path segment, or after `env` the first word not starting with `-`;
      trailing version digits and dots stripped (`python3.11` → `python`); `matchLanguageName(languages, name, true)`'s
      `name`; no match → nothing for this text.
   2. `<?php` → `PHP`. 3. `<?xml` → `XML`. 4. `<!DOCTYPE html` or `<html` (any case) → `HTML`.
   3. `<!--`, or `<` followed by a letter → `XML`.
   4. `{` followed (after whitespace) by `"` or `}` → `JSON`; `[` followed (after whitespace) by `{`, `[`, `"`, `]`, a
      digit, `-`, `true`, `false` or `null` → `JSON` (so an INI `[section]` is not JSON).
   5. otherwise nothing.
      Every name returned is a `languages` entry's exact `name` (a test asserts it through `matchLanguageName`).

## Acceptance

Node tests (`*.test.ts` beside each module), each naming the bug it catches and the hand mutation it was proved with:

- `formatJson.test.ts`: the same data in a minified and an odd layout format to the identical text (← `":"` without
  the space); `{"b":1,"2":0}` keeps `b` first and `12345678901234567890` and `1.0e+10` stay as written (←
  `JSON.stringify(JSON.parse(t), null, 2)`); a missing comma on line 3 → `line: 3` (← the line counter not incremented
  on `\n` in whitespace); the final newline kept and its absence kept (← always append `\n`); `{ }` and `[]` compact (←
  a newline inside empty blocks); `"a\"b"` is one token (← the string scan ignoring backslashes); text after the root
  fails (← stop after the root); already formatted → `unchanged` (← always `formatted`); whitespace only →
  `unchanged`; 100,000 nested arrays do not throw (← recursion).
- `formatXml.test.ts`: nested elements re-indented (← indent not increased on a start tag); a text-only element on one
  line (← child text treated as a block); mixed content verbatim (← whitespace collapsed in mixed content); the
  declaration, a comment, CDATA, a DOCTYPE with an internal subset and `&#233;` kept (← entities resolved); `</b>`
  closing `<a>` fails with its line (← end-tag name not compared); `xml:space="preserve"` kept verbatim (← the
  attribute not checked); a self-closing tag and a tag with attributes over two lines kept verbatim; a second root
  fails; already formatted → `unchanged`.
- `detectLanguage.test.ts`: `{"a":1}` JSON and `{ foo }` nothing (← any `{` accepted); `[section]` nothing and `[1, 2]`
  JSON; `<!DOCTYPE html>` HTML (← the XML rule before HTML); `#!/usr/bin/env python3` Python and `#!/bin/bash` the
  shell language (← version not stripped); leading whitespace and a BOM skipped (← no trim); the left wins over the
  right and the right is read when the left finds nothing (← columns swapped); only the first 4,096 characters are
  read; every returned name resolves through `matchLanguageName`.
