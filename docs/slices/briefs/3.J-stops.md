## Contract (fixed; you may add, never change)

```ts
// ui/stops.ts — the one place a stop ends in the window
export type StopEnd =
  | { readonly kind: "outside" }
  | { readonly kind: "continued"; readonly message: string };
export async function nextStop(target: StopTarget, end: StopEnd): Promise<void>;
// the store exposes it as an action: nextStop(end: StopEnd): Promise<void>  (row 8 calls it after Continue's `Stopped`)

// ui/operationText.ts — every operation word, pure
export function operationLine(operation: OperationView): {
  readonly text: string;
  readonly tooltip: string;

export function abortLabel(operation: OperationView): string; // "Abort merge", "Abort rebase", …
// store: `operation: ShallowRef<OperationView | null>` replaces `merging`, written only by listing.ts
```

## Behaviour

1. **One list.** Every list the window makes today (start, focus, after an action) goes through `listStop`. `Files` →
   files and disk changes as today, `operation` and `sideNames` (from `sides`) set from the same reply; `loadSideNames`
   and its call in `main.ts` are gone. `MovedOn` → `nextStop({ kind: "outside" })`.
2. **`nextStop`** clears every per-stop state before listing again: every opened file (views unmount, so controllers and
   undo go and their language-server documents close; the servers keep running), `choices`, `taken`, `notices`,
   `active`, `problem`, `screen` back to the files; every write claim marked overtaken and dropped (a reply that lands
   later changes nothing); `latestOpen` bumped. Then it lists as at start (`loadFiles`: the new stop's first unresolved
   file opens). `outside`: when files had unsaved edits, one notice names them ("The rebase moved on outside yamt; your
   unsaved edits in a.ts, b.ts were dropped" — words in `noticeText.ts` from `operationText.ts`'s operation word).
   `continued`: when the new stop lists no file, the problem bar shows git's `message`.
3. **Top line** (`OperationBar.vue`): the first row of `App.vue`'s right column, above the notices: one row
   (`h-8`, `rounded-md border border-info-border bg-info px-3 text-fg truncate`, `role="status"`), `operationLine`'s
   text with its tooltip; not rendered when `operation` is null. Words exactly as plan §2 #87.
4. **Abort per operation.** `aborting.ts` reads `operation`: none → no Abort (the state formerly `noMerge`), else
   `abortOperation`; the question names the operation and what is lost (#88: for a rebase, sequence or `am` also the
   commits/patches already done = `progress.step - 1`; a merge keeps #74's words verbatim); the button and menu entry
   read `abortLabel` (id `abortMerge` and the stored decisions unchanged); failure words "Could not abort the rebase: …".
5. Store stays ≤ 300 lines (move code out, e.g. into `stops.ts`/`listing.ts`, never compress); no second writer of
   `operation` or `sideNames`.
