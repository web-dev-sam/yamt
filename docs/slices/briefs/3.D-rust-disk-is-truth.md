## Behaviour

### A. Memory and looks

- Every `FileState` keeps `seen: OnDisk`, the worktree entry as yamt last saw it:
  `Missing | File(Vec<u8>) | Link(Vec<u8>) /* read_link target */ | Submodule(Option<Oid>) /* HEAD of
  the checked-out submodule, None = not checked out */ | Other /* a directory or special file */ |
  GitOutput /* changed before start, see D; no read ever equals it */`. Read with
  `symlink_metadata` first (a link is never followed). An executable-bit-only change is not a change.
- `seen` is set in `open()` and **read back from disk** after each of yamt's own writes
  (`finish`, `take`, `reset`, and the staging in B) — never assumed from the bytes written:
  `core.autocrlf`, filters and `checkout -m` rewrite them.
- `MergeSession::refresh()` replaces `refresh_statuses()`. It reads every file, compares it with
  `seen`, settles each difference (B), and **only then** re-reads `git ls-files -u`, so the marks
  include the staging just done. `list_files` and the exit status on close
  (`src-tauri/src/outcome.rs` `ending_on_close`) call it. A git failure of the `ls-files -u` read
  stays `IpcError::Git` as today; a failure to stage one file is that file's
  `DiskResult::StageFailed`, never an error of the whole call.
- `finish`, `take` and `reset` first look at their one file. Changed → nothing is written, the change
  is settled (B), and they return `WriteReply::ChangedOnDisk`. Not an error.
- **Disk version.** Each file has a `DiskVersion(u32)`, starting at 0 and bumped by every settle of
  that file. `load_file` and `describe_file` return it. `finish_file`, `take_side` and `reset_file`
  take the version the window's view was built from. If it is not the file's current version, nothing
  is written and the reply is `ChangedOnDisk` with the file's last settled change. Why: the window may
  click "Mark resolved" right after a focus look already settled a change it has not drawn yet (a click
  on an unfocused window both focuses it and clicks). Without the version, yamt would overwrite a disk
  change the user never saw, which is what #52 forbids.

### B. Settling (one place: `session/src/disk.rs`)

- The file is gone, a directory or special file is at its path, or it is not text, or it is text with
  **no marker lines** (C) → staged, and the mark comes from the following `ls-files -u`:
  - present → `git add -- <paths>`;
  - gone or `Other` → `update-index --force-remove -- <paths>` (`Repo::remove_from_index`'s command
    in batch form).
  - Batch: one `add` and one `force-remove` for all files settled in one `refresh()`.
  - Binary, symlink and deleted-side text files (#47) have no markers, so any change stages them.
    A submodule whose checked-out HEAD moved is staged with `git add` (a gitlink). Never auto-stage
    a file with a `working-tree-encoding` attribute: yamt cannot see its markers, so it stays as it
    is, now and later.
  - Non-UTF-8 or over-the-size-limit text on disk is staged only when it has no marker lines
    (the parser works on bytes).
- Text with marker lines → not staged; the file's view becomes `Disk`, and `load` builds the middle
  from `seen` (C).
- Staging failed (e.g. a held `index.lock`) → `StageFailed { message }`. `seen` is **not** updated,
  so the next look tries again. The view still becomes `Disk`.
- A file already resolved behaves the same: no markers → staged again with the new content;
  markers → `Disk` view, the index is left alone.
- Each settle bumps the file's `DiskVersion` and records its `DiskChange` (needed for a stale-version
  reply).
- After `take` or `reset` the view is `Stages` again. `finish` keeps the view it had.

### C. Reading markers (`session/src/markers.rs`, pure, bytes in)

- **Marker size.** N comes from the `conflict-marker-size` attribute. All paths are read in one
  `git check-attr -z --stdin conflict-marker-size merge working-tree-encoding` at `open()`.
  Unspecified, unset or non-numeric gives 7.
- **Marker lines.** A marker line is exactly N copies of `<`, `|`, `=` or `>`, followed by a space,
  CR, LF or end of file (git `rerere.c` `is_cmarker`). So N+2-long inner markers are text.
- **States.** Outside → Ours → (Base) → Theirs → Outside. `|||||||` and `=======` count only inside
  an open block, so the settled `=======` on line 2 of the samples is text.
- **Ignored or tolerated.** Labels are ignored. A base section is parsed and skipped: base always
  comes from stage 1 (plan §1). CR before LF is stripped for matching only. A last line without a
  newline is accepted.
- **Raw regions.** Anything out of order is a `Raw` region: a missing separator, `>>>>>>>` before
  `=======`, a nested `<<<<<<<`, end of file inside a block, or a stray `<<<<<<<`/`>>>>>>>`. A raw
  region runs to the next `>>>>>>>` (inclusive), or to the line before the next `<<<<<<<`.
- **"Markers left".** At least one `Block` or `Raw` region.
- **Views, for D.** `views(bytes, N) -> Views { ours, theirs }`:
  - the ours view is the settled lines, plus each block's ours section, plus the raw regions as they
    are; the theirs view is the same with each theirs section;
  - both drop marker lines, labels and base sections, and strip CR before LF.

### D. What git wrote, at start (`session/src/start.rs`, used only by `open()`)

A file that differs from what git wrote starts with `seen = GitOutput`. The first `refresh()` (the
window's first `list_files`) then settles it through B, with the same reporting as any later change.
`open()` itself writes nothing. An untouched file keeps `seen` = its bytes and loads as today: the
middle starts from base (#9).

- **Two-sided text** (also two-sided non-UTF-8 or over-limit text):
  - **Regenerate git's output.** Run
    `git merge-file -p -q --marker-size=N -L ours -L base -L theirs <local> <base> <remote>` on the
    stage bytes `open()` already reads. The three inputs go to temp files in one directory under
    `std::env::temp_dir()`, which `open()` creates and removes.
  - **Diff algorithm.** Add `--diff-algorithm=histogram` only when `git version` is 2.44 or later.
    merge-ort merges with histogram, older merge-file has no such flag, and macOS ships Apple git
    2.39.
  - **Exit code.** 0..127 is success: it is the number of conflicts. 128 and above is an error.
  - **Untouched** when the disk's `views` equal the regenerated output's `views`. These are the same
    in every conflict style and ignore labels, base sections and line endings.
  - **Attributes.** `merge=union` regenerates with `--union`. `-merge` or `merge=binary`: git kept
    ours (see the next bullet). Any other `merge` value is a custom driver (e.g. mergiraf): yamt
    cannot know what it wrote, so the file always counts as changed.
  - **Errors.** A merge-file failure logs a `warn` and the file counts as untouched. Never stage on
    doubt.
- **Files git wrote one stage to:**
  - **Which stage.** Two-sided binary, `-merge`/`merge=binary` text, two-sided symlink → stage 2.
    Deleted-side file or link (#47) → the kept stage. Both sides gone → expected missing. Cite
    `merge-ll.c` / `merge-ort.c` on the comment line.
  - **Regular files.** Compare in git's clean form: one `git hash-object --stdin-paths` for all of
    them, so filters and autocrlf apply per path; its oid is compared with the expected stage's oid.
    A path containing a newline cannot go through `--stdin-paths`; compare it raw.
  - **Symlinks.** `read_link` bytes compared with the stage blob.
  - A missing file where a stage was expected, or a present one where none was, differs.
- **Never a start change:** submodules, and `working-tree-encoding` files.
- **Cost.** One `git version`, one `check-attr`, at most one `hash-object`, and one `merge-file` per
  two-sided text conflict. Log the number of merge-file runs and the total time of the detection at
  `debug`.

### E. Seeding a file from the disk (`session/src/seed.rs`, pure; merge-core `line_map`)

- **Blocks are chunks.** One `Conflict` chunk per open block or raw region. Settled text has no
  chunks.
- **Locating a block's sides.** Its local range is its ours section located in stage 2:
  - build "settled lines + each block's ours section", raw regions left out;
  - take a 2-way line map (`merge_core::line_map`, new, pure, over the imara-diff histogram already
    in merge-core) of that against local;
  - the range is `exact`: every line matched; for an empty section, the point after the last matched
    line before it.
  - The remote range is located the same way against stage 3.
- **Base range.** Project the local and remote ranges through `line_map(local, base)` and
  `line_map(remote, base)` with `covering` (grown outward to whole changed hunks); the base range is
  the union of the two.
- **Inexact blocks and raw regions.** A block that is not exact on a side, and any raw region, gets
  `covering` ranges.
- **The middle's starting text.** The settled lines as they are; each exact block replaced by its base
  lines; each raw region or inexact block left verbatim, markers included. Keep the disk's line
  endings, and take `eol` from the disk text.
- **Each chunk** is merge-core's `Chunk { kind: Conflict, base, local, remote }` plus its middle
  range and its `word_changes`.
- **Required property.** Applying ours (local lines over the chunk's middle range) gives exactly the
  file the user would get by keeping the ours section by hand. Worked examples on `style-zdiff3.txt`
  and `style-merge.txt` are in the notes; both must give middle `title, =======, one, two, three,
  shared-b, four … seven, eight-theirs, nine, ten` with one chunk: middle {2,3}, local {2,4},
  remote {2,4}.

### F. Contract (IPC; every type derives `Serialize` + `specta::Type`)

```rust
// session
pub struct MiddleLine(pub u32);          // 0-based line of the middle pane's starting text
pub struct DiskVersion(pub u32);          // bumped by each settle of the file
pub struct MergeChunk { pub chunk: Chunk, pub middle: LineRange<MiddleLine>, pub words: WordChanges }
pub enum NotText { Deleted, Binary, NonUtf8, TooLarge, Link, Directory }
#[serde(tag = "kind")]
pub enum Middle { Stages { text: String } /* base, as today */, Disk { text: String }, DiskNotText { found: NotText } }
pub struct FileMergeData {
    pub path: String, pub middle: Middle, pub local: String, pub remote: String,
    pub deleted: Option<Side>, pub eol: Eol, pub chunks: Vec<MergeChunk>, pub disk_version: DiskVersion,
}   // `base` and `word_changes` are gone; each chunk carries its words
#[serde(tag = "kind")]
pub enum DiskResult { Staged, MarkersLeft { conflicts: u32 /* blocks + raw regions */ }, StageFailed { message: String } }
pub struct DiskChange { pub path: String, pub result: DiskResult }
pub struct FileList { pub files: Vec<FileEntry>, pub disk_changes: Vec<DiskChange> }
#[serde(tag = "kind")]
pub enum WriteReply { Written { files: Vec<FileEntry> }, ChangedOnDisk { files: Vec<FileEntry>, change: DiskChange } }
// FileSides gains `pub disk_version: DiskVersion`.
```

Commands:

- `list_files() -> Result<FileList, IpcError>`
- `load_file(path) -> Result<FileMergeData, IpcError>`
- `describe_file(path) -> Result<FileSides, IpcError>`
- `finish_file(path, text, disk_version) -> Result<WriteReply, IpcError>`
- `take_side(path, side, disk_version) -> Result<WriteReply, IpcError>`
- `reset_file(path, disk_version) -> Result<WriteReply, IpcError>`

`remote_name`, `log` and `IpcError` are unchanged. The CLI fixture (`crates/cli/src/fixture.rs`)
yields `Middle::Stages` and `MergeChunk`s with `disk_version` 0. Then run `just fixtures`.

### G. gitio (bytes in, bytes out; no diff logic)

- `version()`, parsing `git version 2.39.5 (Apple Git-154)` and `2.56.0`.
- `attributes(paths)`: the three attributes in one `check-attr -z --stdin`.
- `hash_objects(paths) -> Vec<Oid>`: `hash-object --stdin-paths`.
- `merge_file(inputs, marker_size, union, histogram) -> Vec<u8>`: temp files, with an exit-status
  tolerant variant of `run`.
- `submodule_head(path)`: `rev-parse --verify --quiet HEAD`, run only when `<path>/.git` exists.
- `add_paths(paths)` and `remove_paths(paths)`: the batch forms.
- Each one gets an integration test on a real temp repo.

## Contract rules

- `session` decides; `gitio` runs git; `merge-core` stays pure.
- `src-tauri` commands are 15 lines or fewer (IPC5).
- Functions are 40 lines or fewer, enforced by clippy.
- No `unwrap` or `expect` outside tests. Use `#[expect(…, reason)]` only, never `#[allow]`. Errors
  follow `skill://rust-conventions`.
- No new dependency: the crate list is closed (`docs/architecture.md` §7). The one `unsafe` stays the
  only one.
- In `deviations_from_brief`, report every IPC type or command whose exact Rust signature differs
  from F, and every new `gitio` method.

## Tests (behaviour, on real temp repos; extend `yamt-conflict-repo` so a test can set config and `.gitattributes` before the merge runs)

- **`session/tests/disk_is_truth.rs`**:
  - **Regenerated file.** No markers → `refresh` reports `Staged`. `ls-files -u` lacks the file, the
    stage-0 blob is the clean form of the disk bytes, and a second `refresh` reports nothing.
  - **One of two blocks removed on disk** (zdiff3 and merge style) → `MarkersLeft { conflicts: 1 }`,
    Unresolved. `load` gives `Middle::Disk` with exactly the worked-example text and one chunk:
    middle {2,3}, local {2,4}, remote {2,4}. Splicing the local lines into the middle by the chunk's
    ranges equals the hand-resolved file. In the mirror case (block 2 open) the chunk's middle is
    {11,1}.
  - **File deleted** → `Staged`, `ls-files -s <path>` is empty, Resolved, and `load` gives
    `DiskNotText { found: Deleted }`.
  - **Change unseen before a write.** Mark resolved after it → `ChangedOnDisk`, the worktree still
    holds the user's bytes, and those bytes are what got staged. The same for `take` (no
    checkout-index) and `reset` (no `checkout -m`).
  - **Stale version.** `refresh` settles a change, then `finish` runs with the old `disk_version` →
    `ChangedOnDisk`, and the disk is untouched.
  - **Read back.** After `finish`, `take` and `reset`, a `refresh` reports nothing, also with
    `core.autocrlf=true`.
  - **Already resolved, changed again** → staged again with the new bytes.
  - **Files without markers.** Binary changed → `git add`. Symlink retargeted → stage 0 with mode 120000. A held `index.lock` → `StageFailed`, the other files are still reported, and the next
    `refresh` retries.
  - **Unchanged disk** → no change, and no git write.
- **`session/tests/start_from_disk.rs`**:
  - **Untouched files** → nothing reported and `Middle::Stages`:
    - merged under each of zdiff3, merge and diff3;
    - then rewritten with `git checkout --conflict=diff3`;
    - a `core.autocrlf=true` worktree;
    - marker size 12 from `.gitattributes`;
    - a rename conflict;
    - only the base section edited before open.
  - **Fixed before open:**
    - regenerated (no markers) → `Staged` at the first `refresh`;
    - one block resolved → `MarkersLeft { conflicts: 1 }` and the worked-example middle;
    - settled text edited → `MarkersLeft { conflicts: 2 }`.
  - **Delete conflict.** Untouched under autocrlf → not staged. Removed before open → staged as
    deleted.
  - **Binary.** Untouched → not staged. Replaced by theirs → staged.
  - **Other attributes and kinds:**
    - a `-merge` text file left untouched is not staged; this catches a "no markers means fixed"
      shortcut;
    - a two-sided symlink left untouched is not staged;
    - `merge=<custom>` with markers → `Disk` view at the first list;
    - `working-tree-encoding=UTF-16` → never staged.
- **Unit tests:**
  - **`markers.rs`**:
    - the three style samples parse to the same two blocks;
    - `marker-size-12.txt` parses with N=12, and is all text with N=7;
    - CRLF;
    - the settled `=======`;
    - a deleted separator → `Raw`;
    - a nested `<<<<<<<`, a stray `>>>>>>> x`, and end of file inside a block;
    - a last line without a newline;
    - N+2-long inner markers stay text;
    - `views` is identical across the three styles.
  - **`seed.rs`**:
    - an edit inside the ours section → that block is raw in the middle, with `covering` ranges;
    - an empty ours section → an insertion point;
    - a repeated section line still gives exact text;
    - CRLF is kept.
  - **`merge-core` `line_map`**: `exact` and `covering` on the boundaries (empty ranges, the start and
    end of the file, an empty input).
- **Updated tests.** Update existing tests to the new return types, and delete any assertion that only
  pinned the old shape. The src-tauri command tests check the `list_files` JSON
  (`{files, disk_changes}`) and `ChangedOnDisk` after an outside write.
