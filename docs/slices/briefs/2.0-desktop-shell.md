# Slice 2.0 — the desktop app starts on a real merge and exposes it to the window

Board v0 wave 1. Owner goal (2026-10-10): "finally lets get the first version production ready. I want
to publish it as v0 and make it able to actually resolve merge conflicts." Today
`src-tauri/src/main.rs` prints `yamt: no commands yet`. This slice makes `yamt` a Tauri 2 app over
`yamt_session::MergeSession`: started in (or pointed at) a repository with conflicts it opens one
window and offers the merge to the frontend through typed commands; closing it reports through the
exit status whether everything was resolved. The frontend keeps reading fixtures until the next
slice (2.1) switches it to these commands — the window showing the fixture list here is expected.

## Behaviour (what the user sees)

- `yamt [--repo <path>]`: the repository is `<path>`, default the current directory (any directory
  inside a work tree). `--help` prints usage, `--version` prints `yamt 0.1.0`; both exit 0. An
  unknown argument or `--repo` without a value: usage on stderr, exit 2.
- Repository with conflicted files: one window opens, titled `<repository folder name> — yamt`,
  1600×1000 logical px (minimum 900×600), its background `#2b2d30` (`--color-window` in
  `frontend/src/style.css`) from the first frame, so no white flash.
- Repository without conflicted files: `yamt: nothing to merge in <root>` on stderr, exit 0, no
  window.
- Not a git work tree, git missing, or git failing while reading the conflicts: `yamt: <error>` (the
  error's own sentence) on stderr, exit 2, no window.
- Closing the window ends the app. Exit status 0 when every file of the merge is resolved, 1
  otherwise, with `yamt: <n> of <m> files still unresolved` on stderr. This is what `git mergetool`
  (`trustExitCode`) and scripts read.
- Logging: `tracing` to stderr, filter from `YAMT_LOG` (default `info`); the frontend's log entries
  arrive through the `log` command as events with target `frontend`, carrying `event` and the fields.
- App icon: Lucide `git-merge` (ISC), light stroke `#dfe1e5` on a rounded square `#8150be`
  (Purple6, the conflict colour, plan §2 #32); the source SVG is committed as
  `src-tauri/icons/icon.svg`, the rest generated with `cargo tauri icon`.
- `tauri.conf.json`: `productName` `yamt`, `identifier` `dev.yamt.merge`, version from the workspace;
  dev URL `http://localhost:5173` with the frontend's vite started as the dev command; production
  assets `frontend/dist`; a content security policy that blocks remote content and still lets the
  window run (CodeMirror injects `<style>` elements); bundling inactive until wave 5.

## Contract (fixed; private items are yours)

```rust
// Commands, registered through tauri-specta and exported into bindings.ts (IPC1, IPC5: each body
// locks the session, calls one MergeSession method, maps the error; no logic).
#[tauri::command] #[specta::specta] fn list_files(state) -> Vec<FileEntry>;
#[tauri::command] #[specta::specta] fn load_file(state, path: String) -> Result<FileMergeData, IpcError>;
#[tauri::command] #[specta::specta] fn finish_file(state, path: String, text: String) -> Result<Vec<FileEntry>, IpcError>;
#[tauri::command] #[specta::specta] fn reset_file(state, path: String) -> Result<Vec<FileEntry>, IpcError>;
#[tauri::command] #[specta::specta] fn log(entry: LogEntry);

#[derive(Debug, serde::Serialize, specta::Type)]
#[serde(tag = "kind")]
pub enum IpcError {
    Git { message: String },                                  // any yamt_gitio::Error, its Display text
    UnknownPath { path: String },
    Unsupported { path: String, reason: UnsupportedReason },
    WriteFailed { path: String, message: String },            // the io::Error's Display text
}
// From<yamt_session::Error> for IpcError: one exhaustive match, no wildcard.

#[derive(Debug, serde::Deserialize, specta::Type)]
pub struct LogEntry { pub level: LogLevel, pub event: String, pub fields: BTreeMap<String, LogValue> }
#[derive(Debug, serde::Deserialize, specta::Type)] #[serde(rename_all = "lowercase")]
pub enum LogLevel { Debug, Info, Warn, Error }
#[derive(Debug, serde::Deserialize, specta::Type)] #[serde(untagged)]
pub enum LogValue { Text(String), Number(f64), Flag(bool) }
```

Decided here (orchestrator; plan §2 row #41 records it):

- `reset_file` returns the file list like `finish_file` (architecture §3.5 had `FileMergeData`): a
  reset file the editor cannot show has no merge data, and the window reloads a text file with
  `load_file` anyway (vision 4: one shape for both outcomes).
- No `quit_if_done`: after the last file the app stays open (plan §2 #37); quitting is the user's
  action, the exit status reports the outcome.
- One `Mutex<MergeSession>` in Tauri state (IPC5). A poisoned lock is taken over (`PoisonError::into_inner`):
  the session's own state stays consistent between calls.
- The window title carries the repository folder name; the smoke repository's folder contains
  `yamt-test`, which is how the owner's window-placement rule recognises a test window (plan §2 #40),
  with no test-only code in the app.
- `bindings.ts` must keep the frontend's lint, type check, unused-export check and formatter green
  without editing `frontend/**`; a `// @ts-nocheck` header set through the exporter is acceptable
  for the generated file. `just bindings-check` keeps working (the bin still takes an output path).

Shape: `src-tauri/src/lib.rs` (or modules under it) shared by the `yamt` bin and the
`export-bindings` bin so both use the same command list; `main.rs` stays a few lines.

## Tests

Behaviour, not wiring (RS11: `src-tauri/tests/` or `#[cfg(test)]` modules; oracle = git's own index
and the worktree bytes):

1. Start-up outcome on a conflict repository (yamt-conflict-repo, 3 files) → merge with those 3
   files; on a repository without conflicts → nothing to merge; on a plain temp directory → the
   not-a-repository failure with exit status 2.
2. Arguments: none → current directory; `--repo p`; `--repo` without value and an unknown flag →
   usage error; `--help`, `--version`.
3. Over Tauri's IPC with the mock runtime (`tauri::test`), the way the frontend will call it:
   `list_files`; `finish_file` with a text containing `\r\n` → worktree bytes equal the text,
   `git ls-files -u` no longer lists the path, exit status still 1 while another file is open;
   finishing every file → exit status 0; `reset_file` on the finished file → `git ls-files -u`
   identical to before, `<<<<<<<` back in the worktree, status 1.
4. The JSON the frontend receives for each `IpcError` variant (`{"kind":"UnknownPath","path":…}`,
   …) and that a `LogEntry` the frontend sends (`{"level":"warn","event":"scroll.drift","fields":
   {"lines":3,"ok":true,"name":"a"}}`) is accepted; a bad level is rejected.

`just mutants <base>` runs over this crate afterwards; tests should kill mutants in the start-up
decision and the exit status.
