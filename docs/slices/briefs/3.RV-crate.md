## Change

1. `spec.rs`: §1's reading rule (split at the first `..`; a following `.` means three dots; neither side may contain
   `..` or start with `-`; an empty side reads as `HEAD`); the valid examples `v1.2..v1.3`, `HEAD~3...main`, `@{u}..`,
   `..`.
2. `open.rs`: resolve (`discover`, two `commit_named`, `merge_base` for three dots — `NoMergeBase` when none — two
   `commit_summary`), the side labels (`MergeBase { left, right }` for the left of `a...b`), then `list`: one
   `changed_files`, one `blob_sizes` over every changed blob id (never a gitlink), entries sorted by display path.
3. `entries.rs`: `RangeEntry` per changed file (a deleted file's path is its old path; renamed carries `old_path`;
   paths as UTF-8, lossy for display only; the bytes kept in `FileAt` for reading).
4. `load.rs`: `decide` in §7's order from listing data first (submodule, kind change, mode only, binary from numstat,
   size over `MAX_TEXT_BYTES` — never reading such a blob), then read at most two blobs with one `BlobReader`, UTF-8
   per side, then `Texts` with `merge_core::compare`; added → `left ""`, deleted → `right ""`, renamed → the old blob
   left; a link's target as text.
5. `lock.rs`: the folder `<range_dir>/<repo key>/<left id>-<right id>/`, repo key = the work tree folder's name + `-` +
   16 hex digits of FNV-1a 64 over the absolute common git dir's bytes (a named ~8-line function, pinned vector
   `"a"` → `af63dc4c8601ec8c`); `File::try_lock` on `lock`; held → `Locked` naming both short ids and the root.
6. `MAX_TEXT_BYTES` moves into merge-core; `session/decode.rs` uses it; `compare/src/lib.rs` gains a unit test
   pinning `usize::try_from(MAX_COLUMN_BYTES) == Ok(MAX_TEXT_BYTES)`.
7. `arch-check.sh`: `yamt-range` may depend on `yamt-gitio` and `yamt-merge-core` only among `yamt-*`, never on tauri;
   `yamt-app` may also depend on `yamt-range`.
