```ts
// ipc/MergeRequestSource.ts
/** A merge request's description as GitLab renders it, reduced by Rust; asked afresh on every call (plan §2 row 171). */
readDescription(iid: MergeRequestIid): Promise<SourceResult<DescriptionReply>>;
/** The address the window loads an uploaded description image from (the app: `convertFileSrc(key, PICTURE_SCHEME)`,
 *  `yamt-picture://localhost/<key>`; served only once a reply offered it). */
uploadedImage(key: UploadKey): string;

// ipc/mergeRequestDomain.ts + ipc/index.ts: the description types are aliases of the generated ones (as JobLogReply).

// ui/mergeRequestDescriptions.ts — the job log's shape (mergeRequestJobLogs.ts:9-74)
export type DescribedRow = { readonly iid: MergeRequestIid; readonly title: string };
export type DescriptionLoad =
  | { readonly kind: "loading" }
  | { readonly kind: "shown"; readonly description: Description }
  | { readonly kind: "refused"; readonly reply: Exclude<DescriptionReply, { readonly kind: "read" }> }
  | { readonly kind: "failed"; readonly cause: ProblemCause };
export type ShownDescription = { readonly row: DescribedRow; readonly load: DescriptionLoad };
export type Descriptions = {
  /** The window's one description panel: null when none is open. */
  readonly description: Readonly<ShallowRef<ShownDescription | null>>;
  /** Opens `row`'s panel and asks GitLab afresh; closes it when `row` is the one open (a second click on its
   *  button); another row's replaces it. */
  toggleDescription(row: DescribedRow): Promise<void>;
  /** Asks again for the open panel's row (Retry): loading, then the reply; nothing when none is open. */
  retryDescription(): Promise<void>;
  closeDescription(): void;
  /** What an image loads: the picture scheme's address for an upload, its own for another site's, null when refused. */
  imageAddress(image: DescriptionImage): string | null;
};
export function createDescriptions(deps: { readonly source: MergeRequestSource }): Descriptions;
```

- **The latest open wins** (RK67). Each ask writes a new `ShownDescription` entry. An answer settles only when that
  entry is still `description.value` (`mergeRequestJobLogs.ts:61-67`), so an answer after a close, a replace or a
  newer Retry is dropped.
- **Log line:** `mergeRequests.description_shown { iid, kind, blocks, ms }`, where `blocks` is the top-level count
  for `shown`. Never text or an address.
- `MergeRequests` (`ui/mergeRequests.ts:45-69`) gains `Descriptions` (`...createDescriptions(deps)`, as `createJobLogs`,
  `:296`). A list load or refresh never writes `description`.
- **`PageKind`** (`mergeRequestsText.ts:15`) gains `"link"`: `NOT_OFFERED.link` = "This link was not listed by GitLab,
  so yamt did not open it."
- **`MergeRequestStep`** (`problem.ts:43-53`) gains `"description"` and `"link"`. `problemText` gives "Could not read
  the description" and "Could not open the link" (`problemText.ts:77-88`).
- **The app** (`tauriMergeRequests.ts`):
  - `readDescription` → `toResult(await commands.readDescription(iid))` unchanged;
  - `uploadedImage(key)` → `convertFileSrc(key, PICTURE_SCHEME)`, as `uploadedPicture` (`:21-23`).
- **The fixture** (`fixtureMergeRequestDescriptions.ts`, spread into `createFixtureMergeRequests` as
  `...descriptionScript(log)`, `fixtureMergeRequests.ts:280-284`).
  - **`hasDescription`.** `row(index)` (`fixtureMergeRequestData.ts:217-237`) sets `hasDescription: index % 7 !== 2`,
    so !638 has none.
  - **Answers.** `readDescription(iid)` logs `mergeRequests.fixture_description { iid }` and answers after 400 ms:
    - **!640, rich:** every element of rule 3, in this order:
      - h1, h2, h3;
      - a paragraph with emphasis, strong, strike, inline code and a line break;
      - a `ruby` code block, a code block with no language, a `mermaid` block;
      - bullets; numbers from 3; a task list (done, open, inapplicable);
      - a table aligned start, center, end;
      - a quote, a rule, a closed `details`;
      - links:
        - page `${ORIGIN}/-/issues/12` with text `#12`;
        - page `https://docs.example/x`;
        - refused `mailto:anna@example.com`;
        - refused `javascript:window.yamtPlanted=true`;
      - images:
        - uploaded `upload~00000000000000000000000000000001` (loads);
        - uploaded `…02` (broken, caption "broken screenshot");
        - web, standing in for another site (a `data:` PNG; documented as such, so the fixture runs offline);
        - refused (caption "refused picture").
    - **!639, long:** 120 paragraphs, so the panel scrolls.
    - **!637:** `read` with no blocks.
    - **!636:** the first ask `failed { message: "glab: a deadline line" }`, each later ask the rich one (a per-iid
      count in the fixture).
    - **!635, planted as text:** paragraphs whose text is `<script>window.yamtPlanted = true</script>`, `<img src=x
      onerror="window.yamtPlanted = true">` and `<iframe src="https://evil.example/">`. It shows how the window renders
      text that looks like markup; Rust would have dropped the elements themselves.
    - **Every other iid:** one paragraph, "Description of !<iid>.".
  - **`uploadedImage(key)`:** a 16×16 PNG `data:` URL for `…01`, `BROKEN_PICTURE` (`fixtureMergeRequestData.ts:39`) for
    any other key.
