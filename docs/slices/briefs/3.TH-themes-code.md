## Change

1. `ipc/themes.ts` + test (design Q9: `themeOf` on the ten names and on `undefined`, `""`, `"Dark"`, `"zed"`;
   `themeKind` per theme; `themeRows` order and count).
2. `editor/internal/syntax.ts` + test: the C2 table with font styles, `syntaxColourClasses`, `paletteHighlight`, moved
   out of `pane.ts`; container tokens first, inner last (design Q4 "Nesting"); `minimapRows.ts` takes the **last**
   matching class (+ test). Test the plausible bugs: each probed tag gets its token (the precedence cases above), the
   minimap's class equals the text's token in nested Markdown, styles only on their rows (heading bold survives).
3. `pane.ts`: the theme compartment holds `EditorView.darkTheme.of(themeKind(theme) === "dark")` and a facet carrying
   the theme name (design Q3); `minimap.ts` drops its cached look when that facet changes (a switch between two dark
   themes redraws); softening still follows the dark flag. `pane.test.ts`: the dark flag for all ten.
4. `main.ts`: `themeOf(dataset["theme"])`. `useThemeAttribute`: also writes `documentElement.style.colorScheme` from
   `themeKind` (+ test: `vscode-light` → `light`).
5. `SettingsView.vue`: the Theme section as five labelled groups (design Q7: `role="group"` + `aria-labelledby` with the
   editor's name, one `ChoiceButtons` per pair, only the chosen theme pressed across all groups).
6. `editor/themes.browser.test.ts` (WebKit, design Q9): for each theme, computed values in a TS merge view equal the
   values parsed from that theme's CSS text (`?raw`): panel and gutter backgrounds, code colour, each syntax token's
