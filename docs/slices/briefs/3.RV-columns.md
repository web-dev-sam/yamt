## Change

1. `compareViews.ts`: split `createColumn` into a pure `columnState(column, { text, kind, settings, extensions })` and
   the view; keep `createColumnViews(texts, hosts, wiring)` (editable, `"center"`, `columnLimit`: unchanged
   behaviour) and add `createReadOnlyColumnViews(texts, hosts, { settings, updated, extensions })`
   (`"readOnlyCenter"`, `differenceField`, `removalTooltip()`, `everyPane()`, no byte limit).
2. `range.ts`: `RangeController` composes `CompareStrip` and `CompareFrame` (bands in one strip, locked scroll through
   `ScrollSync<Column>`, find space), `columnMarks(...)` dispatched once (word marks and removal bars in both columns,
   `changeTone`), `revealDifference`/`keyboardColumn` for the arrows, `languageOf(texts.path)` + `loadLanguage(...)`
   (the merge window's rule), `preferenceEffects("center", …)`. No `format`, `settleNow`, `historyKey`, `setLanguage`
   or `holdsText` (vision 4).
3. The list: `fileTree.ts`, `FileTree.vue`, `FileList.vue` generic with slots; `App.vue` fills them.

## Acceptance

- Node tests in `editor/internal/compareViews.test.ts` (the design §10 table: each names the bug and the one-line hand
  mutation that makes it fail — run each mutation once by hand and report that the test failed): a read-only column's
  state refuses a user insert and keeps its text; a read-only column holds `differenceField`, so `showDifferences`
  lands; an editable column still refuses an insert over its byte limit.
- `fileTree.test.ts`: the existing merge rows unchanged, plus rows of another `{ path }` type through the generic.
- WebKit probe `editor/range.browser.test.ts` (not in `just check`, like `compare.browser.test.ts`; run it through

  colours; `moveToChange("down")` puts the selection on the next difference; typing changes nothing; `destroy()`
  empties the hosts.
- The merge window in fixture mode (WebKit, `just webdriver`): the list and tree look as before (marks, the operation
  tag, the width handle, Ctrl/Cmd+B) — a screenshot of each before and after.
