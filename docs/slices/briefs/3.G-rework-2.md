## Findings (quoted, with the decision)

- #463 (correctness, should, RK5): "'First non-empty' still picks a text that has no line break. With
  base "x" (one line, no newline) and CRLF local/remote, or a deleted side whose base is like that, eol
  becomes Lf; the CM pane then normalises the CRLF lines and finish writes LF bytes." **Decision:** the
  line ending comes from the first of base, local, remote that contains a line break (none → LF as
  today); a case with base `x` (no newline) and CRLF sides expects CRLF.
- #464 (correctness, should, RK5): "No test has base and a side with different line endings, so the
  precedence base → local → remote is not pinned." **Decision:** one case where base (with a line
  break) and the kept side disagree: base wins (LF base, CRLF kept local → LF), so the order is fixed.
- #465 (correctness, should, RK19): "The `len() >= 7` bound … still depends on config: git accepts
  core.abbrev down to 4 … The test also accepts a full 40-character id, so changing the `%h` … to `%H`
  now passes." **Decision:** the expected short id comes from `git rev-parse --short <rev>` run with
  the same configuration gitio's own git calls read (not conflict-repo's isolated one), compared for
  equality, in both `gitio/tests/merge_heads.rs` and `session/tests/remote_name.rs`.
- #462 (nit): `ReadFailed` puts `#[source]` on a field already named `source`; drop it to match
  `WriteFailed`.
