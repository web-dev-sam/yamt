## Behaviour

1. A 0.4.0 file (no `off`) reads with nothing switched off; nothing is migrated or rewritten on read.
2. `set_server_switch` changes only `off[root]` — the answer, the added servers, theme, keys and entries yamt does not
   know stay as the file had them (the same `change` path as every setter). Switching off twice keeps one entry;
   switching on a key that is not there changes nothing but still answers the read.
3. A malformed `off` (not a map of string lists) makes the file `Broken` and nothing is written, as any broken entry.
4. `ipc/tauri.ts` maps the command through the same `toSettingsResult` as `setServerAnswer`; `ipc/fixtureSettings.ts`
   implements it for fixture mode's in-memory file under its repository root (per repository, "on" removes, a root
   left empty removed, other entries kept), and copies `off` where it copies `repositories` today.
5. Command ≤ 15 lines, delegates (IPC5); `src-tauri` depends on `session`/`settings` as today (PM1).

## Tests

- `crates/settings` (where its tests live today, or `tests/language_servers.rs`): a 0.4.0 file without `off` reads with
  nothing off; a switch is stored under this root only; on removes the key and a root left empty; off twice keeps one;
  a switch keeps the answer, the added servers, the theme and unknown entries; a malformed `off` is `Broken` and the
  file's bytes are unchanged.
- `ipc/fixtureSettings.test.ts`: per repository, on removes, an emptied root goes, other entries kept;
  `ipc/tauri.test.ts`: arguments passed, the read returned, the app's error returned.
- `just mutants` runs on your Rust and `ipc/` lines: a switch stored under the wrong root, "on" not removing, a root
  left `[]`, a rebuilt file losing other entries must each fail a test.
