## Contract (fixed; you may add private items, never change these)

```rust
// merge-core/src/line.rs, next to InlineRange (serde::Serialize + specta::Type)
/// A zero-width place inside one line of one text: `column` UTF-16 code units from the line's
/// start, at most the line's length without its line break.
pub struct InlinePoint<L> { pub line: L, pub column: u32 }

// merge-core/src/word.rs
/// One side of a chunk compared with base, line by line.
pub struct SideWordChanges<L> {
    /// Side text that is not in base: sorted by line then start, disjoint, never empty,
    /// never across a line break.
    pub changed: Vec<InlineRange<L>>,
    /// Places where base text this side removed would sit: sorted, at most one per place.
    pub removed_at: Vec<InlinePoint<L>>,
}

/// Where one chunk's sides differ from base.
pub struct WordChanges {
    pub chunk: ChunkId,
    pub local: SideWordChanges<LocalLine>,
    pub remote: SideWordChanges<RemoteLine>,
}

pub fn word_changes(base: &str, local: &str, remote: &str, chunks: &[Chunk]) -> Vec<WordChanges>; // unchanged signature
```

`base` ranges leave the contract (the middle pane draws none).

## Behaviour (rules the output follows)

- **Tokens:** unchanged from today: word runs, whitespace runs (no line breaks), line breaks, any
  other character alone.
- **Anchors, over the whole chunk:** per chunk and side, when both the side's chunk lines and the
  base chunk lines are non-empty, diff the chunk's lines compared **with all whitespace removed**
  (histogram + `postprocess_lines`). Lines matched by this diff pair. Exact line equality is not a
  separate anchor: anchoring a `}` on an identical `}` at another nesting depth is today's bug
  (M9, M14). A pair whose lines are byte-identical carries nothing.
- **Pairing in the gaps:** inside each run of unmatched lines between anchors, base lines and side
  lines pair in order (no crossing; each line in at most one pair) when they are similar enough.
  - The measure counts **words** (word-run tokens: identifiers, keywords, numbers), not
    punctuation or whitespace. Lines without any word compare by their other characters.
  - The measure, the threshold and the way the pairing is chosen are yours. Tune them until every
    catalogue case below passes. Both values are named constants with one line on why.
  - Cost bound: above a named cap of line pairs in one gap, no similarity pairing (the gap's side
    lines are new). State the cap and the timing of `just fixtures` before and after.
- **Inside a pair:** token diff of the two lines only.
  - Side tokens not in base → `changed`.
  - Base tokens removed with nothing added at that place → one point at the side column where they
    sat.
  - Where base tokens were replaced (removed and added at the same place), the `changed` range
    shows it; no point.
  - Keep today's merge rule: two ranges on one line separated only by whitespace become one range.
- **A side line without a partner** is new: `changed` covers its whole text (column 0 to end, no
  line break). An empty line gives nothing.
- **Base lines without a partner** are removed. A run of them between two pairs (or a chunk edge),
  with no new side line in the same gap, gives one point:
  - at column 0 of the side line that follows the gap inside the chunk;
  - if there is none, at the end of the side line before the gap;
  - if the chunk side is empty, no point (the block's own marker shows it).

  With new side lines in the same gap, there is no point; the whole-line marks show the change.

- **Points:** points at the same place collapse into one.
- **Chunk kinds:**
  - `LocalOnly` → remote has no ranges and no points;
  - `RemoteOnly` → the mirror;
  - `BothSame` → both sides equal;
  - add/add chunks (empty base) → nothing.
- **Encoding:** columns count UTF-16 code units; CRLF never inside a range; the same input always
  gives the same output.

## Stress tests (generated)

- **Generator:** a base of 3–30 lines, each with a unique word so the truth is known. Apply a
  random mix of edits to distinct lines: re-indent (tabs/spaces, deeper/shallower), replace a word,
  insert a word, delete a word, insert a line, delete a line, split a line, join two lines. Do this
  on one side, or on both sides for conflicts.
- **Promises,** for every case:
  1. a line no edit touched has no `changed` range (points from neighbouring removals may sit at
     its column 0 or end);
  2. a re-indented-only line has `changed` only inside its leading whitespace;
  3. a line with one replaced or inserted word has `changed` only on that word and whitespace next
     to it;
  4. a deleted word inside a kept line leaves a point on that line.
- **Kept structural properties** (restated for the new shape): ranges sorted, disjoint, non-empty,
  inside their line within the chunk; points inside their line; `BothSame` sides equal; identical
  texts give nothing.
- **Replace the old base-ranges property with:** the side's chunk text minus its `changed` ranges,
  ignoring whitespace, is a subsequence of the base chunk text ignoring whitespace. Unmarked text
  really is in base, in order.

`merge-core` and `ipc/` are mutation-tested (`just mutants`): a wrong column, a missed point, a
dropped pair or a crossed pairing must fail a test.
