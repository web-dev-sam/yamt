## Contract (fixed; you may add, never change)

```ts
// editor/index.ts
export type ProblemCounts = { readonly errors: number; readonly warnings: number; readonly other: number };
export type FormatOutcome =
  | { readonly kind: "formatted" | "unchanged" | "changedMeanwhile"; readonly server: string }
  | FormatRefusal;                              // re-exported from lsp
export type MergeOptions = { …existing; readonly servers: LanguageServers | null };   // null: no servers
class MergeController {
  format(): Promise<FormatOutcome>;             // never rejects; a call while one runs returns the same promise;
                                                // read-only or no servers → { kind: "noFormatter" }
  problems(): ProblemCounts;
  onProblemsChange(listener: (counts: ProblemCounts) => void): void;
}
// ui/useMergeController.ts
type ControllerOptions = { …existing; readonly servers: MaybeRefOrGetter<LanguageServers | null> };
type MergeHandle = { …existing; readonly problems: Readonly<ShallowRef<ProblemCounts | null>>;
                     format(): Promise<FormatOutcome | null> };   // null: no controller
```

`MergeView.vue` passes `servers: null` for now; the status-area slice replaces it with the app's one
`LanguageServers` (the only line of `MergeView.vue` this slice touches).

## Behaviour (settled)

1. **Opened documents:** a controller with an editable Result and `servers !== null` opens one `ResultDocument`
   (`internal/serverDoc.ts`) on construction (`servers.open`), calls `changed()` on every document change, and
   `close()` in `destroy()` (a rebuild after Reset or a disk change is a close, then an open). Read-only views open
   nothing. Paths are `FileMergeData.path` (repo-relative).
2. **`take(version)`** returns the Result text with the document's own line breaks (`state.sliceDoc()`, CM5) and
   remembers that document as `version`. **`showProblems(server, version, problems)`**: positions are converted on
   that version's text (0-based line, UTF-16 character, clamped to the line) and mapped through every change made
   since; problems for a version no longer remembered are dropped; `[]` clears that server's problems. One list per
   server, merged, shown with `@codemirror/lint`'s `setDiagnostics` on the **middle pane only**. Versions no server
   can still answer are forgotten (no unbounded memory).
3. **Look:** a wavy underline per severity (error, warning, info/hint) from new palette tokens in both themes (WebStorm
   New UI's error and warning effect colours as the reference), the message on hover in a tooltip styled with the
   panel tokens, the server name and code after the message in muted text. Problems also show inside waiting
   changes and on marker lines (#70). Check in WebKit that the tooltip is visible above the panes despite the
   `will-change: transform` wrappers in `MergeView.vue`; if it is clipped, use `tooltips({ parent: document.body })`
   with the theme classes kept.
4. **Counts:** errors, warnings, other (info + hint), out through `onProblemsChange` when they change, into
   `MergeHandle.problems` (the `summary` pattern).
5. **`format()`:** options from the Result's indent unit (a tab → `insertSpaces: false`, `tabSize` the pane's tab
   size; n spaces → `tabSize: n`, `insertSpaces: true`); `OpenDocument.format(options)`; on `formatted { sent, result }`:
   the Result no longer equals `sent` → `changedMeanwhile`, nothing applied; else a line diff of `sent` and `result`
   (`internal/lineDiff.ts`, pure Myers on lines; lines split the way the panes split text) dispatched as **one**
   transaction of line replacements with `Text` inserts (never strings with `\n`, so a CRLF Result stays CRLF),
   `userEvent: "yamt.format"` → `formatted`; an empty diff → `unchanged`. `unchanged` and refusals from the client pass
   through. One undo step restores text, spans and statuses (CM2); open blocks keep their arrows unless formatting
   removes every line of one (CM8, as typing would).
