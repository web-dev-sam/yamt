## Findings (verbatim) and what to do

1. [should, correctness] `editor/internal/pane.ts:112` — "The compartment receives the whole
   LanguageSupport, which brings editing behaviours into the editable center pane, not just colours.
   lang-html, lang-vue and JSX bring autoCloseTags (typing '>' inserts '</tag>'). lang-markdown brings
   a Prec.high Enter/Backspace keymap that continues list markup, plus pasteURLAsLink. These change
   the result text the user types in a merge, and the brief asked for syntax colours only."
   Fix: "Put only the parsing language in the compartment: `support.language` (a `Language`) in
   #colour and `description.support?.language` in the constructor, typing paneState's `language` as
   `Language | null`. Nested grammars (Vue's TS script, HTML style/script, Markdown code blocks) are
   configured inside that Language's parser, so colours stay the same."
   **Decision**: do it — colours only (plan §2 #29); typing in the middle pane behaves as before.
2. [should, correctness] `editor/internal/pane.ts:73` — "Lezer uses `tags.character` for character
   literals (@lezer/java CharacterLiteral, @lezer/rust Char, @lezer/go Rune, @lezer/cpp CharLiteral),
   so the brief-mandated `character` → link rule draws 'a' in link blue in Java/Rust/Go/C/C++. […]
   The `angleBracket` → tag rule likewise paints C++ template brackets gold, because @lezer/cpp tags
   '< >' as angleBracket."
   **Decision**: drop `tags.character` from the link rule (character literals fall back to the string
   colour, as WebStorm draws them; HTML entities then show as strings — accepted). Keep
   `angleBracket` → tag: in the owner's languages (Vue, HTML, TSX/JSX, PHP templates) WebStorm draws
   the whole tag gold; gold generic brackets in C++/Rust/Java are the accepted cost. Pin the
   character choice with one `pane.test.ts` case (e.g. a Rust `'a'` literal in the string colour).
3. [should, correctness] `editor/internal/pane.test.ts:76` — "The test is named '…its script setup as
   TypeScript', but it would still pass if the script were parsed as plain JavaScript (for example if
   the lang=\"ts\" nesting were lost), because `const` and \"hi\" are keyword and string in both
   dialects." Fix: "Add a TypeScript-only construct and assert it: e.g. `interface Props {}` in the
   script with `interface` expected in the keyword colour (it is a plain identifier in the JS dialect)."
4. [should, boundary, TS11] `editor/index.ts:81` — "#createViews now spans lines 81–128, 48 lines,
   over TS11's 40-line function limit." Fix: "Declare
   `type ViewSources = { data: FileMergeData; hosts: MergeHosts; language: … | null }` next to
   MergeHosts. Write the signature on one line as
   `#createViews({ data, hosts, language }: ViewSources): PaneViews {`, and fold `const { eol } = data;`
   into `const shared = { eol: data.eol, language };`." (Any equivalent that brings it to ≤ 40 lines.)
5. [nit, boundary] `editor/index.ts:63` — "`#colour` loads a grammar, logs on failure and reconfigures
   the language compartment, but its name says only 'colour'." Fix: rename to `#loadLanguage`.
