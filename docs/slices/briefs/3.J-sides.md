## Contract (fixed; you may add, never change)

```rust
// gitio: git's own names for the stages
pub enum Stage { Base, Ours, Theirs }        // index stage 1, 2, 3

// session
pub enum GitSide { Ours, Theirs }             // git's side; never a pane
// `Orientation` (new `orientation.rs`): decided once at open from the `Stop`, one exhaustive match —
// git's theirs on the left only for `Operation::Rebase(Rebase { redoing_merge: None, .. })`; else ours on the left.
impl MergeSession {
    pub fn stop(&self) -> &Stop;              // the stop read at open (rows 4–5 compare against it)
}
#[serde(tag = "kind")]
pub enum SideName {
    Branch { name: String },
    Commit { short_id: String, subject: String, message: String },
    Revert { short_id: String, subject: String, message: String },  // the commit a revert undoes
    Patch { subject: String, message: String },                        // `am`'s patch
}
pub enum Waiting {
    SideLines,
    /// A conflict as git writes it: `open`, the section of the pane `first` (git's ours: HEAD), `between`, the
    /// other pane's section, `close`.
    Markers { open: String, first: Side, between: Vec<String>, close: String },
    AsShown,
}
```

## Behaviour

1. **One place decides the panes.** `Orientation` is built once in `open` from `repo.stop()` and stored; every consumer
   in the design's question-2 table goes through it. Types keep git's sides and panes apart: `CapturedStages` keyed by
   `GitSide`, `Texts` and every DTO by `Side`, git-ordered ranges untyped until `Orientation` turns them into
   `LocalLine`/`RemoteLine` (vision 4: a consumer that skips it must not compile).
2. **Pane order** from open on: texts, chunks, words, describe, take (`resolve_with` the stage of
   `o.git_side(side)`), Keep/Delete on a deleted-side file, `deleted`, `UnsupportedReason::{LocalDeleted,
   RemoteDeleted}`, names, summary.
3. **Git's order on disk and in the index**: the start check (`start.rs`) re-runs git's merge as git did; a disk block's
   first section is git's ours (`locate.rs`, `seed.rs`); Save writes a waiting conflict's markers with HEAD's section
   first and git's labels, byte-equal to what git wrote (`Waiting::Markers.first` = the pane holding ours, from
   `MarkerStyle`); Reset writes the at-open bytes; `checkout -m` is git's.
4. **Names (#87):** ours-name and theirs-name are read per git side and placed by `Orientation`. Merge and `rebase -r`'s
   merge step: HEAD (#62) / `MERGE_HEAD` (#50); squash merge: HEAD / the merged commit by #50's branch rule, else its
   commit form; rebase: HEAD as a commit / `REBASE_HEAD` as a commit — so the replayed commit lands on the left;
   cherry-pick: HEAD / `CHERRY_PICK_HEAD`; revert: HEAD / `Revert` of `REVERT_HEAD`; `am`: HEAD / `Patch` from the
   `Operation::Am` bytes (lossy UTF-8 as today's `text`); none recorded: HEAD / none. A failed read drops only that
   name and warns (#62). `side_names()` keeps its signature and meaning ("left", "right").
5. **Window:** `fileText.ts` writes the sections in `first` order; `sideHeaders.ts` handles the two new kinds;
   `ipc/fixture.ts` parses `first`; fixtures regenerated (`just fixtures`, then `just fixtures-check` passes).
