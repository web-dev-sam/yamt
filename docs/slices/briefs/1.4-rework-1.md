## Change

1. [block, correctness, RK5/CM5] `internal/apply.test.ts:302` — the only CRLF test builds its
   states with `eolSeparator` directly and checks `state.sliceDoc()`; it never goes through
   `createPane` or `resultText()`, so dropping the separator from `createPane` or switching
   `resultText()` to `doc.toString()` stays green, and CRLF files would reach `finishFile` as LF.
   Fix: move `createPane`'s `EditorState` construction into an exported `pane.ts` function (e.g.
   `paneState({ kind, doc, eol, language, extensions })`, which `createPane` mounts); build the
   test's states with it and assert `\r\n` in the text the controller's serialisation produces
   (the same function `resultText()` uses).
2. [should, correctness, CM1] `internal/chunkField.ts:59` — if the user deletes the unchanged line
   between a half-applied conflict C and the next chunk D, the `«` apply inserts at
   `C.to == D.from`; D's `from` maps before the insertion and the cap cuts `C.to` back, so the
   appended remote lines belong to D and applying D later replaces them. Same for applying an
   empty-range insertion that has become adjacent to the next chunk. Fix: in the mapping, when the
   span being applied in this transaction overruns `next.from`, push `next.from` (and `next.to` if
   lower) up to the applied span's `to` instead of capping the applied span. Test: delete the
   separator line, apply `»` then `«`, assert C's text is local + remote and D starts after it;
   the random-edit invariant test from 1.1 must stay green.
3. [should, correctness] `internal/strips.ts:89` — arrows act on `click`, so a repaint between
   press and release loses the click, and the press on the strip blurs the middle pane so Ctrl+Z
   right after `»` does nothing. Fix: act on `pointerdown` on the arrow, and `preventDefault()` on
   `mousedown` of each strip `<svg>` so the middle pane keeps focus. Smoke: Ctrl+Z right after an
   arrow click undoes it.
4. [should, correctness] `ui/MergeToolbar.vue:49` — the "N changes · M conflict(s)" / "All
   changes processed" label has untested branches. Move it into a pure function in a `ui/` `.ts`
   module (e.g. `summaryLabel(summary)`) with a node test for `{0,0}`, `{1,0}`, `{0,1}`, `{3,1}`,
   `{2,2}`.
5. [should, boundary] `internal/sideStatus.ts:10` — the side mirror sets its own initial
   `pending`, a second definition of the initial status. Seed the side fields from the center
   field's state (create the center pane first) so the mirror never invents a status.
6. [should, boundary, RS16] `internal/apply.ts:47` — `applyChunk`, `applyAllNonConflicting`,
   `dismissChunk` only build and return a `TransactionSpec` but are named as actions, and one
   shares its name with the controller method that dispatches it. Rename for what they return
   (e.g. `applySpec`, `bulkApplySpec`, `dismissSpec`).
7. [should, boundary, TS3] `index.ts:102` — `#act` branches on `ChunkAction.kind` with a ternary;
   use an exhaustive `switch` with a `never` default.
8. [should, boundary] `internal/strips.ts:136` — `paintStrips` repeats a ~15-line block per
   strip. Restore one `paintGap(...)` called twice.
9. [nit, boundary, TS6] `ui/useMergeController.ts:27` restates `"local" | "remote"`; re-export
   `Side` from `editor/index.ts` and use it.
10. [nit, correctness] `ui/store.ts:63` — when `resetFile` succeeds but the following
    `listFiles` rejects, the log says `store.reset_failed`. Give the list refresh its own
    `store.list_failed` log. (Also rename `latestOpen` → `latestLoad`, boundary nit: it now
    tickets resets too.)
