## The feature (owner, 2026-10-16)

"While Alt is held, each pane's scrollbar shows coloured ticks: the side panes show their own waiting changes and
conflicts. The Result shows waiting changes, conflicts and language-server problems. Clicking a tick jumps to that place.
Releasing Alt hides the ticks." Option on macOS.

**Product rules — settled, do not reopen:** `docs/slices/SLICES.md`, section "Change marks", rules 1–8, acceptance and
non-goals. Read them in full first. Two of them are yours to check with evidence and correct if wrong (say so in
`open_risks` with the source): rule 3 (which changes a pane marks — it must equal what that pane colours as waiting
today) and rule 5 (what a click does — WebStorm's error-stripe click, see below).

- the error-stripe colours for inserted, modified, deleted, conflict and error/warning/weak warning in Islands Dark and
  Islands Light: the owner's installed WebStorm is `~/.local/share/JetBrains/WebStorm-262.10968.77/lib/` (scheme XMLs

## What each option must answer

1. **Alt state**: one owner for "marks shown" (vision 2): where the window listeners live (keydown/keyup/blur/
   visibilitychange and the Alt-up fallback on key and pointer events, rules 1–2), how it reaches the shown file's
   panes and not the hidden files', and what a file opened or shown while Alt is held does.
2. **The lane**: which element, inside or outside CodeMirror's DOM, positioned how over an overlay and a classic
   scrollbar (its width when the scrollbar takes no room, its top/bottom against a classic scrollbar's arrows), above
   the scrollbar while shown, absent from hit-testing while hidden (rule 7). How it survives a pane resize, the file
   list hiding (Ctrl/Cmd+B), the find bar opening above line 1 (`findSpace`), theme switches.
3. **Ticks**: the pure function from (pane, statuses, problems, layout heights) to ticks (top, height, colour kind,
   target) — tested on numbers; where heights come from (`lineBlockAt`/`contentHeight`, the find space, collapsed
   runs, CodeMirror's estimated heights for lines never drawn and how far off that can be); when ticks recompute while
   shown (doc change, statuses, problems, folds, resize, measured heights) and that nothing runs while hidden; drawing
   order for overlaps; minimum height.
4. **Click**: hit testing (exact tick or nearest within some px; overlaps), `preventDefault` and focus, and the jump per
   rule 5 for a side tick and for a Result tick, reusing the existing navigation/reveal code rather than a second copy
   (name the functions); what the locked scroll does after the jump.
5. **Tests**: `editor/` is not mutated (VF7), so name node unit tests that fail for each rule's plausible bug (tick
   placement and collapsed heights, which changes are marked per pane, the Alt state transitions incl. blur, another
   key, AltGraph, repeat, a missed release), and the WebKit steps (MiniBrowser through `just webdriver 4446`) and
   real-app steps (`just app-session`, session names `b-…`, real X input via `xdotool keydown alt` … `keyup alt`) that
   prove the acceptance.
6. **Size**: files, changed-line estimate per build (≤ ~25 files, ≤ ~1,500 lines each), `editor/index.ts` budget, new
   public surface on `MergeController` (keep it small).
