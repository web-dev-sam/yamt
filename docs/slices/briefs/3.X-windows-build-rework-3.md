# Slice 3.X-windows — rework 3 (CI's first Windows run)

Gate B, owner's call (#779 authority, #803): a third round, because CI showed what local checks could not. Original
brief `docs/slices/briefs/3.X-windows-build.md`; plan §2 #59.

## Evidence

`ci` run 38449272985 (`main` @ `45427b7`): `rust (windows-2025)` failed in "Rust tests without the runner's git config"
with **exit code 104** (annotation `.github:480`). cargo-nextest's 104 is "test list creation failed": a test binary
could not even list its tests. Known cause in tauri 2 (tauri-apps/tauri#13419, #11028, open): `tauri-build` embeds the
Windows app manifest (Common Controls v6) with `rustc-link-arg-bins`, so only the main binary gets it; every test binary
linking tauri (yamt-app's lib and integration tests use `tauri::test`) dies at load with `0xc0000139
STATUS_ENTRYPOINT_NOT_FOUND`. tauri's own workaround (`examples/api/src-tauri/build.rs` at `tauri-build-v2.7.1`):
`WindowsAttributes::new_without_app_manifest()` plus `cargo:rustc-link-arg=/MANIFEST:EMBED` and
`cargo:rustc-link-arg=/MANIFESTINPUT:<file>` (applies to every artifact), the file being tauri-build 2.7.1's
`windows-app-manifest.xml` (only the Common-Controls 6.0.0.0 dependency). The job log itself is not readable without a
token, so failing test names never reach us.

## Target

Owned: `src-tauri/build.rs`, `src-tauri/windows-app-manifest.xml` (new), `.github/workflows/**`, `.github/actions/**`.
Read-only: everything else.

## Change

1. `src-tauri/build.rs`: when the **target** is Windows MSVC (`CARGO_CFG_TARGET_OS == "windows"` and
   `CARGO_CFG_TARGET_ENV == "msvc"`, read from the environment — not `#[cfg(windows)]`, which is the host), build with
   `WindowsAttributes::new_without_app_manifest()` and print the two link args pointing at
   `src-tauri/windows-app-manifest.xml` (absolute path from `CARGO_MANIFEST_DIR`), with `cargo:rerun-if-changed`. Other
   targets: `tauri_build::build()` behaviour unchanged. The manifest file is tauri-build 2.7.1's, byte for byte, with one
   line saying where it comes from and why (tests need it too). No `/WX`.
2. CI failures readable without logs: in `ci.yml`'s Rust test step keep the output (`tee` to a file under `target/`), and
   a step `if: failure()` that turns the failing lines into workflow annotations (`::error::…`): every nextest
   `FAIL`/`SIGSEGV`/`SIGABRT`/`TIMEOUT` line and `error:`/`Caused by`/`exit code` line (deduplicated, at most ~40), plus
   one annotation with the last ~80 lines (newlines encoded as `%0A`). Annotations are public through the checks API,
   job logs are not. Same for the app build step if cheap.
