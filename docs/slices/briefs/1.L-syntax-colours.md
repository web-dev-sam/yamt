# Slice 1.L — syntax colours for Vue and most other languages

Only TypeScript is coloured today; `.vue` and `.tsx` files show plain text. The owner asked for
"Vue and most other languages". Decision (plan §2 #29, visions 2 and 5): every language in
CodeMirror's official list `@codemirror/language-data` (already installed, pinned 6.5.2), each
grammar loaded on demand; the language is found from the file name in `editor/` by that list's own
table; the `language` field leaves the Rust↔frontend contract and Rust's extension table is deleted
(one table of that fact, maintained upstream).

## Target

Owned:

- `frontend/src/editor/**`, `frontend/src/style.css`
- `frontend/src/ipc/domain.ts`, `frontend/src/ipc/fixture.ts`, `frontend/src/ipc/fixture.test.ts`
- `crates/session/src/decode.rs`, `crates/session/src/session.rs`,
  `crates/session/tests/open_and_load.rs`, `crates/cli/tests/commands.rs`

Generated, never hand-edited: `frontend/src/ipc/bindings.ts` (`just bindings`) and
`frontend/fixtures/golden/*.json` (`just fixtures`). Run both after the Rust change so your
typecheck and tests see the new shape; report that you ran them.
Read-only: everything else — `frontend/src/ui/**`, `frontend/src/connectors/**`, configs,
`frontend/package.json` (dependencies are the orchestrator's: if one is needed or becomes unused,
report it), `docs/**`, `.omp/**`.
Non-goals: a language picker, detection from file content (shebangs, `<?php` without extension),
a different colour for Vue/JSX component tags than for HTML tags, semantic colouring (calls vs
declarations), changing the existing TypeScript colours, word-level highlights, a light theme.

## Behaviour (what the user sees)

- Opening a file colours all three panes in its language: `.vue` (template tags, attributes,
  `{{ }}`, and the TypeScript inside `<script setup lang="ts">`), `.tsx`/`.jsx` (JSX tags), `.ts`,
  `.js`, `.php`, `.html`, `.css`/`.scss`/`.less`, `.json`, `.md`, `.yaml`, `.sql`, `.py`, `.rs`,
  `.go`, `.java`, `.c`/`.cpp`, shell scripts, `Dockerfile`, … — whatever `language-data` matches.
- A file whose name matches nothing stays plain text, exactly as today, with no warning.
- The first file of a language may appear plain for a moment while its grammar loads, then the
  three panes colour; later files of that language colour at once. Recolouring never adds an undo
  step, never moves the scroll position and never changes a chunk's colours, bands or arrows.
- Switching files while a grammar is still loading is harmless: nothing is applied to the closed
  file's panes, nothing throws.
- A grammar that fails to load leaves the file plain and logs
  `log.warn("language.load_failed", { path, language, reason })` through the app logger
  (`log` from `../ipc` / `../../ipc`, as the editor tests already import it).

## Contract (fixed; you may add, never change)

- Rust: `FileMergeData.language`, `session::decode::language_of`, `TYPESCRIPT_EXTENSIONS` and any
  import they leave unused are deleted; the Rust tests drop their `language` assertions. Nothing
  else in Rust changes. `bindings.ts` then has `FileMergeData = { path, base, local, remote, eol, chunks }`.
- `ipc/`: the domain `FileMergeData` loses `language`; the fixture schema follows the generated
  type (`satisfies SchemaOf<Generated.FileMergeData>` stays).
- `editor/`: detection is `LanguageDescription.matchFilename(languages, <basename of data.path>)`
  with `languages` from `@codemirror/language-data` (the basename matters: a `Dockerfile` in a
  subdirectory matches only by its base name). No `@codemirror/lang-*` package is imported
  anywhere (cm6-rules dependency list); `pane.ts` loses its `LANGUAGES` table and the
  `@codemirror/lang-javascript` import. An already-loaded description (`description.support`) is
  used when the panes are created; otherwise `description.load()` and, when it resolves, one
  reconfigure per pane through a `Compartment`, skipped if the controller was destroyed meanwhile.
  `MergeController`'s constructor, `MergeHosts` and public methods stay as they are.
- Colours only from palette tokens (VU17: no colour literals outside `@theme` in `style.css`). Add
  to `@theme` exactly these, taken from the installed WebStorm's New UI dark scheme
  (`themes/expUI/expUI_darkScheme.xml`):
  - `--color-syntax-tag: #d5b778` — HTML/XML/Vue/JSX tag names and their angle brackets
    (`HTML_TAG`, `HTML_TAG_NAME`);
  - `--color-syntax-regexp: #42c3d4` — regular expressions (`JS.REGEXP`);
  - `--color-syntax-link: #56a8f5` — Markdown links and URLs, HTML entities
    (`MARKDOWN_LINK_TEXT`, `HTML_ENTITY_REFERENCE`).
- `paletteHighlight` gains rules (existing rules unchanged): `tagName` and `angleBracket` → tag;
  `attributeValue` → string; `escape` → keyword (`DEFAULT_VALID_STRING_ESCAPE`); `regexp` → regexp;
  `link`, `url`, `character` → link; `heading` and `strong` → bold, `emphasis` → italic,
  `strikethrough` → line-through (no colour). `attributeName` gets no rule: the New UI dark scheme
  draws attribute names in the default text colour (`XML_ATTRIBUTE_NAME` = `#BCBEC4`).

## Tests (`node` project; `EditorState` only for editor code)

- detection by file name: `.vue` → Vue, `.tsx` → TSX, `.ts`/`.mts` → TypeScript, `.php` → PHP,
  `src/docker/Dockerfile` → Dockerfile, an unknown extension → none;
- after loading, a Vue document's `div` (template) is drawn with the tag colour and `const` inside
  `<script setup lang="ts">` with the keyword colour; a TSX document's JSX `div` with the tag colour
  — assert through `paletteHighlight` and the real grammar, not a copy of the rule list;
- recolouring a center-pane state through the language compartment leaves the undo history empty
  and the chunk field unchanged;
- `ipc/fixture.test.ts` and the editor tests no longer mention `language`.

`editor/` is outside the mutation run: break each tested rule by hand once (e.g. map `tagName` to
nothing, match on the full path instead of the basename, skip the reconfigure), paste the failure,
restore. Rust changes are deletions; `cargo test -p yamt-session -p yamt-cli` must pass.
