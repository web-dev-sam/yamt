Facts (given, `feat/raw-compare` at the commit you start from):

- `crates/merge-core/src/compute.rs`: `compute_chunks(base, local, remote, &Options)`; `Options { gap: u32 }`
  (`:92-95`), `DEFAULT_GAP` 1 (`:88`). With `local == base` the base↔local diff has no hunks, so `sweep` sees only
  remote hunks (`:137-160`), every region classifies `RemoteOnly` (`:162-169`), `map_base_to_side` maps each line to
  itself (`:62-81`): `chunk.base == chunk.local` are the left ranges, `chunk.remote` the right ones. Gap 0 gives one
  chunk per hunk; `crates/cli/tests/merge_file.rs:185` already diffs 2-way with `Options { gap: 0 }`.
- `crates/merge-core/src/word.rs`: `word_changes` (`:47-64`) compares each side with base, so for `(left, left, right)`
  it marks only the right; private `side_word_changes(base, all_side_lines, side_range, line_of)` (`:66-97`) marks one
  side against a base slice — called once with the right as side (left lines as base) and once with the left as side
  (right lines as base) it gives both columns' marks. `Removal<L>`, `SideWordChanges<L>`, `InlineRange<L>`,
  `InlinePoint<L>` are generic over the line type.
- `crates/merge-core/src/line.rs`: `BaseLine`/`LocalLine`/`RemoteLine` newtypes, `LineRange<L> { start, len }` with an
  `end()` per line type, all `Serialize + specta::Type`.

  `crates/cli/src/fixture.rs:45` prints `serde_json::to_string_pretty(&data)? + "\n"`; `crates/cli/src/lib.rs` `run`.

## Contract (fixed; you may add, never change)

```rust
// crates/merge-core/src/line.rs — two new line spaces (vision 4), same derives as BaseLine
pub struct LeftLine(pub u32);   // 0-based line index in the left text of a 2-way compare
pub struct RightLine(pub u32);  // 0-based line index in the right text of a 2-way compare
impl LineRange<LeftLine> { pub fn end(&self) -> LeftLine; }
impl LineRange<RightLine> { pub fn end(&self) -> RightLine; }

// crates/merge-core/src/compare.rs — re-exported from lib.rs: Difference, DifferenceWords, LeftLine, RightLine, compare
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Type)]
pub struct Difference {
    pub left: LineRange<LeftLine>,   // empty = the right inserted lines here
    pub right: LineRange<RightLine>, // empty = the right removed the left's lines here
    pub words: DifferenceWords,
}
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Type)]
pub struct DifferenceWords {
    pub left: SideWordChanges<LeftLine>,   // left compared with right: left text the right lacks; removals = right text the left lacks, where it would sit in the left
    pub right: SideWordChanges<RightLine>, // right compared with left
}
#[must_use]
pub fn compare(left: &str, right: &str) -> Vec<Difference>; // sorted, disjoint; compare(t, t) is empty
```

```
yamt-cli compare <case-dir>     # reads <case-dir>/left.txt and right.txt, prints pretty JSON + "\n":
{ "left": "<left text>", "right": "<right text>", "differences": [Difference, …] }   # serde field names as above
```

## Change

1. `LeftLine`/`RightLine` and their `end()` in `line.rs`; `compare.rs` with a private `COMPARE_GAP: u32 = 0` next to
   its only user, calling `compute_chunks(left, left, right, &Options { gap: COMPARE_GAP })` once and the existing
   `side_word_changes` in both directions per difference (make it `pub(crate)`; no copy of its logic). No second diff
   rule, no I/O, no `serde_json` (merge-core's fences).
2. `yamt-cli compare <case-dir>`: a `Command::Compare { case_dir }`, missing files → the existing error kinds.
3. Three cases in `tests/compare/<case>/{left,right}.txt`, hand-written: `json-payload` (two pretty-printed JSON payloads:
   a changed value, a key only on the right, a key only on the left, a line with two changed words), `words` (plain
   text: a word changed inside a line, a word removed inside a line, a whole-line insertion, a whole-line deletion, a
   multi-line block replaced), `typescript` (a ~40-line TypeScript sample with two separated changes). Generate
   `frontend/fixtures/compare/<case>.json` by running your command (the loop below), and report the exact `justfile`
   lines for the orchestrator: `compare` added to `fixtures-into`'s `rm -rf`/`mkdir -p`, a loop
   `for case in tests/compare/*/; do target/debug/yamt-cli compare "$case" > "{{ dir }}/compare/$(basename "$case").json"; done`,
   and `diff -ru frontend/fixtures/compare target/fixtures-check/compare` in `fixtures-check`.
4. `AGENTS.md` of both crates: one line each naming `compare` / the command.

## Acceptance

- `crates/merge-core/tests/compare.rs` (proptest over line-structured texts, as the existing invariants tests build
  them): rebuilding the right text from the left text and the differences' line ranges gives the right byte for byte;
  ranges sorted and disjoint on both sides, never both empty; `compare(t, t)` is empty; the line ranges equal
  `compute_chunks(l, l, r, &Options { gap: 0 })`'s base/remote ranges; every word range lies inside its difference's
  lines on its own side and never crosses a line break; every removal text is non-empty; for a one-word change both
  columns get exactly that word's range. Each test names the bug it catches.
- `crates/cli/tests/commands.rs`: `compare` on a case prints the three keys and is stable (byte-equal on a second run);
  a missing `right.txt` fails with the existing error and exit code.
