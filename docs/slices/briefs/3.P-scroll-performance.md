# Slice 3.P — scrolling stays smooth

The owner, after the UX-list build (#487): "scrolling lags, its getting slow … slow = laggy". The
orchestrator measured the cause on the owner's machine (below). Fix it with **no behaviour change**:
everything the window does today it still does, only faster.

## Target

Owned: `frontend/src/editor/**`, `frontend/src/ui/**`. Read-only: everything else (`ipc/`, Rust,
docs). `editor/`'s public surface (`MergeController` and its exports) stays as it is unless a change
is unavoidable; say so in `deviations_from_brief`.

Non-goals: dropping the editors of opened files (plan §2 #37/#14: every opened file keeps its
editor and its work for the app's lifetime — not up for change here); WebKit settings; the Rust
side; new features.

### The three causes

1. **Every opened file's three editors are laid out on every frame.** `MergeView.vue` hides inactive
   files with `invisible` (`visibility: hidden`): still laid out, so each scroll frame lays out
   every file ever opened. Since Mark resolved / Keep / Take open the next file (#48), they pile up
   fast — this is the owner's "getting slow". `display: none` is out (2.K: a hidden scroller loses
   `scrollTop` in WebKit). Measured: `content-visibility: hidden` on an inactive file's root keeps
   all three `scrollTop`s in this WebKit (set 20 000, hidden 400 ms, shown → identical
   `[21735, 20000, 19717]`) and removes the growth.
2. **Both strips are rebuilt from scratch every frame.** `paintGap` (`editor/internal/strips.ts`)
   creates new `<path>`, `<g>`, `<title>`, `<rect>`, imported icon `<svg>` nodes and a `pointerdown`
   listener per icon, then `strip.replaceChildren(...)`. Inserting new nodes every frame (style,
   layout and paint of fresh subtrees) costs about 15 ms per frame on pnpm-lock.yaml (the "never
   inserted" row) and about 4 ms on renderer.ts. Layout containment (`contain: strict` on strips or
   pane hosts, also tried) did not help: it is the rebuild, not layout spreading.
3. **Every frame recomputes geometry for every chunk.** `chunkRows` (three `lineBlockAt` per chunk)
   and `anchorsOf` over all chunks run on every scroll frame: about 4 ms per frame on pnpm-lock.yaml's
   186 chunks (the controller's JS with strips gone), although chunk heights only change with the
   document, the line heights CodeMirror measures, or the find space.

## Change

Decide the shapes yourself; keep them boring (vision 5) and readable (vision 1).

1. **Inactive files skip rendering, keep their state.** An inactive file's view is not laid out or
   painted, yet keeps its editors, scroll positions, selections, undo history, an open find bar and
   its query. When it becomes active again it shows exactly what it showed before, also after the
   window or the file list was resized while it was inactive (CodeMirror must re-measure). Measured
   candidate: `content-visibility: hidden` (Tailwind arbitrary property is fine). Keep `invisible`
   only if it is still needed for something; say which.
2. **Strips are updated, not rebuilt.** Per scroll frame only positions change; nodes are created or
   removed only when a band/icon enters or leaves the strip, or a chunk's status, mode or the
   covered set changes. Icon behaviour stays exactly: press-on-release apply/ignore, drag to cover
   several (one undo step), the covered highlight, titles ("Ignore", the apply titles), focus kept in
   the editor (`keepEditorFocus`), nothing in a read-only view.
3. **Per-chunk geometry is computed when it can change, not per scroll frame.** Recompute rows (and
   the sync's anchors) when the document, the measured heights (`geometryChanged`), statuses or the
   find space change; a scroll frame reuses them. Scroll sync must keep the panes aligned exactly as
   now (chunk edges line up; the 0.5 anchor; the echo handling).
4. Any other per-frame cost your profile finds (for example reading layout after writing
   `scrollTop` in the same frame) — fix it if it shows in the numbers, and say what it was.

Constraints: `editor/index.ts` is at 296 of 300 lines (lint `max-lines`): move the frame logic into an
`internal/` module if it grows. Follow `skill://cm6-rules` (effects/fields, mapping) and the house
conventions. Tests: a new pure helper (e.g. picking the chunks in view, or deciding when rows are
stale) gets tests that would catch a wrong boundary; never pin DOM node reuse or call counts.
