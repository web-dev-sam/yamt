## Contract

Fixed: design §4.6 "src-tauri" exactly (`ResolveReply`, `ContinueMergeReply`, the three page commands,
`second_window`'s two functions, `Merge::Committed { offer }`, `MergeState`'s `_claim`, `Listing::Files.merge_request`,
`ContinueReply::ReadyToPush { branch }`, `AbortReply { leftovers }`, the four merge commands and their window rules,
`session()`/`has_ended()`/ending of `Committed`) and §4.6
"TS". Existing names that stay: `continue_operation`, `abort_operation`, `list_stop`, `open_merge_request`,
`find_gitlab_project`, `list_merge_requests`, `open_page`; RK42's test names move with the code into `second_window.rs`.

Behaviour:

- `resolve_merge_request(iid)` (async, `blocking_reply`): no project → `GitLabRefused { Failed { NO_PROJECT } }`;
  `prepare_resolve` refusal → `GitLabRefused`; `yamt_local_merge::start(target.root, &MergeRequestBranches { iid:
  target.iid.0, remote, branch, target })` refusal → `Refused`; `Started` → `second_window::start_merge(root)`: `Ok` →
  `Started`, `Err(message)` → `WindowFailed { started, message }`. The window start is a parameter of the private
  composing function (an `FnOnce(&Path) -> Result<(), String>`) so a test passes a recorder; the command passes
  `second_window::start_merge`.
- `continue_merge_request(iid)` (async, `blocking_reply`; request rule 9): no project → `Ended`; `find_live(root)`
  `None` (or a git error, logged) or `live.iid() != iid.0` → `Ended`; `window_is_open(root)` → `AlreadyOpen`; else the
  window start → `Ok` → `Opened { branch, target }` (from `live.view()`), `Err(message)` → `WindowFailed { message }`.
  The same injected window start as resolve (one composing pattern).
- `find_local_merge()` (async, `blocking_reply`): no project → `Free`; else `yamt_local_merge::local_merge(root)`.
- `start_merge(root)`: `yamt --repo <root>` with cwd `root`, `--repo` and the path as two arguments, the same program,
  detach and reap rules as `start_range` (one private spawn function for both).
- `list_stop`: after `refresh_stop` gives `Files`, `merge_request = find_live(root)?.map(|live| live.view())`; a git
  error of `find_live` → `IpcError::Git { message }`.
- `abort_operation`: `find_live` before handing the session to the worker; on the worker `session.abort_operation()`
  then, for a live record, `live.restore()`; `Aborted(kind)`; reply `AbortReply { leftovers }`; the command destroys the
  window only when `has_ended()` and `leftovers` is empty.
- `continue_operation`: `find_live` before the worker; `Continued::Finished` with a live record → `live.committed()`,
  state `Committed { offer }`, reply `ReadyToPush { branch: offer.branch() }`, window kept; without a record as today.
- `push_merged_branch` (async, on a worker as `on_worker` does, state `Running(Merge)` meanwhile): only from
  `Committed` (else `IpcError::NoOperation`); `Pushed` → `Finished(Merge)`, window destroyed; `Failed` → back to
  `Committed { offer }`, window kept.
- `close_ended_merge()`: `Committed` → `Finished(Merge)`; then the window is destroyed when `has_ended()`; any other
  state: nothing.
- `outcome::startup`: with a live record (`find_live(root)` `Some`), first `claim_window(root)`: `None` →
  `Startup::Done(Ending::failure("the merge of !<iid> is already open in another yamt window"))` (exit 2), `Some(claim)`
  → kept in `MergeState` (`_claim`) for the process's life, and a session with no file opens the window; without a
  record "nothing to merge" as today. The close ending of `Committed` is `Finished`'s.

TS (`frontend/src/ipc`): `domain.ts` — `export type MergeView = Readonly<Generated.MergeView>`, likewise `ReturnTo`,
`BranchBefore`, `Leftover`, `AbortReply`, `PushReply`; `Listing`'s `Files` gains `readonly mergeRequest: MergeView |
null`, `toListing` maps `merge_request`. `mergeRequestDomain.ts` — aliases `Readiness`, `BlockedReason`, `ChangeSize`,
`Started`, `Refusal`, `ResolveRefusal`, `ResolveReply`, `ContinueMergeReply`, `LocalMerge` (no conversion: none carries
a brand). `index.ts` exports all fifteen names.
