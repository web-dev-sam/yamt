# Slice line-ranges-domain — the window's `ThreadPlace`, its conversions and the seeded range threads

Design: `docs/slices/briefs/line-ranges-design.md` option A (§1 "Data", "Fixtures"). This build exists because the
window's share of the type cutover (ipc + ui + agent, 28 files) is over the size guide, and because the editor and
window builds both need these types in the tree before they start side by side.

## Target

**Owned:** `frontend/src/ipc/threadLine.ts`, `frontend/src/ipc/ReviewSource.ts`, `frontend/src/ipc/reviewDomain.ts`,
`frontend/src/ipc/reviewDomain.test.ts`, `frontend/src/ipc/tauriReview.ts`, `frontend/src/ipc/tauriReview.test.ts`,
`frontend/src/ipc/fixtureReview.ts`, `frontend/src/ipc/fixtureReview.test.ts`, `frontend/src/ipc/fixtureThreads.ts`,
`frontend/src/ipc/fixtureRange.test.ts`, `frontend/src/ipc/index.ts`, `frontend/src/ipc/AGENTS.md`.

**Read-only:** `frontend/src/ipc/bindings.ts` (regenerated by the orchestrator after the rust build; never edit),
everything else.

**Needs:** the rust build committed and `just bindings` run (generated `DiffLine`, `ThreadPlace`, `Thread.place`,
`commands.addThread(file, place, text)`; contract in `line-ranges-rust.md`).

**Non-goals:** any file under `editor/` or `ui/` (the editor and window builds); a fixture refusal of a backward place
(the window cannot make one; Rust's `BackwardPlace` is not mirrored).

After this build `src/editor/` and `src/ui/` do not typecheck (they still read `line`); the editor and window builds
fix their own layers.

## Contract

`frontend/src/ipc/threadLine.ts` after this build (exactly these exports; bodies are yours):

```ts
export type ThreadLine = /* unchanged: removed | added | unchangedOnLeft | unchangedOnRight */;

/** A line of the diff in GitLab's one-column order: an unchanged line once, a change's removed lines, then its added lines. */
export type DiffLine =
  | { readonly kind: "removed"; readonly left: LeftLine }
  | { readonly kind: "added"; readonly right: RightLine }
  | { readonly kind: "unchanged"; readonly left: LeftLine; readonly right: RightLine };

/** From `start` to `end` in GitLab's order, both included; one line when `start` is `end`'s line. `end` decides the box's column. */
export type ThreadPlace = { readonly start: DiffLine; readonly end: ThreadLine };

export type ShownThread = {
  readonly key: string;
  readonly place: ThreadPlace;
  readonly shown: "open" | "collapsed" | "draft";
};

export function shownLine(line: ThreadLine): { readonly column: Column; readonly line: number }; // unchanged
export function shownColumn(line: ThreadLine): Column;                                            // unchanged
export function changedThreadLine(column: Column, line: number): ThreadLine;                      // unchanged
export function unchangedThreadLine(column: Column, lines: { readonly left: number; readonly right: number }): ThreadLine; // unchanged
/** The line without the column it was picked in: `unchangedOnLeft`/`unchangedOnRight` → `unchanged`. */
export function diffLineOf(line: ThreadLine): DiffLine;
/** The one-line place on `line`: `{ start: diffLineOf(line), end: line }`. */
export function onePlace(line: ThreadLine): ThreadPlace;
export function sameDiffLine(a: DiffLine, b: DiffLine): boolean;
/** `start` is `end`'s own line. */
export function isOneLine(place: ThreadPlace): boolean;
/** Brands every number, naming the field (`${field}.start.left`, `${field}.end.right`, …) on a bad one. */
export function toThreadPlace(raw: Generated.ThreadPlace, field?: string): ThreadPlace; // field defaults to "place"
export function fromThreadPlace(place: ThreadPlace): Generated.ThreadPlace;
```

`fromThreadLine` goes (no user after the cutover); `toThreadLine` stays as the module's private helper for `end`.
`ipc/index.ts` exports from `./threadLine`: `changedThreadLine`, `diffLineOf`, `isOneLine`, `onePlace`, `sameDiffLine`,
`shownColumn`, `shownLine`, `unchangedThreadLine`, `type DiffLine`, `type ShownThread`, `type ThreadLine`,
`type ThreadPlace`.

Other fixed shapes:

- `ReviewSource.addThread(file: RangeFileId, place: ThreadPlace, text: string): Promise<SourceResult<ThreadAdded>>`.
- `reviewDomain.ts` `Thread` has `readonly place: ThreadPlace` in place of `line`; `toThread` uses
  `toThreadPlace(raw.place, \`${field}.place\`)`.
- `tauriReview.addThread` → `commands.addThread(file, fromThreadPlace(place), text)`.
- `fixtureReview` stores `place: fromThreadPlace(place)`.
- `fixtureThreads.ts` `?threads=seeded` on `src/board/board.ts`: threads 0–3 unchanged in kind, line, messages and
  session, each now `place: { start: <its line without the column>, end: <its line> }`; appended:
  - thread 4: `place: { start: { kind: "unchanged", left: 400, right: 388 }, end: { kind: "added", right: 405 } }`,
    one note "Does the snooze need a column of its own?", `notQueued`, session `null`;
  - thread 5: `place: { start: { kind: "removed", left: 254 }, end: { kind: "added", right: 259 } }`, one note "Why
    does the limit check move?", `notQueued`, session `null`.
    board.ts's differences (0-based, `frontend/fixtures/range/review.json` `files[7]`): `d3` left 254+1 / right 258+3,
    `d4` 308+18 / 314+0, `d5` 415+0 / 403+33, so left 400–414 are unchanged with right = left − 12. Queued counts stay
    (both new notes are `notQueued`); message and thread ids 0–3 keep their numbers.

## Change

1. `threadLine.ts` as above; `ReviewSource.ts`, `reviewDomain.ts`, `tauriReview.ts`, `fixtureReview.ts`,
   `fixtureThreads.ts`, `index.ts`.
2. Tests: `reviewDomain.test.ts` — a thread's place comes through with both ends; every bad number is refused naming

   place; `diffLineOf`, `onePlace`, `sameDiffLine` (each kind, each mismatch), `isOneLine` (a one-line place on each end

   places; `addThread` stores a two-line place. `fixtureRange.test.ts` — every seeded place's start and end sit on
   board.ts lines as their kinds say (inside a difference or paired outside).
3. `ipc/AGENTS.md`: `toThreadPlace`/`fromThreadPlace` and the seeded range threads in its words.
