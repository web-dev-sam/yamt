## Blocks

### #877 (boundary, should; `crates/session/src/disk.rs:123`)

**Problem:** Reset has to ask `at_open` two questions that must agree: `regular_entry()` picks the entry (writes.rs:108), and `seen_after_reset(disk)` picks the view (writes.rs:131-134). The second one takes back a clone of the payload `at_open` already holds, and its `AtOpen::Unread` arm can never run, because `regular_entry` returns `None` for `Unread`. Growth: a new `AtOpen` variant or a new reset rule has to be decided in both methods and kept consistent by hand. The types allow a `Seen` for an `Unread` reset even though that state cannot happen.

**Fix:** Replace both methods with one, e.g. `AtOpen::reset_to(&self) -> Option<(OnDisk, Seen)>` (or a small `ResetTo { entry, seen }`) that returns the entry and the view from the same match. `reset` then writes `entry` and assigns `seen` with no second lookup.

### #878 (boundary, should; `crates/session/src/open.rs:75`)

**Problem:** `open_file` first builds every readable file as `AtOpen::Untouched` with `Seen::ViewFromStages`. After `check.untouched`, `changed_at_open` rewrites both fields. So the rule 'Changed/Unread → `Seen::GitOutput`' is written twice (open.rs:128-131 and 75-85), and the `AtOpen::Changed(_)` arm in `file_state` never runs. Growth: the next fact derived from the at-open state has to be patched in both places, and `FileState.at_open` ('Set once by `open`') is in fact assigned twice.

**Fix:** Have `open_file` return the parts, the `OnDisk` and the `StartLook`, and build each `FileState` once after `check.untouched` with the final `AtOpen`. Derive `seen` from it in one place, e.g. an `AtOpen::first_seen()` in disk.rs.

### #879 (boundary, should; `crates/session/src/seed.rs:53`)

**Problem:** Whether a block is exact is branched on twice. `seed` picks `waiting` from `located.exact` (lines 53-58), and `push_conflict` separately picks base lines or disk lines from `located.exact` (lines 104-108). The result goes into a third parallel `Vec` (`waiting`), which `seeded` zips by position with `chunks` and `ranges`. Growth: each new per-chunk fact adds another parallel vector and another copy of the exact/inexact branch. Nothing user-visible changes today.

**Fix:** Pass `Option<&Block>` to `push_conflict` (`None` for a raw region) so its one `if located.exact` branch pushes the base lines plus `block_markers`, or the disk lines plus `Waiting::AsShown`. Keep each chunk's range and waiting together in one `Vec<(LineRange<MiddleLine>, Waiting)>`.

### #880 (boundary, should; `crates/session/src/waiting.rs:7`)

**Problem:** The comment says the labels are the ones `start.rs` passes to `git merge-file`. They are actually hard-coded in `crates/gitio/src/merge_file.rs:44` (`-L ours -L base -L theirs`), and start.rs only calls `repo.merge_file`. A reader who follows the reference finds nothing, and a later change to gitio's labels would drift from `OURS_LABEL`/`THEIRS_LABEL` with no pointer. Growth: only that silent drift; it does not change behaviour.

**Fix:** Point the comment at `yamt_gitio` `merge_file.rs` (`Repo::merge_file`, `-L ours -L base -L theirs`). Exporting the two labels from gitio is the better fix, but gitio was read-only in this slice, so that belongs in a later slice that owns gitio.

### #883 (correctness, block; `crates/session/src/writes.rs:252`)

**Problem:** Survivor `rebuild_markers -> Ok(())` is not equivalent and can hide a bug users would see. Take Remote on the symlink conflict, then Reset: with the mutant, git lists the file as conflicted again, but the worktree link still points at `remote-target`. That is the taken side, not what Reset promises. The same gap covers a regular file that was unreadable at open. The patch moved RK17's proving test (`reset_after_finish_restores_git_stages_and_conflict_markers`) onto the at-open-bytes path, so #69's rule (links, submodules and unread files keep `checkout -m`) has no test that runs `checkout -m`. `reset_after_take_brings_back_the_stages_of_every_kind` includes SYMLINK but only checks `ls-files -u`.

**Fix:** In `take.rs` `reset_after_take_brings_back_the_stages_of_every_kind`, under unix, assert after the resets that `fs::read_link(dir.path().join(SYMLINK))` is no longer `remote-target`; this kills the mutant. Name that test as RK17's proving test for the `checkout -m` half.

### #884 (correctness, block; `crates/session/src/locate.rs:125`)

**Problem:** Survivor `&&`→`||` in `end_last_line` is not equivalent. It changes behaviour whenever a side's view is empty, for example a file whose whole text is one raw region: an add/add file that is one block, where the user deleted the `=======` line, giving `<<<<<<< ours\nL\nR\n>>>>>>> theirs\n` with local `L\n` and remote `R\n`. Today `line_map("", "L\n")` has an empty-before hunk, so `covering(0..0)` = 0..1. With the mutant, `""` becomes one empty line, so `after_changes_at(0)` returns 0 and the raw chunk gets local 0..0 and remote 0..0. The conflict then links to no side lines and applying a side inserts nothing. No test seeds an all-raw disk file.

**Fix:** Add a `locate::tests` case: `seed` that disk with base `""`, local `"L\n"`, remote `"R\n"`, and assert one `Waiting::AsShown` chunk whose local and remote ranges are both (0, 1).

### #885 (correctness, block; `crates/session/src/disk.rs:126`)

**Problem:** No test calls `load` after a reset, so the view rule from brief Change 5 (`Untouched` → stages view, `Changed` → disk view) is unproven. If `Changed` mapped to `ViewFromStages`, S6 (`reset_of_a_file_changed_by_hand_before_start_brings_back_the_hand_edit`) would still pass, because `Seen::is` compares bytes only. The window would then show git's conflict from the stages while the disk holds the hand edit, and the next Save would write over that hand edit. cargo-mutants cannot catch this: `Seen` has no default and the match has no wildcard arm.

**Fix:** In `save.rs`, after the reset in S6 assert `session.load(TEXT).unwrap().middle == Middle::Disk { text: <FOREIGN as str> }`. In S4 (`reset_after_a_save_brings_back_the_bytes_and_the_stages_of_this_run_s_start`) assert `Middle::Stages { .. }`.

### #886 (correctness, should; `crates/session/src/disk.rs:126`)

**Problem:** The `AtOpen::Unread` arm of `seen_after_reset` never runs, because `regular_entry` returns `None` for `Unread` and `reset` then calls `read_back`. That dead arm answers `ViewFromDisk`, while the path that does run gives `ViewFromStages`. As the code grows, anyone changing reset for unread files will read and edit a rule that has no effect.

**Fix:** Drop `seen_after_reset` and let `reset` pick the view in the one `match &file.at_open` that already chooses between writing the bytes and `rebuild_markers`, so `Unread` never needs an answer.
