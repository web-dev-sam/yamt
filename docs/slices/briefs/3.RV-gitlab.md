## Contract (fixed; you may add, never change)

```rust
// crates/review/src/lib.rs (IPC types; serde tag "kind", camelCase sums, snake_case fields)
pub struct MergeRequestRef { pub reference: String, pub title: String, pub web_url: String }
pub enum LookedAt { Branch { name: String }, Commit { short_id: String } }
pub enum NotLinedUp {
    GlabMissing,
    NotLoggedIn { detail: String },
    NoMergeRequest { looked_at: LookedAt },
    Several { looked_at: LookedAt, references: Vec<String> },
    Moved { merge_request: MergeRequestRef, gitlab_head: String, shown_head: String },
    OtherBase { merge_request: MergeRequestRef, gitlab_base: String, shown_base: String },
    Preparing { merge_request: MergeRequestRef },
    Failed { message: String },
}
pub enum GitLabCheck { LinedUp { merge_request: MergeRequestRef }, NotLinedUp { why: NotLinedUp } }
pub struct SendProgress { pub done: u32, pub of: u32 }
pub enum SendReply {
    NotLinedUp { why: NotLinedUp },
    Sent { list: ThreadList, sent: u32, refused: u32 },
    Stopped { list: ThreadList, sent: u32, refused: u32, reason: String },
}
pub fn check_gitlab(range: &Range, glab: Option<&Glab>) -> GitLabCheck;
pub fn send_queue(range: &Range, glab: Option<&Glab>, threads: &Mutex<ThreadStore>,
                  progress: &dyn Fn(SendProgress)) -> Result<SendReply, Error>;
```

`threads` is locked only briefly (snapshot, then after each sent message to record and write); never across a glab
call. A `MAX_MERGE_REQUESTS_CHECKED = 5` constant next to its user.

## Change

As the design: `right_branch.rs` (the right side's branch from `symbolic_full_name` + `remote_names`; an empty side or
`HEAD` → the current branch; none for a commit id), `gitlab.rs` (the REST shapes parsed with serde_json, an unexpected
shape → `Failed` naming the field; the endpoint builders), `lines_up.rs` (pure `lines_up(compared, found)`),
`position.rs` (the post body from a `ThreadLine` and the entry's paths; `same_draft` for step 4), `send.rs`
(`check_gitlab` and `send_queue`: steps 1–6 of the design's "One send, sequential"; HTTP status from `glab api
--include`'s output as measured in row 15).
