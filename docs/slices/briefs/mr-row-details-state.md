## Contract

Generated by `mr-row-details-rust` (given): `Person { username, name, picture: PersonPicture }`; `PersonPicture =
{ kind: "uploaded" } | { kind: "gravatar"; address: string } | { kind: "none" }`; `ReviewState = "requested" |
"reviewed" | "approved" | "changesRequested"`; `Reviewer { person, state }`; `Label { title, colors: LabelColors | null
}`; `LabelColors { background, text }`; `MergeRequestRow` with `author: Person | null`, `reviewers: Reviewer[]`,
`labels: Label[]`, `approvedBy: Person[]` (no `approvals`), `mayRerequest: boolean`, `size` `{0,0,0}` for a known empty
diff; `RerequestReply = requested { reviewers } | notReviewer | notOpen | glabMissing | notLoggedIn { detail } | refused {
message } | failed { message }`; `commands.rerequestReview(iid, username) → Result<RerequestReply, IpcError>`; uploaded
pictures at `yamt-picture://localhost/<username>` (404 when none) through `convertFileSrc(username, "yamt-picture")`;
Gravatar addresses already checked by Rust (CSP admits exactly Gravatar's two hosts).

Rules (this slice's):

- **Due dates dropped:** a load that ends `loaded` (not `cut`, not a failure) calls `keepOnly` with that load's iids (the
  rows it showed, or its buffer when a refresh swaps in). No other writer.
- **A re-request:** a second click on the same reviewer while running does nothing; `requested` → `replaced(iid,
  reviewers)` writes that row's `reviewers` in `rows` and, while a refresh buffers, in its buffer (the only new writer
  of rows besides pages and checked rows), and the ask goes; another reply → `refused` kept until
  `dismissRerequestRefusals(iid)` or the next ask for that reviewer; a source failure → the ask goes and `report({
  action: "mergeRequests", step: "rerequestReview", cause })`. Whether a button shows is the page's (core
  `reviewDone` and `row.mayRerequest`); this slice asks for whatever username it is given — Rust refuses a
  non-reviewer.
- **Fixture** (`fixtureMergeRequestData.ts`), every script's rows: titles, assignee sets, label titles and their cycles
  unchanged (so the owner's example "Assignee: not Me" + "Label: frontend" on `?mr=list` keeps exactly 6 of 40:
  !639, !627, !623, !619, !607, !603 — pinned by a test); `author` = the next person of `PEOPLE` after the row's index;
  `reviewers`' states cycle requested, reviewed, approved, changesRequested by row; every 8th row from index 2 has three
  reviewers, none of them its assignee, in three different states (a stack of 4: three shown and "+1"), and `dmitri`
  is a done reviewer (reviewed, approved or changes requested) on at least one such row with `mayRerequest`; `approvedBy`
  the first `index % 4` people; `mayRerequest` false on every 9th row from index 8, else true; label colours as CSS
  colour names (no hex: the palette fence), e.g. `teal`/`white`; index 5 (!635, the `?mr=local` `mergesCleanly` row
  with a pending pipeline) has `size {0,0,0}`; `PEOPLE`' pictures: `sam` and `anna` a tiny PNG as a `data:` URL
  (standing in for an uploaded and a Gravatar picture: the fixture never loads a remote address), `ben`
  `data:image/png;base64,AAAA` (does not decode → initials), `chiara` and `dmitri` none (`picture: null`). The fixture
  source's `rerequestReview` answers after `RE_REQUEST_PAUSE_MS = 1000`: `dmitri` → `refused { message: "You are not
  allowed to re-request a review on this merge request." }`; someone not among that row's reviewers → `notReviewer`;
  any other reviewer → `requested` with the row's reviewers where that one reads `requested`; it logs
  `mergeRequests.fixture_rerequest { iid, username }`.
