# Slice 3.Q-group — fix round 1 (`ServerGroupHeaderR1`)

Board "Servers and panes" row 7. Round 1 is commit `832a988` (brief `briefs/3.Q-group.md`, notes
`.omp/run/notes/ServerGroupHeader.md`). Five findings, verbatim:

> **#1292** (block, correctness) `frontend/src/ui/useDropdownMenu.ts:94` — Rule 5 says a press outside closes the
> drop-down, but a right-press does not. The outside close goes through vueuse `onClickOutside`, which acts only on the
> `click` event (`@vueuse/core` 15.0.0 `dist/index.js:266-279`; `pointerdown` only arms it). A secondary button fires
> `contextmenu`/`auxclick`, not `click` ([INFERENCE] UI Events; WebKit not probed). So with the Servers list open, a
> right-click anywhere in the toolbar (the group button too) opens `ToolbarMenu` (`MergeToolbar.vue` header
> `@contextmenu.prevent="openMenu"`) on top of the list, which stays open. Both are `fixed z-10` and the later teleport
> covers the list. Escape then closes only `ToolbarMenu`, whose window capture handler stops it. The pinned buttons' and
> rows' `ServerMenu` closes on any `pointerdown`, so the header now has two different close rules side by side.
> Fix: in `useDropdownMenu`, also close on a window capture `contextmenu` (or a `pointerdown` with `button !== 0`) whose
> target is outside the menu and the opener, using the same `closeAfterClick` path. Add a WebKit step: open the list,
> right-click the toolbar, and see only `ToolbarMenu`.

> **#1290** (promoted, boundary) `frontend/src/ui/ServerGroup.vue:21` — Lines 21-38 copy, line for line, the code in
> `ServerMenu.vue:25-51` that places a teleported menu: `useElementSize(…, { box: "border-box" })` + `useWindowSize()` +
> `menuPosition({ pointer, menu, viewport })` → `{ left, top }`. Lines 45-48 also repeat the bottom-left anchor from
> `ServerStatus.vue:38-41`. The next teleported menu will copy this a third time.
> Fix: move the measure-and-place step into one `ui/` composable (e.g. `useMenuPlacement(menu, at)` returning the
> `placement` style). Use it in ServerMenu and ServerGroup, and drop the inline copies.

> **#1289** (promoted, boundary) `frontend/src/ui/ServerGroup.vue:14` — `type RowMenu = { name; at: Point; opener:
> HTMLElement }` is a second hand-written copy of `OpenMenu` in `ServerStatus.vue:15`. Both mirror `ServerMenu`'s props.
> Fix: declare the open-menu shape once and import it in both components, for example `export type OpenMenu` in
> `serverMenuToggle.ts`, which already holds the open-menu rule (`menuAfterClick<Menu extends { name }>`).

> **#1291** (promoted, boundary) `frontend/src/ui/AGENTS.md:5` — "Fixture mode (no host) only loads and refreshes" is now
> wrong for `?servers`. Fix: reword it as "With no host (fixture mode without `?servers`) it only loads and refreshes."

> **#1293** (promoted, correctness) `frontend/src/ui/menuKeys.test.ts:32` — "rows and pins are one list" is the existing
> count-arithmetic test again, and `stepMenuItem` never sees roles. It still passes if `MENU_ITEMS` loses
> `[role=menuitemcheckbox]`. Fix: delete the test. WebKit step 8 is the evidence for `MENU_ITEMS` (no DOM in the node
> project).
