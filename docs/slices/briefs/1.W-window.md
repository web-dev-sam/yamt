## Contract (fixed; you may add, never change)

```ts
// frontend/src/editor/index.ts — sole public surface of editor/
export type MergeTexts = {
  readonly local: string;           // left pane, read-only
  readonly base: string;            // center pane seed, editable (plan §2 #9: result seeded from BASE)
  readonly remote: string;          // right pane, read-only
  readonly language: string | null; // "typescript" → TS highlighting; anything else → none
};
export type MergeHosts = { readonly left: HTMLElement; readonly center: HTMLElement; readonly right: HTMLElement };
export class MergeController {
  constructor(texts: MergeTexts, hosts: MergeHosts);
  destroy(): void; // destroys all three views; hosts left empty (CM14)
}
```

`MergeTexts` is a stand-in until the generated `FileMergeData` exists (merge engine not built
yet); `MergeController` will then take `FileMergeData` per architecture §5.2. Do not invent
`FileMergeData`, `ChunkSource`, or chunk types now.

```ts
// frontend/src/ui/useMergeController.ts — the only ui/ file that imports from ../editor (VU11)
export type { MergeTexts } from "../editor";
export function useMergeController(
  texts: MaybeRefOrGetter<MergeTexts | null>,
  hosts: {
    left: Readonly<ShallowRef<HTMLDivElement | null>>;
    center: Readonly<ShallowRef<HTMLDivElement | null>>;
    right: Readonly<ShallowRef<HTMLDivElement | null>>;
  },
): void;
```

Creates one `MergeController` once `texts` and all three hosts are non-null; destroys and
recreates it when `texts` changes; destroys it when the owning scope is disposed. The
controller is a plain `let`, never a ref (VU10).

Components (VU15 v0 set, minus `Banner`): `App.vue` (layout only, VU16), `Sidebar.vue`
(`defineProps<{ paths: readonly string[]; active: string | null }>()`, no emits),
`Toolbar.vue` (no props, no emits), `MergeView.vue` (`defineProps<{ texts: MergeTexts }>()`,
owns the three host `div`s via `useTemplateRef` and the two connector `<svg>` gaps, calls
`useMergeController`). Sample data module: `frontend/src/ui/sample.ts` exporting the sample's
display path plus its `MergeTexts`, built from `?raw` imports of `frontend/fixtures/sample/*`.

## Change

   formatter off them), LF, a realistic 60–90 line TypeScript module shown in the file list as
   `src/cart.ts`. Make it useful for chunk work later: local alone changes one function and adds
   an import; remote alone changes a different function and renames a constant; both change one
   function differently (a real conflict); both make one identical change.

   `src/style.css`, used by chrome as utilities (`bg-editor`, …) and by the editor theme as
   `var(--color-…)`. Make sure the variables exist at runtime even when no utility uses them
   (e.g. `@theme static`); verify by computed style in WebKit. Starting values from memory of
   JetBrains New UI dark, adjust by eye: window/panels `#2B2D30`, editor `#1E1F22`, separators
   `#393B40`, UI text `#DFE1E5`, muted text `#868A91`, code text `#BCBEC4`, line numbers
   `#4B5059` (active `#A1A3AB`), active line `#26282E`, selection `#214283`, caret `#CED0D6`,
   hover `#393B40`, selected row `#2E436E`, primary button `#3574F0`; syntax: keyword `#CF8E6D`,
   string `#6AAB73`, number `#2AACB8`, comment `#7A7E85`, function `#56A8F5`,
   property/constant `#C77DBB`, decorator `#B3AE60`. Chrome font: `system-ui`, 13px; set the
   page background in `index.html`/`style.css` so there is no white flash.
3. **editor/** (`skill://cm6-rules`): `internal/pane.ts` `createPane(kind, doc, language, parent)`
   with the shared base extensions on every pane (CM4: bundled JetBrains Mono via
   `@fontsource/jetbrains-mono`, line numbers, TS highlighting via a `HighlightStyle` on the
   palette variables, a dark `EditorView.theme`, identical font size/line height); side panes
   `EditorState.readOnly.of(true)` + `EditorView.editable.of(false)`, no history, no keymap (CM3);
   center pane `history()` + `keymap.of([...defaultKeymap, ...historyKeymap])`. Language by a static
   table in `pane.ts` (one entry: `"typescript"`). `MergeController` in `index.ts` wires three
   panes and implements `destroy()` (CM14).
4. **ui/** (`skill://vue-conventions`): JetBrains-like layout filling the viewport, no page
   scroll; each pane scrolls on its own.
   - Left: file list tool window (~240px, header "Files"), one row = the sample path, shown
     selected, with a small file-type badge.
   - Top: toolbar. Icon buttons (inline SVG, `title` + `aria-label`): "Apply non-conflicting
     changes from the left", "Apply non-conflicting changes from the right", "Undo", "Redo".
     Right end: text buttons "Reset file" (secondary) and "Mark resolved" (primary blue).
     All six enabled, hover state, **no handlers**.
   - Main: pane headers "Local (yours)" | "Result" | "Remote (theirs)" above the panes;
     between panes an empty `<svg aria-hidden="true">` gap (~40px) where connectors go later.
   - `main.ts` keeps mounting `App`.
5. Run once at the end: `pnpm lint && pnpm typecheck && pnpm test && pnpm fmt:check && pnpm sfc-order && pnpm build`.
