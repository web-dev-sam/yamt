# Slice 3.F-clipboard — `read_clipboard`: a selection's text through GTK, never its format list

Board "Paste crash" row 2. Product rules: `docs/plan.md` §2 **#99** — read it in full. Request:
`docs/slices/request-paste-crash.md` (rules 1–4, the cause). Design: `.omp/run/notes/PasteCrashDesign.md` option B,
"Command, Linux". Row 3 (the window's paste listener) builds on the generated command.

Facts (given):

- The crash: WebKitGTK 2.54.0/2.54.1's `WebKit::Clipboard::formats` reads GTK's failed format list `(NULL, -1)` as a
  span of 2^64−1 entries (`Source/WebKit/UIProcess/gtk/ClipboardGtk3.cpp:85` at `webkitgtk-2.54.1`). The window will
  stop WebKit from reading the pasteboard at all and ask this command for the text instead.
- GTK 3's `gtk_clipboard_request_text` asks the owner for text targets (UTF8_STRING, then the older text targets) and
  never for TARGETS (`gtkclipboard.c:1021-1060`, gtk-3-24); its callback gets NULL when nothing can be read. gtk-rs
  0.18: `gtk::Clipboard::get(&gtk::gdk::SELECTION_CLIPBOARD | SELECTION_PRIMARY)`,
  `Clipboard::request_text(|clipboard, text: Option<&str>| …)` — safe, no `unsafe`.
- `gtk` 0.18.2 is already a Linux dependency of `src-tauri` (`src-tauri/Cargo.toml:39-40`). GTK may only be called on
  the main thread: `AppHandle::run_on_main_thread(closure)`.
- A hung owner: GTK gives up on each requested target after 30 one-second ticks (`IDLE_ABORT_TIME`), so a request can
  take minutes. The main-thread closure only starts the request; the wait for its callback happens off the main thread,
  so the window keeps answering meanwhile. Pattern: `src-tauri/src/compare.rs:51-68` `on_worker`
  (`tauri::async_runtime::spawn_blocking`, a failed join logged with `tracing::error!`).
- Registration: `src-tauri/src/commands.rs:11-45` `specta_builder` — one builder for both windows and for
  `export_bindings`; async commands are registered as `name::<tauri::Wry>`. The command needs no managed state, so it
  works in the merge window and the compare window alike.
- `src-tauri/AGENTS.md` names every module of the shell.

## Target

Owned: `src-tauri/src/clipboard.rs` (new), `src-tauri/src/commands.rs`, `src-tauri/src/lib.rs`, `src-tauri/AGENTS.md`.

Read-only: everything else — `src-tauri/Cargo.toml` (needs no change), `frontend/**` (`frontend/src/ipc/bindings.ts` is
generated: run `just bindings` locally to check the export; the orchestrator regenerates it after your patch),
`docs/**`, `.omp/**`.

Non-goals: any window code (row 3); writing the clipboard; images, files or other formats; a WebKit version check; a
notice of any kind.

## Contract (fixed; you may add, never change)

```rust
// clipboard.rs
#[derive(Clone, Copy, Debug, serde::Deserialize, specta::Type)]
#[serde(rename_all = "camelCase")]
pub enum ClipboardSelection { Clipboard, Primary } // visibility as compare.rs's items

#[tauri::command]
#[specta::specta]
async fn read_clipboard<R: Runtime>(app: AppHandle<R>, selection: ClipboardSelection) -> Option<String>;
// Linux: that selection's text through GTK's text request, started on the main thread; None = no owner, no text,
// unreadable, or the main thread gone. Never asks GTK for the format list (no request_targets, wait_for_targets,
// wait_is_*_available, wait_for_contents, request_contents). Other systems: None (the window never calls it there).
```

Generated (check with `just bindings`): `export type ClipboardSelection = "clipboard" | "primary"` and
`commands.readClipboard(selection: ClipboardSelection) : Promise<string | null>`.

## Change

1. `clipboard.rs`: the enum, the command (thin, IPC5), and the Linux reading behind `#[cfg(target_os = "linux")]`; the
   other systems' `None` behind `#[cfg(not(target_os = "linux"))]`. The command waits for GTK's callback without
   blocking the main thread or an async worker thread.
2. `commands.rs`: register `clipboard::read_clipboard::<tauri::Wry>` in `specta_builder`.
3. `lib.rs`: the module.
4. `src-tauri/AGENTS.md`: name `clipboard.rs` and its one rule (plan §2 #99) where the other modules are named.

- Real smoke on a **private** Xvfb only (`Xvfb :N`, then `env -u WAYLAND_DISPLAY GDK_BACKEND=x11 DISPLAY=:N`; never
  the owner's desktop, finding #1560): call the command in the running debug app (`cargo tauri build --debug
  --no-bundle`, then e.g. `just app-session start-app --fresh-repo` and a WebDriver `execute/async` of
  `window.__TAURI_INTERNALS__.invoke("read_clipboard", { selection })`; or a throwaway binary calling your Linux function
  after `gtk::init()` — never committed). Start every clipboard owner as `xclip … -loops 0 -quiet & pid=$!` and end it
  with `kill $pid` (never `pkill`: it kills the owner's own xclip). Observe and paste:
  1. a live owner of `printf 'one\ntwo\n'` → `"one\ntwo\n"` for `"clipboard"`;
  2. that owner killed → `null`, the app still running (`pgrep`, and a second call answers);
  3. a fresh display whose clipboard nobody ever owned → `null`;
  4. `xclip -selection primary` owning `sel` → `"sel"` for `"primary"`, and `null` for `"primary"` once it is killed;
  5. a hung owner (`kill -STOP $pid`): while the call waits, another command (e.g. `log` or a second
     `read_clipboard`) answers at once — the main thread is free; then `kill -CONT`/`kill` it.
- No unit test can reach GTK without a display; say in `open_risks` which lines `just mutants` will report and that
  the real smoke above is their evidence. A pure piece you add (if any) gets its test.
