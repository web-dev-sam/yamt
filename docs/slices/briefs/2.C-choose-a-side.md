# Slice 2.C — the app can describe and resolve files the editor cannot show; "Mark resolved" never half-writes

Board v0 wave 3, Rust half. Owner decision plan §2 #36 (suggestion approved 2026-10-10): files the
editor cannot show get a choice in the middle pane — two buttons, one sentence per side:
binary or non-UTF-8 → take left / take right; deleted on one side → take the kept side / delete;
symlinks → each side's link target shown as text, take left / take right (a link deleted on one
side: keep / delete); a file on one side and a link on the other → "a file, N lines" / "a link to
…"; submodules → each side's commit id, take left / take right. The choice is written and staged
like "Mark resolved" and can be reset. This slice gives the app what the window needs for that
(the window's panel is the next slice), and closes a gap the 2.1 smoke found: when `git add` fails,
"Mark resolved" has already overwritten the worktree file while git still lists it as unmerged.

## Behaviour

- `describe_file(path)` tells, per side, what that side holds: deleted, a text file with N lines,
  a binary / non-UTF-8 / too-large file with its size in bytes, a symbolic link with its target, or
  a submodule commit with its id. Works for every conflicted file (text files: both sides "text, N
  lines"); `reason` is the file's `UnsupportedReason`, or none for text files.
- `take_side(path, side)` resolves the file with one side's version, exactly as git would after
  `git checkout --ours/--theirs` + `git add` — and when that side deleted the file, as after
  `git rm`: the index holds that side's single stage-0 entry (same mode and object id) or nothing;
  the worktree holds that side's bytes / link / nothing (a submodule's worktree is left alone; only
  the index records the chosen commit). The file becomes `Resolved`; `reset_file` brings the
  conflict back as today (stages restored; markers only where git can rebuild them).
- **"Mark resolved" is all or nothing:** when staging fails (e.g. a held `index.lock`), the worktree
  file is put back exactly as it was before (bytes or absence), the error is returned as today, and
  the file stays `Unresolved`. Same for `take_side`.

## Contract (fixed)

```rust
// session — DTOs (serde::Serialize + specta::Type), re-exported from lib.rs
#[serde(rename_all = "lowercase")] pub enum Side { Local, Remote }      // TS: "local" | "remote", like the window's Side
#[serde(tag = "kind")] pub enum SideContent {
    Missing,
    Text { lines: u32 },
    Binary { bytes: u64 },
    NonUtf8 { bytes: u64 },
    TooLarge { bytes: u64 },
    Link { target: String },     // the link's target, lossily decoded
    Commit { id: String },       // a gitlink's commit id
}
pub struct FileSides { pub path: String, pub reason: Option<UnsupportedReason>, pub local: SideContent, pub remote: SideContent }

impl MergeSession {
    pub fn describe(&mut self, path: &str) -> Result<FileSides>;   // UnknownPath
    pub fn take(&mut self, path: &str, side: Side) -> Result<()>;  // UnknownPath; Git; WriteFailed
}

// src-tauri/src/commands.rs (IPC5: lock, one session call, map the error; finish/take return files())
describe_file(path: &str) -> Result<FileSides, IpcError>
take_side(path: &str, side: Side) -> Result<Vec<FileEntry>, IpcError>
```

`IpcError` is unchanged. The base version plays no part in describing or choosing.

## Tests (session/tests, against git's own index and the worktree bytes; conflict-repo fixtures)

1. `describe` for: modify/delete both ways (`Missing` + `Text`), binary vs binary (`Binary` sizes),
   non-UTF-8, symlink vs symlink (targets), file vs symlink, submodule vs submodule (commit ids), and a
   plain text conflict (both `Text`, `reason` none).
2. `take` local / remote for binary, symlink (worktree is a link to the chosen target), file-vs-link,
   delete/modify (taking the deleted side removes index entry and worktree file; the kept side
   restores it), submodule (index stage 0 = the chosen commit, mode 160000). After each: `git
   ls-files -u` lacks the path; `git ls-files -s` shows the expected single entry or none; status
   `Resolved`; `remaining()` one lower.
3. `reset` after `take` brings `git ls-files -u` back identical to before (RK1) for each kind.
4. Finish and take with a held `.git/index.lock`: an error comes back, the worktree bytes (or
   absence) equal what they were before the call, `git ls-files -u` unchanged, status `Unresolved`.
5. Through the mock IPC (`src-tauri`): `describe_file` JSON for one binary file and `take_side` with
   `"remote"` returning the list with that file resolved.

`just mutants <base>` runs over `session` and `src-tauri` afterwards.
