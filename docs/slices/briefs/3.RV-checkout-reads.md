# Slice 3.RV-checkout-reads — `yamt-gitio` makes and reads the AI's checkout; `yamt-compare` diffs two texts

Board "Review a commit range" row 11 (C3a; needs nothing of A or B). Product rules: `docs/plan.md` §2 **#110** (the
shared clone without remotes, "changed" = status or a moved `HEAD`), **#114** (edit diffs from `merge_core::compare`
through `diff_texts`) — read them. Design: `.omp/run/notes/AgentDesign.md` option B "Point 4 (checkout)" (the five
gitio methods), the build table's C3a line, "8. Edit diffs", §10 "gitio" and "yamt-compare" tests. Row 12's
`yamt-agent` (C3b) builds the checkout's life on these reads.

Facts (given):

- `crates/gitio/src/run.rs` has two runners: the deadline runner for reads and `git_command_as_user` + `run_to_end`
  (no deadline, stdin closed, the user's locale) for git's long operations (abort/continue). A clone and a checkout of
  a large repository can take minutes: they use the no-deadline runner.
- `git clone --shared --no-checkout --quiet <repo> <into>` borrows the source's objects through
  `objects/info/alternates`; `git -C <into> remote remove origin`; `git -C <into> checkout --detach <commit>`;
  `git status --porcelain=v1 -z --untracked-files=all --no-renames` lists modified, added, deleted and untracked
  files, never ignored ones; `git rev-parse HEAD`.
- `yamt_compare::MAX_COLUMN_BYTES` (8 MiB, pinned equal to `merge_core::MAX_TEXT_BYTES`), `merge_core::compare(left,
  right) -> Vec<Difference>`; `yamt-compare` may depend on merge-core only (PM1).
