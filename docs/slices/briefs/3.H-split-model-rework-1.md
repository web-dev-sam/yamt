> **#1279** (block, correctness) `frontend/src/ui/paneSplit.test.ts:166` — Every test of the remote boundary uses widths
> where Local equals Remote: {300,400,300} at :166, {250,500,250} at :177, and WIDTHS at usePaneDividers.test.ts:12. So
> swapping `moved` and `kept` for the remote boundary still passes; these are the survivors paneSplit.ts:44:17 and
> :45:16. A user would see it: after any drag of the left divider, pressing the right one snaps Remote to Local's width
> and Local to Remote's. For example, {200,500,300} with dx 0 gives remote 0.2 instead of 0.3.
> Fix: use widths with Local and Remote different, e.g. {local: 200, center: 500, remote: 300}. Assert
> dragged(w,'remote',0) = {0.2, 0.3} and dragged(w,'local',0) = {0.2, 0.3}; dragged(w,'remote',-100) = {local 0.2,
> remote 0.4} with local*1000 === 200; dragged(w,'remote',400).remote*1000 === 220 with local*1000 === 200. Make
> usePaneDividers.test.ts's WIDTHS asymmetric too.

> **#1280** (promoted, correctness) `frontend/src/ui/usePaneDividers.ts:41` — No test reaches `usePaneDividers` (the
> four NoCoverage mutants at :41–44). Swapping its 'local'/'remote' keys, or the '' mutant, which `dragged`'s
> `boundary === "local"` ternaries treat as remote, would make the left divider move the right boundary.
> Fix: add one usePaneDividers.test.ts case inside an `effectScope`, with the same stubbed PointerEvent/Element globals
> as useColumnDrag.test.ts and asymmetric widths. Send pointerdown then pointermove (dx 100) through
> `.local.listeners` and through `.remote.listeners`, and assert each records `dragged` for its own boundary.

> **#1274** (promoted, boundary) `frontend/src/ui/paneSplit.ts:55` — `parsed(raw)` (`try JSON.parse, catch → null`) is a
> line-for-line copy of `parseJson` in `toolbarButtons.ts:63-69`. That makes two stored-JSON choices with two copies,
> and the next JSON value kept through `storedValue` will copy it a third time.
> Fix: export one `parseStored(raw: string): unknown` from `ui/windowStorage.ts` (the one way to keep a choice) and use
> it from both `paneSplit.ts` and `toolbarButtons.ts`.

Orchestrator: row 5's `ui/serverPins.ts:17-21` is that third copy (try `JSON.parse`, catch); it uses `parseStored` too.

> **#1275** (promoted, boundary) `frontend/src/ui/useColumnDrag.ts:7` — `ColumnHandle` (what goes in:
> accepts/press/reset) and `ColumnDragHandle` (what comes out: listeners + dots) have nearly the same name for opposite
> roles, and `ColumnHandle` is exported with no importer.
> Fix: rename the output type to something like `ColumnDragBinding` (used in `usePaneDividers.ts:3,41`), and drop
> `export` from `ColumnHandle` unless row 6 imports it.
