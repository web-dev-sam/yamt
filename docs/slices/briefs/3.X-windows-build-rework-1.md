## Blocks

1. **#784 (promoted) — symlinks must not compile on Windows.** Put `#[cfg(unix)]` on `FileKind::Symlink` (and its
   `write_side` arm, and anything only it uses) in `crates/conflict-repo/src/lib.rs`, and delete the non-unix `link_to`
   stub that returns `Unsupported`. From then on `cargo check --all-targets --target x86_64-pc-windows-msvc` rejects every
   fixture that builds a link without a gate — that is the detector for blocks 2 and 3.
2. **#781 — `crates/session/tests/deleted_side.rs`** scripts a link (`KEPT_LINK` in `DELETED_ON_ONE_SIDE`): gate that
   fixture element and its expectation row (`deleted_side.rs:125`) with `#[cfg(unix)]` (turn the fixture into a slice or
   whatever lets one element carry the attribute), so the other five kinds run on Windows.
3. **#782 — gate the smallest unit.** Remove the four whole-file `#![cfg(unix)]` lines (`disk_is_truth.rs`,
   `start_from_disk.rs`, `describe.rs`, `take.rs`). Gate the link element of each shared fixture (`FILES` in
   disk_is_truth/start_from_disk, `every_kind/mod.rs`, `file_against_link` at `every_kind/mod.rs:99`) and only the tests
   that name a link (LINK/SYMLINK/FILE_OR_LINK), create one, or use permission modes; each gate's reason in its name or
   one line. Everything else — the disk-is-truth suite (#52/#53), the rename/ort/histogram cases, the submodule take —
   runs on Windows.
4. **#783 — one setup for both workflows.** A composite action under `.github/actions/` holding the steps `ci.yml` and
   `release.yml` share (Linux system packages, rustup from `rust-toolchain.toml`, tauri-cli 2.12.1, node 24, pnpm,
   `pnpm -C frontend install --frozen-lockfile`), with an input that lets the frontend-only job skip the Rust/Tauri part.
   Both workflows call it; no version or package list is written twice.
