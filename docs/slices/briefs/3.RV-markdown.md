# Slice 3.RV-markdown — yamt's own Markdown subset rendered as DOM nodes, code coloured by the editor's one table

Board "Review a commit range" row 11 (C6; needs nothing of A or B). Product rule: `docs/plan.md` §2 **#112** — read it
in full — and #102 (the one colour table). Design: `.omp/run/notes/AgentDesign.md` "7. Markdown", option B's build
table line C6, §10 "Markdown" (the node tests with their hand mutations and the browser test). The AI's answers (C7,
`ui/AiTurn.vue`) are its first user, through `ui/useMarkdown.ts`.

Facts (given):

- The answer text is the agent's: rendering must never run anything in it; the window can reach the IPC. No HTML
  string is ever built: `document.createElement`, `textContent`, `className` only; never `innerHTML`,
  `insertAdjacentHTML`, `outerHTML`, `setAttribute("on…")`, `href`, `src`.
- `editor/internal/syntax.ts:116,128` exports `paletteHighlight` and `fontHighlight` (`HighlightStyle`s the panes use;
  #102); `editor/internal/language.ts:19` `languageNamed(name)` → `LanguageDescription | null` from
  `@codemirror/language-data`. `@lezer/highlight` 1.2.5 (a dependency already) exports `highlightCode(code, tree,
  highlighter, putText, putBreak)`. A `HighlightStyle`'s `module` is a `StyleModule`; `StyleModule.mount(document,
  …)` mounts it once.
- `frontend/scripts/fences.ts` rules PM2/PM3/PM5: `ui/` reaches the editor only through `editor/index.ts` and named
  seams (`useMergeController`, `useCompareController`, and row 9's `useRangeController`); `useMarkdown.ts` becomes the
  next seam. `editor/index.ts` is near its 300-line cap: export from it in at most 3 lines.

## Contract (fixed; you may add, never change)

```ts
// editor/markdown.ts — re-exported by editor/index.ts
export class MarkdownView {
  constructor(host: HTMLElement); // renders into host; owns its children
  show(text: string): void; // re-renders from the first block whose source changed (streaming)
  destroy(): void; // empties host
}
// ui/useMarkdown.ts — the ui seam (fence: ui/ reaches MarkdownView only here)
export function useMarkdown(
  host: Readonly<ShallowRef<HTMLElement | null>>,
  text: () => string,
): void;
```

## Change

1. `markdownBlocks.ts` (pure): source → blocks: paragraphs, ATX headings, fenced code (``` and ~~~, an info string),
   `-`/`*`/`1.` lists nested by indent with lazy continuation, block quotes, GFM tables (a delimiter row required),
   `---` rules, blank-line rules. Anything else is a paragraph of literal text; raw HTML is literal text.
2. `markdownInline.ts` (pure): `*`/`_` emphasis and strong, `~~strike~~`, inline code (backticks win over emphasis),
   links `[text](url)` → text + the address (muted, selectable), images `![alt](url)` → `alt (url)` as text, autolinks
   as text; an unmatched marker stays literal.
3. `markdownDom.ts`: blocks and inlines → DOM through `createElement`/`textContent`/`className` only, a fixed tag set
   (`p h1–h6 pre code ul ol li blockquote table thead tbody tr th td hr em strong del span br`), `class` the only
   attribute.
4. `codeBlock.ts`: `languageNamed(info)` → `await description.load()` → `parser.parse(code)` → `highlightCode` with
   `[paletteHighlight, fontHighlight]` (their modules mounted once); unknown language → plain text; a later block's
   load never paints into a destroyed view.
5. `fences.ts`: `ui/` imports `MarkdownView` only from `ui/useMarkdown.ts`; a test in `fences.test.ts`.

## Acceptance

- Node tests (`editor/` is not mutated, VF7: each test names the bug and the one-line hand mutation that makes it
  fail — run each mutation once and report that the test failed): "a fenced block keeps a line that looks like a
  heading" (check headings before the fence state); "a list item's indented continuation joins the item" (drop the
  indent check); "a table needs its delimiter row" (accept any pipe line); "backticks win over emphasis" (parse
  emphasis first); "an unmatched `*` stays literal"; "raw HTML stays text"; "an image is its alt text and address".
- Browser test `markdownDom.browser.test.ts` (WebKit through `just webdriver <port>`, report its output): "the tree holds
  only allowed tags and only `class` attributes for an answer with `<script>`, `<img onerror>`, an HTML block and a
  `javascript:` link" (mutation: `innerHTML` for paragraphs); "a ts code block carries the editor's highlight classes"
  (drop the highlighter); "show() with a longer text keeps the unchanged first block's node".
- `fences.test.ts`: a `ui/` file importing `MarkdownView` from `editor/index.ts` outside `useMarkdown.ts` is a PM2
  violation.
- A screenshot (WebKit) of one rendered answer with a heading, a list, a table, a quote, a ts block and a link, in the
  dark and a light theme.
