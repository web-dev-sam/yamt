## The contract you consume (generated; exact names in `bindings.ts`)

```ts
type MiddleLine = number;
type DiskVersion = number;
type MergeChunk = { chunk: Chunk; middle: LineRange<MiddleLine>; words: WordChanges };
type NotText = "Deleted" | "Binary" | "NonUtf8" | "TooLarge" | "Link" | "Directory";
type Middle =
  | { kind: "Stages"; text: string }
  | { kind: "Disk"; text: string }
  | { kind: "DiskNotText"; found: NotText };
type FileMergeData = {
  path;
  middle: Middle;
  local;
  remote;
  deleted: Side | null;
  eol;
  chunks: MergeChunk[];
  disk_version: DiskVersion;
};
type DiskResult =
  | { kind: "Staged" }
  | { kind: "MarkersLeft"; conflicts: number } // always ≥ 1
  | { kind: "LeftAsIs" } // a working-tree-encoding file or an unchecked-out submodule: yamt never stages it
  | { kind: "StageFailed"; message: string };
type DiskChange = { path: string; result: DiskResult };
type FileList = { files: FileEntry[]; disk_changes: DiskChange[] };
type WriteReply =
  | { kind: "Written"; files: FileEntry[] }
  | { kind: "ChangedOnDisk"; files: FileEntry[]; change: DiskChange };
// FileSides gains disk_version. IpcError gains { kind: "ReadFailed"; path; message } (a disk read
// before or around a write failed): problemText words it "reading <path> failed: <message>";
// and { kind: "NotAFile"; path } (Mark resolved refused: a link, folder or submodule is on disk at
// that path): "<path> is not a regular file on disk; nothing was written".
// commands: listFiles() -> FileList; loadFile(path) -> FileMergeData; describeFile(path) -> FileSides;
//   finishFile(path, text, diskVersion), takeSide(path, side, diskVersion), resetFile(path, diskVersion) -> WriteReply
```

`bindings.ts` is the authority. Where it differs from this sketch, follow it and say so in
`deviations_from_brief`.

## Behaviour

### ipc

- **Domain types.** The domain `Chunk` becomes `{ id, kind, middle: LineRange<MiddleLine>, local,
  remote, words }`; the base range is dropped, because no pane shows base. The domain
  `FileMergeData` is `{ path, middle: Middle, local, remote, deleted, eol, chunks, diskVersion }`.
  New: `FileList { files, diskChanges }`, `WriteReply`, `DiskChange`, `DiskResult`, `NotText`.
- **Brands.** `MiddleLine` and `DiskVersion` are branded in `domain.ts` by type guard (IPC3, TS4).
- **`ChunkSource`.** `listFiles(): SourceResult<FileList>`. `finishFile(path, text, diskVersion)`,
  `takeSide(path, side, diskVersion)` and `resetFile(path, diskVersion)` each return
  `SourceResult<WriteReply>`. `tauri.ts` maps them.
- **Fixture source.**
  - The valibot schema follows the new fixture JSON shape. The fixtures are already regenerated.
  - `listFiles` returns `{ files, diskChanges: [] }`.
  - The writes return `Written`, and every disk version is 0.
  - The schema rejects a record whose chunk middle range is missing or negative, naming the file
    (as it does for the other ranges today).

### editor

- **Middle pane.** It starts from `data.middle`:
  - `Stages` or `Disk` → its `text`;
  - `DiskNotText` → an empty, read-only middle. The sentence about it is the ui's job.
- **Chunk spans.** `chunkField` seeds each chunk's span from `chunk.middle`. Base no longer exists
  here; `lineSpan` and the tests that build from `data.base` follow. `tone.ts` decides "inserted"
  from `middle.len === 0`.
- **Required property.** On a disk-seeded file the user can apply ours, and the middle then equals
  the hand resolution exactly. Use the worked example: middle `title, =======, one, two, three,
  shared-b, four, five, six, seven, eight-theirs, nine, ten`, one Conflict chunk with middle {2,3},
  local {2,4}, remote {2,4}, local = `.omp/run/markers/ours.txt`. Apply ours → `title, =======, one,
  TWO, shared-a, three-ours, shared-b, four, five, six, seven, eight-theirs, nine, ten`. Undo brings
  back `one, two, three`. Keep CRLF as CRLF.
- **Read-only.** `readOnly` holds when `deleted !== null` (as today) or when the middle is
  `DiskNotText`.

### ui

- **One place for disk changes.** Add `applyDiskChanges(changes, when)` to `store.ts`, where `when`
  is `"start" | "running"`. For each change:
  1. Note whether the file had unsaved edits: `guard.unsavedFiles()` includes the path. Read this
     **before** anything is rebuilt.
  2. Add or replace that path's notice.
  3. Drop `taken[path]`. If the result is `Staged` and the file shows a choice (`choices`, or a
     deleted-side view), record `taken[path] = { by: "disk" }` (`Taken = { by: "side"; side } |
     { by: "disk" }`).
  4. If the file is shown (`opened` or `choices`), fetch its view again (`fetchView`) and apply it
     (`putOpened` / `putChoice`). The new record rebuilds the editor, which drops the edits and the
     undo history. `useMergeController` sets `saved` to the new `resultText()`, so the close guard
     forgets the dropped edits without new code. A file that is not shown gets only the notice and
     its new mark; opening it later loads the disk view.
- **Where the changes come from.**
  - `refreshFiles` takes `FileList`, sets `files`, and calls `applyDiskChanges(diskChanges, …)`.
    The first call, from `loadFiles` at start, passes `"start"`; every focus look passes
    `"running"`.
- **Writes.**
  - `finish`, `takeSide` and `reset` send the disk version of the view they act on. `finish` takes it
    from the `FinishRequest`, which `MergeView` fills from `props.data.diskVersion`; `takeSide` and
    `reset` look it up in `opened` or `choices`.
  - `Written` → today's behaviour.
  - `ChangedOnDisk` → set `files`, `applyDiskChanges([change], "running")`, no `markSaved`, no
    `moveOn`.
- **Notices.**
  - Kept in `notices: ShallowRef<readonly Notice[]>`, with
    `Notice = { path, result: DiskResult, editsDropped: boolean, when }`; one per path, the newest
    replacing the older one.
  - `dismissNotice(path)` removes one.
  - `NoticeBar.vue` (`role="status"`) sits above `ProblemBar` in `App.vue`. It shows one row per
    notice, each with a close button like `ProblemBar`'s. It does not hide the "All files are
    resolved" bar or the problem bar.
  - Colours: a new neutral-info token pair in `style.css` in the JetBrains New UI dark style,
    e.g. `--color-info: #25324d` / `--color-info-border: #35538f` (adjust to the existing palette).
  - A notice is information, not a failure: never a `Problem`. Log it once with `log.info`
    (`file.disk_changed {path, result, editsDropped, when}`). For `StageFailed`, use `log.warn`.
- **Words** (`noticeText.ts`, pure, tested). Each notice is one sentence plus a tail:
  - Opening:
    - `running` with `editsDropped` → "`<path>` changed on disk; your edits in yamt were dropped";
    - `running` without edits → "`<path>` changed on disk";
    - `start` → "`<path>` differs on disk from git's merge".
  - Tail, after " — ":
    - `Staged` → "staged as resolved";
    - `MarkersLeft` → "1 conflict left" or "N conflicts left";
    - `LeftAsIs` → "left unstaged";
    - `StageFailed` → "staging failed: `<message>`".
- **Views of files changed on disk.**
  - `MergeView`, with a `DiskNotText` middle, shows one sentence in the middle column instead of an
    editor:
    - `Deleted` → "Deleted on disk — staged as deleted.";
    - `Binary` / `NonUtf8` / `TooLarge` → "Not shown: the file on disk is binary / not UTF-8 / too
      large — staged as it is.";
    - `Link` → "A link on disk now — staged as it is.";
    - `Directory` → "A folder on disk now — staged as deleted.".
  - Such a view offers no Mark resolved and no apply buttons. Reset stays.
  - A choice view (`ChoiceView`) whose `taken` is `{ by: "disk" }` says "Changed on disk — staged as
    it is" where it names the taken side today.
  - A deleted-side view (#47) whose middle is `Disk` or `DiskNotText` shows that middle; Keep and
    Delete stay available (they carry the disk version).

## Tests (behaviour; delete tests that only pinned the old `base`/`word_changes` shape)

- **`store.test.ts`:**
  - a running change for an opened file with edits → a new record, one notice with
    `editsDropped: true`, `taken` dropped, `unsavedFiles()` no longer lists it;
  - the same without edits → `editsDropped: false`;
  - a file not shown → only the notice and its mark;
  - changes from the first `loadFiles` → `when: "start"`;
  - `ChangedOnDisk` on finish → no `markSaved`, no move to the next file, the view reloaded;
  - each write sends the shown view's disk version;
  - `dismissNotice` removes one notice;
  - a second change for the same path replaces its notice.
- **`noticeText.test.ts`:** every opening × every tail, singular and plural.
- **Editor:**
  - the worked example as an apply test, including undo;
  - spans from `chunk.middle` where they differ from where base would put them;
  - `DiskNotText` → read-only;
  - CRLF kept.
- **`useMergeController.test.ts`:** after a data swap, `unsaved()` is false even when the old
  controller had edits.
- **`fixture.test.ts` / `tauri.test.ts`:** the new shape maps, and a missing `middle` range is
  rejected, naming the file.
