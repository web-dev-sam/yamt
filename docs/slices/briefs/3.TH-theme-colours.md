## What yamt paints today

`frontend/src/style.css`: the `@theme static` block (yamt Dark) and `:root[data-theme="light"]` (yamt Light) define
every colour token; nothing else holds a colour literal. Read where each token is used (`--color-<name>` under
`frontend/src/`, e.g. `editor/theme.css`, `editor/internal/pane.ts`, `ui/*.vue`) so you map it to the element the
editor paints for the same job.

Syntax today: `frontend/src/editor/internal/pane.ts:112-146` (`SYNTAX_COLOURS`: Lezer tags → 10 tokens). The parsers
are CodeMirror's Lezer grammars in `frontend/node_modules` (`@lezer/javascript`, `@lezer/css`, `@lezer/html`,
`@lezer/json`, `@lezer/markdown`, `@codemirror/lang-vue`; their `styleTags(...)` calls name the tags each token gets).
TypeScript/TSX/Vue are the owner's languages: get those right first.

## Output, per theme (two themes per editor: its dark and its light)

**A. Window and editor colours** — one row per yamt token in `style.css` (all of them, `--color-window` …
`--color-minimap-slider-active`), plus these rows yamt may need for flat themes: `panel border` (the line between
side bar and editor, editor and panel), `header/tab bar background`, `input background`, `input border`, `menu/drop-down
background`, `tooltip background` and `border`, `scrollbar thumb`.

| yamt token | value (`#rrggbb` or `#rrggbbaa`, lowercase) | editor key / variable | source (file:line or URL#L) | how resolved (direct, default, alias chain, computed: show the math) |

**B. Syntax** — one row per Lezer tag (with modifier, e.g. `function(variableName)`, `definition(propertyName)`,
`controlKeyword`, `typeName`, `className`, `operator`, `punctuation`, `bracket`, `variableName`, `local(variableName)`,
`special(variableName)`, `propertyName`, `attributeName`, `tagName`, `string`, `number`, `bool`, `null`, `regexp`,
`escape`, `comment`, `docComment`, `meta`, `heading`, `link`, `url`, `self`, `atom`, `labelName`, `namespace`,
`modifier`, `definitionKeyword`, `moduleKeyword`, `operatorKeyword`, `angleBracket`, …) that the grammars above emit for
TS/TSX/JS, Vue, CSS, HTML, JSON and Markdown:

| Lezer tag | example token | value | editor's scope / capture / attribute for the same token | source | font style if not normal (italic, bold) |

Then: which tags the editor colours the same (groups), so the design can pick the fewest tokens that keep every
distinction this editor makes.

**C. Change colours** — every diff, merge and conflict colour the editor has, line and word level, gutter, scrollbar
or minimap marks: added/inserted, modified/changed, deleted/removed, conflict (and ours/theirs/base, the conflict
marker lines, any "incoming"/"current" colours). Same columns as A. Then a proposed mapping onto yamt's
`--color-chunk-*` and `--color-mark-*` tokens (what each paints: `editor/theme.css`, `editor/internal/minimapRows.ts`),
naming each gap (a kind the editor has no colour for) and the closest colour it does have.

**D. Shape** — does the editor draw rounded panels with gaps or flat panels with 1 px lines? The line colour and
which elements have lines; corner radius of anything yamt draws (buttons, inputs, menus, tooltips) if readable from
the theme or the editor's CSS.

**E. Kind** — dark or light (the editor's own type, e.g. VS Code `uiTheme`).
