## Change — fix each finding (verbatim from the reviews)

1. **#607 / #609 (block, both reviewers)** `frontend/src/editor/internal/sideFocus.ts:115` —
   `decided()` reveals the focused side's mark after every decision, even when the decision did not
   move it. Example: keyboard on the left with change A outlined, the view wheel-scrolled down, then a
   click on the apply icon of another left change B (or Ctrl+click on B, a drag, or a remote icon). A
   still waits, so the mark stays on A and `#reveal` scrolls all panes back to A, away from the change
   the user just clicked. Fix: capture the focused side's mark before the dispatch (next to `before`,
   or have `SideFocus` snapshot it) and reveal only when the settled mark's `markedId` differs from it.
2. **#610 (should)** `frontend/src/editor/internal/sideFocus.ts:106` — nothing at unit level covers the
   reveal-or-handover branch in `decided()`; deleting the reveal or revealing unconditionally passes
   every test. Fix: a pure `navigation.ts` helper, e.g. `afterDecisionFocus({ beforeMark, afterMark,
   handover }) → "handover" | "reveal" | "stay"`, used by `decided()`, unit-tested for: mark moved
   (reveal), mark unchanged (stay), mark became alone (stay), handover (handover wins).
3. **#608 / #611 (nit)** `frontend/src/editor/internal/historyKey.ts:24-27` — the fallback to `code`
   also fires for a Latin layout whose KeyZ/KeyY key gives a non-letter (Dvorak: physical KeyZ is ';',
   so Ctrl+; undoes from a side pane), unlike CodeMirror's keyCode fallback the comment cites. Fix:
   fall back to `code` only when `key` is a single non-ASCII letter (`/^\p{L}$/u` and not a Latin
   letter); add a row: key ';' with code 'KeyZ' gives null. Keep the 'я'/KeyZ and QWERTZ rows.
