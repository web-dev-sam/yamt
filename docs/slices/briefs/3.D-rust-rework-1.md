## Decisions (orchestrator)

- **#519 → `IpcError::ReadFailed { path, message }`.** A new variant for a disk read that fails
  before or around a write. Session `Error::ReadFailed` maps to it, and the message keeps the
  "cannot read" wording.
- **#520 → `DiskResult::LeftAsIs`.** A new variant for files yamt deliberately never stages: a
  `working-tree-encoding` file, and a submodule that is no longer checked out. `conflicts` in
  `MarkersLeft` is computed only for files that are staged when their markers are gone, and is
  then always ≥ 1.
- **#526 → rename `Seen`'s variants** after the view they select: `GitOutput`,
  `ViewFromStages(OnDisk)`, `ViewFromDisk(OnDisk)`. Drop the enum-level explanation.
- **#528 + #529 → resolve the merge driver as git does.** Read the config once at `open()` with a
  new gitio method that returns raw values: `merge.default`, plus the names that have a
  `merge.<name>.driver`. One `git config` call, e.g. `--get-regexp`. session maps them:
  - an unspecified attribute → `merge.default`, if it is set;
  - `binary` → Binary;
  - `union` → Union;
  - `text` or unset → Text;
  - a name whose driver is configured → Custom;
  - a name whose driver is not configured → Text (git's "default to the 3-way").

  Tests: `merge.default=binary` with untouched files → no change and nothing staged; `merge=lfs`
  without a driver → untouched; `merge=mergiraf` with `merge.mergiraf.driver` configured (a script
  that writes markers and exits 1) → Disk view at the first list.
- **#534 → `finish` never writes through a link or into a directory.** If the worktree path is a
  symlink, a directory, a submodule or a special file, it writes nothing and returns an error: reuse
  `Error::Unsupported` (reason `Symlink` or `Submodule`) or name a new session error in your report.
  A missing file is still created. Add a test in `disk_is_truth.rs`.
- **#518 → a read-back that fails after a successful write is a warning,** and the reply is still
  `Written`. `finish` sets `seen` from the bytes it wrote (`fs::write` applies no filter). `take` and
  `reset` keep `seen` as it was, so the next look settles whatever is there.
- **#517 = #531 → an unreadable path at `open()`.** Log a `warn` and start that file as
  `Seen::GitOutput` without a start look.
- **#524** is the orchestrator's: project-map gets `line_map`. Do not edit `.omp/**`.
- **All other findings** (#521, #522, #523, #525, #527, #530, #532, #533, #535): apply the fix the
  reviewer gives.

After the IPC changes, run `just fixtures`. Then run
`cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`,
`just fixtures-check` and `just arch-check`, and paste the tails. Report in `deviations_from_brief`:
the exact new IPC variants, and the new gitio config method with its signature.

## Findings (verbatim, ids from `.omp/run/findings.jsonl`)

- **#517** (boundary, should) `crates/session/src/open.rs:78` — One conflicted path that cannot be read (EACCES, or a submodule whose `rev-parse` fails with a real git error) now makes `MergeSession::open` fail, so yamt does not start, although `refresh` treats the same read error as a warning and skips the file. *Fix:* On a read error in open_file, log the same `disk_unread` warning and start the file as `Seen::GitOutput` without a start look; the first refresh then retries it the way it retries any other unread file.
- **#518** (boundary, should) `crates/session/src/writes.rs:46` — If the read-back after a successful `git add` (and likewise in take/reset) fails, finish returns `Err(ReadFailed)` although the file is written and staged. The window then reports a failed write, and because `seen` keeps the pre-write bytes, the next refresh reports yamt's own write as an outside 'changed on disk' change. *Fix:* After the write has succeeded, treat a failed read-back as a warning and still return `Written`. For finish, set `seen` from the bytes just written (`fs::write` applies no filter); for take/reset, log the failure and leave `seen` for the next look.
- **#519** (boundary, should) `src-tauri/src/commands.rs:43` — `Error::ReadFailed` becomes `IpcError::WriteFailed` with only the io message, so problemText.ts will show 'writing <path> failed: Permission denied' when yamt failed to read the file before any write. *Fix:* Propose `IpcError::ReadFailed { path, message }` to the orchestrator before the window half binds problemText's exhaustive switch (bindings are regenerated anyway). Until then, at least keep the session's 'cannot read' wording in `message`.
- **#520** (boundary, should) `crates/session/src/disk.rs:137` — Files yamt deliberately never stages (a working-tree-encoding file, a submodule that is no longer checked out) are reported as `MarkersLeft { conflicts: 0 }`. That says 'markers left: none' while meaning 'left alone', and for a UTF-16 file the count comes from parsing UTF-16 bytes, which is meaningless. *Fix:* Give this case its own `DiskResult` variant (e.g. `LeftAsIs`), proposed as a #53 amendment before the window half reads `conflicts`. Compute `conflicts` only for `StageWithoutMarkers` files.
- **#521** (boundary, should) `crates/session/src/writes.rs:124` — To settle one file, changed_on_disk builds a `Vec<Option<OnDisk>>` as long as all files, using a `disk.take()` closure, because `settle` couples its input to file order by position (its doc comment has to explain 'one per file, in file order'). *Fix:* Let `settle` take `Vec<(usize, OnDisk)>` (file index and read). refresh then pushes only the changed files, changed_on_disk passes `vec![(index, disk)]`, and the positional doc comment goes away.
- **#522** (boundary, should) `src-tauri/src/commands.rs:15` — commands.rs is 437 lines and crates/session/tests/describe_and_take.rs is about 415, both over the 400-line file limit (implementer open_risk). *Fix:* Move `IpcError`, its `From<yamt_session::Error>` and the `every_session_error_serialises…` test into `src-tauri/src/ipc_error.rs` (a separate responsibility, about 85 lines). Move describe_and_take.rs's take/reset tests into `tests/take.rs`.
- **#523** (boundary, should) `crates/gitio/src/merge_file.rs:15` — The public `MergeInputs<'a>` puts a lifetime into gitio's public signature (`merge_file(&self, scratch, inputs: &MergeInputs<'_>, options)`), which RS1 forbids. *Fix:* Drop `MergeInputs` and take the three borrowed slices as parameters: `merge_file(&self, scratch: &Path, base: &[u8], local: &[u8], remote: &[u8], options: &MergeFileOptions)`.
- **#524** (boundary, should) `crates/merge-core/src/line_map.rs:1` — `line_map.rs` is tracked under crates/merge-core/src/, but skill://project-map does not name `line_map`. `just map-check` therefore fails on this tree, and the report's 'map-check: ok' cannot hold for commit e11a6d3. *Fix:* Orchestrator: add `line_map (2-way LineMap: exact/covering)` to project-map's merge-core line, together with the other doc updates the implementer listed, before running `just check`.
- **#525** (boundary, should) `crates/session/src/seed.rs:28` — `Located { local: Range<u32>, remote: Range<u32> }` and `Maps::base` carry local and remote lines as bare u32. Passing `located.remote` through `local_to_base` would compile, although vision 4 makes mixing line spaces a type error. *Fix:* Build `Located` as `LineRange<LocalLine>` / `LineRange<RemoteLine>` in `Maps::block`/`Maps::raw`, unwrap to `Range<u32>` only at the `LineMap` call, and reuse those ranges directly in `push_conflict`.
- **#526** (boundary, nit) `crates/session/src/disk.rs:50` — `Seen` is both the last read and the selector for the window's view, so its doc comment has to explain the double meaning, and `load` chooses the view by matching on a field named `seen`. *Fix:* Rename the variants to say which view they select, e.g. `ViewFromStages(OnDisk)` / `ViewFromDisk(OnDisk)`, and drop the enum-level explanation.
- **#527** (correctness, block) `crates/session/src/seed.rs:160` — `push_base_lines` copies base's last line as it is, even when it has no final newline, and settled disk lines follow it, so two lines join. Example: base `{\n  "a": 1\n}` (no EOF newline), ours/theirs adding `"x"`/`"y"` before a shared `}\n` (git leaves `}` settled after the block). The middle comes out as `…  "a": 1\n}}\n`, `line_count` says one line more than the text has, every later middle range is off by one, and applying ours over middle {2,2} drops the closing `}`. *Fix:* When a pushed base line does not end in `\n` and is not the last line of the middle, append the disk's line ending (CRLF or LF per `self.eol`). Add a seed test with a base lacking its final newline and a settled line after the block, asserting the middle text and applying ours.
- **#528** (correctness, block) `crates/session/src/start.rs:101` — An unspecified `merge` attribute is always treated as the text driver, but git uses `merge.default` for such paths (merge-ll.c `find_ll_merge_driver`). With `merge.default=binary`, git leaves every conflicted text file as ours without markers, yamt's merge-file output has markers, the file counts as changed, and the first `list_files` stages every untouched conflict as ours. The design notes (line 175) list only smudge filters as start false positives that stage. *Fix:* Resolve the driver as git does: for an unspecified attribute, read `merge.default` (one `git config --get` in gitio) and map `binary`/`union`/`text`/other the same way as an attribute value. Add a start_from_disk case with `merge.default=binary` asserting no disk change.
- **#529** (correctness, should) `crates/session/tests/start_from_disk.rs:278` — `merge=<name>` with no `merge.<name>.driver` configured falls back to git's text merge (merge-ll.c: 'default to the 3-way'), but start.rs:107 calls it Custom/changed. A common case is `merge=lfs` written by `git lfs track`, which does not define a driver. Such untouched files open from disk with a MarkersLeft notice. This test pins that false positive: in its hermetic repo git did a plain text merge, because mergiraf is not configured. *Fix:* Count a name as Custom only when `merge.<name>.driver` is configured (fall back to Text otherwise). Have the test configure `merge.mergiraf.driver` (e.g. a script that writes markers and exits 1), and add an unconfigured-name case expecting no change.
- **#530** (correctness, should) `crates/session/src/seed.rs:145` — Two blocks can sit inside one local→base hunk: git's zealous refine splits a conflict on ≥4 shared alnum lines both sides added. Both blocks then get the same covering base range, `push_base_lines` writes those base lines twice into the middle, and the chunks overlap in base space. That breaks the invariant that chunks are pairwise disjoint in base space (architecture §3.1). Open risk #3 names wider spans, not duplication. *Fix:* Clamp each chunk's base range so it starts no earlier than the previous chunk's base end (and push only the clamped lines). Add a seed test with a conflict that git splits into two blocks around 4 shared lines, asserting disjoint base ranges and applying ours on both.
- **#531** (correctness, should) `crates/session/src/open.rs:78` — `read_on_disk(...)?` in `open_file` makes one unreadable conflicted path fail the whole open (the app refuses to start; before the patch it opened). Examples: permission denied, or a submodule whose `.git` file points at a missing gitdir. `refresh` skips such a file with a warn. *Fix:* On a read error at open, log a warn and start that file with `seen = Seen::GitOutput` (no start look). It then follows refresh's skip-and-retry path, and writes report ReadFailed.
- **#532** (correctness, should) `crates/gitio/tests/what_git_wrote.rs:144` — No test has inputs where histogram and myers merges differ: this test sets `histogram: true` but only checks union output, and every start_from_disk case merges the same either way. Dropping `--diff-algorithm=histogram` or mutating `version >= HISTOGRAM_SINCE` therefore survives (the implementer reports the surviving mutant). *Fix:* Add a start_from_disk case (or a merge_file test) on a triple whose merge-ort/histogram output differs from myers (e.g. RK13's pinned case A/B in cli/tests/merge_file.rs), and assert the untouched file reports no change.
- **#533** (correctness, should) `crates/session/src/seed.rs:356` — In a_section_line_repeated_elsewhere_still_applies_the_exact_text, the ours view equals local line for line, so the diff has no hunks and the repeated `dup` can never be aligned elsewhere. The test passes for any mapping that is the identity. *Fix:* Give remote a clean change next to the repeated line (so the settled text, and hence the ours view, differs from local around it), then assert the exact ranges and that applying ours and theirs both give the by-hand file.
- **#534** (correctness, should) `crates/session/src/writes.rs:182` — `finish` writes with `fs::write`, which follows a symlink. After a text file was replaced by a link and settled (`Seen::Disk(Link)`, view DiskNotText{Link}), a finish with the current version writes the user's text into the link's target, a file yamt never showed (it may be outside the repo). *Fix:* In `finish`, refuse when the file's seen entry is a Link/Other/Submodule (e.g. return Error::Unsupported or ChangedOnDisk), or remove the link before writing; add a test in disk_is_truth.rs.
- **#535** (correctness, nit) `crates/session/src/start.rs:299` — The scratch dir that holds the base/local/remote blobs is created with the default mode (0777 minus umask, usually 0755), so other local users can read the merge inputs while open runs. *Fix:* Create it with `std::fs::DirBuilder::new().mode(0o700)` (std `os::unix::fs::DirBuilderExt`).
