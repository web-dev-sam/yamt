## Findings (verbatim) and decisions

### #226 should (boundary, RS16) — `LinePair` names a cursor

> `LinePair` is documented as 'a base line and the side line compared with it', but most of its
> uses are cursors that are never compared: `equal_from` (line_pairs.rs:35,46), `first` in
> similar_pairs, and `after_previous`/`chunk_end` (word.rs:72,76,81, chunk_end being one past both
> ends). A reader of `mark_gap(from: LinePair, until: LinePair)` is told it receives pairs.
>
> Fix: Rename the type to a neutral position (e.g. `LinePosition { base, side }`, documented as 'a
> line index in base and one in side, counted from the chunk's first line') and keep the word
> 'pair' for the values returned by `line_pairs`.

**Decision:** as proposed.

### #227 should (boundary, RS13) — unnamed Dice scale

> The Dice scale `200` (2 × 100 for a percentage) is an unnamed literal in `pair_score`, and the
> threshold it is compared against is a named constant.
>
> Fix: Name it next to MIN_SHARED_PERCENT, e.g. `const DICE_PERCENT_SCALE: usize = 200; // shared
> counts once per line (×2), as a percentage (×100)`, or compute `100 * shared / average_len` with
> a named average.

**Decision:** as proposed. Pick the form that reads best to a Rust beginner.

### #231 nit (correctness) — a wordless line never pairs with a worded one

> A wordless line is compared by its symbols while its partner is compared by its words, so the two
> sets never intersect. A common real edit like `}` → `} else {` or `});` → `}, { passive });`
> therefore never pairs: the side line is marked whole and the removed base line gets no point.
>
> Fix: When either line of a candidate pair has no words, compare both lines by their symbol
> tokens (or by words plus symbols), and add a line_pairs unit test for `}` → `} else {`.

**Decision:** fix it, because these are everyday edits (the owner asked to tune pairing on common
edits). When either line has no words, compare both by **words plus symbols** (all non-whitespace
tokens). Comparing by symbols alone would pair `});` with an unrelated `foo(a, b);`. New catalogue
cases, each a test on both sides like C1–C30:

| #   | base  | side               | expected side                                         |
| --- | ----- | ------------------ | ----------------------------------------------------- |
| C31 | `}`   | `} else {`         | `}[ else {]`                                          |
| C32 | `});` | `}, { passive });` | `, { passive }` added as one range; the rest unmarked |
| N4  | `});` | `foo(a, b);`       | not paired: the side line whole                       |

Add them to the demo file too (`tests/showcase/word-marks`, one block each, commented like the
others). If the threshold must move to meet these, say so and show that C1–C30, N1–N3 and M14
still pass.
