# Slice 1.1 — the engine's change blocks get their colours

The window now opens the 10 real conflicts as plain text. This slice colours the engine's change
blocks in all three panes, the way PhpStorm's merge window does, and keeps the middle pane's
colours on the right lines while the user types there. Apply buttons, bands between the panes and
locked scrolling are later slices; nothing here is clickable.

## Contract (fixed; you may add, never change)

- `editor/index.ts`: `new MergeController(data: FileMergeData, hosts: MergeHosts)` where
  `FileMergeData` is the domain type from `../ipc`; `destroy()` as today. `MergeTexts` is
  deleted (clean cutover). No other public method in this slice.
- `ui/useMergeController.ts` takes `MaybeRefOrGetter<FileMergeData | null>` (VU11); `MergeView.vue`
  passes its `data` prop. Nothing else in `ui/` changes.
- `editor/internal/chunkField.ts`: one `StateField` on the **center** state (CM1, CM9) holding,
  per chunk, `{ id, kind, from: DocPos, to: DocPos }` — the chunk's base range in the current
  center document. `DocPos` is a brand created only in `editor/`.
  - Representation: `from` = start of the range's first line; `to` = start of the line after the
    range (or the document end). An empty base range (a pure insertion on a side) is
    `from === to` at the start of the line it precedes, or the document end.
  - Mapping: both ends map with `tr.changes.mapPos(pos, -1)`. Effect: typing anywhere in the
    chunk's lines, including at the start of its first line, stays inside; typing at the start of
    the line after the chunk stays outside; text typed at an empty chunk's point lands after it.
    **This overrides CM1's `+1` for `to`**: CM1's `+1` belongs to an "end of last line"
    representation, which cannot tell a one-empty-line chunk from an insertion point. Say so in
    `deviations_from_brief`.
- Tone of a chunk on one side (one pure function, used by every pane): `Conflict` → `conflict`;
  otherwise compare that side's range with the base range: base empty → `inserted`, side empty →
  `deleted`, both non-empty → `modified`.
- What each pane shows (PhpStorm's merge window):
  - left (local): chunks where local changed — `LocalOnly`, `BothSame`, `Conflict` — on their
    `local` lines, by local's tone;
  - right (remote): `RemoteOnly`, `BothSame`, `Conflict` on their `remote` lines, by remote's tone;
  - center: every chunk on its current mapped range, by the tone of the side that changed
    (`LocalOnly` → local, `RemoteOnly` → remote, `BothSame` → local, `Conflict` → conflict);
  - an empty range is drawn as a thin line at its insertion point, not as a coloured line.
  - Side-pane decorations are built once per file (CM3); center decorations follow the field.
- Decorations never change line height (no border, margin or padding on lines; use backgrounds
  or inset shadows). Equal line metrics in all panes is what the bands and scroll sync of the
  next slice rely on (CM4).
- Colours: four tones as new `--color-*` tokens in the `@theme` block of `style.css`, JetBrains
  New UI dark from memory (green inserted, blue modified, grey deleted, red conflict; muted
  enough that syntax colours stay readable on `--color-editor`); decoration classes styled once,
  reading only palette variables (VU14). The palette test (`scripts/palette.test.ts`) must stay
  green.

## Tests

Before you start, the orchestrator has changed `vite.config.ts`: the `node` project now runs
`src/editor/**/*.test.ts` except `*.browser.test.ts`, and the `browser` project runs only
`src/editor/**/*.browser.test.ts` (Playwright WebKit cannot launch on this machine; the browser
project is not in the gate). Rename `engine.test.ts` to `engine.browser.test.ts` first. Your tests
use `EditorState` only (no view), in the `node` project:

- the field's initial ranges for a real fixture (`vite-modulepreload-polyfill.json`: chunk 1 has
  an empty base range at base line 8 → `from === to` at the start of line 9) and for a chunk at
  the end of the document;
- mapping: an edit before a chunk shifts it; typing inside grows it; typing at the start of the
  next line stays outside; typing at an empty chunk's point lands after it; deleting all of a
  chunk's lines collapses it to `from === to`; undo (center `history()`) restores the range;
- tone: one case per outcome, including `BothSame` and a `Conflict` with an empty side;
- which chunks each pane decorates and with which tone, for one real fixture
  (`vueuse-use-magic-keys.json` has `LocalOnly`, `RemoteOnly` and `Conflict`).

`editor/` code is not covered by the mutation run yet: for each test group, break the code it
guards by hand once (e.g. map `to` with `+1`), watch it fail, restore, and report the failure line.
