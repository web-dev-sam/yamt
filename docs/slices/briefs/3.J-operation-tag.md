# Slice 3.J-operation-tag — the operation as a gray tag at the bottom of the file list

Board "Git operations" row 13. Product rule: `docs/plan.md` §2 **#92** (read it whole; it replaces #87's **Top line**
placement, #87's words stay). Owner's words (#1449): "putting the merge type at the top a bit space-wasting … at the
bottom of the left sidebar (where the files are) … a uppercased gray for "REBASE" "MERGE" "CHERRY-PICK" with a tooltip
on hover on details of what is merged into what".

## Target

Owned: `frontend/src/ui/{App.vue,FileList.vue,OperationBar.vue (delete),OperationLabel.vue (new),operationText.ts,operationText.test.ts,AGENTS.md}`.
Read-only: everything else (`ipc/`, `editor/`, Rust, `docs/**`, `.omp/**`).
Non-goals: new words for the hover (it stays `operationLine`'s tooltip); the step count in the tag; anything about the
Continue/Abort buttons; the file list's width, view or folders.

## Facts (given)

- `ui/OperationBar.vue`: `<p role="status" :title="line.tooltip">{{ line.text }}</p>` with info tokens, `h-8`; rendered
  by `App.vue:72` as the right column's first row when `operation !== null`. Its only users: `App.vue`.
- `ui/operationText.ts`: `operationLine(operation) -> { text, tooltip }` (text: "Rebasing feature onto main · 2 of 5";
  tooltip: the text, then the commit messages, joined by blank lines); `NAMES`/`TITLES` are `Record<OperationKind, …>`
  tables there.
- `ui/FileList.vue`: `<aside class="relative flex w-60 shrink-0 flex-col rounded-island bg-panel pb-1">`, the header row
  `h-10 … pl-3` with "Files", then `FileTree` or the `<ul class="… flex-1 overflow-y-auto …">`, then the resize handle.
  Props `{ files, active }`. `App.vue` hides it with `v-show="fileListShown"` (#61).
- Muted text elsewhere: `text-fg-muted` (e.g. `ChoiceView.vue:90`, `FileMark.vue`).

## Change

1. `operationText.ts`: `operationTag(kind: OperationKind): string` from one `Readonly<Record<OperationKind, string>>`
   table: `MERGE`, `SQUASH MERGE`, `REBASE`, `CHERRY-PICK`, `REVERT`, `AM`. The words are stored uppercase (no CSS
   `uppercase`), so tests pin what the user reads.
2. `OperationLabel.vue` (replaces `OperationBar.vue`, which is deleted): the tag text, `title` = `operationLine`'s
   tooltip, accessible name = `operationLine`'s text (a screen reader hears "Rebasing feature onto main · 2 of 5", not
   "REBASE"); muted (`text-fg-muted`), small, semibold, one line, left-aligned with the "Files" heading (same left
   padding), truncated if the panel is narrow.
3. `FileList.vue` renders it as the panel's last row, below the list or tree, only when an operation is recorded; the
   list or tree keeps scrolling above it, so the tag stays at the bottom with a long list. `FileList` gets the operation
   as a prop from `App.vue` (the store stays the one writer, plan §2 #87).
4. `App.vue`: the right column's first row is gone (the notices, problem bar or toolbar row is now the first).
5. `ui/AGENTS.md`: where it names the top line or `OperationBar`, name the tag.

## Acceptance

- Node test: `operationTag` for each of the six kinds (a `test.each` table).
- WebKit (`just app-session start-fixture`, then `just webdriver`), dark **and** light: `?operation=rebase`,
  `merge`, `squash`, `cherry-pick`, `revert`, `am` → the tag reads `REBASE`, `MERGE`, `SQUASH MERGE`, `CHERRY-PICK`,
  `REVERT`, `AM` at the bottom of the file list; its `title` and accessible name as above (paste the rebase ones);
  `?operation=none` → no tag; the right column starts with the toolbar (no empty row above); list and tree view both;
  a window short enough that the list scrolls (e.g. 1400×600) → the tag stays visible at the bottom; Ctrl+B hides it
  with the list. Screenshots of the file list with the tag (dark, light) and of the whole window.
- `pnpm -C frontend typecheck`, `test`, `lint`, `unused`, `fmt:check` pass: paste the tails.
