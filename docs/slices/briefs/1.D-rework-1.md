## Changes

1. **Decision — line-anchored word diff** (orchestrator, plan §2 #28). On `nuxt-island-test`
   chunk 0 the token diff over the whole chunk matches base `/utils'` (line 2) to the new local
   line 3, so the unchanged local line 2 gets `[utils']`, base line 2 gets `[-vitest]`, and the added
   line 3 is only partly marked:
   ```
   local  2| import { mountSuspended } from 'nuxt-vitest/[utils']
   local  3| [import { flushPromises } from '@vue/test-]utils'
   base   2| import { mountSuspended } from 'nuxt[-vitest]/utils'
   ```
   Do it as IntelliJ does — by line first, then by word inside changed lines: diff the chunk's side
   lines against its base lines (imara-diff histogram, as `compute.rs` does for lines); a side line
   matched to an equal base line gets no ranges; run the token diff only inside each changed line
   hunk (its side lines against its base lines; a hunk with no base lines or no side lines marks its
   lines whole, line breaks excluded). Expected here: local line 2 and base line 2 unmarked, local
   line 3 marked whole. All other range rules of the base brief stay (whitespace bridge, union,
   UTF-16, no line break inside). Pin it with a hand test of the same shape and update the brief's
   other expectations only where line anchoring changes them (report each).
2. [should, correctness, RK14] `tests/word_invariants.rs:124` — "The 'sorted' assertion
   `line < next_line || start + len < next_start` accepts a later range on an earlier line whenever
   its column is larger. For example (5,0,1),(2,3,1) passes, so a union built by concatenating the
   two sides' base ranges without sorting would survive the proptest." Fix: "Assert
   `line < next_line || (line == next_line && start + len < next_start)`."
3. [should, correctness] `src/word.rs:190` — "No test covers the `token.kind != TokenKind::LineBreak`
   guard in is_changed_text. A mutant that drops it, so that a whitespace run between a changed
   word and a changed line break gets highlighted, passes every hand test and proptest." Fix: "Add a
   hand test such as base `x old \n`, local `x new \r\n` expecting local [(0,2,3)] and base
   [(0,2,3)]. The trailing space must stay unhighlighted even though both of its neighbours
   changed." (Re-derive the expected ranges under change 1.)
4. [should, boundary, principles-2] `src/word.rs:169` — "`is_highlighted` looks up again
   (`tokens.get(index) else false`) the token its only caller already holds. `is_changed_text`
   takes an `Option<usize>` and falls back on `changed.get(index).unwrap_or(false)` for a vector that
   always has the same length as `tokens`. Some of these branches can never run." Fix: "In `ranges`,
   first build one `text_changed: Vec<bool>` (changed and not a line break). Then pass `token.kind`,
   `text_changed[index]` and the two neighbours to `is_highlighted` … Delete the `Option<usize>`
   parameter and the `tokens.get` fallback." (Any equivalent with no unreachable branch.)
5. [nit, boundary] `src/word.rs:80` — "`kind_of` never returns `TokenKind::LineBreak`, yet the
   tokenizer's `byte_len` match must still handle it." Fix: a character-kind enum without
   `LineBreak` for splitting a line; `LineBreak` only on tokens.
