# Slice 3.J-operation-tag, fix round 1 — a screen reader hears every step

Board "Git operations" row 13. Round 1: `5a504c0` (notes `.omp/run/notes/GitOpsTag.md`, both reviews). Finding #1451
(block, verbatim in `.omp/run/findings.jsonl`): `OperationLabel.vue` is a `role="status"` live region whose text is the
bare tag; the line sits only in `aria-label`. A live region announces text changes, not attribute changes, so at the next
stop of the same operation ("1 of 3" → "2 of 3") nothing is announced, where the old top line announced the new line.

## Target

Owned: `frontend/src/ui/OperationLabel.vue`, `frontend/src/ui/AGENTS.md`. Everything else read-only.

## Change

1. Drop `:aria-label`. Inside the `role="status"` element: the visible tag in a `<span aria-hidden="true">`, and the line
   (`operationLine(...).text`) in a `<span class="sr-only">` (Tailwind's utility). `title` stays the tooltip. The
   accessible name and the announced text are then the line, and both change with every step and kind.
2. `ui/AGENTS.md`: the sentence naming the tag says the line is its screen-reader text.
