## Contract (fixed; you may add, never change)

```rust
// src-tauri/src/merge.rs
pub(crate) enum Merge {
    Held(MergeSession),
    Running(OperationKind),      // git aborts or continues; the session is with the worker
    MovedOn { root: PathBuf },   // the stop moved on: the old session is dropped; the next list opens the new one
    Aborted(OperationKind),
    Finished(OperationKind),
}
// commands (generated: listStop, continueOperation, abortOperation)
#[tauri::command] #[specta::specta] fn list_stop(..) -> Result<Listing, IpcError>;
#[tauri::command] #[specta::specta] async fn continue_operation(..) -> Result<ContinueReply, IpcError>;
#[tauri::command] #[specta::specta] async fn abort_operation(..) -> Result<(), IpcError>;
#[serde(tag = "kind")] pub enum Listing { Files { files, disk_changes, operation: Option<OperationView>, sides: SideNames }, MovedOn }
#[serde(tag = "kind")] pub enum ContinueReply { Finished, Stopped { message: String } }
// IpcError gains: StopMovedOn, GitRunning, MergeFinished, NoOperation (session's GitRefused → Git { message })
```

## Behaviour

1. **States.** `Held` answers every command as today. `Running`: every merge command answers `GitRunning`, nothing
   runs git. `MovedOn`: every write (finish, save, reset, take) and load/describe answer `StopMovedOn` and write
   nothing; `list_stop` opens a new `MergeSession` at `root` (zero conflicted files is a valid empty stop) → `Held`,
   and answers its `Files`. `Aborted`/`Finished`: every command answers `MergeAborted`/`MergeFinished`, runs no git.
   The old commands follow the same states (`list_files` in `MovedOn` → `StopMovedOn`).
2. **`list_stop`** = `refresh_stop`: `Files` as it comes; `MovedOn` → the state becomes `MovedOn` (session dropped)
   and the reply is `MovedOn`.
3. **Continue/Abort** take the session out of the mutex (`Running(kind)`), run on a blocking worker
   (`tauri::async_runtime::spawn_blocking` or equal) so the main thread and other commands never wait on git, and put
   the result back: Continue `Finished` → `Finished(kind)`, the window destroyed as `abort_merge` does, reply
   `Finished`; `Stopped` → `MovedOn`, reply `Stopped { message }`; an error (refused, no operation, moved on) → the
   session back in `Held`, the error as the reply. Abort success → `Aborted(kind)`, window destroyed; failure → `Held`,
   error. A worker panic must not leave `Running` forever (the session back, or a failure ending).
4. **Endings** (`outcome.rs`): `Finished(kind)` → exit 0, stderr `yamt: <operation> finished`; `Aborted(kind)` →
   exit 1, `yamt: <operation> aborted` (merge keeps today's `merge aborted`); words per `OperationKind`: merge, squash
   merge, rebase, cherry-pick, revert, patch application. `MovedOn` at close → git's unmerged list as #41/#49 (exit 0
   when none). `Running` at close: wait for the worker to finish, then end by the state it left; never kill git.
5. **Commands stay thin** (IPC5: ≤ 15 lines each, logic in `merge.rs`). `MergeSession` is large (row 3 boxed its
   `side_names` to stay inside clippy's `large_enum_variant` window): hold it boxed in `Merge::Held` and
   `outcome::Startup::Merge` and drop the `#[expect(clippy::large_enum_variant)]` on `Merge`, so session fields stop
   being limited by `src-tauri`'s enums (row 9 then unboxes `side_names` in `session`).
6. **Fixture mode** (`ipc/fixtureOperations.ts`, new): `?operation=merge|squash|rebase|cherry-pick|revert|am|none`
   (default: merge, as today's `merging: true`) gives `listStop` that operation with names and progress ("rebase" 1 of
   3, `editor_steps_ahead` false; `?rewords` sets it); `continueOperation` advances a sequence — the next `listStop`
   lists the same fixture files unresolved again with the next step — and answers `Finished` (logged once) after the
   last step or for a merge; `abortOperation` answers done and logs once (as today's `abortMerge`); `none` gives
   `operation: null`. Sides as today's fixture names, with a rebase's own commit on the left.
7. **Error words** (`ui/problemText.ts`): `StopMovedOn` "The operation moved on; the list is being read again.",
   `GitRunning` "Git is still running; try again when it is done.", `MergeFinished` "The operation is finished.",
   `NoOperation` "Git has no operation to continue or abort." (final words may be refined in row 6/8).
8. **`scripts/operations-repo.sh <run> <dir>`** builds the real-app repositories for the final run, one per `run`:
   `merge`, `squash`, `rebase` (3 own commits on `feature` onto `main`, conflicts in commits 1 and 2 incl. a binary file
   and a file `main` deleted that the first own commit changes), `rebase-apply`, `rebase-interactive` (a `reword` ahead),
   `cherry-pick` (a range of 3, conflicts at 1 and 2), `revert` (a range of 2, both conflict), `am`, `stash-pop`,
   `rerere` (a resolution recorded, then the same conflict replayed with `rerere.autoUpdate` off), `hook` (a merge
   whose `pre-commit` hook prints "hook says no" and exits 1); sources `git-sandbox.sh`, refuses a non-empty folder,
   `require_conflicts`.
