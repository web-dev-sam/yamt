## What each option must answer

1. **Owner and element**: who owns the minimap (vision 2: one geometry cache, `Frame`; #80 rejected a per-pane
   ViewPlugin and Vue-drawn lanes), which element it is, where it is mounted so it floats over the right pane's right
   edge at the panes' row height (rule 2) without moving the layout, its stacking against the right pane's text,
   scrollbar, find bar and strip icons, and how it survives a window resize, the file list hiding (Ctrl/Cmd+B) and the
   find bar opening (`findSpace`). How "shown" reaches it (rename of `marks`/`showMarks`), and what a file opened or
   shown while Alt is held does.
2. **Rows**: the pure mapping between Result lines and minimap rows — collapsed runs as one row (rule 3), the find
   space, CodeMirror's estimated heights for lines never drawn — and where it reads them (`Frame`'s rows, the height
   map, `lineBlockAt`); tested on numbers.
3. **Drawing**: canvas 2D (confirm vs. `@replit/codemirror-minimap`, request facts; DR3); characters from the Result's
   syntax tree in its theme colours (how colours are resolved per theme without per-frame `getComputedStyle`; what a
   line not yet parsed shows), 120 columns, tabs, device pixel ratio, only the rows in the minimap's window; what is
   cached and when it is invalidated (document, folds, statuses, problems, theme, resize, DPR) versus what runs per
   scroll frame while shown; that nothing runs or is measured while hidden (rule 9). Files up to 8 MiB.
4. **Scroll and slider**: the proportional layout (VS Code's formulas, cited) as a pure function tested on numbers,
   including the file that fits, the find space, and the end of the document (#1219: the locked scroll can land wrong
   at a side's very end — say whether your design is exposed).
5. **Edges**: problem marks (error over warning, info/hint dropped, a problem inside a collapsed run on its row) and
   change marks (`paneTone(…, "center")`, waiting only); their x, width and minimum height (orchestrator default: you
   propose one); colours: reuse the `--color-mark-*` tokens or replace them, each a token per theme in `style.css`.
6. **Pointer**: press on a row → that line centred; press on the slider → drag; wheel → scroll; all through the
   Result's scroll so the sides follow (`ScrollSync.follow`); no focus, cursor, selection, fold or keyboard change; the
   press never reaches the right pane (no selection, no side focus, no icon drag); Alt released mid-drag ends the drag
   (the hold hides it). Name the existing functions you reuse.
7. **Cutover**: the exact removal list for build A from the request table (what of `marks.ts` survives, if anything),
   how `editor/index.ts` gets under its cap with room for B (move what out, to which file), and docs B must touch.
8. **Tests**: `editor/` is not mutated (VF7) — for each node unit test name the plausible bug it catches and the
   one-line hand mutation that makes it fail (the orchestrator hands these to the build as failing-path steps). Plus
   WebKit steps (MiniBrowser through `just webdriver 4447`, dev server on its own port) and real-app steps
   (`just app-session`, session names `m-…`, real X input `xdotool keydown alt` … `keyup alt`, as #80's final run did:
   `.omp/run/notes/AltMarksVerify.md`) for every acceptance line, and the scroll-timing measurement
   (`.omp/run/scroll-timing.py`).
9. **Size**: files and changed-line estimate per build; new public surface on `MergeController` (keep it small).
10. **Plan §2 #81**: a draft row in the style of #80 (rule text, rejected alternatives, visions cited).
