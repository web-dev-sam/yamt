## Behaviour

1. **Button.** A text button with `continueLabel`, right after "Mark resolved" (same look), id `continue`: in the
   right-click menu, shown at first, its stored decision like the others. `ready` only when an operation is recorded,
   git lists no file `Unresolved` or `Remembered`, no write claim is held and git is not running; otherwise disabled
   with a hover: "2 files are not resolved yet" / "Saving…" / "Continuing…".
2. **Click.** Unsaved edits in any opened file ask first: "Continue the rebase without saving them?" naming the files,
   confirm "Continue Without Saving" (cancel changes nothing). A rebase with `editor_steps_ahead` then asks: "A later
   step rewords or squashes a commit. yamt cannot open an editor, so that message stays as git prepares it." confirm
   "Continue rebase". Then `continueOperation()` with the state `running`.
3. **Reply.** `Finished` → nothing (the window closes from Rust; log it). `Stopped { message }` →
   `nextStop({ kind: "continued", message })`. `Git { message }` → the problem bar "Could not continue the rebase: …",
   the state back, the list read again. `StopMovedOn` → `nextStop({ kind: "outside" })`. Other errors through
   `problemText.ts` as today.
4. **Closing while git runs** (`closeGuard.ts`): the close is refused and the problem bar says "Git is still running;
   close yamt when it is done." — never a question, never a kill.
5. **Where there is no toolbar** (`OperationButtons.vue`: Continue and Abort with the same states and words): in the
   choice view's and the deleted-side view's header rows, and in `StopView.vue` — shown in the merge area when an
   operation is recorded and the list is empty (a stop without conflicts): "Git stopped without conflicts." plus git's
   message when one came, and both buttons.
6. **The all-resolved line** names the next step: "All files are resolved. Continue rebase to let git go on." (merge
   and squash merge: "… Commit merge to commit it."); with no operation, today's words.
