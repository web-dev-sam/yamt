## Contract

New public surface (names fixed):

- `ui/fileTree.ts` (pure, no Vue):
  ```ts
  export type TreeRow =
    | {
        readonly kind: "folder";
        readonly path: string;
        readonly label: string;
        readonly depth: number;
        readonly open: boolean;
      }
    | {
        readonly kind: "file";
        readonly file: FileEntry;
        readonly label: string;
        readonly depth: number;
      };
  export function treeRows(
    files: readonly FileEntry[],
    closed: ReadonlySet<string>,
  ): readonly TreeRow[];
  export function folderPaths(path: string): readonly string[];
  ```
  `treeRows` returns the visible rows in display order. A folder row's `path` is the full path of the last folder
  on the row (its open/closed key and, by its last segment, its icon); `label` is the row's folders joined by "/"
  ("packages/core/src"); `open` is `!closed.has(path)`; a closed folder's descendants are absent. A file row's
  `label` is its name (last segment). `depth` counts rows, not folders: children of "packages/core/src" are one
  deeper than it. `folderPaths("a/b/c.ts")` is `["a", "a/b"]` (every folder holding the file, outermost first; `[]`
  for a top-level file) — FileList removes these from its closed set when `active` changes (reveal).
- `ui/fileIcon.ts`: `export function folderIcon(name: string, open: boolean): Component` — `name` is one folder
  name, matched lower-cased against the table below; `default-folder` / `default-folder-opened` otherwise. Static
  imports like the file icons (`~icons/vscode-icons/folder-type-src`, `…-opened`); one exported row table
  (`FOLDER_ICON_ROWS`, mirroring `ICON_ROWS`) so the test can check every name.
- `ui/fileListMode.ts`:
  ```ts
  export type FileListMode = "list" | "tree";
  export function createFileListMode(storage?: StorageLike): {
    readonly mode: Readonly<Ref<FileListMode>>;
    toggle(): void;
  };
  ```
  `StorageLike` from `@vueuse/core`; default the window's `localStorage`, memory where there is none (node tests),
  as `createHiddenButtons` does (`toolbarButtons.ts`: read it, follow its pattern). Key `"yamt.files.view"` (one
  `const`), value the plain string `"list"` or `"tree"`; anything else or nothing → `"list"`; a storage that throws
  on read or write → the choice still applies for this run, one `log.warn` (snake_case event, the error's message as
  a field), no problem bar, never throws. `useStorage` with a serializer first (VU12); plain code only if it cannot
  express a rule, say which.
- `FileList.vue` creates one mode with `createFileListMode()` and keeps it, the closed-folder set
  (`shallowRef<ReadonlySet<string>>`, session only) and the width as its own presentation state (the store is not
  involved: one reader, one writer).

## Behaviour (what the user sees)

### The header and its button

1. The header row keeps "Files" on the left; at its right end one icon-only button, `type="button"`, styled like
   `SettingsButton.vue` (`rounded p-1.5 hover:bg-hover`, icon `size-4`), vertically centred; the header's height
   stays as today or grows by at most the button's padding (say which).
2. In the list view it shows lucide `list` with `title` and `aria-label` "View as tree"; in the tree view lucide
   `list-tree` with "View as list" (VS Code's Source Control title button: the icon shows the current view, the
   words say what a click does; `scmViewPane.ts` `SetTreeViewModeAction` `Codicon.listFlat`,
   `SetListViewModeAction` `Codicon.listTree`).
3. A press switches the view at once and keeps the keyboard where it was: prevent the `mousedown` default as
   MergeToolbar's arrow buttons do (`MergeToolbar.vue` `keepsKeyboard`), so a side pane holding the keyboard keeps
   it.
4. The choice is remembered across restarts (#58's way). The list is the starting view.

### The list view

5. Exactly today's rows (`role="listbox"`, `aria-label="Conflicted files"`, options with full paths, resolved mark,
   selection look). Nothing in it changes.

### The tree view

6. Rows from `treeRows(files, closed)`. Order (VS Code `SCMTreeSorter` in tree mode): within each folder, folders
   first, then files; each group by name with `new Intl.Collator(undefined, { numeric: true, sensitivity: "base"
   })` (VS Code's `compareFileNames`), ties by plain code-unit order so the order is total ("a.ts" vs "A.ts").
   `file2.ts` before `file10.ts`; `B` and `b` side by side.
7. Compact folders (VS Code `scm.compactFolders` default true): a folder whose only child is one folder joins it on
   one row, repeatedly — files `packages/core/src/a.ts` and `packages/core/src/b.ts` show one folder row
   "packages/core/src" and two file rows under it; files `a/b/x.ts` and `a/b/c/y.ts` show "a/b", then "c" and
   "x.ts" under it (folders first), then "y.ts" under "c". A folder holding a file is never joined to its child.
   Top-level files sit at depth 0 next to top-level folders.
8. Every folder starts open (VS Code `collapseByDefault` false for folders). A click anywhere on a folder row
   opens or closes it (chevron and label alike) and selects nothing, emits nothing. Open/closed is kept by folder
   `path` for the session and survives a switch to the list and back and a Ctrl/Cmd+B hide.
9. Reveal (VS Code `scm.autoReveal` default true): whenever `active` changes to a file — picked in the tree or the
   list, or the next unresolved after Mark resolved — every folder in `folderPaths(active)` opens.
10. A click on a file row emits `select` with its full path, exactly as a list row does. The shown file's row has
    the list's selected look.
11. Look (VS Code's tree defaults; `listService.ts` `workbench.tree.indent` 8, `tree.css` `.monaco-tl-twistie`):
    every row has the list rows' height, padding, hover and corner radius; indent 8 px per `depth`; then a 16 px
    twistie slot — on folder rows lucide `chevron-down` (open) or `chevron-right` (closed), `size-4`, muted colour;
    empty on file rows so a file's icon lines up with its sibling folders' icons; then the icon (`size-4`): a
    folder row `folderIcon(lastSegment(path), open)`, a file row `fileIcon(file.path)`; then the label, truncated
    with an ellipsis like today; a file row also carries the list's muted name and "✓ resolved" mark when
    resolved.
12. Indent guides (VS Code `workbench.tree.renderIndentGuides` default "onHover"): for each level a row is nested
    in, a 1 px vertical line under that level's twistie centre, drawn only while the pointer is over the tree
    (fade allowed, ≤ 100 ms as VS Code's 0.1 s), continuous from row to row; colour an existing palette token for
    borders (say which). Tailwind only (VU14).
13. Accessible: `role="tree"`, `aria-label="Conflicted files"`; rows `role="treeitem"` with `aria-level`
    (depth + 1); folder rows `aria-expanded`; file rows `aria-selected`. Icons `aria-hidden`.
14. Scrolling, width drag, and the panel look are as today in both views.
