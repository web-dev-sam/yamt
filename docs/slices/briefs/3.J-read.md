```rust
// crates/gitio/src/operation.rs, re-exported from lib.rs
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Stop { pub operation: Option<Operation>, pub head: Option<Oid> }

impl Stop {
    /// What makes this stop this stop: the operation's kind, the commit (or patch number) it applies, and HEAD.
    /// Progress and the todo list are not part of it, so `git rebase --edit-todo` is the same stop.
    pub fn id(&self) -> StopId;
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct StopId { /* private */ }

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Operation {
    Merge { merging: Oid },                                            // MERGE_HEAD, no rebase in progress
    SquashMerge { merging: Option<Oid> },                              // SQUASH_MSG's first `commit <oid>`, no MERGE_HEAD
    Rebase(Rebase),                                                    // rebase-merge/, or rebase-apply/ without `applying`
    CherryPick { picking: Option<Oid>, progress: Option<Progress> },   // CHERRY_PICK_HEAD and/or the sequencer
    Revert { reverting: Option<Oid>, progress: Option<Progress> },     // REVERT_HEAD and/or the sequencer
    Am { subject: Vec<u8>, message: Vec<u8>, progress: Option<Progress> }, // rebase-apply/ with `applying`
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Rebase {
    pub branch: Option<Vec<u8>>,       // head-name without refs/heads/; a detached rebase → None
    pub onto: Option<Oid>,
    pub replaying: Option<Oid>,        // REBASE_HEAD
    pub redoing_merge: Option<Oid>,    // MERGE_HEAD while `rebase -r` re-does a merge commit
    pub progress: Option<Progress>,
    pub editor_steps_ahead: bool,      // a `reword`, `squash` or `fixup -c` (any spelling git accepts) left in the todo
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Progress { /* step, total: private */ }
impl Progress {
    pub fn new(step: u32, total: u32) -> Option<Progress>;   // Some only when 1 ≤ step ≤ total
    pub fn step(&self) -> u32;
    pub fn total(&self) -> u32;
}

impl Repo {
    /// What git is doing now; `operation: None` when git records nothing (no conflict operation, stash pop/apply,
    /// `checkout -m`). Git failures are `Err`, as every `Repo` read.
    pub fn stop(&self) -> Result<Stop>;
}
```

## Behaviour

1. Precedence as git's own `wt_status_get_state` (design fact 4), plus the squash merge. Refs through
   `rev-parse --verify --quiet <ref>^{commit}` (`commit_named`); files through **one** batched `rev-parse --git-path`
   call per `stop()`, never a `.git/` path (a linked worktree's state lives elsewhere). Text files git wrote are read
   as bytes; a missing file is `None`/absent, an unreadable one is `Err(ReadFailed)` as `rebase_in_progress` does.
2. Progress is git's count: rebase `msgnum`/`end` (merge backend) or `next`/`last` (apply backend); `am` `next`/`last`;
   a cherry-pick or revert sequence = commits in `sequencer/head..HEAD` + 1, out of that plus the `todo` lines still
   to run (design fact 3 — check where the stopped command sits in `todo` after a conflict); a single pick or revert
   without a sequence: `None`. `Progress::new` failing (a file with nonsense) gives `None`, not an error.
3. `editor_steps_ahead`: true when a line left in the merge backend's todo (after the stopped one) is a `reword`/`r`,
   `squash`/`s`, or `fixup`/`f` with `-c`; comment lines ignored; the apply backend has no todo → false.
4. Every `Run` scripted with the sandboxed config `conflict-repo` already uses (no user config, git ≥ 2.32 gate).

## Acceptance

`crates/gitio/tests/operations.rs`, one test per line, each with the bug it catches in its name or a one-line comment:

- every `Run` reads its `Operation` with the ids `git rev-parse` gives for that ref (Merge, SquashMerge, Rebase,
  RebaseApply, RebaseInteractive, RebaseMerges → `Rebase` with `redoing_merge` set — not `Merge`, CherryPick,
  CherryPickRange, Revert, RevertRange, Am with the patch's subject and message); StashPop and a repository with no
  conflict → `None`;
- progress: a 3-step rebase stopped at step 1 then, after resolving and `git rebase --continue` inside the test, at
  step 2 (both backends); a cherry-pick range 1/3 then 2/3; a revert range likewise; `am` 1/3 then 2/3;
- `editor_steps_ahead` true for RebaseInteractive, false for Rebase and RebaseApply;
- identity: two reads of one stop give equal `id()`s; `--continue` to the next stop gives a different one; a refused
  `--continue` (a file still unmerged) gives the same one; `git rebase --edit-todo` that drops a later step keeps it;
- a linked worktree (`git worktree add`) stopped in a rebase reads its own `Rebase`, the main checkout reads `None`.
