## Behaviour

### The view (`SettingsView.vue`)

1. Below "Back" (unchanged), three sections with small headings, in this order: **Theme**,
   **Keymap**, **Settings file**. Same panel and column as today (`rounded-island bg-panel`,
   `mx-auto w-full max-w-3xl p-6`); the column scrolls when taller than the window, "Back" scrolls
   with it.
2. **Theme**: two buttons side by side, "Dark" then "Light", the current one pressed
   (`aria-pressed`, the filled look "Mark resolved" uses when ready; the other bordered). A press
   calls `setTheme`; the whole window recolours at once (earlier build).

### Keymap (`KeymapList.vue`, VU15 reason: "14 rows with a menu each; the view stays a layout")

3. One group per `KEYMAP_GROUPS` entry: the group title, then a row per action: its name
   (`ACTION_NAMES`), its keys as small bordered key labels (`keyLabel(key, navigator.platform)`)
   or a muted "None", and a muted line saying where it acts (`ACTION_PLACES`). A row whose keys
   differ from the defaults shows its name in the primary colour (WebStorm marks changed actions
   the same way, `ActionsTree` modified colour) — report the colour you used.
4. Each row is one focusable button-like element (Tab moves between rows; Up/Down move between
   rows too, as in WebStorm's tree). Click, Enter or Space on a row opens **WebStorm's edit menu**
   (`KeymapPanel.createEditActionGroup`, `KeymapPanel.java:749-788` under
   `/tmp/ij-diff/platform/platform-impl/src/com/intellij/openapi/keymap/impl/ui/`) anchored below
   the row:
   - "Add Keyboard Shortcut";
   - a separator, then per key "Change <label>…" and "Remove <label>" (yamt's "Change" is the
     owner's re-bind, #664);
   - when the action has more than 2 keys: a separator and "Remove All";
   - when its keys differ from the defaults: a separator (unless one already precedes) and
     "Reset Shortcuts".
     The menu is a real menu (`role="menu"`/`menuitem`), Up/Down/Enter/Escape work, a click outside
     or Escape closes it and returns focus to the row. "Remove …", "Remove All" and "Reset Shortcuts"
     call the store at once.

### Key dialog (`KeyRecorder.vue`, VU15 reason: "WebStorm's Keyboard Shortcut dialog")

5. "Add Keyboard Shortcut" and "Change <label>…" open a modal dialog like WebStorm's (DR6:
   `KeyboardShortcutDialog.java`, `ShortcutDialog.java`, `ShortcutTextField.java`):
   - title "Keyboard Shortcut"; the action's name on top (`ShortcutDialog.java`);
   - one key field without a caret, focused on open, showing the key being recorded; "Change"
     opens it prefilled with that key (`KeymapPanel.java:516-525`);
   - each key pressed together with its modifiers (`keyOfEvent`) replaces the shown key; a
     modifier alone changes nothing (`ShortcutTextField.processKeyEvent`);
   - Escape with no modifiers cancels the dialog; Enter with no modifiers confirms once a key is
     shown, otherwise it records Enter; Tab / Shift+Tab move focus out of the field;
   - a "+" button at the field's end opens a small menu "Set Enter", "Set Escape", "Set Tab",
     "Set Shift+Tab" (`ShortcutTextField.showPopup`/`getKeyStrokes`), so those keys can be bound;
   - below the field, while the shown key is used by another action, a live warning naming it
     ("Already used by: Find"; WebStorm's conflicts panel, `ShortcutDialog.setShortcut`); the
     action's own keys are not conflicts;
   - "OK" (disabled while the field is empty) and "Cancel". OK calls `addKey` or `changeKey`; the
     store asks the clash question itself when needed ("Move" / "Cancel").
   - The dialog's keys never reach a file or the window's undo (it is a dialog over the settings
     view; check that Ctrl+Z recorded in the field does not undo anything).
   - Focus returns to the row when the dialog closes.

### Settings file

6. A text field labelled "Settings file", prefilled with the path in use (`settings.read.path`;
   while `read` is null, empty and disabled), then "Use" (also Enter in the field) →
   `moveSettings(text)`, and "Default" → `moveSettings(defaultPath)`, disabled when the default is
   already in use. Escape in the field restores the path in use. On a failure the typed text stays
   and the problem bar says why (earlier build). A muted line under the field: "yamt reads this
   file again whenever its window gets focus."

### Toolbar

7. `MergeToolbar.vue`: one constant `const HISTORY_BUTTONS_SHOWN = false;` with a one-line
   comment saying why (the owner hid them for now, #662); Undo and Redo are filtered out of the
   rendered buttons by it; their entries, icons and emits stay. Ctrl/Cmd+Z/Y keep working.
