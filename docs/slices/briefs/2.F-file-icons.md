# Slice 2.F — file-type icons in the file list

Board v0 wave 2. Owner decision (plan §2 #39): file-type icons in the file list come from
vscode-icons (MIT) through the same `unplugin-icons` setup as the Lucide icons (#34). Today each
row shows a coloured badge with the upper-cased extension (`FileList.vue` `extension()`).

## Target

Owned: `frontend/src/ui/FileList.vue`, new `frontend/src/ui/fileIcon.ts` and `fileIcon.test.ts`.
Read-only: everything else — notably `ui/store.ts`, `ui/App.vue`, `ipc/**`, `main.ts` (another task
changes them now), `editor/**`, `style.css`, configs, `docs/**`, `.omp/**`, Rust. Needed elsewhere →
stop, `deviations_from_brief`.
Already added by the orchestrator: `@iconify-json/vscode-icons` 1.2.87 (devDependency, exact).
Non-goals: folder icons, icons anywhere but the file list, a tree view, theming the icons.

## Behaviour (what the user sees)

- Each row of the file list starts with the vscode-icons icon of its file type, 16 px, where the
  badge is today; the badge and `extension()` are gone. Everything else in the row stays (path,
  muted text and "resolved" mark for resolved files, selection colours).
- The icon is chosen from the file **name** first (`package.json`, `tsconfig.json`, `Dockerfile`,
  `.gitignore`, `README.md`, `composer.json`, `Cargo.toml`, lock files you find worth it), then the
  **extension**, case-insensitive (`.ts`, `.tsx`, `.d.ts` → the TypeScript-definition icon, `.js`,
  `.jsx`, `.mjs`, `.cjs`, `.vue`, `.php`, `.json`, `.css`, `.scss`, `.less`, `.html`, `.md`, `.yml`,
  `.yaml`, `.toml`, `.rs`, `.go`, `.py`, `.sh`, `.sql`, `.xml`, `.svg`, images, `.txt` — at least
  every language plan §2 #29 colours), else vscode-icons' generic file icon. Paths may have
  directories (`src/app/main.ts`): only the last segment counts.
- Files the editor cannot show (binary, deleted on one side, links) get the icon of their name like
  any other file.

## Contract

- `fileIcon.ts` exports one function from a path to the icon component, backed by one table (one
  source per fact, vision 2): name → icon, extension → icon, fallback. Icons imported as Vue
  components (`~icons/vscode-icons/<name>`), never `?raw` (that form is for `editor/`, #34).
- Every icon name you use exists in the installed `@iconify-json/vscode-icons` set (check its
  `icons.json`; a missing name fails the build).
- `FileList.vue` props and emits unchanged.

## Tests

Behaviour, not wiring:

- name beats extension (`package.json` gets the npm icon, not the JSON one); `.d.ts` beats `.ts`;
  extension match ignores case (`App.VUE`); a directory in the path is ignored; no extension, a
  dotfile without a table entry and an unknown extension all get the generic icon.
