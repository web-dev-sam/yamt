## The rule to implement (one place, `rangeAi.ts`)

- `loaded` is kept only when it is omp's replay of the thread's current session **and** its length equals the
  number of that session's answers the store holds. Anything else (a failed load, a failed replay check, a failed
  `addAiAnswer` write, a replay longer than the store) leaves the conversation unloaded or marked stale, so the next
  show loads it again.
- At load, every turn the replay holds beyond the stored answers is recorded (`load`'s loop) before the conversation
  is kept; a failed write stops there and the conversation is not kept.
- `canAsk` is false while a load runs or while the replay holds more turns than the stored answers.
- At a recorded end: the fast path appends `end.turn` only when the store's returned turn equals `loaded.turns.length`
  (an exact append); every other case loads again, and when that reload answers for this end, the answered turn object
  takes the store's turn position (so `liveTurn` is null and no Retry shows for an answer the thread already has).
