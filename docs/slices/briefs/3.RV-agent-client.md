## Acceptance

The design §10 "Window, node" list: the fold over recorded streams (thinking concatenated, steps by id pending →
running → done, a diff output, the answer = text after the last step, `cancelled` → stopped, an unfinished step →
`noResult`); the replay split into turns at each `user_message_chunk`; two sessions routed apart; a crash ends every
running turn once, then the next ask reloads before prompting with the replay dropped; a load "not found" →
`sessionGone`, any other error → `refused`; a failed prepare not cached; the command read at each process start; the
permission table (a command allowed; a delete inside allowed; a move whose destination is outside refused; no locations
and not a command → refused; options without `allow_once` → cancelled; never `allow_always`/`reject_always`);
`inside.ts` (a sibling prefix, `..`, a Windows drive in another case); `firstMessage` (known, unknown kept, repeated,
spacing variants). Recorded fixtures: `just record-agent`-style script (`frontend/scripts/record-agent.ts`) run once
against real `omp acp` in a checkout of `scripts/range-repo.sh` for the four cases `edit-and-command`, `cancelled`,
`load`, `permission-outside`, committed with `{{CHECKOUT}}`/`{{SESSION}}` substituted. Your tests kill the mutants on
your lines (Stryker, SP5).
