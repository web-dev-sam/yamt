## Contract (fixed)

- `Question` gains `{ readonly kind: "abort" }`; `questionText` gives exactly: title `Abort Merge`; message `Every
  resolution and every save in this merge will be lost, and so will unsaved edits. The repository goes back to how it was
  before the merge, and yamt closes.`; list none; note null; confirm `Abort Merge`; cancel `Cancel`.
- `Problem` gains `{ readonly action: "abort"; readonly cause: ProblemCause }`; `attempted` gives `Could not abort the
  merge`; `logProblem` logs `store.abort_failed` with the cause's fields; `clearProblemAbout` never clears it.
- The store exposes git's `merging` (written only by `refreshFiles` from `listed.merging`, `false` until the first list)
  and one action `abortMerge(): Promise<void>`.
- `FileList` shows the button only while `merging`; hover title and accessible name `Abort merge`; icon
  `~icons/lucide/git-pull-request-closed`; left of the list/tree toggle, same button styling, `@mousedown.prevent`; it
  emits `abort`; disabled while an abort runs and after a successful one. Pass `FileList` one value for the button's
  state (hidden / ready / running), not two booleans that can disagree (vision 4); its name is yours.

## Behaviour

1. Press → `ask({ kind: "abort" })`. Anything but `"yes"` → nothing else happens: no call, no problem, no state change.
2. `"yes"` → the button is disabled, `source.abortMerge()` is called once (through `attempt`).
   - Failure → `report(…, { action: "abort", cause })`: the problem bar reads "Could not abort the merge: " and git's
     message (cause `Git`) or the `MergeAborted` sentence; the button is enabled again; nothing else changes (files,
     opened views, notices, the screen).
   - Success → the button stays disabled; nothing else (the app is ending).
3. A press while an abort runs or after a success does nothing (no question, no call).
4. The button follows git's view: shown or hidden with each file list (start, focus); hidden with the file list.

## Tests (node, `ui/`)

Behaviour, not words or wiring: "yes" calls `abortMerge` once; "no" and Escape (dismissed) call nothing; a press while
the first abort runs asks nothing and calls nothing; a refusal sets the abort problem whose `problemText` is "Could not
abort the merge: " + git's message and leaves files and opened views as they were, and a later press asks again; the
button state follows `merging` across two lists (true → false). `just mutants` runs on your `ui/` lines: a dropped
`=== "yes"`, a missing disabled guard or a cleared problem must fail a test.
