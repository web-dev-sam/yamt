## Findings (quoted, with the decision)

- #458 (correctness, should): "The 'still active' guard misses a pending user open. Click Mark
  resolved, then click a not-yet-opened file B before the finish returns: `active` is still the
  finished file, so moveOn opens the next unresolved file C, and its newer `latestLoad` ticket throws
  away B's load. The window shows C, not the file the user clicked." **Decision:** move on only when
  the acted-on file is still active and no open was started since the action began (any open the user
  started meanwhile wins, shown or still loading).
- #459 (correctness, should): "'a finish of a file no longer shown does not switch files' still passes
  with the active guard deleted: the next unresolved file after a.ts is b.ts, which is already
  active." **Decision:** a list where the next unresolved file is a third file, plus a case where the
  user's open is still loading when the finish (and a take) returns; both fail without the guard.
- #461 (correctness, should) / #454 (boundary, should): the deleted-side view's rules "live in untested
  component computeds (Keep shown, Delete shown, the deletion line in the middle, Reset enabled only
  after a take)"; "`kept` uses `SIDES.find(side => side !== deleted) ?? null` for a fact that is total
  … A second copy of 'other side' already exists in choiceText.ts:58." **Decision:** a total
  `otherSide(side)` used by both, and one pure function (e.g. `deletedSideView(deleted, taken)` →
  what Keep, Delete, the middle line and Reset show) with a node test for each side × taken state;
  MergeView only binds it.
- #460 (correctness, should): "`keptShown` reads `summary !== null` as 'the controller exists'. A
  rebuild sets summary null and then non-null inside one watcher callback, so the watch never sees a
  change." **Decision:** key the apply on the state the view must reach (kept side taken and the
  middle still showing changes to apply), so any controller showing base after a Keep is corrected.
- #453 (boundary, should): "ChoiceView takes [the taken side] as a prop that App.vue computes with a
  Map lookup in its template, while MergeView reads useAppStore().taken itself." **Decision:** ChoiceView
  reads it from the store like MergeView; App.vue stops deriving it.
- #455 (boundary, should): "The store ref `remote` holds the merged-in RemoteName, but `remote` already
  names a Side literal and FileMergeData.remote is the remote side's text." **Decision:** rename to
  `remoteName` everywhere.
- #456 (nit): `column.column` → `gridColumn` in both views. #457 (nit): `filter(([taken]) …)` names a
  path `taken` → `takenPath` (or copy and `delete`).

`store.ts` must stay ≤ 300 lines (it is at 300): if the guard needs lines, move the unsaved-work and
close guard (track/untrack/unsavedFiles/mayClose/watchWindowClose) into its own module held by the
store, as the round-1 report proposed; name any new file in `deviations_from_brief`.
