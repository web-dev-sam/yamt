## Findings (verbatim from review)

1. **block #771** `frontend/src/ui/ToolbarMenu.vue:24` — [INFERENCE: not run in WebKit] The menu
   closes only on a `mousedown` outside it. FileList.vue:19 calls preventDefault on `pointerdown` at
   the file-list resize handle, which suppresses the compatibility `mousedown` (Pointer Events spec,
   implemented by WebKit), so a press there leaves the menu open while the list resizes. That breaks
   #58's "closes … on a press elsewhere". Fix: also close on a capture-phase `pointerdown` on the
   window, keeping the `mousedown` listener the WebDriver run needs (closing twice is harmless); the
   inside-the-panel check is the same.
2. **should #772** `frontend/src/ui/MergeToolbar.vue:141` — [INFERENCE: not observed] While a file
   loads (summary null), Mark resolved and the six icons are `disabled`. WebKit does not dispatch
   mouse events to disabled form controls, so a right-click on them opens no menu and the engine's
   own menu may show, against #58 "anywhere on the toolbar". Fix: add `disabled:pointer-events-none`
   to Mark resolved and to the icon buttons, so the press and contextmenu target the header, which
   opens the menu and keeps focus.
3. **should #773** `frontend/src/ui/MergeToolbar.vue:107` — [INFERENCE: macOS not exercised; dmg is a
   shipped bundle] On macOS, Ctrl+left-click fires `contextmenu`, but `barPressed` prevents the press
   only for button 2. A Ctrl+click on the empty bar, Mark resolved, an apply/undo/redo button or the
   gear therefore clears focus from the side pane, so the keyboard does not stay where it was. Fix:
   prevent the mousedown default when `event.button === SECONDARY_BUTTON || event.ctrlKey` (Ctrl+left
   has no use on the toolbar on any platform).
4. **should #774** `frontend/src/ui/toolbarButtons.test.ts:82` — The malformed-value cases pass even
   with parseJson's try/catch or the `Array.isArray` guard deleted: the resulting
   TypeError/SyntaxError is swallowed by useStorage's catch and the set stays empty. Such a mutant
   survives, although its visible effect is a false `toolbar.storage_failed` warning for a merely
   unreadable value. Fix: in the `test.each`, install `spyWarnings()` and also expect `warnings` to
   equal `[]`, so the reading rule must reject bad values itself instead of relying on the storage
   error path.
5. **nit #775** `frontend/src/ui/MergeToolbar.vue:156` — `@close="menuAt = null"` is the only inline
   assignment handler in ui/; every other handler names a function or emits. Fix: add
   `function closeMenu(): void { menuAt.value = null; }` next to `openMenu` and bind
   `@close="closeMenu"`.
