## Block

### #926 (boundary, block; `src-tauri/src/servers.rs:25`)

**Problem:** `servers::manage` builds `HostState` and also registers the app's page-load hook, so a function named for managed state now holds a hook Tauri keeps only one of: `Builder::on_page_load` replaces any earlier hook (tauri-2.12.1 app.rs:1854 `self.on_page_load.replace(..)`). Any later `.on_page_load` in `with_session`, `window.rs` (which owns the page lifecycle: close watch, page ping) or 3.Z would therefore turn off the reload cleanup without anything showing it, and the deviation says this wiring has no test because the mock runtime never fires page loads. A reload would then leave the previous page's servers running again (#913). This also repeats #906's complaint about a name that lies: the brief's #913 fix said to register the hook in `with_session`.

**Fix:** Have `servers::manage` only build and manage `HostState`. Register the hook in `with_session`, where `invoke_handler` is already set, e.g. `.on_page_load(|webview, page| servers::stop_runs_on_page_start(&webview.state(), page.event()))` with `stop_runs_on_page_start` made `pub(crate)`. Update the `servers.rs`/`commands.rs` lines in `src-tauri/AGENTS.md` to match.
