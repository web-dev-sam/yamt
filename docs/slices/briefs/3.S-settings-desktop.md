## Contract (fixed — exactly these public items)

```rust
// crates/settings (yamt-settings): dependencies serde, serde_json, specta, thiserror (all
// workspace); dev-dependency tempfile. No tauri, no yamt-* crate. `#![forbid(unsafe_code)]`.

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Serialize, Deserialize, specta::Type)]
#[serde(rename_all = "lowercase")]
pub enum Theme { #[default] Dark, Light }

/// What the window holds and sends: `keys` = action id → key strings, only for actions whose
/// keys differ from the defaults (the window knows the defaults; Rust never does).
#[derive(Clone, Debug, Default, PartialEq, Eq, Serialize, Deserialize, specta::Type)]
pub struct StoredSettings {
    #[serde(default)] pub theme: Theme,
    #[serde(default)] pub keys: BTreeMap<String, Vec<String>>,
}

/// `Some(keys)` replaces the action's entry (an empty list = the action has no key);
/// `None` removes the entry (the action is back on its defaults).
#[derive(Clone, Debug, PartialEq, Eq, Deserialize, specta::Type)]
pub struct KeysChange { pub action: String, pub keys: Option<Vec<String>> }

#[derive(Clone, Debug, PartialEq, Eq, Serialize, specta::Type)]
pub struct SettingsRead { pub path: String, pub default_path: String, pub stored: StoredSettings }

pub struct Places { /* private: default file, location file, home */ }
impl Places {
    /// `config_dir` = the platform's per-user config folder; files go in `<config_dir>/yamt/`.
    pub fn new(config_dir: &Path, home: &Path) -> Places;
    pub fn default_file(&self) -> &Path;
}

pub fn theme_at_start(places: &Places) -> Theme;   // Dark when anything is missing, unreadable or broken
pub fn read(places: &Places, current: &StoredSettings) -> Result<SettingsRead, Error>;
pub fn set_theme(places: &Places, current: &StoredSettings, theme: Theme) -> Result<SettingsRead, Error>;
pub fn set_keys(places: &Places, current: &StoredSettings, changes: &[KeysChange]) -> Result<SettingsRead, Error>;
pub fn relocate(places: &Places, current: &StoredSettings, to: &str) -> Result<SettingsRead, Error>;

#[derive(Debug, thiserror::Error)]
pub enum Error {
    ReadFailed { path: PathBuf, message: String },
    Broken { path: PathBuf, message: String },   // message names line and column, or the entry
    WriteFailed { path: PathBuf, message: String },
    NotAbsolute { path: String },
}
```

## Behaviour

### The file (`yamt-settings`)

1. **Places.** Default file `<config>/yamt/settings.json`; location file
   `<config>/yamt/settings-location` holding one line, the absolute path of the file in use. No
   location file → the default file is in use. The location file is read on every call (two yamt
   windows open on two repositories both follow a move).
2. **Format.** JSON, pretty-printed with a two-space indent and a final newline, so it reads well by
   hand: `{"theme": "light", "keys": {"apply": ["Mod-Enter"], "ignore": []}}`. `keys` is left out
   when empty. Entries yamt does not know (top level, or action ids inside `keys`) are kept and
   written back unchanged. Entry order: serde_json's default map order (no extra feature).
3. **Parsing.** Parse into a `serde_json::Map` first, so a syntax error reports line and column;
   then take `theme` and `keys` out with `from_value`, so a wrong type names its entry (`theme`
   must be `"dark"`/`"light"`; `keys` must map strings to lists of strings). Any of these →
   `Error::Broken` with the file's path. A missing `theme` or `keys` → its default.
4. **`read`.** Missing file → its folder (if missing) and the file are created from `current`
   (`theme` and `keys` exactly as given), then returned. Existing file → parsed and returned;
   **never rewritten** by a read, not even to reformat it.
5. **Changes** (`set_theme`, `set_keys`): read the file again first (missing → start from
   `current`); a broken file → `Error::Broken`, **nothing written**; otherwise replace only the
   entry concerned (`theme`, or per `KeysChange` the action's entry: `Some` sets it, `None`
   removes it) and write. So an outside edit to another entry survives, and two windows changing
   different entries both keep their change; the same entry: last write wins.
6. **Writing.** Write a temporary file in the same folder (`<name>.<pid>.tmp`), then rename it over
   the target; no temporary file is left behind, also on failure. When the file in use is a
   symlink (a dotfiles link), write to its resolved target so the link stays a link.
7. **`relocate(to)`.** `to` must be absolute, or start with `~/` (expanded with `home`); anything
   else → `NotAbsolute`, nothing changes. `to` equal to the default file → the default file is
   read (created from `current` when missing) and the location file is removed. Otherwise: an
   existing file at `to` → parsed (broken → `Broken`, the old location stays in force); a missing
   one → created from `current` (its folder too); a folder that cannot be written → `WriteFailed`,
   the old location stays in force. Only after that succeeds is the location file written. Returns
   the new file's read.
8. **`theme_at_start`.** The file in use's theme; `Dark` when the location file, the file or its
   `theme` is missing, unreadable or broken. Never creates or writes anything.
9. `SettingsRead.path` = the file in use, `default_path` = the default file, as display strings.

### The shell (`src-tauri`)

10. **Start.** In `window::open_and_wait`, after the app is built and before the window is: compute
    `Places` (no config folder → `Dark`, logged), `theme_at_start`, then build the window with
    `background_color(background(theme))` and an `initialization_script` that sets
    `data-theme="<theme>"` on the page's `<html>` element before the page's first frame. Find out
    whether `document.documentElement` already exists when WebKitGTK runs the script; if it may not,
    wait for it (for example a `MutationObserver` on `document`, disconnected once set). Keep the
    script a small `fn start_script(theme) -> String` with a unit test. The page's own CSS for light
    arrives in the next build; until then a light start shows the light native background, then
    the dark page — expected.
11. **Every settings command** applies the theme it returns to the native window background
    (`show_theme`), so a switch, a move to another file and a hand edit picked up on focus all
    recolour the window frame. A failed `set_background_color` is logged, not an error.
12. `IpcError` stays one tagged enum (IPC4); the new variants serialise with `kind`.

## Constraints

- `skill://rust-conventions` (owned types at the boundary, no `unwrap`/`expect`/`panic`, `for`
  loops over long iterator chains, no new dependency beyond the ones named, no `#[allow]`),
  `skill://ipc-contract` (IPC4, IPC5: commands ≤ 15 lines, no logic in `src-tauri`).
- No state in `src-tauri` for settings: every command computes `Places` and calls the crate.
- `scripts/arch-check.sh`: `yamt-settings` depends on no `yamt-*` crate and not on `tauri`;
  `yamt-app` may depend on `yamt-session` and `yamt-settings`. `scripts/map-check.sh`: read
  commands from every `src-tauri/src/*.rs`, not only `commands.rs` (the four new commands live in
  `settings.rs`). The map check will then ask for the four commands in the project map; the
  orchestrator adds them — say so in your report rather than editing `.omp/`.
- **Never touch the owner's real config**: every run of the app sets `XDG_CONFIG_HOME` (and `HOME`
  when needed) to a folder under `/tmp`. Never read or write `~/.config/yamt`.
