## Blocks to fix (verbatim, promoted ones included)

1. **#1645 / #1647 — an Edit box on a sent note** (`rangeDrafts.ts:94`, `RangeMessage.vue:162`): if Edit is open on a
   queued note and the user presses Send, the reply turns the note `pending`; `keepStored` keeps the edit draft because
   the message is still in the list, so the box stays next to "Pending on GitLab" with Save on, and Save can only fail
   with `MessagePending`. Fix: keep an `edit` draft only while its message is still changeable (in `isStored`'s
   `"edit"` case, check the changeable rule on the found message — move that rule so `rangeDrafts` does not import
   `rangeThreads`), and show the box only while the message is changeable. Test: open an edit on a queued note,
   `replace` with a list where that note is pending, expect the edit draft gone.
2. **#1646 (VU15) — the edit box copies the Post editor** (`RangeMessage.vue:162`): the inline box repeats
   `RangePostEditor.vue` (textarea, submit/cancel keys, a submit that is off when blank, Cancel, focus on open) and
   already differs from it (`rows`, background, `@mousedown.prevent`, focus timing); RangeMessage gains a second job.
   Fix: one in-place message editor used for both Post and Edit. It takes which draft it edits (`post` | `edit`), reads
   and writes that draft, supplies the field label and submit word, takes the submit-off state and its title, focuses
   on mount, and emits submit/cancel. RangeMessage only switches between it and the message text.
3. **#1648 (SP5) — `editKey` untested** (`rangeDrafts.ts:60-61`): one shared edit key would show one message's text in
   another's box and save it into the wrong note. Test: `writeEdit` on two messages in different threads, each edit
   draft returns its own text; then `writePost` on one leaves the other's edit draft unchanged.
4. **#1649 (SP5) — `some` → `every` untested** (`rangeDrafts.ts:95`): drafts would be kept only when their thread
   holds one message, so any list reply would close a Post box on an AI answer or an Edit box on a note with replies,
   losing the text. Test: a Post draft on a thread's AI answer and an Edit draft on that thread's note (a thread with
   several messages) both survive a delete elsewhere.
5. **#1650 (promoted) — the Edit/Delete-off rule lives in the component** (`RangeMessage.vue:52`): a send running,
   then the AI running in the thread, decided in the template's script with no node test; a second place offering
   Edit/Delete would copy it. Fix: a pure `noteChangeBlock(sending, threadAi)` (name yours) next to the changeable
   rule, with a node test for its order; RangeMessage calls it (Save's off state uses it too).
6. **#1651 (promoted) — two meanings of "edit"** (`RangeMessage.vue:47`): `editing` means the Post box is open and
   `PostAction` `"edit"` opens Post, beside the new Edit box's names. Fix: rename `editing` → `postOpen` (or the
   shared editor's own name) and `PostAction` `"edit"` → `"write"` in `rangeGitLab.ts` and its tests.
