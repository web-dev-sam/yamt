## Change (findings, then what to do)

1. [should, boundary, TS11] `internal/tone.ts:4` — four exports, and the center's
   "BothSame → local" rule hides in `CHANGED_SIDES[kind][0]` (chunkField.ts:45). Fix:
   `chunkTone(chunk, pane: "local" | "center" | "remote")`, center resolving to remote for
   `RemoteOnly` and local otherwise; `CHANGED_SIDES` and `Side` become private to
   `decorations.ts` (they are needed again by the next slice's bands — keep them easy to export
   later, but do not export them now); `tone.ts` exports `Tone` and `chunkTone` only.
2. [should, boundary, TS1] `internal/lineStart.ts:3` — `lineStart(doc, line: number)` takes an
   engine line as a bare number, and the from/to pair is written twice. Fix:
   `lineSpan(doc: Text, range: Chunk["base"] | Chunk["local"] | Chunk["remote"]): { from; to }`
   (rename the file to match) used at both call sites.
3. [should, boundary] `index.ts:19` — `const spans` holds a `StateField`; `createPane`'s new
   `chunks:` parameter holds an `Extension` while `chunks` two lines above is `Chunk[]`. Fix:
   rename the local to `field` and the parameter to `decorations`.
4. [should, boundary, CP1] `internal/chunkField.ts:51` — undo correctness depends on the _last_
   `restoreSpans` effect winning. Fix: `tr.effects.findLast(...)` with a one-line comment citing
   why (history merges events with the oldest inverted effects last —
   `@codemirror/commands` `HistoryState.addChanges`).
5. [should, correctness, CM1] `internal/chunkField.ts:33` — at an unterminated end of file a
   chunk's `to` is `doc.length`, the end of its last line, so typing at the end of that line or
   Enter + text lands outside the chunk. Fix: for a non-empty span whose `to` is not a line start
   in `tr.startState.doc`, map `to` with `+1`; keep `-1` for line-start `to` and empty spans. Test:
   `'a\nb'` with `{1,1}`, insert `'\nc'` at 3 ⇒ `[2,5)`.
6. [should, correctness] `theme.css:2` — one shared `--chunk-tone` per line: when a center edit
   puts an empty chunk's marker on another chunk's band line, the line takes whichever tone comes
   later in the file; a line with both markers loses one shadow. Fix: give the marker its own
   tone variable (separate classes for band tone and marker tone), and a rule that draws both
   shadows when a line carries both markers. Test the classes a line gets when a marker and a
   band of different tones share it.
7. [should, correctness, RK10] `internal/chunkField.test.ts:122` — undo covers one history event
   only; "last wins" would survive becoming "first wins"; redo is never exercised. Fix: delete
   `[5,13)`, then insert `x` at 5 in the same history event, undo once ⇒ original doc and ranges
   `[[5,13],[19,19]]`; redo ⇒ `[[5,5],[11,11]]`-equivalent with the deletion and `x` re-applied.
8. [should, correctness] `internal/chunkField.ts:45` — no test checks which side gives the center
   its tone; `chunk-deleted` is never asserted. Fix: a synthetic `RemoteOnly` deletion (base len 2,
   local len 2, remote len 0): center `chunk-deleted` band on both lines, right pane a deletion
   marker at the point, nothing on the left.
9. [nit, boundary] `internal/decorations.ts:17` — `chunk-gap-above`/`-below` reuse "gap" (the
   engine's grouping distance). Rename to `chunk-point-above`/`-below`.
