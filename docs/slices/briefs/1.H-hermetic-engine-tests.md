# Slice 1.H — engine tests ignore the runner's personal git settings (RK19)

Approved by the owner at the last rules review. The engine's tests build throwaway git repos.
Today a personal setting of whoever runs them — an attributes file saying `* -merge`, a global
ignore file, or config passed through environment variables — reaches those repos, so the same
tests can pass on one machine and fail on another. `scripts/golden-repo.sh` was already fixed
the same way; the test helper was not.

## Target

Owned: `crates/conflict-repo/**`, `crates/cli/tests/merge_file.rs`, `crates/cli/src/golden.rs`,
`crates/cli/tests/commands.rs`.
Read-only: everything else (`crates/gitio/**`, `crates/session/**`, `crates/merge-core/**`,
`scripts/**`, `docs/**`, `.omp/**`, `Cargo.*`, `justfile`).
Non-goals: any product behaviour change; gitio/merge-core tidy-ups; `scripts/golden-repo.sh`
(the orchestrator edits it).

## Contract (fixed)

`yamt-conflict-repo`'s public API does not change. Every git command the helper runs
(`isolated_git`, `crates/conflict-repo/src/lib.rs:49`) additionally:

- passes `-c core.attributesFile=/dev/null -c core.excludesFile=/dev/null`;
- removes `GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_COUNT` from its environment (config passed
  through the environment, #105).

`crates/cli/tests/merge_file.rs:138-142` builds its own git command the same way; give it the
same two `env_remove`s.

## Change

1. The isolation above.
2. A unit test in `crates/conflict-repo`: with `XDG_CONFIG_HOME` pointing at a temp dir whose
   `git/attributes` says `* -merge` and whose `git/ignore` says `*`, and with
   `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=merge.conflictStyle GIT_CONFIG_VALUE_0=zdiff3` set on
   the test process for that test only, `conflict_repo(…)` still produces an ordinary conflict
   (the file has standard `<<<<<<<`/`=======`/`>>>>>>>` markers with no `|||||||` base section,
   and `git ls-files -u` lists stages 1, 2 and 3). The test must not leak its environment to other
   tests (nextest runs each test in its own process; say how you made sure).
3. Ride-alongs (logged review findings for these files):
   - #104: rename `enough_generated_triples_are_clean_for_both_to_exercise_the_cross_check` in
     `merge_file.rs` to a name that says both things it asserts (e.g.
     `sample_is_often_clean_for_both_and_rarely_clean_only_for_yamt`).
   - #111: `crates/cli/src/golden.rs:82` — the `NotFound` guard survives mutation. Add a test in
     `crates/cli/tests/commands.rs` where a case's `expected.json` exists but cannot be read as a
     file (e.g. it is a directory) and assert `golden run` reports a read error for it, not
     "missing".
4. Run once at the end: `cargo clippy --workspace --all-targets -- -D warnings`,
   `cargo nextest run -p yamt-conflict-repo -p yamt-cli -p yamt-gitio -p yamt-session`,
   `cargo fmt --all --check`.

## Acceptance

- Step 4 exits 0; paste the tails with the new test names.
- The hostile-environment test fails without the isolation: remove the two `-c` options or the
  two `env_remove`s by hand once, run it, paste the failure, restore. (The mutation run that
  follows the wave cannot remove whole arguments, so this proof stays by hand.)
- `cargo mutants --in-diff` is run by the verifier afterwards; tests should kill the mutants on
  your changed lines.
