## Behaviour

1. **Keys** (#83 "Identity"): unique per detection (a test pins it, Vue's is not TypeScript's); unchanged when a second
   project brings the suffix or the command changes (tsc ↔ tsgo, installed ↔ not installed).
2. **Off, one place**: `apply` hands `setSpecs` only the found specs whose key is not in `offServers(settings, root)`,
   plus the added ones. So switching off stops a running server at once (problems cleared, exit logged), and an off
   server is never started by the question's "Start", by focus or at the next start. The start question lists only the
   shown servers and is not asked when none show.
3. **`switchServer(key, on)`** sends `setServerSwitch`, adopts the reply, then `apply`; a failed write changes nothing
   (the settings in use stay, the problem is shown as for every settings write).
4. **Settings → "Found in this repository"** lists every found server (never filtered); each row's name cell is a
   `<label>` around `<input type="checkbox" role="switch">` and the shown name (accessible name = the name, state
   on/off), checked when on; an off row's name is muted (`text-fg-muted`); the row's `:key` is the server key. The
   switch also shows and works while the answer is "Don't start" or not given.
5. **Pins** (#83 "Pins"): none at first; per root; a non-object or wrongly typed entry reads as none; other roots kept
   as written; a root left with none removed; with no root nothing is pinned and `togglePin` does nothing. Pins never
   look at `off`, so a server switched on again is pinned again. Nothing shows pins yet (row 7).
