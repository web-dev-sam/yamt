## Behaviour (settled; plan #65/#69 and the design)

1. **The key:** action `"save"`, name "Save", place "anywhere in the shown file", group "Anywhere in the file"
   (`keyText.ts`), rebindable in the keymap like every action. `MergeView.vue` handles it on `window` `keydown` next
   to `historyKeyInShownFile`: only when `props.shown`, no question is open, the Result is editable, the event is not
   `defaultPrevented`, and `pressesKey(event, bindings.save, platform)`; it calls `preventDefault()` (also in the find
   bar) and saves. Choice views and deleted-side views do nothing; a file that is not shown is never saved.
2. **`store.save`:** a write to the same path already in flight (`writing: Set<string>`, not reactive; `finish` and
   `reset` register in it too) → ignored. Otherwise `outcome = await handle.format()`, record it in `formatOutcomes`
   (a `null` handle result records nothing), then `snap = handle.snapshot()`; nothing to do when `null` or not
   `unsaved`; `text = file resolved ? snap.asShown() : snap.fileText()`; `source.saveFile`; `Written` → update `files`,
   `snap.markSaved()`, `clearProblemAbout`; `ChangedOnDisk` → exactly what `finish` does with it; an error →
   `report({ action: "save", … })` with its words in `problemText.ts`. Remove the path from `writing` in `finally`.
   A format outcome is recorded even when the write later fails. Whatever the format outcome, the save goes on.
3. **`fileText`** (pure, the design's rules table): decided spans as shown; a waiting `SideLines` change → its side's
   lines; a conflict with both sides waiting → `open`, local lines, `between`, remote lines, `close`; a half-decided
   conflict → markers whose decided section holds the Result's lines and the waiting side's section its own lines;
   `AsShown` → as shown; every line joined with the Result's own line separator (`state.lineBreak`), built with one
   `ChangeSet` over the document, no transaction (no chunk mapping, no CM8). A resolved file writes `asShown()`.
4. **The dot:** `MergeController` owns the saved point (the Result's `Text` and every change's statuses at open or at
   the last save); unsaved while the text differs (`Text.eq`) or, with equal text, any status differs; **also while
   typing sits inside a change whose sides all wait** (that typing is not written, plan #69). Undo back to the saved
   point clears it. `markSaved()` sets the point to the snapshot's state, so typing during the write keeps the dot.
   `finish` ("Mark resolved") takes a snapshot too, writes `asShown()` and calls `markSaved()` after `Written`.
   In the Result header, at the right end after "Reset": a small filled circle (`ml-auto`), palette tokens only,
   `title` and `aria-label` "Not saved".
5. **Close question** (`question.ts`): only when some opened file is unsaved: title "Unsaved Changes", message
   "These files have changes that are not saved to disk. Exit without saving them?", the files listed, buttons
   "Exit Without Saving" / "Cancel".

## Acceptance

1. Node tests, each naming its rule: `fileText` (the design's list: CRLF marker lines, a span at the end without a
   final line break, an insertion-point conflict, an empty side, `AsShown`, a resolved file, a half-decided conflict
   with typing in the decided section); `savedPoint` (type → dot, undo → none, ignoring a one-sided change → dot,
   apply + undo → none, typing inside a fully waiting change → dot stays after save); `store.save` (`Written` →
   `markSaved` and `formatOutcomes` set, `ChangedOnDisk` → notice and reload, in flight → ignored, no dot → no IPC
   call, format refusal → still saved, error → reported with its words); `closeGuard` asks only when unsaved; the key,
   key-text and question wording tests; fixture `saveFile`. Failing-path proofs for the editor rules.
2. WebKit on the fixture page (`pnpm -C frontend dev --port <own port>` + `just webdriver <own port>`; real keys and
   pointer; `skill://verification`): type in the Result → the dot shows; Ctrl+S → `fixture.save` logged with the
   text of the rules (paste it for a file with a waiting conflict: markers present) and the dot gone; Ctrl+Z after a
   save → dot back; Ctrl+S inside the find bar saves; Ctrl+S in a choice view does nothing; closing with unsaved work
   asks with the new words; screenshot of the header with the dot.
3. `pnpm -C frontend lint`, `typecheck`, `test`, `unused`, `fmt:check`, `sfc-order`: exit 0 (tails).
