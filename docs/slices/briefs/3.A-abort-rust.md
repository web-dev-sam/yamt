# Slice 3.A-abort-rust — `git merge --abort`, no merge held after it, the app ends with status 1

problem words for a failed abort are row 2; this slice changes the contract end to end — Rust, the generated bindings and

## Behaviour

1. **`merging`** is read on every `refresh()` (so every `list_files`, at start and on each window focus): `MERGE_HEAD`
   names a commit and `rebase_in_progress()` is false. A git failure while reading it logs a `tracing::warn!` and gives
   `false`; it never fails the list.
2. **`abort_merge`** locks the app's merge state and calls `MergeSession::abort_merge` once.
   - Git refuses or fails → `IpcError::Git { message }` (git's message, as every git failure); the merge stays held,
     every command works as before, the close ending is unchanged.
   - Success → the app holds **no merge** from then on: replace the managed `MergeSession` by a state that has none (a
     sum type, vision 4 — not a flag inside the session), then ask the app to end (`AppHandle::exit`, or destroying the
     window; say which and why). Return `Ok(())`.
3. **After an abort**, every command that reads or writes the merge — `list_files`, `load_file`, `describe_file`,
   `finish_file`, `save_file`, `reset_file`, `take_side`, `side_names`, `abort_merge` — answers `IpcError::MergeAborted`
   and runs no git and writes nothing. Settings, language-server and `log` commands are unaffected.
4. **The ending**: with a merge held, `ending_on_close` is as today. After an abort: exit status 1 (`Exit::Unresolved`)
   with the message `merge aborted` (printed `yamt: merge aborted`), and nothing is read or written — no `refresh`, so a
   file changed on disk after the abort is not staged. `stop_all` still runs first, as at every close.
5. Commands stay ≤ 15 lines and delegate (IPC5); `src-tauri` still depends on `session` only (PM1, `just arch-check`).
6. **Window side (`ipc/`)**: `toFileList` maps `merging`; `createTauriSource().abortMerge()` maps the generated
   command through `toResult` like the write commands; `sideNames()` rejects with an `Error` naming the failure's `kind`
   when the reply is an error (the existing `store.side_names_failed` log takes it). Fixture source: `listFiles` answers
   `merging: true` (the fixtures stand for a merge); `abortMerge` answers `{ ok: true, value: null }` and logs one info
   entry through the source's log (fixture mode cannot end the page; the app ends it). `ui/problemText.ts`: the cause
   `MergeAborted` reads `` `${attempted(problem)}: the merge was aborted.` ``.

## Tests

- gitio (real temp repositories, `crates/conflict-repo`): `abort_merge` after a staged resolution, a `git rm` and an
  unstaged change leaves `git status --porcelain` with only the untracked file and no `MERGE_HEAD`; the `MM` refusal
  returns `GitFailed` with status 128 and git's stderr, and `git status --porcelain` plus `ls-files -s` are identical
  before and after; `rebase_in_progress` false in a merge, true in a stopped `rebase` and in a stopped `rebase -r` on a
  merge commit (RK19: hermetic git as the existing tests).
- session: `refresh().merging` true in a merge; false in a cherry-pick stop, a rebase stop, a `rebase -r` merge-commit
  stop (`MERGE_HEAD` present), a `merge --squash` stop; false on the next refresh after `git merge --abort` ran outside.
- src-tauri (`mock_window`): after `abort_merge`, each merge command answers `{"kind":"MergeAborted"}`; a `save_file`
  sent after it leaves the file's bytes as git restored them; a file changed on disk after the abort is not staged by the
  ending (`ls-files -s` unchanged) and the ending is exit 1 with `merge aborted`; a refused abort (`MM`) answers `Git`
  with git's message, `list_files` still works and the ending is the usual one; a second `abort_merge` after a success
  answers `MergeAborted`. If the mock runtime cannot observe the end request, say so and cover it in Acceptance 3.
- ipc (`tauri.test.ts`, `fixture.test.ts`): `merging` mapped; `abortMerge` ok and its failure unchanged; a failed

- `just mutants` runs on your Rust and `ipc/`/`ui/` TypeScript lines: a dropped rebase check, a lost `merging`, a command
