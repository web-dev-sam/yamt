## What each option must answer

1. **Owner of the split**: one owner for the window (vision 2), its stored key and shape, validation (rule 5), who holds
   it, how every `MergeView` and `ChoiceView` reads it (the grid template from shares) without a copy per file.
2. **Divider element and hit area**: which element takes the press for each pane divider, its size and stacking, how
   strip presses (icons, icon drag, wave click, Ctrl/Cmd+click) still reach the editor's listeners, and where the
   dots go so they never cover a band, a wave join or an icon (rule 1). The file list's dots.
3. **Drag math** as a pure function tested on numbers: the dragged boundary moves, the third pane constant, the
   minimum (rule 3, cited), rounding so shares sum to one, a window too narrow for the stored shares.
4. **During a drag**: pointer capture, no text selection, the keyboard stays, the cursor over the whole window while
   dragging; what re-lays out per pointer move (three editors, strips, `WavePhases`), whether that needs a frame
   throttle, and the scroll-timing check (`.omp/run/scroll-timing.py`).
5. **Reset** on double-click (rule 4, cited), and both answers to rule 6 with their cost.
6. **Unchanged** (rule 7): why the locked scroll, bands, waves (#64), minimap (#81) and find bar need no change, or the
   change they need.
7. **Tests**: for each node unit test the plausible bug it catches; if `editor/` changes, the one-line hand mutation
   that makes each of its tests fail (`editor/` is not mutated, VF7). WebKit steps (fixture page, `just webdriver
   4448`) and real-app steps (`just app-session`, session names `h-…`) for every acceptance line.
8. **Builds**: files per build, changed-line estimate, disjoint ownership, the contract between them.
9. **Plan §2 #84**: a draft row (rule text, rejected alternatives, visions cited).
