## Blocks to fix (verbatim from the reviews; `.omp/run/findings.jsonl`)

- **#861/#866 (block) + #862 (promoted):** "The middle pane's phase is pinned for the period
  `P = D/(k+½)` (`connectors/index.ts:64`), but the mask draws a different period, `round(64·P)/64`. The
  difference builds up over the stretch and appears only at the middle's right edge (C|remote):
  `(k+½)·|64P − round(64P)|/64`, up to `(k+½)/128` CSS px … Two modules now decide the drawn period, and
  the node tests use the unrounded one, so they cannot see the gap." Fix: decide the drawn period once in
  `connectors` — move `MASK_PERIODS` (64) next to `wavePhase`, have `through` return the period the mask
  will draw (`round(64·P)/64`, so 64 waves are whole CSS px), and pin the offset at the **midpoint** of
  `enters` and `leaves` so each edge gets at most half the remaining drift. `foldView.ts` multiplies
  `var(period)` by 64 with no rounding rule of its own. Extend the `through` sweep: both edges met within
  `(k+½)/256` px using the returned period.
- **#867 (block):** acceptance misses at fractional edges (WebKit C|remote 1.04 at ratio 1, 1600, file list
  hidden; 1.18–1.29 at ratio 2, 1237, hidden). After the fix above, measure those two layouts again. If
  either still exceeds **1 device px**, round the measured edges to device pixels in the measurement
  (`Math.round(x · devicePixelRatio) / devicePixelRatio`) and measure again when the resolution changes
  (`matchMedia("(resolution: <n>dppx)")` change → re-measure); prove it in node with fake ratios.
  **Tolerance (plan #64, owner's ruling):** ≤ 1 device px in WebKit at ratios 1 and 2 — the engine of
  record, and WebKitGTK draws only whole ratios (plan §3); ≤ 1.5 device px in Chromium at 1.25 and 1.5
  (WebView2's stand-in), where the mask's vertical position snaps to device pixels while the joins are
  anti-aliased at sub-pixel heights.
- **#868 (promoted):** "No test covers how the DOM is mapped into a `WaveLayout` … the strip pair swapped,
  the host's rect read instead of `scrollDOM`'s, `Folds.destroy` not calling `#phases.destroy()`, or
  `destroy()` not disconnecting the observer." Fix: a pure `layoutOf(views, strips)` over
  `{ getBoundingClientRect }` fakes, tested in node (local is `strips[0]`, edges from `scrollDOM`); a node
  test that `WavePhases.destroy()` disconnects its observer and removes both properties (fake
  `ResizeObserver`).
- **#863 (promoted):** the mask comment says device pixels while the code rounds CSS pixels, and cites the
  slice id. Fix: name the condition (WebKitGTK draws at whole ratios only, plan §3) and point at plan §2 #64
  (or a WebKit bug), not at a slice.
- **#865 (promoted, in part):** `PANES` is written a third time. Fix: export it from `geometry.ts` next to
  `Pane`; import it in `wavePhase.ts` and `foldRuns.ts`.
