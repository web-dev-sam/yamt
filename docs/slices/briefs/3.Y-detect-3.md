## Behaviour

1. **Vue** (plan #72 "Vue"; design "Vue (V1)"): in a project whose TypeScript is 5.x/6.x (the `typescript-language-server`
   branch) and that has `node_modules/vue/package.json` up the folder chain: with `node_modules/@vue/typescript-plugin/
   package.json` up the chain, the TypeScript spec also serves `vue` and sends `initializationOptions: { plugins: [{
   name: "@vue/typescript-plugin", location: <the project folder's absolute path>, languages: ["vue"] }] }`
   (typescript-language-server's `docs/configuration.md`: `location` is a directory from which tsserver `require`s the
   plugin); without the plugin, an extra spec "Vue" (never started; `install` = the node hint with reason `vue`,
   package `@vue/typescript-plugin`, the project's manager and folder). In a TypeScript ≥ 7 or native-preview project
   with `vue`: the TypeScript spec carries the note `vueNeedsTypeScript6`. Once the plugin is installed and the window
   regains focus, the next detection drops "Vue" and the changed TypeScript spec restarts (check how `setSpecs` treats a
   changed spec; report).
2. **Phpactor's tools** (plan #72, #996): each integration is on only when the project has the tool's program
   (`vendor/bin/<tool>` in the project folder) and one of its configs there: PHPStan `phpstan.neon`, `phpstan.neon.dist`,
   `phpstan.dist.neon` → `language_server_phpstan.enabled`; Psalm `psalm.xml`, `psalm.xml.dist` →
   `language_server_psalm.enabled`; PHP-CS-Fixer `.php-cs-fixer.php`, `.php-cs-fixer.dist.php` →
   `language_server_php_cs_fixer.enabled`; phpcs `.phpcs.xml`, `phpcs.xml`, `.phpcs.xml.dist`, `phpcs.xml.dist` →
   `php_code_sniffer.enabled` (Phpactor's `doc/reference/configuration.rst`; check each key and config name there and
   report any difference). Phpactor formats only with PHP-CS-Fixer or phpcs on.
3. **pyright's venv**: when the project's virtualenv has a Python (`.venv`/`venv`, `bin/python` or
   `Scripts/python.exe`, place `Project`), pyright's settings are `{ python: { pythonPath: <its absolute path> } }`.
4. **`help`**: every detected preset spec that was found carries the hint it would have carried had it been missing
   (rust-analyzer found as rustup's stub → the rustup hint); `install` stays null.
5. **Settings list**: Deno (`deno lsp`; js jsx ts tsx mjs mts; formats; init `{ enable: true, lint: true }`, settings
   `{ deno: { enable: true, lint: true } }`) and bash-language-server (`bash-language-server start`; sh bash; formats)
   join the preset table as list-only (never detected). `presetChoices()` lists every preset's own server command in
   table order (TypeScript as `typescript-language-server --stdio`, eslint as `vscode-eslint-language-server --stdio`,
   PHP as two entries, Phpactor then Intelephense), each name once.
6. **Hand-added servers** (`added.ts`): one whose program's file name (folder and a Windows `.exe`/`.cmd`/`.bat` dropped)
   and arguments equal a preset's command gets that preset's name, settings, `initializationOptions` built for the
   repository root (`root`), formats rule ("never" stays never; otherwise true) and `help`; others as today. Every added
   spec looks for its program in every ecosystem's folders (project and home lists, de-duplicated, ecosystem table
   order). Names stay unique as today.
