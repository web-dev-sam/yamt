## Change

1. `editor/internal/pane.ts` `paneTheme`, `.cm-scroller`: `lineHeight: "20px"` (was `"1.4"`) and `backgroundColor:
   "var(--color-panel)"` (#60: whole device pixels per line at 1, 1.25, 1.45 via 2×, 1.5, 1.75, 2; Chromium keeps
   subpixel text in a composited scroller only over an opaque background). Check that nothing else assumes 1.4 or 18.2
   (strip icon offsets, reveal gaps, tests): fix what breaks, keep tests that use 18.2 as an arbitrary fractional height.
2. Selection, active line, chunk tints, word marks, removal bars, the drag highlight and the find bar still show over
   the now-opaque scroller (CodeMirror's selection layer has a negative `z-index` inside `.cm-scroller`'s stacking
   context; it must stay above the scroller's own background — verify, do not assume).
3. Other scrolling containers that hold text (file list, settings view, key list, choice view, anything with
   `overflow-*: auto|scroll`): give the scrolling element itself an opaque background where Chromium at device scale
   factor 1.5 turns its text grey. Measure first with the probe's harness (`/tmp/yamt-crisp/chromium/probe.mjs`,
   `analyze.py`; copy into your scratch dir and adapt); change only what measures grey.
4. The settings: `ipc` method, `ui/settings.ts` (`SettingsInUse`, `startSettings`, `storedSettings`, `sameStored`, `adopt`,
   the action), the store's forwarding as the others, and in `SettingsView.vue` a section "Antialiasing" between Theme and
   Keymap, **only when `navigator.platform` starts with `Linux`**: two buttons "Subpixel" and "Greyscale" styled and
   pressed exactly like the Theme buttons, and under them one muted line "Takes effect the next time yamt starts."
5. Tests (node project): `ui/settings.ts` — a read whose only difference is `antialiasing` is adopted; `setAntialiasing`
   sends the settings in use with the new value; `startSettings` starts on `"subpixel"`; fixture settings round-trip.
