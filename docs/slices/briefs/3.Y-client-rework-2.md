## Findings to fix

### #917 (correctness, block; `frontend/src/lsp/index.ts:67`)

**Problem:** Three of the six #897 survivors can be seen through the public API, so the #916 triage ('memory only,
not observable') is wrong for them. The mutants are `retired === server`, `(retired) => false` and `() => undefined`.
Each removes other retired servers that are still stopping as soon as one retired server finishes. `destroy()` then
resolves while a removed server is still in its shutdown, which breaks the brief's '#897: destroy keeps awaiting the
ones still in the list' and acceptance 3 (no new survivor). The only evidence is 'destroy waits for servers removed by
setSpecs' (index.test.ts:2040). That test calls `destroy()` before any halt has resolved, so the filter has not run
yet when `destroy` reads `#retired`, and the test passes with a wrong filter.

**Fix:** Add a test with two specs that both serve a.ts, only one with `ignoresStop`. Call `setSpecs([])`, then
`settle()` so the other one's halt finishes and the filter runs, then `destroy()`. Expect `destroyed === false` until
the `ignoresStop` server's `exit(0)`, and true after it. This kills `===`, `false` and `() => undefined`.

### #919, lsp half (boundary, promoted; `frontend/src/editor/internal/problems.ts:109`)

**Problem:** The rule for stale problem answers is split across the boundary. lsp's `DocProblems.push` drops a
version newer than the one sent; the editor drops an answer older than that server's last one. Plan #70 says the lsp
owns "one slot" per server for pushed and pulled problems.

**Fix (this round):** `DocProblems` never hands the editor an answer older than the last one it showed for that
document on that server (a late pull must not replace a newer push, and vice versa); a test pins it. The editor's
fix round then removes its own `version < last` check and relies on this guarantee.

### #920, lsp half (boundary, promoted; `frontend/src/editor/internal/problems.test.ts:12`)

**Problem:** The `DocVersion` brand rule (`Number.isSafeInteger(n) && n > 0`, lsp/internal/version.ts) is copied into
three editor tests as local guards, so versions are created outside their owner.

**Fix (this round):** export a guard `isDocVersion(n: number): n is DocVersion` from `lsp/index.ts` (built on
`version.ts`'s rule). The editor's fix round imports it in its tests.
