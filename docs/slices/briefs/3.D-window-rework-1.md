## Decisions (orchestrator)

- **#552 → each view passes its own disk version.** `MergeView` passes `props.data.diskVersion`,
  `ChoiceView` passes `sides.diskVersion` (as `finish` does already). Remove `shownVersion` and
  `notShown`.
- **#553 → `noticeCloseLabel(path)`** lives in `noticeText.ts` and is tested there.
- **#554 → `finishFile({ path, text, diskVersion })`** takes one object in `ChunkSource`, `tauri.ts`,
  `fixture.ts` and the store.
- **#555 → the read-only rule is stated once, in `MergeView`:**
  `editable = deleted === null && middle.kind !== "DiskNotText"`. It is passed down as
  `readOnly: !editable`, and `centerPane` only maps `DiskNotText` to an empty document.
- **#556 → reload every opened view after a successful take.** Drop the `fromDisk` branch.
- **#557 → rename `base` to `middle` in the editor test helpers and titles.** Keep `chunk.base` only
  where the generated shape needs it.
- **#559 (nit) → `ViewSources` carries `center: CenterPane`.** Revert the move.
- **#560 → `taken { by: "disk" }` comes from data, not from what is shown.**
  - On `Staged`, record it whenever the listed entry is unsupported or the file is a deleted-side
    file, shown or not, at start too.
  - A deleted-side view is resettable when `middle.kind !== "Stages"`.
  - Add a store test: a start change to a choice file that is opened later shows "Changed on disk —
    staged as it is." with Reset enabled.
- **#561 → add the add/add apply test** with the reviewer's exact chunks. Two Conflict chunks with
  empty middles: middle {0,0}/{19,0}, local {0,2}/{21,4}, remote {0,5}/{24,3}. Steps and checks:
  1. apply local on chunk 0 → its lines are at the top, and still 2 conflicts;
  2. ignore remote → 1 conflict;
  3. apply both sides of chunk 1 in append order → exact text.
- **#562 (nit)** → merge the duplicate `useMergeController` swap test into the existing one.
- **#558 (docs)** is the orchestrator's: project-map, ts-conventions and ipc-contract brands.

## Findings (verbatim)

- **#550** (boundary, block) `frontend/src/ui/store.ts:262` — Acceptance desktop item 2 is unproven. 'Applying a side did nothing' was judged only from the status staying at '2 conflicts'. But by #33 (status.ts:21-27, :64-67), applying one side of a two-sided conflict leaves the other side pending, so the conflict count cannot drop. The observation used the wrong check, and the middle text was never examined. *Fix:* Rerun observation 2 on /tmp/yamt-3dw-golden-tanstack-query-svelte-base-query. After one apply, read the middle's text and the arrow count (the applied side's arrow must disappear), then ignore the other side with × and check the status drops to '1 conflict'. Report both, or the real defect if the text did not change.
- **#551** (boundary, block) `frontend/src/editor/index.ts:1` — The acceptance line 'pnpm -C frontend test:browser exits 0' has no evidence: the WebKit probe never launched because host libraries are missing (libflite, libicu74). *Fix:* Have the verifier run `pnpm -C frontend test:browser` on a host with Playwright WebKit's dependencies (or after `pnpm exec playwright install-deps webkit`) and paste the tail.
- **#552** (boundary, should) `frontend/src/ui/store.ts:214` — notShown writes an English sentence ('<path> is not shown') in store.ts and passes it off as an `Unexpected` cause, which so far only carried thrown errors (problem.ts:19). This covers a state no view can reach: only a shown MergeView or ChoiceView can call takeSide or reset. *Fix:* Pass the version from the view, as finish already does (props.data.diskVersion in MergeView, sides.diskVersion in ChoiceView), so shownVersion and notShown go away. Since the brief prescribed the lookup, get the orchestrator's OK first; otherwise give the case its own cause kind worded in problemText.ts.
- **#553** (boundary, should) `frontend/src/ui/NoticeBar.vue:14` — The close button's accessible sentence 'Close the notice about <path>' is built in the component, while the map says notice words live only in noticeText.ts. *Fix:* Export `noticeCloseLabel(path)` (or put the label on the row helper) from noticeText.ts, test it in noticeText.test.ts, and use it in NoticeBar.
- **#554** (boundary, should) `frontend/src/ipc/ChunkSource.ts:15` — finishFile(path: string, text: string, diskVersion) now takes three positional parameters, two of them swappable strings, so swapping path and text compiles. *Fix:* Make it `finishFile({ path, text, diskVersion })` in ChunkSource, tauri.ts, fixture.ts and store.ts. tauri.ts still calls the generated `commands.finishFile` positionally.
- **#555** (boundary, should) `frontend/src/ui/MergeView.vue:62` — `editable` is derived from `centerLine === null` (which sentence is shown) rather than from the rule itself. The rule 'read-only when deleted or DiskNotText' now lives in three places: useMergeController.ts:62, pane.ts centerPane, and here. *Fix:* Write `editable` as `props.data.deleted === null && props.data.middle.kind !== "DiskNotText"` and pass `readOnly: !editable` through useMergeController, so the window states the rule once. centerPane then only maps DiskNotText to an empty document.
- **#556** (boundary, should) `frontend/src/ui/store.ts:262` — `fromDisk` reloads after a take only when the opened middle is not Stages. This silently depends on Rust's take resetting the view to the stages, so a reader cannot tell from the store why the Stages case is skipped. *Fix:* Reload every opened (deleted-side) view after a successful take, which drops the branch and the hidden assumption about Rust. Or extract a named predicate in views.ts (e.g. `showsDiskMiddle`) whose name states the fact.
- **#557** (boundary, should) `frontend/src/editor/internal/apply.test.ts:28` — After the cutover, the synthetic helpers still name the middle text and middle ranges `base` (apply.test.ts:28-50, decorations.test.ts:49-71, sides.test.ts:35-52). Test titles still say 'empty base range' (apply.test.ts:201, chunkField.test.ts:79), so readers see a base that no longer drives the editor. *Fix:* Rename the helper parameters and fields `base` → `middle` (keep the DTO's chunk.base only where the generated shape requires it) and retitle the two tests to 'empty middle range'.
- **#558** (boundary, should) `.omp/skills/project-map/SKILL.md:107` — Docs out of the slice's ownership drifted. The state table says `taken` is set only by takeSide and has no `notices` row, while architecture.md:434-436 has both. 'BaseLine … TS brands created only in ipc/domain.ts' (project-map:131, ts-conventions TS1, ipc-contract IPC3, architecture.md:367) names a brand that domain.ts no longer has: it now has MiddleLine and DiskVersion. *Fix:* Curator: add 'and by a disk change that staged a shown choice (diskChanges.ts)' to row 107, add a notices row (store.ts, written by diskChanges.ts, words in noticeText.ts), and replace BaseLine with MiddleLine (plus DiskVersion) in the TS-brand sentences.
- **#559** (boundary, nit) `frontend/src/editor/index.ts:52` — `ViewSources` was moved below `Layout` with no change, and #createViews now takes `centerSource` alongside a `data` whose `middle` it overrides. *Fix:* Revert the move, and make `center: CenterPane` a field of ViewSources instead of a second parameter.
- **#560** (correctness, should) `frontend/src/ui/diskChanges.ts:44` — taken {by:'disk'} is only recorded for files shown at the moment of the change, and start changes are applied before any file is opened. So a binary/choice file or a deleted-side file staged by the disk and opened later shows 'Take the left or the right version.' (or Keep/Delete) with Reset disabled, while its list mark says resolved; a file shown at the time instead gets 'Changed on disk — staged as it is.' with Reset enabled. *Fix:* Derive this from data rather than from whether the file was shown: record {by:'disk'} on Staged whenever the listed entry is unsupported, and make the deleted-side view resettable when data.middle.kind !== 'Stages'. Add a store test for a start change to a choice file opened afterwards.
- **#561** (correctness, should) `frontend/src/editor/internal/apply.test.ts:675` — The only window test of applying on a reopened chunk uses one chunk with a non-empty middle. Nothing covers the shape the desktop smoke hit: an add/add file reopened from the disk, with two Conflict chunks of empty middle at line 0 and mid-file. Nothing pins that a one-sided apply keeps the chunk counted as a conflict until the other side is applied or ignored, and that missing fact is what led to the wrong 'apply did nothing' report. *Fix:* Add a diskSeeded case with chunks middle {0,0}/{19,0}, local {0,2}/{21,4}, remote {0,5}/{24,3}: apply local on chunk 0 → its lines at the top and summarize() still 2 conflicts; ignore remote → 1 conflict; then apply both sides of chunk 1 in append order and check the exact text.
- **#562** (correctness, nit) `frontend/src/ui/useMergeController.test.ts:96` — The new test repeats the swap check the previous test already makes at lines 80-89 (edits, then a new data object, then unsaved() is false). *Fix:* Remove the new test, or merge its 'changed on disk' wording into the existing one.
