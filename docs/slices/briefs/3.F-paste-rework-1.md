## Blocks (verbatim)

**#1565 (boundary)** — `linuxPaste.ts:58`: "When focus moves to nothing, `document.activeElement` is `<body>`, and
`body.contains(pasted)` is true for every target. A slow answer can then still be pasted. Example: a hung owner answers
later, or the user clicks somewhere that takes no focus or moves to another file. The text is then dispatched on the old
editor's contentDOM, and CodeMirror's `handlers.paste` (`@codemirror/view` index.js:5167) inserts it at that view's
selection without checking focus. The brief's 'only if the target is still the focused element' rule does not hold
here. The tests miss it because `beforeEach` sets `activeElement` to `body`, and the lost-focus test only moves focus
to another element."

**#1571 (correctness)** — `linuxPaste.ts:65`: "The paste is sent again on the original `event.target`, which can be
removed from the page while the read is in flight even though the editor keeps focus. That target is the element at the
caret: a highlight `<span>` or a `.cm-line` inside CodeMirror. CodeMirror 6.43 rebuilds a line's marks from a cache
whenever that line's decorations change (index.js:2433 reuses any equal mark's DOM, and `destroyDropped` at :3511 drops
the rest). That happens when language-server problems arrive, a parse finishes, the compare window's differences arrive
after a settle, or the user types during the read. Once the target is detached, `activeElement.contains(pasted)` is
false at :58 and the paste is silently lost while the editor still has focus. Even if a detached target got past the
focus check, `eventBelongsToEditor` (index.js:4896) would walk up to `null` and ignore the event."

Fix for both: when the trusted paste arrives, record the focused element; deliver only if
`document.activeElement` is still that element and it is not `<body>` (nor `null`); dispatch on the original target
when it is still connected, else on the recorded focused element (the editor's contentDOM or the field). Tests: focus
moves to `<body>` before the answer → nothing dispatched; the target is detached before the answer while focus stays →
the paste is dispatched on the focused element (and a field gets `insertText`).
