## Findings (quoted, with the decision)

- #450 (correctness, should): "at scrollTop 0 a match on line 1 (and on most of line 2) stays under
  [the bar] … the bar covers about 85% of the right pane's width … The smoke's 'overlaps false' does not
  test this." **Decision** (plan §2 #44 says the current match is never hidden): while any pane's find
  bar is open, all three panes get the same extra space above their first line, the bar's height, so
  line 1 can scroll below the bar and the panes stay aligned (VS Code adds space on top the same way).
  Closing the last bar removes it. The smoke searches a word on line 1 and shows it below the bar;
  alignment is checked as in rework 1 (bar open, scrolled, closed).
- #451 (correctness, should): "`bulkApplySteps` switched to `chainedChanges` … but no test runs bulk
  apply on touching spans." **Decision:** an `apply.test.ts` case: the touching setup of
  `sides.test.ts` ("touching spans whose last deletes an unterminated final line"), bulk apply → text
  `a\nB`, spans equal to clicking each change, one undo restores the original.
- #448 (boundary, should): "`chainedChanges(target, spans, side)` takes `ChunkSpan[]` but must ignore
  their stale `from`/`to`/`status` … and it builds the same `setStatus.of(...)` that `bulkApplySteps`
  and `actionSteps` build a second time for the real transaction." **Decision:** it takes chunks and
  returns `{ changes, effects }`; the callers use those effects instead of rebuilding them.
- #449 (boundary, nit): `right: "16px"` and `calc(100% - 32px)` write one inset twice — if the inset
  remains, one named constant builds both.
