## The block (verbatim, finding #1575)

> `clipboardFence.ts` imports `FenceViolation` and `SourceFile` from `./fences`, and `fences.ts:7` imports
> `clipboardViolations` from `./clipboardFence`, so the two files now form an import cycle. PM5 says no import cycles,
> and the project's own fence counts type-only imports as edges: it builds its graph with `ts.preProcessFile`, and
> `fences.test.ts:185` shows a type-only import is a fence violation. The cycle passes today only because oxlint's
> `import/no-cycle` skips type imports by default (`ignoreTypes: true` in its configuration schema) and
> `readSourceTree` scans only `src/`. This is the first such cycle in the frontend, and the next fence split out of
> `fences.ts` would copy it.
>
> Fix: drop the import from `./fences`: make `clipboardViolations(path: string, texts: readonly string[])` return a
> local `type ClipboardViolation = { readonly rule: "PM8"; readonly file: string; readonly specifier: string; readonly
> reason: string }` (assignable to `FenceViolation`), and have `fences.ts:224` call `clipboardViolations(file.path,
> texts)`, so the only edge left is `fences.ts` → `clipboardFence.ts`.
