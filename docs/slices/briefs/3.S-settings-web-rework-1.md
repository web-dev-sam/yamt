## Findings (verbatim from `.omp/run/findings.jsonl`; the fix is the reviewer's unless noted)

1. **#682 block** (`ipc/keys.ts:36`, contract): the brief fixes `export type KeyName` as public
   surface for the next build, but KeyName is neither exported nor re-exported from
   `ipc/index.ts`. The stated reason, that knip fails on an export nobody imports, does not hold:
   package.json's knip config makes `**/*.test.ts` an entry, which is why ACTION_PLACES, imported
   only by keyText.test.ts, passes. → Export KeyName from keys.ts and re-export it from
   `ipc/index.ts`, then import it in `ipc/keys.test.ts` so knip sees a user.
2. **#683 should** (`ipc/keys.test.ts:79`): the DEFAULT_KEYS test cites sources this patch deletes or
   rewires (SIDE_KEYS gone, historyKey.ts and find.ts read DEFAULT_KEYS, indentWithTab gone). →
   Cite sources that still exist and are independent of DEFAULT_KEYS: the base commit
   (`sideFocus.ts SIDE_KEYS at 9b717cb`, `find.ts:269-284 at 9b717cb`) or plan §2 #54/#44/#35.
3. **#684 should** (`editor/internal/sideFocus.test.ts:4`): after the move it tests only
   `sideKeyCommands` from sideKeys.ts. → Rename it to `editor/internal/sideKeys.test.ts`; report
   the rename.
4. **#685 should** + **#691 should** (`ui/settings.ts:63/72`): `use()` replaces settings with a fresh
   object on every reply, so every window focus yields a new `preferences` value even when the file
   did not change (every opened file reconfigures four compartments in three panes), and key
   problems are reported again on every focus — overwriting another problem (e.g. a failed
   Finish), bringing a dismissed bar back, logging at error level again. → Keep `settings.value`
   and skip the report when `read.path` and `read.stored` equal those in use (compare the stored
   theme and the key texts); report key problems only when they differ from those in use. Store
   tests: a second identical load after `dismissProblem` leaves `problem` null and leaves
   `preferences` the same object.
5. **#686 should** + **#693 should** (`editor/internal/pane.ts:159-173`): three compartments are
   placed and reconfigured in pane.ts, the side-key compartment is placed in `editor/index.ts:164`
   and reconfigured through a callback into the controller; and no test exercises the reconfigure
   path behind `setPreferences` (a `showPreferences` that skipped the side panes, the theme or the
   find keys would pass every test). → Have `MergeController.setPreferences` dispatch the side-key
   reconfigure to the side views itself (drop the callback), and extract the effects per pane kind
   into a pure function (e.g. `preferenceEffects(kind, preferences)`), tested by applying them to
   a center and a side state: `EditorView.darkTheme` flips, side "a" binds, find F10 binds, middle
   undo moves to Alt-Backspace. Watch `editor/index.ts` ≤ 300 lines (move, never compress).
6. **#687 nit** (`ui/settings.ts:63`, VU13): `use` is not a composable, yet `use*` marks composables
   in ui/. → Rename (`adopt` or `applyRead`).
7. **#688 nit** (`ipc/fixtureSettings.ts:4`, TS16): `FixtureSettings` is exported but unused
   outside. → Drop the `export` or inline the return type.
8. **#689 should** (`editor/internal/pane.ts:153`, CM3): every middle binding, Indent and Outdent
   included, has `preventDefault: true`; in a read-only Result pane `indentMore`/`indentLess` refuse
   but the default is still prevented, so Tab no longer moves focus out (the old `indentWithTab`
   had no preventDefault). → `preventDefault` only on undo/redo; indent/outdent without it. Test:
   a read-only center's Tab binding leaves the key unhandled.
9. **#690 should** (`editor/internal/pane.ts:180`): when Undo/Redo are bound away from Mod-z, nothing
   binds or prevents Mod-z in the middle; WebKit's native undo fires `beforeinput` `historyUndo`,
   and `history()`'s own handler turns it into a CodeMirror undo (`@codemirror/commands`
   dist/index.js:267-271), so Ctrl+Z still undoes there. → A `Prec.highest`
   `EditorView.domEventHandlers({ beforeinput })` in the center that prevents and handles
   `historyUndo`/`historyRedo`, so undo comes only from the bound keys and the toolbar. Check
   first in WebKit (fixture mode is enough: with the default keys, type text in the middle and
   watch for `beforeinput` `historyUndo` on Ctrl+Z, `execute` to read) and say what you saw.
10. **#692 should** (`ui/settings.ts:78`): settings replies are applied in arrival order; a
    focus-triggered `loadSettings` resolving after a later `setTheme`/`setKeys`/`moveSettings`
    reply puts the older file state back; `editKeys` plans before the clash question and sends
    after it, even if a focus reload changed the bindings meanwhile. → A call counter like
    `State.latestOpen`: apply a reply only when no later settings call has started; in `editKeys`,
    plan again on the current bindings after the answer. Store tests for both.
11. **#694 nit** (`ipc/keys.ts:121`): `parseKey` accepts Shift before a non-letter character
    ("Shift-1", "Shift-?"), which `keyOfEvent` never produces. → Refuse it; add both to the
    refusal test; `bindingsOf` reports them unreadable.
12. **#695 nit** (`ui/store.test.ts:1686`): the fake `setKeys` replaces the whole key map instead of
    Rust's per-action merge. → Merge per action as `crates/settings` does, or back the store test
    with `createFixtureSettings()`.
