## Decisions (orchestrator as product owner; these fix the open shapes in the findings)

1. **Escape (#966/#974).** `Asking.ask(question)` resolves `Reply = "yes" | "no" | "dismissed"` (export the type from
   `asking.ts`); `answer(yes: boolean)` stays; new `dismiss()` resolves the waiting question with `"dismissed"`. `ask`
   while another question waits resolves `"dismissed"` at once (it was `false`). Every caller migrates in this round:
   `closeGuard.ts`, `saving.ts` (`finish`), `settings.ts` (key clash) compare `=== "yes"`, so Escape on those questions
   still means their cancel; their test fakes return a `Reply`. The store's `dismissQuestion` is `state.asking.dismiss`
   (App.vue's binding keeps its name). serverSetup loses `dismissals`, `dismissQuestion` and the
   `question.value !== null` pre-check; `"dismissed"` maps to "no answer stored". The asking rules get their own
   node test (`asking.test.ts`): Yes, No, Escape, and a second `ask` while one waits.
2. **One home for server words (#967).** `serverText.ts` exports `projectLabel(folder)`: `""` reads
   **"the repository root"**, otherwise `folder/`. `installText`'s folder line uses it ("In the repository root:",
   "In frontend/:" as today), and so do the question's lines ("— the repository root") and Settings. One
   not-installed string lives in `serverText.ts`; the status line ("Not installed"), Settings and the question
   ("TypeScript (not installed)") derive from it. `question.ts` keeps only question wording.
3. **One owner for the start and focus sequences (#968).** `SetupTarget` gains `loadFiles`, `refreshFiles`,
   `loadSettings`. `ServerSetup` replaces `setUpServers`/`findServers` with `startUp(): Promise<void>` (the file list
   and the settings, then detection and the question) and `refocus(): Promise<void>` (refresh the list and the
   settings, then detect again; detection only once `startUp` has run). `main.ts` calls `void store.startUp()`;
   App.vue's focus watch calls `void refocus()` and nothing else. In fixture mode both still load/refresh files and
   settings.
4. **Halting without a user stop (#969).** `LanguageServers.haltAll(): void` halts every server's run without marking it
   stopped by the user; specs and `startOnOpen` are unchanged, so a later `setSpecs(..., { startOnOpen: true })` starts
   them again on open, and a server the user stopped stays stopped. `lsp/index.test.ts` proves both.
5. **The answer in force (#973 with #969).** `answer()` writes, then applies what the settings now hold
   (`storedAnswer`), like `changeAdded`. It calls `haltAll()` only when this click changed the stored answer to
   `"dontStart"` (stored before ≠ `"dontStart"`, stored now = `"dontStart"`); a failed write changes nothing in the
   window. The `setSpecs([])` call and its comment go.
6. **#975:** `started` is set once `startUp` has run, whether or not its look succeeded; focus then looks again and
   never asks.
7. **#976:** a file type that still contains a dot after the leading dots are dropped gives `null` (Add stays
   disabled).
8. **#970:** `settingsActions(state)` is built once in `createAppStore` and handed to both `actions` and
   `createServerSetup`. store.ts stays under its 300-line cap.

## Findings to fix

### #966 (boundary, block; `frontend/src/ui/serverSetup.ts:167`)

**Problem:** Escape now runs through `serverSetup.dismissQuestion` for every question, including exit, clash and unprocessed (App.vue:101 → QuestionDialog `dismiss`). serverSetup works out that a question was dismissed by comparing a `dismissals` counter before and after an `await` (:91-96). It also copies asking's one-question-at-a-time rule (:88 repeats asking.ts:19), because asking's `false` cannot be told apart from Don't start. So the waiting question is ended by two modules, and the dialog's general behaviour is tested in serverSetup.test.ts:330 ('Escape on another question still means its cancel'). Growth: the next question that has to tell Escape apart from No must either go through the language-server module or add another counter, and asking.ts no longer owns how its questions end.

**Fix:** Have asking.ts answer with three outcomes, for example `ask` resolving to `"yes" | "no" | "dismissed"` plus a `dismiss()` (existing callers map `"yes"` to true). Wire `dismissQuestion: asking.dismiss` in store.ts and delete `dismissals`, the `question.value !== null` pre-check and the dismissal tests from serverSetup. The orchestrator has to grant asking.ts, which is outside `Owned`.

### #967 (boundary, block; `frontend/src/ui/question.ts:31`)

**Problem:** `projectLabel` copies how a project folder reads, which serverText.ts:147 (`installText`) already decides ("" → the repository root, otherwise `folder/`). Settings now takes this server label from the question-words module (LanguageServerSettings.vue:7,64). The words for a server that is not installed now exist three times: question.ts:36 "(not installed)", LanguageServerSettings.vue:32 "not installed", and serverText.ts:81 "Not installed". The map puts every server word in serverText.ts. Growth: changing how a folder or a missing server reads means finding and editing two or three modules, and they will drift apart.

**Fix:** Move `projectLabel` and one not-installed label into serverText.ts. Use `projectLabel` inside `installText`'s folder line. Have question.ts `serversText` and LanguageServerSettings.vue import both from serverText.ts.

### #968 (boundary, should, promoted; `frontend/src/ui/App.vue:44`)

**Problem:** Three places each own a piece of the start and focus flow. The rule 'detect after the file list and the settings are in' is written once for start in main.ts:16 and again for focus as `await Promise.all(...)` then `findServers()` in App.vue:44-49. serverSetup.ts:112/116 adds a `started` guard on top. App.vue is supposed to be a composition surface with no feature logic. Growth: a new input to detection has to be awaited in both main.ts and App.vue, and App.vue keeps picking up flow logic.

**Fix:** Give serverSetup's target `loadFiles`, `refreshFiles` and `loadSettings`, and expose `start()` and `refocus()` that do the ordering themselves. main.ts calls `store.start()` and App.vue's watch calls `refocus()`, so the ordering and the `started` guard live in one module.

### #969 (boundary, should, promoted; `frontend/src/ui/serverSetup.ts:126`)

**Problem:** Don't start stops the running servers by calling `setSpecs([])` first. That only works because of how the private `LanguageServers.#create` carries `userStopped` across a reconcile, and the comment quotes that private member. lsp offers no named operation to stop servers without marking them as stopped by the user. Growth: a refactor of lsp's private carry-over silently changes Don't start, and the next caller that needs the same thing has to copy the two-call trick.

**Fix:** Have lsp provide the behaviour, for example `setSpecs(specs, { startOnOpen: false })` halting live runs without `userStopped`, or a `halt()` (needs a grant, lsp is read-only here). Then `answer` calls only `apply`, and the comment goes.

### #970 (boundary, should, promoted; `frontend/src/ui/store.ts:143`)

**Problem:** `settingsActions(state)` is built twice: once in `actions()` (:180) and once for `createServerSetup` (:143). Growth: today the two copies only share `state.latestSettings`. If `settingsActions` ever holds its own state, such as a ticket or a pending edit, the store and serverSetup will quietly use separate instances.

**Fix:** Build it once in `createAppStore` (`const settingsActs = settingsActions(state)`), spread it into the store and pass it to both `actions(state, buttons, settingsActs)` and `createServerSetup`.

### #973 (correctness, block; `frontend/src/ui/serverSetup.ts:123`)

**Problem:** `answer()` applies the new choice even when `setServerAnswer` fails. Failures are real here: a broken or unwritable settings file gives `SettingsBroken`, and `send` in settings.ts:208-221 reports the error and returns without throwing. So when the user clicks "Don't start" in Settings, the servers stop, but the button stays on "Start", and at the next window focus `findAgain` applies the stored "start" (line 119) and starts them again. A failed "Start" does the reverse: servers run while the button says "Don't start". Every other settings action changes nothing in the window after a failed write. `changeAdded` (line 139) follows that rule by applying `storedAnswer`, so this is a second, conflicting copy of the rule for which answer is in force.

**Fix:** After the write, apply what the settings now hold, the way `changeAdded` does: `const now = storedAnswer(setup)`, call `setSpecs([], …)` only when `now === "dontStart"`, then `apply(setup, now)`. Add a serverSetup.test.ts case where the fake `setServerAnswer` leaves the settings unchanged and expect the servers' states to stay as they were.

### #974 (correctness, block; `frontend/src/ui/serverSetup.ts:168`)

**Problem:** Escape for every question now goes through the server set-up. App.vue sends QuestionDialog's `dismiss` to the store's `dismissQuestion`, which belongs to `ServerSetup`. It bumps a `dismissals` counter in serverSetup and calls `asking.answer(false)`; `ask()` (lines 93-97) then compares counters to tell Escape from "Don't start". The state table says `ui/asking.ts` owns the question waiting for an answer, but this lifecycle state now lives in a second module. The unsaved-changes, key-clash and Mark-resolved questions (exit/clash/unprocessed) depend on serverSetup for their Escape, and the next question that needs Escape to differ from cancel would need another counter.

**Fix:** Give `asking.ts` a `dismiss()` and let a question resolve to dismissed, for example `ask` resolving `true | false | null` behind a small wrapper for the existing boolean callers. Bind QuestionDialog's `dismiss` to it, then delete `dismissals` and `dismissQuestion` from serverSetup. This needs asking.ts added to Owned.

### #975 (correctness, should, promoted; `frontend/src/ui/serverSetup.ts:103`)

**Problem:** If the start `look` fails (`host.context()` or a detection IPC call rejects), `setUp` returns before `started = true`, so every later `findServers` does nothing for the rest of the run. That breaks #70's "looked for again whenever the window regains focus" after a single transient IPC failure. Today it is reachable only when the IPC itself rejects, because the Rust commands cannot fail. The test at serverSetup.test.ts:394 pins the start behaviour but has no focus case. As the app grows, any fallible lookup added to detection would inherit this one-strike rule without anyone noticing.

**Fix:** Separate "the start flow has run" from "the start look succeeded": set `started` in a `finally` (or before the early return), so focus looks again without ever asking. Add a test where the first context call fails and a later `findServers` finds the servers stopped and asks nothing.

### #976 (correctness, should, promoted; `frontend/src/ui/serverSetup.ts:45`)

**Problem:** `parseAddedServer` keeps file types with an inner dot (`d.ts`), and serverSetup.test.ts:575 pins that as correct. But `extensionOf` in lsp/internal/spec.ts:24-27 returns only the part after the last dot, so such a type can never serve a file, and the Settings row looks valid while doing nothing. Nothing else builds on this.

**Fix:** Return null for a file type that still contains a dot after the leading dots are dropped, so Add stays disabled, and change the `d.ts` assertion to expect null.
