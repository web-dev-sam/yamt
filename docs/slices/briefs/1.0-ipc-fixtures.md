# Slice 1.0 — generated types, fixture source, real conflicts in the window

The engine (Rust) is done. This slice connects it to the window the cheap way: the Rust types
are exported to TypeScript (`bindings.ts`), the engine's output for the 10 real conflicts is
committed as JSON (`frontend/fixtures/golden/<case>.json`, made by `just fixtures`), and the
window lists those 10 files and shows the selected one's three texts. Chunk colours, connectors
and apply buttons are later slices; this one makes real data arrive.

## Contract (fixed; you may add, never change)

Rust (`src-tauri`): `bin/export-bindings.rs` registers `yamt_session::FileEntry` and
`yamt_session::FileMergeData` (specta pulls in `Chunk`, `ChunkKind`, `ChunkId`, `LineRange`,
`BaseLine`, `LocalLine`, `RemoteLine`, `Eol`, `FileStatus`, `UnsupportedReason`). `Ping` is
deleted, with anything that only existed for it. No other Rust change.

`frontend/src/ipc/` (architecture §4, `skill://ipc-contract`):

```ts
// domain.ts — the only place brands are applied (IPC3)
export type BaseLine = number & { readonly __brand: "BaseLine" };
export type LocalLine = number & { readonly __brand: "LocalLine" };
export type RemoteLine = number & { readonly __brand: "RemoteLine" };
export type ChunkId = number & { readonly __brand: "ChunkId" };
export type LineRange<L> = { readonly start: L; readonly len: number };
export type Chunk = {
  readonly id: ChunkId;
  readonly kind: ChunkKind;
  readonly base: LineRange<BaseLine>;
  readonly local: LineRange<LocalLine>;
  readonly remote: LineRange<RemoteLine>;
};
export type FileMergeData = {
  readonly path: string;
  readonly base: string;
  readonly local: string;
  readonly remote: string;
  readonly eol: Eol;
  readonly language: string | null;
  readonly chunks: readonly Chunk[];
};
export function toDomain(dto: Generated.FileMergeData): FileMergeData;
// ChunkKind, Eol, FileEntry, FileStatus, UnsupportedReason carry no brand: alias the generated
// types (one definition, vision 2), do not retype them.

// ChunkSource.ts
export interface ChunkSource {
  listFiles(): Promise<FileEntry[]>;
  loadFile(path: string): Promise<FileMergeData>;
  finishFile(path: string, text: string): Promise<FileEntry[]>;
  resetFile(path: string): Promise<FileMergeData>;
}
```

- Brands are applied without `as` (TS4 allows `as` only in `fixture.ts`): a type guard per
  space that accepts a non-negative safe integer; `toDomain` throws an `Error` naming the field
  when one fails. If this proves impossible, stop and report instead of widening the `as` rule.
- `fixture.ts`: the fixture source over `frontend/fixtures/golden/*.json` (Vite
  `import.meta.glob`, eager). Each file is parsed with valibot into `Generated.FileMergeData`,
  then `toDomain`. The schema is typed against the generated DTO so that a field added,
  removed or renamed on the Rust side fails `pnpm typecheck` (prove this by hand once, report
  the error line, revert). Parsing is testable on in-memory records (no glob in the test path).
  A malformed fixture throws an `Error` naming the fixture file.
  - `listFiles()`: one `FileEntry` per fixture, sorted by path, `unsupported: null`, status
    `Resolved` once finished, else `Unresolved`.
  - `loadFile(path)`: the parsed data; an unknown path rejects with an `Error` naming it.
  - `finishFile(path, text)`: keeps `text` in memory, marks the file `Resolved`, logs
    `fixture.finish` with `path` and `text`, returns `listFiles()`.
  - `resetFile(path)`: forgets the finished text, marks `Unresolved`, returns the original data.
- The one app logger: `createLog()` (no forward in fixture mode) lives in `ipc/` and is what
  `ui/` and `fixture.ts` log through (IPC8). `log.ts` itself only changes if this needs it.
- `index.ts` is the public surface; `ui/` imports only from it (IPC2). Export only what has an
  importer today (TS16, `pnpm unused`); brands that only `editor/` will need are exported when
  `editor/` imports them.

`frontend/src/ui/` (`skill://vue-conventions`, architecture §5.4):

- `store.ts`: `createAppStore(source: ChunkSource)` (called once in `main.ts`) and
  `useAppStore()` (components; throws if called before `createAppStore`). Holds the file list,
  the active path, and the active file's `FileMergeData` in a `shallowRef` (the immutable
  load payload; the editable text lives only in CodeMirror — this is how VU10 is read here).
  Actions: load the file list and open the first file; open a path. **A later open wins**: a
  slower earlier load must not replace a newer selection. A failed load logs
  `store.load_failed` (path, reason) and leaves the current file open. A successful load logs
  `file.loaded` with `path` and the chunk count (the smoke recipe looks for it).
- `FileList.vue`: renders the store's files, marks the active one, emits `select` on click;
  `App.vue` wires it to the store (VU16). Keyboard navigation: not in this slice.
- `MergeView.vue` / `useMergeController.ts`: today they take the editor's `MergeTexts`
  (`{local, base, remote, language}`); the domain `FileMergeData` is assignable to it, so pass
  it as is. Handle "nothing loaded yet". Renaming `MergeTexts` is the next editor slice.
- `ui/sample.ts` is deleted (clean cutover; the window no longer shows the stand-in sample).

## Change

1. Rust: register the two types, delete `Ping`; `just bindings`; read the generated file.
2. `ipc/`: `domain.ts`, `ChunkSource.ts`, `fixture.ts`, `index.ts` as above.
3. `ui/` + `main.ts`: store, `FileList` selection, `App` wiring, delete `sample.ts`.
4. Tests, Vitest `node` project (`src/ipc/**/*.test.ts`, `src/ui/**/*.test.ts` are included):
   - the committed fixtures load: 10 files, sorted, all `Unresolved`; each file's chunk count
     equals its JSON's; one exact chunk arrives intact — `vueuse-use-magic-keys.ts` has a
     `Conflict` with base `{start:128,len:10}`, local `{128,8}`, remote `{140,14}`;
   - malformed records are rejected naming the file: unknown chunk kind, negative line,
     non-integer `len`, missing `chunks`;
   - finish → `Resolved` + one `fixture.finish` log; reset → `Unresolved` + original data;
   - store: `open(b)` issued after `open(a)` wins when `a`'s load resolves last (a fake
     `ChunkSource` with promises you resolve by hand); the first file opens after loading the
     list; a rejected load keeps the previous file and logs `store.load_failed`.
     Each failing-path test must fail if the behaviour it guards is removed: break it by hand
     once (e.g. drop the "later open wins" guard), watch the test fail, restore, and report it.
5. Run once at the end: `cargo clippy -p yamt-app --all-targets -- -D warnings`,
   `just bindings-check`, `pnpm -C frontend lint && pnpm -C frontend typecheck && pnpm -C frontend test && pnpm -C frontend fmt:check && pnpm -C frontend unused && pnpm -C frontend sfc-order`.
