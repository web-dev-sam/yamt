## Behaviour

**A. Deleted on one side, other side text** (#47).

- When one side is deleted and the kept side and base (absent base = empty) are UTF-8 text within the
  size limit, and none of them is a symlink or submodule, the file is no longer unsupported:
  `FileEntry.unsupported` is `null` and `load_file` returns `FileMergeData` with a new field
  `deleted: Side | null` (Rust `Option<Side>`) naming the deleted side. The deleted side's text in it is
  the base text, so every chunk is a change of the kept side against base; `eol` as today.
- Every other file has `deleted: null`. A kept side (or base) that is binary, not UTF-8, too large, a
  link or a submodule stays exactly as today (`unsupported: LocalDeleted | RemoteDeleted`).
- `take_side`, `reset_file` and `describe_file` work on such a file as they do today for a
  deleted-on-one-side file (Keep writes and stages the kept side; Delete removes it from index and
  worktree; reset brings the stages back and leaves the worktree as it is). `finish_file` keeps its
  generic behaviour.

**B. Resolved marks are git's view** (#49).

- `list_files` re-reads git's unmerged entries (`ls-files -u`) and returns each file of the session as
  `Unresolved` when git has an unmerged entry for it and `Resolved` otherwise, storing that status in
  the session (so `take`'s rollback logic and the exit status see the same). Files that were not
  conflicted at start are never added. A git failure here is `IpcError::Git` as today.
- `finish_file`, `take_side`, `reset_file` keep returning the session's list after their own action
  (they know the outcome; no extra git call needed).
- Closing the window: the exit status (0 when every file is resolved, else 1) uses git's view at that
  moment; if git fails then, fall back to the session's statuses and log a warning.

**C. What is merged in** (#50). A new command `remote_name() -> Option<RemoteName>`:

```
#[serde(tag = "kind")] enum RemoteName {
    Branch { name: String },                                   // e.g. "minor", "origin/main"
    Commit { short_id: String, subject: String, message: String },  // git's %h, %s, %B (message trimmed)
}
```

- Read once in `MergeSession::open` (stored in the session; the command only returns it).
- Order: `MERGE_HEAD` → `CHERRY_PICK_HEAD` → `REBASE_HEAD`; the first that resolves to a commit wins;
  none → `None`. Use git itself to find them (`rev-parse --verify -q <NAME>^{commit}`, `--git-path`
  for `MERGE_MSG`), so linked worktrees work.
- For `MERGE_HEAD` only: the local and remote-tracking branches pointing at that commit (skip symbolic
  refs such as `origin/HEAD`). Exactly one → `Branch`. Several → the one named in quotes in the first
  line of `MERGE_MSG` (`Merge branch 'minor' into vapor`, `Merge remote-tracking branch
  'origin/main'`) if it is among them, else `Commit`. None → `Commit`.
- `CHERRY_PICK_HEAD` / `REBASE_HEAD` → `Commit`.
- Any git failure while reading this → `None` and a `warn` log line; it never stops the app starting.

## Contract

- New git reads are `gitio::Repo` methods (bytes/strings in, no diff logic), each with an
  integration test on a real temp repo; `session` decides; `src-tauri` command ≤ 15 lines (IPC5),
  registered in the one tauri-specta builder. The new types derive `Serialize` + `specta::Type`.
- `FileMergeData.deleted` uses the existing `Side` (`"local" | "remote"`).
- Rust functions ≤ 40 lines (clippy), no `unwrap`/`expect` outside tests, `#[expect(…, reason)]` only
  (no `#[allow]`), errors per `skill://rust-conventions`. The one `unsafe` stays the only one.
- Report every changed or new IPC type and command in `deviations_from_brief` (the orchestrator
  regenerates bindings and updates architecture + ipc-contract, PM6).

## Tests

Behaviour, on real temp repos (`yamt-conflict-repo`; extend it for cherry-pick / rebase / two branches
at one commit if needed):

- A: remote deleted + local text → loads, `deleted: "remote"`, every chunk one-sided on local, middle
  starts as base; local deleted mirrored; kept side binary → still `unsupported: RemoteDeleted`; Keep
  then reset, Delete then reset → stages back; a both-sides-present file → `deleted: null`.
- B: `git add <file>` outside after start → `list_files` says Resolved; `git checkout -m <file>` outside
  after `finish_file` → Unresolved; exit status at close follows git (one file resolved outside, the
  other left → 1; all → 0).
- C: merging branch `remote` → `Branch { name: "remote" }`; merging a commit no branch points at →
  `Commit` with `%h`, subject, message; two branches at the merged commit → `MERGE_MSG`'s name;
  cherry-pick conflict → `Commit`; rebase conflict → `Commit` of the replayed commit; a conflict with
  none of these heads (e.g. `git stash pop`) → `None`.
