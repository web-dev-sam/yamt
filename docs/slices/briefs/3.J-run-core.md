## Contract (fixed; you may add, never change)

```rust
// gitio
pub struct GitRun { pub succeeded: bool, pub output: Vec<u8> }   // stdout then stderr, as git printed them
impl Repo {
    /// git's own abort for `operation` (#88's table; a squash merge: `reset --merge`). Refusal: Err(GitFailed).
    pub fn abort(&self, operation: &Operation) -> Result<()>;
    /// git's own continue for `operation` (#89's table; a squash merge: `commit`). A non-zero exit is not an Err:
    /// the caller re-reads the stop to learn what happened.
    pub fn continue_operation(&self, operation: &Operation) -> Result<GitRun>;
}

// session — new `operation.rs`, DTOs (Serialize + specta::Type) for row 5 to export
#[serde(tag = "kind")]
pub enum OperationView {
    Merge { merging: Option<SideName>, into: Option<SideName> },
    SquashMerge { merging: Option<SideName>, into: Option<SideName> },
    Rebase { branch: Option<String>, onto: Option<SideName>, replaying: Option<SideName>,
             progress: Option<ProgressView>, editor_steps_ahead: bool },
    CherryPick { picking: Option<SideName>, progress: Option<ProgressView> },
    Revert { reverting: Option<SideName>, progress: Option<ProgressView> },
    Am { subject: String, message: String, progress: Option<ProgressView> },
}
pub struct ProgressView { pub step: u32, pub total: u32 }          // from gitio's Progress: 1 ≤ step ≤ total
#[derive(Clone, Copy, ...)] pub enum OperationKind { Merge, SquashMerge, Rebase, CherryPick, Revert, Am }

pub enum Refreshed { Files(StopList), MovedOn }
pub struct StopList { pub files: Vec<FileEntry>, pub disk_changes: Vec<DiskChange>,
                      pub operation: Option<OperationView>, pub sides: SideNames }
pub enum Continued { Finished { kind: OperationKind, output: String }, Stopped { message: String } }

impl MergeSession {
    /// Reads the stop first: another stop than the one opened → MovedOn, nothing settled or staged. Otherwise
    /// today's `refresh` (settle, then git's marks) plus the operation as read now and the names read at open.
    pub fn refresh_stop(&mut self) -> Result<Refreshed>;
    /// Re-reads the stop: none → Err(NoOperation); another stop → Err(StopMovedOn); else git's abort.
    pub fn abort_operation(&mut self) -> Result<OperationKind>;
    /// Re-reads the stop as abort does, runs git's continue, re-reads the stop: none → Finished; the same stop →
    /// Err(Error::GitRefused { message }) (git's output); another → Stopped { message }.
    pub fn continue_operation(&mut self) -> Result<Continued>;
}
// session::Error gains: NoOperation, StopMovedOn, GitRefused { message: String }
```

## Behaviour

1. **No deadline, user's locale, no editor.** Abort and Continue run git without the 30 s deadline (a kill mid-commit
   leaves `index.lock`), stdin closed, both streams captured, **without** `LC_ALL=C` so hooks run as in a terminal, and
   Continue with `GIT_EDITOR=:` (git keeps its prepared message, comment lines such as `# Conflicts:` stripped — design
   fact 1). Every other git call keeps today's `git_command`.
2. **Commands** exactly as #88/#89 per operation; the stop is re-read before git runs, so a stale view never aborts or
   continues the wrong thing.
3. **The operation view** carries #87's names: merge/squash `merging` by #50's branch rule, `into` = HEAD's branch or
   commit (#62); rebase `onto` by #50's branch rule (`main`), `replaying` as a commit, `branch` from head-name; pick and
   revert targets as commits (`Revert` form for a revert); `am` subject/message lossy UTF-8; a failed name read drops
   only that name (warn), never the list.
4. **Stop identity** is `Stop::id()` (row 2); progress changes alone never count as moved on.
5. `refresh_stop` with **no operation** at open and none now (stash pop) behaves as `refresh` with `operation: None`.
   An operation that ended or was aborted outside (open stop had one, now none) is not "moved on": the list is git's
   view with `operation: None` (#89 "Ended or aborted outside").
6. **Fixtures first (row 2's review, #1316/#1317):** before adding the fixtures this slice needs (a refusing hook, a
   squash step, abort baselines), make "git did not stop" one check with one error (`DidNotStop { run }` for every
   `Run`, also the older `conflict_repo_with`/`rebase_merges_repo` paths; `stopped` takes an optional stdin so `am`
   uses it) and pull the `tempdir` + `init` + `core.autocrlf false` setup into one `empty_repo()` the builders share;
   `STEP_TWO_FILE` is used by `resolve_and_continue` to resolve step 1's files by path, or becomes private; `SquashMerge`
   is built on the three-commit sequence repo so a test proves `SQUASH_MSG`'s first `commit` line (the tip) is the
   merged commit, not the last (#1321; add that assertion to `gitio/tests/operations.rs`).

## Acceptance

Tests (`gitio/tests/abort_continue.rs`, `session/tests/operations.rs`; fixtures in `conflict-repo`), each naming the
bug it catches:

- abort per operation (merge, squash merge, rebase both backends mid-way after one replayed commit, cherry-pick range
  after one picked, revert range, `am` after one patch): `git status --porcelain`, the branch tip and `git stash list`
  equal what they were before the operation started; refusal (a file staged then changed again in a merge) → Err with
  git's text, nothing changed;
- continue with `core.editor=false` (and `GIT_EDITOR` unset in the test's environment) for each operation commits with
  git's prepared message (no `# Conflicts`), the original commit's message for a rebase/pick, the revert message for a
  revert; an interactive rebase `squash` step continued past gives the combined message;
- a `pre-commit` hook that prints to stderr and exits 1 (merge): `continue_operation` → `GitRefused` whose message holds
  the hook's line; HEAD, the index and the session's files unchanged; the hook sees the user's `LANG`/`LC_ALL`, not
  `C`;
- outcomes: a 3-step rebase with conflicts at steps 1 and 2 → `Stopped` (stop 2), then `Finished { kind: Rebase }`;
  cherry-pick range likewise; merge → `Finished { kind: Merge }`; continuing with a file unmerged → `GitRefused`;
- `refresh_stop`: after `git rebase --continue` in the test (a terminal), `MovedOn` and the old stop's files neither
  settled nor staged (a file git rewrote for the next stop is not `git add`ed); same stop → `Files` with the operation
  and progress; stash pop → `Files` with `operation: None`; a rebase aborted in the test → `Files`, `operation: None`;
- `OperationView` per operation with its names and progress (rebase 1/3: `onto` = Branch `main`, `branch` = the
  rebased branch, `replaying` = Commit of the first own commit).
