## Block to fix (verbatim from the re-check)

**#1325** The #1314 fix makes `git_path` check that `git_paths` gave back one path per name and answer
`UnexpectedOutput` if not, and `state_paths` (operation.rs:137-148) does the same check by hand with its own literal
`"rev-parse"`. Two callers now hold the same rule, and every later multi-name caller (for example #90's `MERGE_RR` next
to another state file) would add a third copy. **Fix:** make `git_paths` total:
`pub(crate) fn git_paths<const N: usize>(&self, names: [&str; N]) -> Result<[PathBuf; N]>`, converting the collected
`Vec` with `try_into` and mapping a length mismatch once to `UnexpectedOutput { command: REV_PARSE, .. }`. Then
`git_path` is `let [path] = self.git_paths([name])?; Ok(path)` and `state_paths` is
`let [rebase_merge, rebase_apply, sequencer, squash_msg] = self.git_paths(STATE_PATHS)?;` with no `match` and no
`"rev-parse"` literal.
