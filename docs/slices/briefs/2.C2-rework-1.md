## Findings to fix (quoted, with the decision)

- #357 (boundary, should): "The rule 'unsupported → describeFile + putChoice, else loadFile +
  putOpened' is written twice, in open (store.ts:145-147) and in reopen (store.ts:243-257). reopen
  has to return Outcome<unknown>, which throws away the value type, so a third kind of view would
  have to be added in both places." **Decision:** one `fetchView(state, path): Promise<Outcome<() =>
  void>>` picks the source call and returns a commit function (`() => putChoice(state, sides)` /
  `() => putOpened(state, data)`); `load` runs it when its ticket is still current, reopen after a
  reset runs it without a ticket. The generic `fetch`/`put` parameters and `Outcome<unknown>` go.
- #358 (boundary, should): "AppStore's five public refs are now a mapped type over a string union
  … that a TS-beginner reader must expand in their head. It saves four lines in a file now at 298
  of its 300 lines." **Decision:** write the five `readonly files/opened/choices/active/problem`
  fields out again. Room comes from #357; if `store.ts` still exceeds 300 lines, move the choice
  actions (`putChoice`, `takeSide`) into their own `ui/` module and say which in the report.
- #359 (boundary, should): "The column headers 'Local (yours)' / 'Remote (theirs)' are now typed in
  two places, HEADERS here and MergeView.vue:48/52, although the brief requires them to be the
  same." **Decision:** one `SIDE_HEADERS: Readonly<Record<Side, string>>` in a new
  `frontend/src/ui/sideHeaders.ts`, read by both `ChoiceView.vue` and `MergeView.vue`. (The
  orchestrator names the file in the project map after landing.)
- #360 (boundary, should): "`finished: Map<string, string>` values are never read (only
  `finished.has` at fixture.ts:131), yet takeSide (fixture.ts:190) now stores `data[side]` into it.
  That unread write is the only reason `changed`'s callback receives `data`, and the name `changed`
  does not say that it checks the path and returns the list." **Decision:** `finished` becomes a
  `Set<string>`, the callback loses `data`, `changed` gets a name saying what it does (e.g.
  `updateKnown(records, path, update)`).
- #363 (boundary, should): "Now that ipc exports the generated `Side = "local" | "remote"`, the
  editor's hand-written `Side` is a second definition of the same fact." **Decision:**
  `editor/internal/side.ts` re-exports the ipc type (`export type { Side } from "../../ipc"`); nothing
  else in `editor/` changes. The generated union must stay exactly `"local" | "remote"` — check
  `ipc/bindings.ts` before relying on it.
- #364 (correctness, should): "Every choice test puts exactly one choice in the store, so the path
  filters in takeSide (store.ts:219-221), putChoice (store.ts:194) and reopen (store.ts:251) are
  never tested. A mutant that marks every choice as taken, or drops every choice on reset, would
  pass." **Decision:** the take and reset store tests describe two files the editor cannot show
  (e.g. `logo.bin` and `docs/removed.md`) and assert the one not acted on keeps `taken: null` and
  stays the same object.
- #365 (correctness, nit): "takeSide clears the problem bar whatever file the problem is about …
  the same mistake #347 just fixed for reset." **Decision:** one helper (e.g.
  `clearProblemAbout(state, path)`) used by reset and takeSide; a store test where a take finishes
  after another file's open failed keeps that failure.
