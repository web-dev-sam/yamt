# Slice 2.R — yamt 0.1.0 can be built, installed and understood by someone who is not us

Board v0 wave 5. Owner decision plan §2 #38: v0 is published as GitHub releases for Linux and macOS
under the MIT license, version 0.1.0; the macOS build is unsigned (first start: right-click → Open).
Plan §2 #6: yamt takes over the whole merge (all conflicted files at once), so it is started in the
repository, not once per file. This slice adds what a release needs; the GitHub repository itself
is the owner's to create, so the workflow is written and checked locally, not run.

## Target

Owned (new unless noted): `README.md`, `LICENSE`, `CHANGELOG.md`, `THIRD_PARTY_NOTICES.md`,
`.github/workflows/release.yml`, `docs/screenshot.png`, `src-tauri/tauri.conf.json` (the `bundle`
section only), `frontend/src/main.ts` (only if the fixture data must be split out, below).
Read-only: everything else. The version stays `0.1.0` from the workspace `Cargo.toml` (the app
config takes it from there; no second copy).
Non-goals: signing or notarising; Windows; auto-update; a package-manager recipe (AUR, Homebrew);
pushing, tagging or creating the GitHub repository.

## Behaviour

- `README.md` (plain English, short; the owner reads it): what yamt is in two sentences (a
  three-way merge window like JetBrains', for the whole merge at once) and the screenshot;
  **install** (Linux: AppImage or `.deb` from the releases page; Arch: the AppImage, or build from
  source; macOS: the `.dmg`, then right-click → Open the first time because the build is unsigned —
  or `xattr -d com.apple.quarantine /Applications/yamt.app`); **use**: after `git merge` / `rebase` /
  `cherry-pick` stops with conflicts, run `yamt` in the repository (or `yamt --repo <path>`); what
  the window does (apply arrows, ×, bulk apply, Tab indent, undo/redo, Mark resolved stages the file,
  Reset file brings the conflict back, the choice for files the editor cannot show); closing exits
  with 0 when everything is resolved and 1 otherwise (useful in scripts); a `git` alias
  (`git config --global alias.resolve '!yamt'`) and why `git mergetool` is not the way to start it
  (it runs a tool once per file, yamt handles all files in one window); **build from source**
  (rustup toolchain from `rust-toolchain.toml`, pnpm, `cargo install tauri-cli --version 2.12.1`,
  `pnpm -C frontend install`, `cargo tauri build`; Linux needs webkit2gtk-4.1); the NVIDIA note (the
  app handles it itself; a user value of `WEBKIT_DISABLE_DMABUF_RENDERER` wins); license.
- `LICENSE`: MIT, "Copyright (c) 2026 Samuel Braun" (the repository's git author).
- `THIRD_PARTY_NOTICES.md`: what the app bundles and their licenses — JetBrains Mono (OFL-1.1,
  include the notice the font package ships), Lucide icons (ISC), vscode-icons (MIT), CodeMirror
  (MIT), Vue (MIT), Tauri (MIT/Apache-2.0); generated from the actual dependency trees where a tool
  exists (`cargo deny list` / `pnpm licenses list --prod`), hand-checked otherwise; say which.
- `CHANGELOG.md`: Keep a Changelog format, `## [0.1.0] - unreleased` with what v0 does, in user
  terms.
- `tauri.conf.json` `bundle`: `active: true`; targets AppImage and deb on Linux, app + dmg on macOS;
  `category` `DeveloperTool`; short and long description; `license` `MIT`; `copyright`; the existing
  icons. The app's identifier and name stay.
- `.github/workflows/release.yml`: on a pushed tag `v*`, build on `ubuntu-22.04` (AppImage + deb)
  and `macos-14` (universal `.dmg`, `--target universal-apple-darwin`) with `tauri-apps/tauri-action`
  (pinned to a release tag, not a branch), pnpm via `pnpm/action-setup` (pinned), the Rust toolchain
  from `rust-toolchain.toml`, Linux system packages for webkit2gtk-4.1; upload to a **draft** release
  named after the tag; `permissions: contents: write` only. No secrets beyond the default token.
- The app build must not carry the fixture data: after `VITE_CHUNK_SOURCE=tauri pnpm -C frontend
  build`, `frontend/dist` contains none of the golden/showcase fixture JSON (check by a known case
  string such as `nuxt-island-test`); if it does, `main.ts` loads the fixture source by dynamic
  import only when not in the app, and the check passes (finding #298).

  the median.
- The fixture check above, before and after (paste the grep counts).
- The workflow file passes `actionlint` if installed (else say so) and is reviewed by reading: tag
  trigger, pinned actions, draft release, no extra permissions.
- `pnpm -C frontend lint && pnpm -C frontend typecheck && pnpm -C frontend test` if `main.ts`
  changed; `just bindings-check` and `cargo clippy --workspace --all-targets -- -D warnings`.
- Stop everything you started.
