## Findings and decisions

1. [block, implementer, SP1] `frontend/src/editor/internal/pane.test.ts:100` — "the status literal
   `"pending"` must become `{ local: "pending", remote: "pending" }`"; typecheck and one test are
   red on HEAD.
   **Decision:** change exactly that literal (use `PENDING` from `status.ts` if it reads better).
   The other task added tests further down in the same file: touch nothing else.
2. [should, boundary, PM3] `frontend/scripts/fences.ts:29` — "Neither fences.ts nor
   .oxlintrc.json:134 blocks `~icons/lucide/<name>` without `?raw` inside editor/, model/ or
   connectors/. With `compiler: "vue3"` that import compiles to a module that imports `vue`, so the
   Contract's 'never from a Vue component' rule has no detector (vision 3)."
   **Decision:** fences.ts reports PM3 for an `~icons/` import without the `?raw` query in a
   framework-free module (note that `bare` already has the query stripped, so the query has to be
   read from `specifier`); `?raw` stays allowed; `ui/` stays allowed. Add `fences.test.ts` cases
   for both. No oxlint pattern: one detector is enough.
3. [should, boundary] `strips.ts:147` — "The ignore icon is imported as a bare `x` (line 7) and
   used as `{ x: ignoreX, lineHeight, icon: x }` next to `applyX`/`ignoreX` coordinates, so the same
   name means a pixel offset in one property and SVG markup in the next."
   **Decision:** name every icon import `<name>Icon` (`xIcon`, `chevronsLeftIcon`, …), so they
   all follow one pattern.
4. [should, boundary, TS7] `status.ts:37` — "`handle(chunk, status, side, value)` is a vague verb
   with four positional parameters, so a reader of `statusAfterApply` has to open it to learn that
   it sets every changed side of a non-conflict and only the clicked side of a conflict."
   **Decision:** a name that states the rule and one object parameter, as the reviewer suggests
   (e.g. `markSides({ chunk, status, side, value })`).
5. [should, boundary, CP1] `icons.d.ts:1` — "The why-comment states a TypeScript resolution fact
   … without a reference."
   **Decision:** add the reference on the same comment (TypeScript `findBestPatternMatch`,
   `src/compiler/utilities.ts`: the first pattern with the longest prefix wins).
6. [should, correctness] `strips.ts:88` — "iconElement runs the HTML fragment parser (`innerHTML`)
   twice for every visible arrow row on every requestAnimationFrame … the same five constant SVG
   strings are re-parsed dozens of times per scroll frame."
   **Decision:** parse each markup once (on first use, a module-level map keyed by the markup)
   with the `instanceof SVGSVGElement` check there; each button gets a `cloneNode(true)` with its
   own x/y/width/height.
7. [should, correctness, CM8] `sides.test.ts:286` — "The CM8 test deletes only a fully open
   conflict; deleting a half-handled conflict (one side applied or ignored) is the new combination
   this slice creates, and a regression that made collapsedByUser fire only while both sides are
   pending would pass every test."
   **Decision:** as the reviewer suggests: run the test over the open conflict and the conflict
   after `»` on the left (deleting the span's current lines), asserting `ignored ignored`,
   `conflicts: 0`, one undo step each. `sides.test.ts` stays ≤ 300 lines (TS11): make room by
   tightening, never by dropping a case.
8. [nit, correctness] `sides.test.ts:206` and `:230` — "`not.toContain("129 replace")` would still
   pass if the handled side's arrow stayed visible in append mode."
   **Decision:** assert no arrow at all on that line.
9. [nit, boundary] `strips.ts:32` — "`CENTER = 0.5` is a halving factor … its name reads like a
   position." **Decision:** rename to `HALF`.
