Owner skills: `skill://ts-conventions`, `skill://ipc-contract`. The window's agent client (plan §2 #108, #109, #113, #114): speaks the Agent Client Protocol (ACP) to `omp acp` over `jsonrpc/` through an `ipc/AgentSource` (the app's `tauriAgent.ts`, fixture mode's `fixtureAgent.ts`); Rust only pipes lines. Framework-free (PM3) and imports only `ipc/index.ts` and `jsonrpc/index.ts` (PM2, `scripts/fences.ts`). Public surface is `index.ts`: `AgentClient { ask, loadConversation, editDiff, isRunning, destroy }`, the turn model's types, `AgentFailure`, `TurnEnd`, `agentSessionId`, `firstMessage`/`unknownPlaceholders`/`PLACEHOLDERS`/`DEFAULT_FIRST_MESSAGE`, `DEFAULT_AGENT_COMMAND`; everything else in `internal/`. `AgentClient` is built only in `main.ts` (C8 adds that fence).

`AgentClient` (`index.ts`) owns the checkout's folder (`prepareCheckout` once; a failure or a `NoCheckout` start is not kept, so Retry makes it again) and one process at a time (`internal/process.ts` `AgentProcess`: `initialize` once, protocol version 1 or `refused`; the command words read from `AgentSetup.command` at each start, `internal/command.ts`, nothing appended; a process that exits is dropped and the next ask starts another). A turn (`ask`): a new thread sends `session/new` and reports its id at once (`TurnEvents.session`); a thread with an id is loaded once per process (`AgentProcess.load`, its replay dropped); then `session/prompt` without a deadline. A second ask on a running thread ends `busy` at once. `stop()` sends `session/cancel` once the prompt is out, else the turn ends `stopped` without prompting. `isRunning()` is "any turn is running". `destroy()` stops the process; running and later turns end `stopped`.

Updates are routed by `sessionId` to the one listener of that session (`AgentProcess.listen`): a running `TurnRun` (`internal/session.ts`: the fold, `changed` at most once per 50 ms and always at the end, one end) or `loadConversation`'s collector. `internal/protocol.ts` parses with valibot only what yamt reads (`agent_thought_chunk`, `agent_message_chunk`, `user_message_chunk`, `tool_call`, `tool_call_update`; anything else is ignored) into `TurnUpdate`s; an edit's absolute `diff` path becomes checkout-relative there. `internal/turn.ts` is the one pure fold: thoughts concatenated until a step, message text accumulates as `answer` and moves into a `said` entry when a step follows, a step's update changes only the fields it names and its `content` replaces the outputs (a refusal kept), and `endTurn` turns pending and running steps into `noResult`. `internal/conversation.ts` splits a `session/load` replay into turns at each user message. The `stopReason` table is `session.ts` `stopEnding`.

The agent's requests are answered by the fixed table in `internal/answers.ts` (sync, through `jsonrpc`'s handler): `session/request_permission` with `toolCall.kind == "execute"` → `allow_once`; any other kind → `allow_once` only when it has locations and every one lies inside the checkout (`internal/inside.ts`: lexical, `/` and `\`, case-folded under a drive letter, the checkout itself not inside, symlinks not followed), else `reject_once` and a `refused` output on that step (created if its `tool_call` has not arrived yet); no wanted option → `cancelled`; never an `*_always` option; any other method → −32601. Failures are `internal/failure.ts`: omp's words come from `error.data.details`; a load error naming "session not found" is `sessionGone`, any other `refused`; a request closed by the process's exit is `crashed` with its code and last stderr line.
