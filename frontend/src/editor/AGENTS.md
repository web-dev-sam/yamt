Owner skills: `skill://cm6-rules`, `skill://ts-conventions`. Framework-free: no `vue`, no `@vueuse`, no `@tauri-apps` (oxlint). Public surface is `index.ts` (`MergeController`, `CompareController` from `compare.ts`, `RangeController` from `range.ts`, `MarkdownView` from `markdown.ts`); everything else in `internal/`. Layout tests run in the Vitest browser project (WebKit); the browser tests mount the three panes and two strips through `paneHarness.ts` (the app's grid inside `will-change: transform` wrappers), imported by tests only.

An editable Result is one document of `lsp/` (plan §2 #67, #70): `internal/serverDoc.ts` opens it on `LanguageServers`, says changed on each edit and closes it on destroy; `problems.ts` keeps the versions handed out and shows each server's problems through `@codemirror/lint` in the middle pane only (tooltips in `document.body`), relying on `lsp/` never to hand it an answer older than the last one shown, and leaves the diagnostics untouched when an answer changes nothing shown (an open tooltip stays); `format.ts` splits a formatter's result on any line break and applies it as yamt's own line diff (`lineDiff.ts`), each old line paired with a new one and changed only in the characters that differ, extra lines inserted or deleted whole, in one `yamt.format` transaction.

Save (plan §2 #65, #69): `internal/fileText.ts` builds the file Save writes from the chunk field, each chunk's `waiting` and the side texts, as one `ChangeSet` over the Result (no transaction, so no chunk mapping), with `apply.ts`'s `wholeLines`; its `dropsShownText` is the one rule for a change whose shown text the file leaves out. `savedPoint.ts` owns the saved point (the Result's `Text`, every status and which text was written — `markSaved("asShown" | "fileText")` — at open or the last save) behind `MergeController.snapshot()` and `onUnsavedChange`; typing that `dropsShownText` leaves out keeps the dot only after a `fileText` write.

Removal tooltip (plan §2 #73): each side pane's removal bar (`words.ts` `RemovalPoint`, class `REMOVAL_BAR_CLASS`) carries its removed text, and `eq` compares tone and text; `removalTooltip.ts` opens a `hoverTooltip` (in `document.body`) only while the pointer is on a bar's own box (`:hover` on that class), reads the text from that bar's decoration (`removalAt`), never from `chunk.words`, copies the pane's font, ligatures and code colour from its computed style, and closes when the bar goes; `removalText.ts` holds the pure display rules (the one joining line break left out — on an empty line the trailing one first — whitespace-only text as `·`/`→`/`↵` marks); `theme.css` draws a kept final line break as its empty line (`::after` zero-width space, not copied). The removal and problem tooltips' surface (border, radius, background) is `src/style.css`'s `hover-tooltip` utility and the problem tooltip's text (colour, font, size) its `tooltip-text`, which `theme.css` takes through `@reference "../style.css"` and `@apply`; `ui/`'s operation tag tooltip uses the same two, so the look lives in one place.

Minimap (plan §2 #81): `Frame` owns `internal/minimap.ts` (`Minimap`), one `.minimap` box (a `<canvas>` and a `.minimap-slider`) appended to the right pane's `view.dom`, outside `scrollDOM`/`contentDOM`, so no pane handler sees its presses; `display: none` while `MergeOptions.minimap`/`showMinimap` say no, and then `changed` and `paint` return at once and every tile is dropped. It paints in `Frame`'s frame after `ScrollSync.sync`, from the Result's `scrollTop` and `minimapLayout.ts` (VS Code's `MinimapLayout.create`; rows by `rowOfTop`/`topOfRow`): the slider moves on every frame, the canvas is redrawn only when its window, padding rows, size, tiles or edges changed. Code rows come from `minimapTiles.ts` (`MinimapTiles`: 128 Result rows per detached canvas through `ImageData`, `minimapPixels.ts` glyphs, `minimapRows.ts` syntax colours and theme tokens read once per show or theme change; dropped by `staleTiles`), each row looked up at its middle; a collapsed run's row is a wave line. Edges (`minimapMarks.ts`): problems left, waiting changes right, cached until rows move or diagnostics arrive. `minimapPointer.ts`: `mousedown` is prevented and stopped (focus and selection stay), a press puts its row's top in the Result's middle, the slider drags with pointer capture, a wheel scrolls the Result; each ends in `ScrollSync.follow("center")`.

Far scrolls (#1240, plan §2 #82): every pane carries `exactScroll` (`internal/exactScroll.ts`, beside `cutOnce.ts`, the other WebKitGTK quirk). A scroll event whose position shows none of CodeMirror's rendered lines (the pure `farTop`, node-tested) is turned into a CodeMirror scroll request (`placeTop` + `EditorView.scrollIntoView`; the `scrollHandler` writes that exact `scrollTop`), so CodeMirror renders the target before its measure; without it WebKitGTK pulls such a jump back while the viewport is swapped inside CodeMirror's scroll handler (a minimap press, a follower write, a script). Code that scrolls a pane keeps writing `scrollTop`.

Compare (plan §2 #93, #96, #98): `compare.ts` (`CompareController`, re-exported by `index.ts`) is the second public class, two `"center"` panes built by `internal/compareViews.ts` (each with `differenceField`, `columnLimit`, the removal tooltip, `everyPane`), never a flag through `MergeController`'s parts. `compareFrame.ts` (`CompareFrame`) is its once-per-frame paint: find space over both columns, rows and anchors cached until `differenceField` or the measured heights change (never per scroll, plan §2 #51), `ScrollSync<Column>` over `COLUMNS`, then `compareStrip.ts` (keyed `chunk-<tone> chunk-band` paths, `mousedown` prevented). `compareFormat.ts` formats each column alone as one whole-document `yamt.format` replace (`isolateHistory`: one undo step, never joined with typing); `compareLanguage.ts` keeps the tab's language and Auto's finding (`detected` only when it changed) and puts it into both `languageCompartment`s. `ScrollSync`, `syncFindSpace` and `loadLanguage` take any list of panes; the merge `Frame` passes `PANES` and its three views.

Themes (plan §2 #102): `internal/syntax.ts` holds the code colours — one row per `--color-syntax-<token>` (39) with the Lezer tags it colours and only its own `--syntax-<token>-{style,weight,line}` font styles — and builds from that one table `paletteHighlight` (colours: Markdown containers first and what they hold later), `fontHighlight` (font styles: link and url before the containers, so a container's style wins) — both on the text and the removal tooltip — and `syntaxColourClasses` (the minimap); the minimap takes the matching class defined last, as CSS does. A tag whose parent has a row but which means something else needs its own row (CodeMirror takes the first tag in `tag.set` with a rule: `function(definition(variableName))`, `derefOperator`, `angleBracket`, `attributeName`, …). The theme compartment in `pane.ts` holds the dark flag from `themeKind` and the `themeName` facet; the minimap drops its look when `themeName` changes (two dark themes included) and softens by the dark flag. `themes.browser.test.ts` checks every theme's computed values against its CSS text.

Markdown (plan §2 #112): `markdown.ts` (`MarkdownView`, reached from `ui/` only through `ui/useMarkdown.ts`, fence PM2 in `scripts/fences.ts`) renders yamt's own subset of the AI's answers. `internal/markdownBlocks.ts` (pure: lines → `Block`s, each top-level block with its source lines) and `internal/markdownInline.ts` (pure: a block's text → `Inline`s; code spans and escapes are skipped while an emphasis looks for its closer, so backticks win) never build markup; anything outside the subset, raw HTML included, stays literal text; images become `alt (url)` text and links their text plus the address in `.markdown-address`, never navigable. `internal/markdownDom.ts` builds nodes with `createElement`, `createTextNode`, `textContent` and `className` only, from a fixed tag set, `class` the only attribute — never `innerHTML` or a URL attribute, since the page reaches the IPC. `show(text)` keeps every leading block whose source is unchanged and rebuilds from the first that differs (streaming). `internal/codeBlock.ts` colours a fenced block by its info string through `languageNamed` and `highlightCode` with the panes' own `paletteHighlight` + `fontHighlight` (their rules in one `<style class="markdown-highlight-styles">`, mounted once per document; style-mod's `StyleModule.mount` is not reachable from yamt's own packages), after `load()` only while the block is still in a live view; an unknown language stays plain. The answer's look (spacing, code block, table, quote, list numbers, muted address) is the `.markdown-*` rules in `theme.css`, palette tokens only.

Range threads (plan §2 #116): `range.ts` (`RangeController`) shows the review's threads as block rows inside its two read-only columns; Vue fills them through the hosts `RangeEvents.hosts` hands out, never through the editor. `internal/threadAnchor.ts` (`anchorAt`, `linePlace`) is the one rule from a column line to a `ThreadLine` and to its partner line; which column and line a `ThreadLine` shows in is `ipc`'s `shownLine`; `threadRows.ts` (pure) groups the shown threads by aligned place (a removed or added line's gap after its difference's other side, an unchanged line's after its partner; collapsed threads place no row), gives each row its `kind` (`unchanged`, `changed`, or `leftEmpty`/`rightEmpty` when the gap is on a difference's empty side) and `rowHeight` (the larger column's summed host heights); `threadField.ts` holds each column's rows and count marks from `showThreadRows` and provides one `block` widget per row (`side: 1 + k` at the end of line `place − 1`; on its empty side a row sits before line `place` with a negative side, so it joins that line's block), plus `threadAnchors` (the text bottom above and the next line's block top below each unchanged row) that `CompareFrame` merges, sorted, into its scroll anchors; `CompareFrame` measures an empty difference side from its joined block's top to its text's top, so the empty side's rows are inside the band; `threadWidget.ts` (`ThreadRowWidget`) `eq`s by row key, column and keys only, so a height change keeps its DOM; `threadHosts.ts` (`ThreadHosts`, built after the views) keeps one host per shown key for as long as the key is shown, one `ResizeObserver` on every host (disconnected hosts skipped) and on both scrollers and gutters writes the row height on both cells and calls `requestMeasure`, writes `--thread-left`/`--thread-width` on each column host (the rows are `position: sticky`), and gives focus back to a field inside a host after CodeMirror re-attaches it, unless a press outside every host left that field; `threadNumbers.ts` merges a `mousedown` into the number gutter (a number starts a thread, the count badge toggles that line's threads; `pressedLine`: the empty line after a last newline and an empty column's line are no line of the file and do nothing) and draws the number plus the badge as a `lineNumberMarkers` marker; the hover icon is a `theme.css` mask from `--thread-icon`.

Collapsed unchanged lines in both windows (plan §2 #63, #64, #68, #126): one fold core serves the merge panes and the range columns — `foldRuns.ts` (runs and their 4/8/16 steps), `foldSteps.ts` (the step state), `foldView.ts` `paneFoldView` (wave line, gutter wave, atomic ranges), `folding.ts` (hover and click), `wavePhase.ts` (`chainEnds`/`ChainPhases` over a chain of panes and strips; `WavePhases` is the merge's three-pane chain), `gap.ts` `joinPaints` and `strips.ts` `WaveLayer` (the strip's wave joins). The merge's state lives in the middle pane (`folds.ts`); the range's lives in the left column (`columnFolds.ts`: `ownerSteps`, the right's `mirrorSteps` copied by a push), its view, hover, click and phases in `rangeFolds.ts` (`RangeFolds`, `columnWaves`), reaching `CompareFrame` through its opt-in `waves` part and `CompareStrip` only when given `hovered`, so the compare window paints as before. A press on a wave's gutter cell starts no thread (`threadNumbers.ts`) and shows no comment icon (`theme.css`). Unchanged-line threads are run edges; runs are computed at build and at each `setCollapsed(true)`, never on a thread change.
