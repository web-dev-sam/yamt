Owner skills: `skill://cm6-rules`, `skill://ts-conventions`. Framework-free: no `vue`, no `@vueuse`, no `@tauri-apps` (oxlint). Public surface is `index.ts` (`MergeController`, and `CompareController` from `compare.ts`); everything else in `internal/`. Layout tests run in the Vitest browser project (WebKit); the browser tests mount the three panes and two strips through `paneHarness.ts` (the app's grid inside `will-change: transform` wrappers), imported by tests only.

An editable Result is one document of `lsp/` (plan §2 #67, #70): `internal/serverDoc.ts` opens it on `LanguageServers`, says changed on each edit and closes it on destroy; `problems.ts` keeps the versions handed out and shows each server's problems through `@codemirror/lint` in the middle pane only (tooltips in `document.body`), relying on `lsp/` never to hand it an answer older than the last one shown, and leaves the diagnostics untouched when an answer changes nothing shown (an open tooltip stays); `format.ts` splits a formatter's result on any line break and applies it as yamt's own line diff (`lineDiff.ts`), each old line paired with a new one and changed only in the characters that differ, extra lines inserted or deleted whole, in one `yamt.format` transaction.

Save (plan §2 #65, #69): `internal/fileText.ts` builds the file Save writes from the chunk field, each chunk's `waiting` and the side texts, as one `ChangeSet` over the Result (no transaction, so no chunk mapping), with `apply.ts`'s `wholeLines`; its `dropsShownText` is the one rule for a change whose shown text the file leaves out. `savedPoint.ts` owns the saved point (the Result's `Text`, every status and which text was written — `markSaved("asShown" | "fileText")` — at open or the last save) behind `MergeController.snapshot()` and `onUnsavedChange`; typing that `dropsShownText` leaves out keeps the dot only after a `fileText` write.

Removal tooltip (plan §2 #73): each side pane's removal bar (`words.ts` `RemovalPoint`, class `REMOVAL_BAR_CLASS`) carries its removed text, and `eq` compares tone and text; `removalTooltip.ts` opens a `hoverTooltip` (in `document.body`) only while the pointer is on a bar's own box (`:hover` on that class), reads the text from that bar's decoration (`removalAt`), never from `chunk.words`, copies the pane's font, ligatures and code colour from its computed style, and closes when the bar goes; `removalText.ts` holds the pure display rules (the one joining line break left out — on an empty line the trailing one first — whitespace-only text as `·`/`→`/`↵` marks); `theme.css` draws a kept final line break as its empty line (`::after` zero-width space, not copied). The removal and problem tooltips' surface (border, radius, background) is `src/style.css`'s `hover-tooltip` utility and the problem tooltip's text (colour, font, size) its `tooltip-text`, which `theme.css` takes through `@reference "../style.css"` and `@apply`; `ui/`'s operation tag tooltip uses the same two, so the look lives in one place.

Minimap (plan §2 #81): `Frame` owns `internal/minimap.ts` (`Minimap`), one `.minimap` box (a `<canvas>` and a `.minimap-slider`) appended to the right pane's `view.dom`, outside `scrollDOM`/`contentDOM`, so no pane handler sees its presses; `display: none` while `MergeOptions.minimap`/`showMinimap` say no, and then `changed` and `paint` return at once and every tile is dropped. It paints in `Frame`'s frame after `ScrollSync.sync`, from the Result's `scrollTop` and `minimapLayout.ts` (VS Code's `MinimapLayout.create`; rows by `rowOfTop`/`topOfRow`): the slider moves on every frame, the canvas is redrawn only when its window, padding rows, size, tiles or edges changed. Code rows come from `minimapTiles.ts` (`MinimapTiles`: 128 Result rows per detached canvas through `ImageData`, `minimapPixels.ts` glyphs, `minimapRows.ts` syntax colours and theme tokens read once per show or theme change; dropped by `staleTiles`), each row looked up at its middle; a collapsed run's row is a wave line. Edges (`minimapMarks.ts`): problems left, waiting changes right, cached until rows move or diagnostics arrive. `minimapPointer.ts`: `mousedown` is prevented and stopped (focus and selection stay), a press puts its row's top in the Result's middle, the slider drags with pointer capture, a wheel scrolls the Result; each ends in `ScrollSync.follow("center")`.

Far scrolls (#1240, plan §2 #82): every pane carries `exactScroll` (`internal/exactScroll.ts`, beside `cutOnce.ts`, the other WebKitGTK quirk). A scroll event whose position shows none of CodeMirror's rendered lines (the pure `farTop`, node-tested) is turned into a CodeMirror scroll request (`placeTop` + `EditorView.scrollIntoView`; the `scrollHandler` writes that exact `scrollTop`), so CodeMirror renders the target before its measure; without it WebKitGTK pulls such a jump back while the viewport is swapped inside CodeMirror's scroll handler (a minimap press, a follower write, a script). Code that scrolls a pane keeps writing `scrollTop`.

Compare (plan §2 #93, #96, #98): `compare.ts` (`CompareController`, re-exported by `index.ts`) is the second public class, two `"center"` panes built by `internal/compareViews.ts` (each with `differenceField`, `columnLimit`, the removal tooltip, `everyPane`), never a flag through `MergeController`'s parts. `compareFrame.ts` (`CompareFrame`) is its once-per-frame paint: find space over both columns, rows and anchors cached until `differenceField` or the measured heights change (never per scroll, plan §2 #51), `ScrollSync<Column>` over `COLUMNS`, then `compareStrip.ts` (keyed `chunk-<tone> chunk-band` paths, `mousedown` prevented). `compareFormat.ts` formats each column alone as one whole-document `yamt.format` replace (`isolateHistory`: one undo step, never joined with typing); `compareLanguage.ts` keeps the tab's language and Auto's finding (`detected` only when it changed) and puts it into both `languageCompartment`s. `ScrollSync`, `syncFindSpace` and `loadLanguage` take any list of panes; the merge `Frame` passes `PANES` and its three views.

Themes (plan §2 #102): `internal/syntax.ts` holds the code colours — one row per `--color-syntax-<token>` (39) with the Lezer tags it colours and only its own `--syntax-<token>-{style,weight,line}` font styles — and builds `paletteHighlight` (the text, the removal tooltip) and `syntaxColourClasses` (the minimap) from it; Markdown containers come first and what they hold later, and the minimap takes the matching class defined last, as CSS does. A tag whose parent has a row but which means something else needs its own row (CodeMirror takes the first tag in `tag.set` with a rule: `function(definition(variableName))`, `derefOperator`, `angleBracket`, `attributeName`, …). The theme compartment in `pane.ts` holds the dark flag from `themeKind` and the `themeName` facet; the minimap drops its look when `themeName` changes (two dark themes included) and softens by the dark flag. `themes.browser.test.ts` checks every theme's computed values against its CSS text.
