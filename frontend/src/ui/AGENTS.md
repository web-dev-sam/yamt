"A reply after the stop was dropped changes nothing" is written once, `currentStop.ts` (`Stop`, `landed(stop, call)`: null once dropped): every write, the format step, Abort, Continue and every reload (`views.ts` `reload`, also for disk changes, `diskChanges.ts` `applyDiskChanges`) capture `target.stop` before they call. `StopMovedOn` always means the stop the window shows is gone (#1435): a list answered after it would only open the new stop under the old views, so every failure answered `StopMovedOn` — the writes, Abort, Continue, an open and every reload — goes once to `nextStop({ outside })` through `problem.ts` `reportFailure` (logged, no problem shown; its target asks only for `nextStop`), the one path. `operationText.ts` holds every operation word (the tag `operationTag`, the line `operationLine` and its tooltip, Continue's and Abort's labels, Continue's hover, Abort's title and question); `OperationLabel.vue` is the tag (plan §2 #92): `FileList.vue`'s last row under the list or tree while git records an operation, `App.vue` passing the store's `operation`. Paste on Linux (plan §2 #99): `linuxPaste.ts` `takeLinuxPastes`, installed once by `main.ts` for both roots only with the Tauri source on Linux (`isLinux`), cancels every trusted `paste` in the capture phase before WebKitGTK reads its pasteboard, records the focused element, reads the text through `readClipboard` (the selection after a middle-button release in the same task, else the clipboard) and dispatches the paste again with the text in memory only while that element still has the focus and is not `<body>`: on the original target while it is still in the page, else on the focused element; a field nobody handled gets `insertText`.
