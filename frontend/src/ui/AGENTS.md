Language servers (plan §2 #67, #70): the store holds the app's one `LanguageServers` (built in `main.ts`) through `servers.ts` (`serverViews` follows `onChange`, the shown log, the actions, `screen` for the log); `ServerStatus.vue` sits left of the gear in all three header rows, `ServerMenu.vue` and `ServerLogView.vue` hang off it; every word is in `serverText.ts`, except an install hint's text (the commands per package manager, steps and lines), which is `installText.ts`. The menu reads each `ServerView`'s `help` and `notes` (plan §2 #72): a failed start or an exit (`failureHelp`) shows "If it is not installed:" and the same install text as "Not installed"; each note is one muted line under the state (`noteLine`).

Which servers exist (plan §2 #67, #70, #71): `serverSetup.ts` owns the start and focus sequences — `startUp` (from `main.ts`) loads the file list and the settings, then detects and asks the question when the repository (the host context's root) has no answer; `refocus` (App's focus watch) refreshes both, then detects again without asking, once `startUp` has run. The answer in force is always what the settings file holds after a write (a failed write changes nothing); "Don't start" halts the runs (`haltAll`) without marking them stopped by the user. With no host (fixture mode without `?servers`) it only loads and refreshes. Its Settings section is `LanguageServerSettings.vue`, whose add form starts with `PresetPicker.vue` ("From the list": `presetChoices()` in the key list's row-menu pattern, filling Command and File types, plan §2 #72); the question's wording is in `question.ts`, every server word (folder labels, "Not installed") in `serverText.ts`.

Header group and pins (plan §2 #83): `ServerStatus.vue` shows the counts and the format note, then the pinned servers' buttons (`serverButtons.ts`: one `ServerButton` per view in view order, `pinned` by `ServerKey` from `pinnedServers`, `DOT_CLASSES`), then `ServerGroup.vue`: the "Servers" button (dot = `groupDot` over every view's `dotKind`), its teleported list (`useDropdownMenu`; per server a `menuitem` row and a `menuitemcheckbox` pin calling `togglePin(key)`), and a chosen row's `ServerMenu` in the list's place with the group button as opener; a click on the group button while that menu is open only closes it. The open menu's shape is `OpenMenu` (`serverMenuToggle.ts`, also `ServerMenu`'s props); the list and `ServerMenu` are placed by `useMenuPlacement` (measured size, window size, `menuPosition`), anchored `belowLeft` of their opener. Menus step over `MENU_ITEMS` (`menuKeys.ts`); every `useDropdownMenu` drop-down also closes on window blur and on a right-press (`contextmenu`) outside it, the opener included; `ServerMenu` closes on any press outside it and gives the keyboard back to its opener on Escape/Tab. Fixture mode builds a server host only with `?servers` (`ipc/fixtureServers.ts`, `main.ts`): four servers that never start.

Resizing (plan §2 #84): `ResizeDots.vue` draws the three dots of every resize handle (`DotsState` from `useColumnDrag`). `PaneDivider.vue` is the one pane divider shared by `MergeView` and `ChoiceView`: the separator role, its label per side, `usePaneDividers`' listeners and the dots. MergeView's header cells above the strips are dividers and the strip wrappers take the same listeners; ChoiceView's 1 px gutters carry a divider with a 5 px hit box; `FileList`'s handle uses `useColumnDrag` and `FILE_LIST_BOUNDS`, its dots centred as an absolute box (flex-centred dots there cost WebKitGTK scroll frames).

Questions (`asking.ts`): one at a time; `ask` resolves `"yes" | "no" | "dismissed"` (Escape is `dismiss`, a second `ask` while one waits is dismissed at once). Callers whose Escape means cancel compare `=== "yes"`.

Abort merge (plan §2 #74): `aborting.ts` holds the action and whether an abort runs; `merging` is git's view, written only by `listing.ts` `refreshFiles`. `AbortState` is `noMerge` / `ready` / `running`; `running` stays after a success, since the app is ending. A refusal is the `abort` problem, never cleared by a path. The button is the toolbar's first icon button (#58): `toolbarButtons.ts` `listedButtons` leaves it out of the menu and the toolbar while git has `noMerge`; whether the user hid it is a separate fact, `hiddenButtons`, which starts it hidden.
