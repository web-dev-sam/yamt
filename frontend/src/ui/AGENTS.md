A failed push is the `push` problem ("Could not push <branch>"); a failed `closeEndedMerge`, after the push offer or after Abort's leftovers, is the `closeMerge` problem of the merge read before the action began ("Could not close the merge of <target> into <branch>"), never Abort's. Once Continue answers ReadyToPush, or Abort answers leftovers, git stays running: the window is ended for every reader.

People on a merge request (request `docs/slices/request-mr-people.md`, design `docs/slices/briefs/mr-people-design.md` option A, plan §2 #169, #170): `useMergeRequests()` carries `peopleSearch`/`searchPeople`/`endPeopleSearch` (the window's one search, 250 ms after the last call, newest answer only), `peopleAsks`/`changePeople` (`mergeRequestPeople.ts`: one change at a time per merge request, `queue[0]` running, `notDone` kept until the box closes; `rowPeopleAsks(peopleAsks, iid)` is the one reader of a row's asks, empty for a row with none) and `openPeopleBoxes`/`peopleBoxOpened`/`peopleBoxClosed`: `shownRows` holds a row whose box is open (rule 9; the one hold rule, `mergeRequestsShown.ts` `heldOf`/`keptInPlace`, which also holds a row whose discussions box or thread panel is open, #2476: a held row stays shown and keeps its index in the order shown before, the other rows fill the rest), so `MergeRequestPeople.vue` calls Opened when `useHoverBox`'s `open` turns true and Closed when it turns false or the box unmounts open. On a row with `mayRerequest` the box always shows both groups ("None" when empty; a row with nobody opens it from the dimmed icon), each header with a `user-plus` add button that opens `MergeRequestPeopleSearch.vue` under it (one field per box, `adding`): a `role="combobox"` field over a `role="listbox"` of `mergeRequestPeopleLines.ts` `pickList` (the core's `peopleSuggestions` while empty, else the search's people; "Already an assignee/reviewer" lines `aria-disabled`, a queued add spinning), arrows over the addable lines (`steppedHighlight`), the highlight back on the first addable line whenever the lines change (`keptHighlight`), Enter or a click (its `mousedown` prevented) adds, and once that add is answered the field clears unless its text changed meanwhile (not at the pick, so the picked line shows its spinner) and takes focus back only from `document.body`, never from a control the user moved to while waiting; Escape closes the field (focus to its add button), a second Escape the box. Each assignee and reviewer line ends with `MergeRequestPersonMenu.vue` (`ellipsis-vertical`, one `useDropdownMenu<true>` menu with "Remove assignee/reviewer", `position: fixed` inside the box so the hover box holds it; the spinner, `aria-disabled` and no menu while that remove is queued or running). A change GitLab did not make is one `peopleChangeText` sentence (`personState` under the listed person for a remove, else `groupNotices` under the group). Every control of a line carries `data-control`, its key built once on the line (`BoxLine`'s `review.rerequest.control` and `menuControl`, null when not shown) and bound by the template; when a reply removes the focused one (`lineControls` over the same lines), focus moves to the box.

A merge request's description (request `docs/slices/request-mr-description.md`, design `docs/slices/briefs/mr-description-design.md` option A, plan §2 #171–#174): the row's info column (`w-7`, between the approvals and the links column, always rendered so the column stays) holds a button only when `row.hasDescription`; it calls `toggleDescription({ iid, title })` and carries `data-description-opener="<iid>"`. `MergeRequestsView.vue` renders the window's one `MergeRequestDescription.vue` after the list while `description` is set, keyed by the iid (a replace is a new panel), and closes it when the page unmounts. The panel is a non-modal `role="dialog"` that takes focus on mount; Escape and the close button call `closeDescription` and return focus to the row's opener when it is still listed. Escape is a window `keydown` listener in the bubble phase that acts only on an Escape nothing took (`defaultPrevented`) and not while a question is asked (a modal `dialog`'s cancel is the keydown's default action, so its Escape reaches the window unprevented): a focused field or box (the search field with text, a people box, a job log) handles Escape first, and the page's own listener, registered before the panel's, closes an open filter menu and otherwise leaves every Escape alone. A press outside it closes it (`onClickOutside`), ignoring every opener (whose toggle closes or replaces) and every element with `data-refreshes-list` (Refresh and the failed list's Retry: rule 2 keeps the panel over a list refresh, and onClickOutside would close it on their clicks, keyboard ones included); `useHoverBox`'s pinned rule reads the same attribute, so a refresh keeps a pinned discussions box and its thread panel too; a new refresh trigger carries the attribute. A scroll leaves it open. Its renderers use interpolation only and never `href`, `v-html`, `innerHTML` or `title` (RK66): `MergeRequestDescriptionBlocks.vue` and `MergeRequestDescriptionInlines.vue` each render nested content by referring to themselves, with `editor/theme.css`'s `markdown-*` classes; a link is an `a` with `role="link"`, `tabindex="0"` and no `href`, whose click or Enter calls `openPage("link", page)` for a `page` link (branded in `ipc/descriptionDomain.ts` `toDescriptionReply` by `ipc/domain.ts` `isLinkedPage`, http or https) and does nothing for a `refused` one; task boxes are Lucide icons with `role="img"` and their word; `MergeRequestDescriptionImage.vue` loads `imageAddress(image)` with `referrerpolicy="no-referrer"` and shows the caption (else the `web` address, else "picture") when that is null or the image fails; its `style` is `mergeRequestImageSize.ts` `imageStyle(size, natural)` (plan §2 #184: GitLab's width as given, never wider than the column, with its proportions; a pixel height scaled from the natural ratio once the image loaded; both by their ratio; a height in % ignored; no size: `max-width: 100%`, `height: auto`); `MergeRequestDescriptionCode.vue` hosts one `MarkdownView` through `useMarkdownCode`. The words are `mergeRequestDescriptionText.ts`. The thread panel's comments and previews render through the same blocks and inlines.

A merge request's links (request `docs/slices/request-mr-links.md`, design `docs/slices/briefs/mr-links-design.md` option A, plan §2 #176, #177, RK70): the row's links column (`w-7`, directly after the info column and before the CI box, always rendered so the column stays) holds `MergeRequestLinks.vue` only when `row.hasDescription`: Lucide `link` opening a hover box (`useHoverBox`, the discussions box's rules and look; `@click.stop`, so a click never opens the row's page). Its state is the slice's `links` (`mergeRequestLinks.ts`, written only by its queue: one call at a time, newest ask first, dropped with the list on a refresh); `useRowLinks` asks when the box opens and the row has no entry or a failed one, and Retry calls `keepFocus()` (below), then `askLinks(iid)`. Every word and line is `mergeRequestLinkLines.ts` `linkBox(load, platform)`: "Loading…", the empty sentence, the failure sentence (`linksFailedText`, `problemText` step `links` for a thrown call; the glab Retry sentences are `glab.ts` `glabRetryText`, shared with the description panel) with Retry, or the non-empty groups Epics, Issues, Commits; a line (group icon, reference, title and "Closed", or "Not found or no access") calls `openPage("link", page)` and the box stays; an issue GitLab shows with a parent has a second button (Lucide `arrow-up-to-line`, `parentTooltip`) opening the parent's page.

A hover box control the page removes while it may hold focus (the links box's Retry, a people line's re-request or menu after a reply) is preceded by `useHoverBox`'s `keepFocus()`: focus inside the box moves to the box, because the HTML focus fixup after a removal sends no focusout and the box would stay held. The spans of a box line button (links, discussions) are separated by a `{{ " " }}` text node, so its accessible name reads "#12 Snooze a reminder Closed"; `gap` keeps the visual spacing (Vue's whitespace condensing drops the template's own line breaks between them).
