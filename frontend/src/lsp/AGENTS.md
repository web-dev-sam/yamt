Owner skills: `skill://ts-conventions`, `skill://ipc-contract`. yamt's own language-server client (plan §2 #67, #70): speaks the protocol to programs an `ipc/ServerHost` starts; owns each server's lifecycle and state, the documents open on it, its problems (pushed and pulled into one slot per server: `DocProblems` never shows an answer older than the last one it showed), formatting, and its log. Framework-free: no `vue`, `@vueuse`, `@tauri-apps`, and never imports `editor/`, `ui/`, `model/`, `connectors/` (oxlint + `scripts/fences.ts`); only `ipc/index.ts` types. Public surface is `index.ts` (`LanguageServers`, `isDocVersion`, `detect`, `addedSpecs` and the types); everything else in `internal/`. Every message from a server is external data, parsed once with valibot (`messages.ts` envelope, `protocol.ts` payloads); a malformed one is logged and dropped.

A server's run is one sum type, `Run` in `internal/run.ts` (idle, launching, starting, running, halting), held by `internal/server.ts` (the lifecycle); its `state` and `running` (the documents, the capabilities, the attempt) are derived from it. `internal/attempt.ts` is one process run: it starts and stops the process and routes its messages.

Which specs exist (plan §2 #70 "Detection", "Not installed"): `internal/detect.ts` `detect(paths, lookups, root)` is a pure function over the host's two generic lookups (`findProgram`, `projectFiles`; Rust never learns a server's name). A path's project is the nearest folder with a `package.json` up to the repository root; each project is read in one `projectFiles` batch and run through the one preset table `internal/presets.ts` (oxfmt, oxlint, TypeScript, eslint: what to look for, command, file types, formats, settings); a missing server gets an `InstallHint` whose manager comes from `internal/packageManager.ts` (the `packageManager` field, else the nearest lock file). "The project has this program" has one test, `findProgram` answering `place: "Project"` (oxfmt, oxlint, the native preview's `tsgo`), so detected and can start agree; a project's workspace URI is `handshake.ts` `projectUri`, the one the handshake sends. A rejecting lookup means "not found"; nothing throws. `internal/added.ts` `addedSpecs` turns the settings file's added servers into specs served at the repository root; an entry whose program has no file name is skipped. Where a program is looked for (plan §2 #72) is the window's: `internal/spec.ts` `PROGRAM_FOLDERS` (`node_modules/.bin` in the project and each parent up to the root, no home folders; the host tries PATH between the two) goes with every detection `findProgram` call and on every spec, detected or added, as `ServerSpec.folders`; the start command sends `spec.folders`.

Reading path of one message from a server: `ServerHost` event → `internal/attempt.ts` `#onEvent` → `connection.ts` `receive` (parse) → a response settles its request; a request goes to `answers.ts` (pure table) and back through `send`; a notification goes to `attempt.ts` `#notified` → `problems.ts` `pushProblems` → `DocProblems` → `ResultDocument.showProblems`. Outward: `index.ts` `open` → `documents.ts` (`DocEntry`: version, 300 ms sync) → `serverDocs.ts` (`didOpen`/`didChange`/`didClose`) → `connection.ts` → `ServerHost.send`; pulls go from `problems.ts` `DocProblems.pull`, the formatting request from `formatting.ts`.
