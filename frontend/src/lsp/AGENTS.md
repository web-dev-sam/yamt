Owner skills: `skill://ts-conventions`, `skill://ipc-contract`. yamt's own language-server client (plan §2 #67, #70): speaks the protocol to programs an `ipc/ServerHost` starts; owns each server's lifecycle and state, the documents open on it, its problems (pushed and pulled into one slot per server: `DocProblems` never shows an answer older than the last one it showed), formatting, and its log. Framework-free: no `vue`, `@vueuse`, `@tauri-apps`, and never imports `editor/`, `ui/`, `model/`, `connectors/` (oxlint + `scripts/fences.ts`); only `ipc/index.ts` types. Public surface is `index.ts` (`LanguageServers`, `isDocVersion`, `detect`, `addedSpecs` and the types); everything else in `internal/`. Every message from a server is external data, parsed once with valibot (`messages.ts` envelope, `protocol.ts` payloads); a malformed one is logged and dropped.

A server's run is one sum type, `Run` in `internal/run.ts` (idle, launching, starting, running, halting), held by `internal/server.ts` (the lifecycle); its `state` and `running` (the documents, the capabilities, the attempt) are derived from it. `internal/attempt.ts` is one process run: it starts and stops the process and routes its messages.

Which specs exist (plan §2 #70 "Detection", "Not installed", #72): `internal/detect.ts` `detect(paths, lookups, root)` is a pure function over the host's two generic lookups (`findProgram`, `projectFiles`; Rust never learns a server's name or an ecosystem). `internal/ecosystems.ts` is the one table of ecosystems (node, python, rust, go, php, clang): each one's project rule (manifests tried in order, nearest folder up to the repository root; rust prefers the nearest `Cargo.toml` with a `[workspace]` table, go `go.work` over `go.mod`, clang's `build/compile_commands.json` makes the folder holding `build/` the project) and its `ProgramFolders` (project folders such as `node_modules/.bin`, `.venv/bin`, `vendor/bin`; home folders such as `go/bin`, `.cargo/bin`, `.local/bin`); the folder walking lives there once. A path joins an ecosystem only when some preset of that ecosystem serves its file type. Each project folder is read in one `projectFiles` batch and run through the one preset table `internal/presets.ts` (formatters first: oxfmt, Biome, oxlint, TypeScript, eslint, rust-analyzer, gopls, ruff, ty, basedpyright, pyright, Phpactor else Intelephense, clangd: what counts as used, command, file types, formats rule, settings, start options, install recipe). A `used` look counts a config file, a `pyproject.toml` section or the ecosystem's manifest wherever `findProgram` finds the server (`Project`, `Path`, `Home`), else its spec carries an `InstallHint` (`internal/install.ts`: node's manager from `internal/packageManager.ts` — the `packageManager` field, else the nearest lock file; python's from the nearest `uv.lock`/`poetry.lock`/`pdm.lock`); a program-only sign (oxfmt, Biome, oxlint; ruff, ty, basedpyright without their config) counts only `place: "Project"`, so detected and can start agree. `internal/project.ts` holds what one (ecosystem, folder) project reads: its files, its program lookups with the ecosystem's folders, the nearest of a set of files. A project's workspace URI is `handshake.ts` `projectUri`, the one the handshake sends. A rejecting lookup means "not found"; nothing throws. `internal/added.ts` `addedSpecs` turns the settings file's added servers into specs served at the repository root; an entry whose program has no file name is skipped. Every detected spec carries its ecosystem's folders as `ServerSpec.folders`; added specs carry `internal/spec.ts` `PROGRAM_FOLDERS` (node's); the start command sends `spec.folders`.

Reading path of one message from a server: `ServerHost` event → `internal/attempt.ts` `#onEvent` → `connection.ts` `receive` (parse) → a response settles its request; a request goes to `answers.ts` (pure table) and back through `send`; a notification goes to `attempt.ts` `#notified` → `problems.ts` `pushProblems` → `DocProblems` → `ResultDocument.showProblems`. Outward: `index.ts` `open` → `documents.ts` (`DocEntry`: version, 300 ms sync) → `serverDocs.ts` (`didOpen`/`didChange`/`didClose`) → `connection.ts` → `ServerHost.send`; pulls go from `problems.ts` `DocProblems.pull`, the formatting request from `formatting.ts`.
