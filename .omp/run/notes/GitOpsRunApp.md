The app now runs Continue and Abort for every operation on a worker thread, so the main thread never waits on git. It follows git to a new stop and exits with the status and message for each operation. The three new commands sit beside the old ones in `ipc/`. **summary**
- `Merge` now has five states: `Held(Box<MergeSession>)`, `Running(kind)`, `MovedOn { root }`, `Aborted(kind)` and `Finished(kind)`. The `large_enum_variant` expect is gone.
- New commands `list_stop`, `continue_operation` and `abort_operation` sit beside `list_files`, `side_names` and `abort_merge`. Continue and Abort hand the session to a `spawn_blocking` worker and put the result back.
- Exit messages are now per operation: `<operation> finished` with exit 0, `<operation> aborted` with exit 1, and `merge aborted` is unchanged. At close, `MovedOn` counts the new stop's unmerged files without staging anything, and a close during `Running` waits for git to finish.
- `IpcError` has four new kinds: `StopMovedOn`, `GitRunning`, `MergeFinished` and `NoOperation`. The window side has the three `ChunkSource` methods, the domain types, error words, and a fixture mode for `?operation=`.
- `scripts/operations-repo.sh <run> <dir>` builds a stopped repository for each of the 11 runs.

**deviations_from_brief**
- Added `MergeSession::operation_kind() -> Option<OperationKind>` in `crates/session/src/operation.rs`, plus its test (granted by you). `Running(kind)` needs the kind before git runs. A stop opened with no operation answers `NoOperation` without running git.
- `Merge::Held` holds `Box<MergeSession>`, following Behaviour 5, so the contract's `Held(MergeSession)` is boxed. `outcome::Startup::Merge`, `with_session` and `window::run` take the box.
- `continue_operation` and `abort_operation` take only the `WebviewWindow` and read the state from it. tauri-macros 2.7 checks an async command with a borrowed argument by writing an `unreachable!()` that clippy denies, and an `#[expect]` cannot reach it (`command/wrapper.rs:222`).
- Session's `GitRefused { message }` becomes `Git { message }` with git's own text. Row 4 had sent `"git refused: …"`, which reads twice under "Could not …".
- A worker that panics leaves `MovedOn { root }` (the next list reopens the stop) and answers `Git { message: "yamt's worker stopped while git ran: …" }`.
- On `Finished`, git's output (an autostash note, for example) goes to `tracing::info`, since the contract's `ContinueReply::Finished` has no field for it.
- Fixture mode:
  - `createFixtureSource` gains a third parameter that defaults to `location.search`, because `main.ts` is read-only.
  - `listFiles().merging` is now true only for `?operation=merge`, matching Rust's "MERGE_HEAD and no rebase".
  - A Continue or Abort after Finished answers `MergeFinished`.
  - Sides are unnamed except a rebase, whose replayed commit is on the left.
- The fixture operation tests live in a new `ipc/fixtureOperations.test.ts`, not `fixture.test.ts`, which is already 745 lines.
- `OperationKind` is not in the bindings (no exported Rust type uses it), so `domain.ts` derives it as `OperationView["kind"]`.
- `ipc/index.ts` exports the five types; the new test imports them type-only, so `pnpm unused` passes.
