## Summary (implementer)

- merge-core: `LineChange`, `line_changes(left, right)` (line ranges, no words); `compare()` builds on it.
- yamt-range: `Range::search_texts(from)` (open.rs, delegating to `search::search_page`; `SEARCH_PAGE_BYTES` 4 MiB of
  blob bytes read, at least one file per page, one `BlobReader` per page); files `load` would not answer as `Texts`
  left out through the shared `decide`/`read_sides`/`decoded` in `load.rs`.

- ipc: `LineChange`/`SearchText`/`SearchTexts`, `toSearchTexts` (brands via `branded`/`toRange`),
  `RangeSource.searchTexts`, Tauri mapping, a one-page fixture answer, exports.

## Tests

range: every non-text kind left out, texts and changes equal `load`'s, `next` None at the end; a 5 MiB file alone,

## Deviations (accepted)

1. `search_texts` in open.rs (private fields), page rule in search.rs. 2. `from == len` → empty last page (an empty
   range answers its first page). 3. The budget counts blob bytes read, not-UTF-8 ones too. 4. merge-core tests as unit
   tests in compare.rs. 5. Doc names for the orchestrator (architecture §3.8/§4, ipc-contract, project map, AGENTS.md
   files).

## Open risks (implementer)

A trailing page of left-out files costs one more empty call; a page of only left-out files still spawns one
`cat-file`; the proptest mostly guards a future second rule.
