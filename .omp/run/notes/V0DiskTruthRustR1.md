# V0DiskTruthRustR1 — rework 1 report (commit 3098066, base 5089198)

## Summary

All 19 findings (#517–#535) are fixed, following the orchestrator's decisions. What changed:
- New IPC variants `IpcError::ReadFailed` and `DiskResult::LeftAsIs`. `Seen`'s variants are now `GitOutput`, `ViewFromStages`, `ViewFromDisk`.
- The merge driver is resolved the way git's merge-ll.c does it, from one new `git config` call (`Repo::merge_config`). `finish` refuses to write through a link or into a directory. A failed read-back after a write is only a warning, and a path that cannot be read at `open` starts as `GitOutput` instead of failing.
- Seed fixes: base's last line without a final newline, disjoint base ranges, typed local/remote ranges in the new `locate.rs`. `settle` takes `Vec<(usize, OnDisk)>`. `merge_file` takes three slices. The scratch dir is created 0700.
- Files split: `IpcError` moved to `src-tauri/src/ipc_error.rs`; the take/reset tests moved to `tests/take.rs`, sharing a fixture with `tests/describe.rs`.

## deviations_from_brief

- New IPC variants, exactly: `IpcError::ReadFailed { path: String, message: String }` (in src-tauri/src/ipc_error.rs, serialised `{kind:'ReadFailed', path, message}`), and `DiskResult::LeftAsIs` (unit variant, serialised `{kind:'LeftAsIs'}`). The other IpcError and DiskResult variants are unchanged. bindings.ts was not regenerated (read-only for me), so the orchestrator still needs to run `just bindings`.
- New gitio config method: `pub fn merge_config(&self) -> Result<MergeConfig>` on `Repo` (crates/gitio/src/merge_config.rs), re-exported as `yamt_gitio::MergeConfig`. The struct is `#[derive(Clone, Debug, Default, PartialEq, Eq)] pub struct MergeConfig { pub default: Option<Vec<u8>>, pub drivers: Vec<Vec<u8>> }`. It makes one call, `git -c core.quotepath=false config -z --get-regexp ^merge\.(default|.+\.driver)$`, and accepts exit status 0, or 1 (no key matched). Values are raw bytes; the last `merge.default` wins. `open()` calls it once and propagates a git failure.
- #519 message wording: `IpcError::ReadFailed.message` carries the io message only (e.g. "permission denied"), mirroring WriteFailed. The decision said the message keeps the session's "cannot read" wording. I used the bare io message because the window brief (3.D-window-disk-is-truth.md:63) words this case "reading <path> failed: <message>", and the full wording would print the path twice there. If the full "cannot read <path>: …" text is wanted, it is a one-line change in ipc_error.rs.
- #534 error: a new session error `Error::NotAFile { path }` ("cannot write {path}: it is not a regular file") is used for a link, a submodule, a directory or a special file. I did not reuse Unsupported, because no UnsupportedReason fits a directory or a special file, and Unsupported's window text says "cannot be shown in the editor". On the IPC side it maps to the existing `IpcError::WriteFailed { path, message: "it is not a regular file" }`, so it needs no third new IPC variant. `finish` checks this with a fresh `read_disk` (no link following) that replaces the old `fs::read` before-write. A read error there is now `ReadFailed` rather than `WriteFailed`.
- #528 lookup order: configured `merge.<name>.driver` names are checked before the built-in names, as merge-ll.c `find_ll_merge_driver` does (ll_user_merge first). So a configured `merge.union.driver` counts as Custom. Otherwise the mapping is as listed: unspecified → merge.default if set, else Text; set → Text; unset → Binary; binary/union → Binary/Union; any other name → Text.
- #517/#531: for an unreadable file, open_file returns `StartLook::Changed` together with `Seen::GitOutput`. The batch step in open_files would set GitOutput for that look anyway, and no start comparison runs for the file.
- #522: besides moving the take/reset tests to tests/take.rs, I renamed describe_and_take.rs to tests/describe.rs, since it now holds only describe tests. Both files share the new `tests/every_kind/mod.rs` fixture (consts, `conflict`, `every_kind_of_conflict`, `file_against_link`). To keep disk_is_truth.rs ≤ 400 lines with the #534 test added, its `a_resolved_file_changed_again…` test moved to finish_and_reset.rs (as `a_finished_file_changed_again_is_staged_again_with_its_new_bytes`), and the encoding test moved from start_from_disk.rs to the new left_as_is.rs.
- #525: the locating code (SideView, side_view, Located, Maps, line_number) moved from seed.rs into the new crates/session/src/locate.rs, so that seed.rs stays under 400 lines with the new tests. seed.rs keeps the middle-text building.
- #532: the histogram vs myers triple was found by search (`{ a } x x b` family), because cli/tests/merge_file.rs has no pinned RK13 case A/B. It is pinned both at gitio level and in start_from_disk.
- Docs: I updated crates/session/AGENTS.md (owned). The report file .omp/run/notes/V0DiskTruthRust.md is under read-only `.omp/**`, so this yield is the report. The orchestrator's doc work, per the brief: project-map `line_map` (#524), plus naming `locate.rs`, `merge_config`, `ipc_error.rs`, LeftAsIs, ReadFailed and NotAFile in architecture/ipc-contract.
