**deviations_from_brief**
1. With your OK, `open.rs` and `entries.rs` were added to my files. The accessors live in `open.rs`, because `Range`'s fields are private there.
2. With your OK, `Deserialize` was added to `LeftLine`/`RightLine` in `line.rs`. The TypeScript shape does not change.
3. `Posting`, `MessageBody` and `Message` also derive `Deserialize`, because the file stores them as they are. As a result, a pending message's fields are written `draft_note` and `merge_request` in the file (the same snake_case as on the wire). The design's table said `draftNote`; using one type for both avoids a second copy of the shape.
4. `written` and `draft_note` carry `#[specta(type = u32)]`, copied from `SideContent.bytes`.
5. add_note, queue and unqueue answer `UnknownThread`/`UnknownMessage` for a thread on a path this range does not list. The window never sees those ids. The brief did not decide this.
6. Text is stored as typed; it is trimmed only to check for blank. queue refuses blank text (`EmptyMessage`), as the design's §4 says.
7. A new id that would leave a counter at `u32::MAX` is refused as `Broken` and nothing is written (the `tabs.json` rule).
8. `queued()` returns a named `pub(crate) struct QueuedMessage { thread, message, path, line, text }` rather than a tuple. `queued` and `record` carry `#[cfg_attr(not(test), expect(dead_code, reason = …))]` until row 16 uses them.
9. The `yamt-gitio` dependency is not added yet; row 16 adds it, and arch-check already allows it.
10. Shared edits for you to make:
    - root `Cargo.toml` `members`: add `"crates/review",`
    - `[workspace.dependencies]`: add `yamt-review = { path = "crates/review" }`
    - `src-tauri/Cargo.toml` could then use `yamt-review.workspace = true`; today the path line works because cargo treats it as a workspace member automatically.
    - Docs I don't own need updating: `docs/architecture.md` / project-map (the `yamt-review` crate, the range accessors, the PM1 edge), `crates/range/AGENTS.md` (the accessors, and the split of `Range` into entries and files).
