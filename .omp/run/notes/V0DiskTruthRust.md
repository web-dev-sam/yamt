# V0DiskTruthRust — implementer report (commit e11a6d3, base 5eb25c8)

## Summary

yamt now remembers what it last saw on disk for every conflicted file. `refresh()` (behind `list_files` and the exit status on close) settles each change: no marker lines → staged (one batched `git add` and one batched `update-index --force-remove`); marker lines → `MarkersLeft` and a `Disk` view. finish/take/reset look at their file first and refuse a changed file or a stale `DiskVersion` with `WriteReply::ChangedOnDisk`.
New session modules: `markers.rs` (byte-level marker parser and views), `seed.rs` (middle text and one Conflict chunk per open block or raw region), `start.rs` (compares each file with what git wrote, via `git merge-file` / `hash-object` / attributes), `disk.rs`, `open.rs`, `writes.rs`, `merge_data.rs`. Also new: merge-core `line_map` (exact/covering), the gitio methods version/attributes/hash_objects/merge_file/submodule_head/add_paths/remove_paths, and `conflict_repo_with` (config and `.gitattributes` set before the merge).
The IPC follows section F (`Middle`, `MergeChunk`, `DiskVersion`, `FileList`, `WriteReply`). The commands take `disk_version`, the CLI fixture emits `Middle::Stages`, and the fixtures were regenerated.

## deviations_from_brief

All match F.
- Commands (src-tauri), as in F: `fn list_files(state) -> Result<FileList, IpcError>`; `fn load_file(state, path: &str) -> Result<FileMergeData, IpcError>`; `fn describe_file(state, path: &str) -> Result<FileSides, IpcError>`; `fn finish_file(state, path: &str, text: &str, disk_version: DiskVersion) -> Result<WriteReply, IpcError>`; `fn take_side(state, path: &str, side: Side, disk_version: DiskVersion) -> Result<WriteReply, IpcError>`; `fn reset_file(state, path: &str, disk_version: DiskVersion) -> Result<WriteReply, IpcError>`. remote_name, log and the IpcError type are unchanged. JS argument names are camelCase (`diskVersion`), from tauri's default. The generated TS (checked in target/bindings-3d.ts) shows `finishFile(path, text, diskVersion: DiskVersion)` and the types above. bindings.ts is not touched: the orchestrator runs `just bindings`.
- Session API (Rust): `MergeSession::refresh(&mut self) -> Result<FileList>` replaces `refresh_statuses` (now `pub(crate)`); `finish(&mut self, path: &str, result: &str, disk_version: DiskVersion) -> Result<WriteReply>`; `take(&mut self, path: &str, side: Side, disk_version: DiskVersion) -> Result<WriteReply>`; `reset(&mut self, path: &str, disk_version: DiskVersion) -> Result<WriteReply>`. `pub fn merge_data(path, base, local, remote, deleted, disk_version: DiskVersion) -> FileMergeData` gained a `disk_version` argument (the CLI passes `DiskVersion(0)`). New session `Error::ReadFailed { path, source }` (a disk read failing in a before-write look or a read-back); src-tauri maps it to the existing `IpcError::WriteFailed { path, message }`, so the IpcError type is unchanged.
- New gitio methods (bytes in, bytes out): `Repo::version(&self) -> Result<GitVersion>` (`pub struct GitVersion { pub major: u32, pub minor: u32 }`, Ord); `Repo::attributes(&self, paths: &[&Path]) -> Result<Vec<MergeAttributes>>` (one `check-attr -z --stdin conflict-marker-size merge working-tree-encoding`; `pub struct MergeAttributes { pub conflict_marker_size, pub merge, pub working_tree_encoding: AttributeValue }`, `pub enum AttributeValue { Unspecified, Unset, Set, Value(Vec<u8>) }`); `Repo::hash_objects(&self, paths: &[&Path]) -> Result<Vec<Oid>>` (`hash-object --stdin-paths`); `Repo::merge_file(&self, scratch: &Path, inputs: &MergeInputs<'_>, options: &MergeFileOptions) -> Result<Vec<u8>>` (`pub struct MergeInputs<'a> { pub base, pub local, pub remote: &'a [u8] }`, `pub struct MergeFileOptions { pub marker_size: usize, pub union: bool, pub histogram: bool }`; exit 0..127 is success, through the new `run_accepting` in run.rs); `Repo::submodule_head(&self, path: &Path) -> Result<Option<Oid>>`; `Repo::add_paths(&self, paths: &[&Path]) -> Result<()>`; `Repo::remove_paths(&self, paths: &[&Path]) -> Result<()>`. New `gitio::Error::WriteFailed { path, source }` for a temp-file write.
- merge_file takes a `scratch: &Path` argument that G does not list. D says open() creates and removes the one temp directory, so the directory has to come from session (start.rs `ScratchDir`, created lazily under `std::env::temp_dir()` and removed on drop).
- The single-path `Repo::add(&Path)` and `Repo::remove_from_index(&Path)` were replaced by `add_paths` / `remove_paths` (cutover, no duplicate method); every caller and the gitio tests were updated.
- State shape: instead of `seen: OnDisk` plus `view: View`, `FileState.seen: Seen` with `Seen { GitOutput, Stages(OnDisk), Disk(OnDisk) }`. This combines what was seen with what the view is built from, so the illegal 'Disk view of GitOutput' cannot be built. `OnDisk` is `Missing | File | Link | Submodule(Option<Oid>) | Other`. The last settle is `settled: Option<Settled { version, result }>`; version 0 means never settled.
- StageFailed: brief B says `seen` is not updated so the next look retries. Instead, `seen` is updated, and a file whose last result was `StageFailed` counts as changed at the next look. The behaviour is the same (retried next refresh and before a write) without keeping a second copy of the bytes. After successful staging, `seen` is the read that was settled, not a second read: `git add` does not write the worktree, and re-reading would silently swallow a change made between the two reads.
- Staging is all-or-nothing per batch: if the batched `git add` fails (e.g. a held index.lock), every file in that batch gets `StageFailed` with the git message. The same holds for the force-remove batch.
- Cases the brief left open: a `working-tree-encoding` file that changed on disk is never staged and is reported as `MarkersLeft { conflicts: <marker count from the bytes, usually 0> }` with the Disk view. A submodule directory that is no longer checked out (`Submodule(None)`) is likewise reported as `MarkersLeft { conflicts: 0 }` and left alone, because `git add` of a plain directory would stage its files.
- A disk read error: in `refresh()` it logs a warn and skips that file (it is looked at again next time); in finish/take/reset it returns `Error::ReadFailed`; in `open()` it fails the open.
- A Disk-view middle over LF stages and a CRLF disk: inserted base lines are converted to CRLF, so the middle has one line ending (seed test covers it). Locating ignores CR before LF on both sides.
- Raw regions are located by `covering` an empty range at their place in the side view. Lines inserted at a range's edge count as covered, so a raw region picks up the local/remote lines it stands for.
- Smoke observation 3 ran on the trial clone (renderer.ts, 2 blocks), because the scripts/conflict-repo.sh repo has no file with more than one block. The start-time numbers are from a debug build.
- Updated crates/session/AGENTS.md and crates/conflict-repo/AGENTS.md (owned) for the new modules. Read-only docs still need the orchestrator: docs/architecture.md, .omp/skills/project-map (new session modules, merge-core line_map.rs, gitio modules), the ipc-contract command list, the risk register (start false positives, UTF-16, StageFailed), and CHANGELOG.md.
