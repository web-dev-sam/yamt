# V0DiskTruthWindow — implementer report (commit 76d6eb5, base 98c32a3)

## Summary

The window side of the disk-is-truth slice is in place, but one acceptance item is not met. In desktop smoke 2 (a block removed from a multi-block file), the notice and the disk-seeded middle showed correctly, but applying a side did nothing.

- **ipc:** follows the new bindings. A chunk's `middle` range replaces `base`; `MiddleLine` and `DiskVersion` are branded by type guards; `FileList` and `WriteReply` are new; the fixture source returns no disk changes and `Written`.
- **editor:** the middle pane starts from `data.middle`, chunk spans and tone come from `chunk.middle`, and a `DiskNotText` middle is empty and read-only.
- **ui:** `applyDiskChanges` adds notices, reads `editsDropped` before rebuilding, records `taken = { by: "disk" }` and refetches shown files. Writes send the shown view's disk version and handle `ChangedOnDisk`. New `NoticeBar.vue` and `noticeText.ts`, plus the not-text sentences and the `NotAFile`/`ReadFailed` problem words.

## deviations_from_brief

- `applyDiskChanges` lives in the new `ui/diskChanges.ts`, and the shown-view helpers (isShown, shownVersion, showsChoice, fetchView, reload, putOpened, putChoice) in the new `ui/views.ts`. The brief puts `applyDiskChanges` in `store.ts`, but `store.ts` would have gone past oxlint max-lines 300; it is now at 299. `store.ts` calls both modules.
- New files beyond the brief: `ui/diskChanges.ts` and `ui/views.ts` (see above). `NoticeBar.vue` and `noticeText.ts` were named in the brief. NoticeBar is a 7th component, which the brief itself asked for (VU15 reason: notices are a separate responsibility from problems). project-map (.omp, read-only) needs new lines for these four files, otherwise `just map-check` (PM6) fails.
- `Taken` is defined in `ui/sides.ts`, so that store, diskChanges, choiceText and deletedSide share one definition without an import cycle.
- Domain `FileSides` is mapped to `{ …, diskVersion: DiskVersion }` by a new `toSides`, used in tauri.ts and fixture.ts. Without the mapping, take/reset could not send a branded version for a choice view. The brief only named `FileMergeData.diskVersion`.
- Bindings vs sketch: `Chunk` still carries `base`; the domain drops it as the brief says. `IpcError`, `DiskResult` (incl. LeftAsIs) and `WriteReply` match the sketch.
- Design token added: `--color-info: #25324d`, `--color-info-border: #35538f` in style.css.
- Decisions the brief left open: (a) the choice Result line reads 'Changed on disk — staged as it is.' with a final period, like the other Result lines. (b) A deleted-side view taken by the disk keeps Keep/Delete and enables Reset; its middle state is renamed from 'base' to 'loaded'. (c) After a successful take on an opened file whose middle is not Stages, the view is refetched, because Rust's take sets the view back to the stages. (d) take/reset on a path that is not shown report an Unexpected problem '<path> is not shown' and send nothing. (e) `ChangedOnDisk` clears a problem about that path before applying the change. (f) Notice close buttons carry aria-label 'Close the notice about <path>'.
- Editor read-only: `MergeController` decides it through `centerPane(middle, options.readOnly)`, where DiskNotText forces readOnlyCenter. `useMergeController` still passes `deleted !== null`.
- Desktop observation 2 used a repo from scripts/golden-repo.sh (tanstack-query-svelte-base-query, 3 git blocks) because no file in the conflict-repo.sh repo has more than one conflict block.
- Tests that pinned the old shape were deleted, as the brief allows: the fixture tests about word_changes alignment.
