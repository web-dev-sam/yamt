# V0DiskTruthWindowR1 — window rework 1 report (commit dd50218, base 11343b0)

## Summary

Fixed rework findings #552–#557 and #559–#562. Each view now passes its own disk version to take and reset, so `shownVersion` and `notShown` are gone. `finishFile` takes one `{ path, text, diskVersion }` object. The read-only rule is stated once, in MergeView, and goes through `useMergeController(data, hosts, readOnly)`. `centerPane` now only turns DiskNotText into an empty document.
After a successful take, the store reloads any opened view of that file. `taken {by:'disk'}` is now recorded from data (the listed entry is unsupported, or a loaded deleted-side file), and a deleted-side view can be reset whenever its middle is not Stages.
The editor test helpers say `middle` instead of `base`, and `ViewSources` carries `center`. Also added: an add/add apply test, `noticeCloseLabel` and its test, a store test for a choice file changed before start, and the duplicate swap test is merged into the existing one.

## deviations_from_brief

- #555: MergeView states the rule in a hoisted `function isEditable({ deleted, middle })` used twice: as the `editable` computed and as the `() => !isEditable(props.data)` getter passed to useMergeController. A `computed` declared before the composable call would break VU2 order (state → computed). Declared after it, the getter would hit the TDZ, because `watch(…, { immediate: true })` evaluates its sources synchronously. useMergeController's signature is now `(data, hosts, readOnly: MaybeRefOrGetter<boolean>)`, and readOnly is a watch source. VU11 in vue-conventions and docs/architecture still show `(data, hosts)`; the curator needs to update them (docs are read-only here).
- #559: to keep editor/index.ts under max-lines 300 (it reached 306), the constructor builds `center` and `language` as locals before `#createViews({ data, center, hosts, language })`, and `CenterPane` comes in through a second `import type { CenterPane } from "./internal/pane"` line. With `type CenterPane` folded into the value import, the line is too long, so oxfmt makes the import 7 lines. File: 298 lines.
- #560: a deleted-side *text* file that is not loaded cannot be recognised from FileEntry (its `unsupported` is null in Rust's open.rs `content`). So `takesASide` (views.ts, replaces showsChoice) records {by:'disk'} when the listed entry is unsupported OR a loaded view has `deleted !== null`. A deleted-side text file staged before it was opened is still resettable through the new `middle.kind !== "Stages"` rule. Its view is the same as with {by:'disk'}: Keep/Delete offered, middle 'loaded', Reset enabled.
- #556: the reload after a take runs only when the path is in `opened` (MergeView files, deleted-side included). Choice files are not described again after a take, which keeps the describe calls the existing choice tests count.
- #554: the request type is declared inline in ChunkSource.finishFile. store.ts derives `FinishRequest = Parameters<ChunkSource["finishFile"]>[0] & { summary }` (TS6), so ipc/index.ts needs no new export.
- store `takeSide(path, side, diskVersion)` / `reset(path, diskVersion)` stay positional (TS7: every parameter has its own type). The templates call them with `data.diskVersion` / `sides.diskVersion`.
- Test 'each write sends the disk version…' lost its 'not shown' half: that case no longer exists. 'a take on a deleted-side file shown from the disk…' is kept unchanged apart from the version argument.
