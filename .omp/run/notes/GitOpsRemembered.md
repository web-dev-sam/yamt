`summary`
- When rerere's `autoUpdate` is off and git rerere replays a resolution, yamt now finds it at open: `MERGE_RR` exists, the path is not in it, git's re-run merge has conflict blocks, and the file on disk has no markers. It becomes `AtOpen::Remembered` / `Seen::ViewRemembered`, so nothing settles or stages it.
- New `FileStatus::Remembered`, set while git lists the path unmerged and the file is still shown as rerere left it. `remaining()` and the exit status count it as unresolved. Mark resolved stages it, Save keeps it remembered, Reset writes rerere's bytes back and keeps it remembered, and a later change on disk is staged as before (#52).
- The remembered view is in `session/src/remembered.rs`. The Result is rerere's text (`Middle::Disk`). Each block git wrote is a `Conflict` placed in the stages the same way the disk view places one, with its Result lines found by `line_map(git output, text).covering(block)` and `waiting: Remembered`.
- New `Repo::rerere_tracked()` and a `rerere_repo` test fixture.
- Window side: `fileText.ts` writes a `Remembered` chunk as shown, `nextFile.ts` treats it as not yet resolved, and `fixture.ts` accepts the new values. Fixture mode shows a new showcase case, `remembered.ts`, built by `yamt-cli fixture`.

`open_risks`
- `crates/session/src/session.rs` (the `Seen::ViewRemembered` arm of `load`): the git output comes from `at_open.git_output().unwrap_or_default()`. Every path that sets `ViewRemembered` comes from `AtOpen::Remembered`, but the types don't enforce it; an impossible mismatch would show rerere's text with no chunks.
- `crates/session/src/remembered.rs` (`after_previous` in `remembered_chunks`): if text between two blocks was edited so the line map cannot match it, two blocks' Result ranges would overlap. I clamp each range to start where the previous one ends, which keeps them disjoint but can make the later one empty. This case isn't tested.
- If `MERGE_RR` cannot be read, yamt logs a `rerere_unread` warning and counts no file as remembered, so that file is staged at the first list as before #90. I judged that acceptable, but it is the less safe direction.
