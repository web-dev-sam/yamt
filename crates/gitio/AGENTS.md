Owner skill: `skill://rust-conventions` (RS14–RS15 subprocess rules). Git subprocess layer only: explicit argv, bytes in/out, never depends on `yamt-merge-core`. Tests are integration tests against real temp repositories in `tests/`.

What git is doing is read in one place, `Repo::stop()` in `src/operation.rs` (plan §2 #85, #91): `Stop { operation, head }` with `Operation` (`Merge`, `SquashMerge`, `Rebase(Rebase)`, `CherryPick`, `Revert`, `Am`) and `Progress` (1 ≤ step ≤ total). Order as git's `wt_status_get_state`: `rebase-apply/` (`am` with `applying`), `rebase-merge/`, `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, the sequencer's first command, then `SQUASH_MSG`; except that a `CHERRY_PICK_HEAD`/`REVERT_HEAD` inside a rebase is that single pick or revert (run at an `edit` or `break` stop; no progress), and `MERGE_HEAD` at an `edit` stop is a `Merge` of its own (its abort leaves the rebase at the edit), not a `rebase -r` merge step. An **edit stop** is `rebase-merge/amend` with `edit`/`e` as the last line of `rebase-merge/done` (the stopped step): git writes `amend` at a conflicted `squash`/`fixup` step too, which still replays its commit. `Rebase.replaying` is `REBASE_HEAD`, `None` only at an edit stop (where git keeps `REBASE_HEAD`) and at a `break`/`exec` stop (no `REBASE_HEAD`). `Rebase.editor_steps_ahead`: a `reword`, `squash` or `fixup -c` at this stop (the last line of `done`), in `rebase-merge/current-fixups` (the squash chain this stop is in: git opens the editor at the end of a chain with a squash) or left in `git-rebase-todo`. Refs through `commit_named`, state files through one `rev-parse --git-path` call (`Repo::git_paths`; `git_path` is its one-name case), never a `.git/` path; `read_if_present` and `exists` (missing = `None`/`false`, else `ReadFailed`) live in `src/repo.rs` for every git-dir file. A cherry-pick or revert has sequence progress (`src/sequence.rs`) only when the sequencer's first command is the same kind, the range makes commits (`opts` without `no-commit = true`) and `sequencer/head` names a commit. `Stop::id()` is the stop without its progress or editor steps ahead (an `Am` keeps its patch number); Continue, Abort and the moved-on check compare it. `src/todo.rs` reads git's todo files (comments, first command, the stopped step, edit and editor steps). `src/names.rs` reads what names a side (`current_branch`, `branches_at`, `merge_message`, `commit_summary` → `CommitSummary`). `src/rerere.rs` (plan §2 #90): `Repo::rerere_tracked()` reads `MERGE_RR` (`<id>[.<n>]\t<path>\0` records; a replayed path is dropped by rerere.c `write_rr`) only while rerere is enabled as rerere.c `is_rerere_enabled` decides (`config --type=bool rerere.enabled`; unset → whether `rr-cache` is a directory), so the empty `MERGE_RR` a commit leaves is not read once rerere is off; `None` when rerere is off or without the file, a record without a tab or another `rerere.enabled` answer `UnexpectedOutput`; `tests/rerere.rs` on `yamt_conflict_repo::rerere_repo` (the unset case in a child without the user's and system config). `tests/operations.rs` scripts every operation through `yamt_conflict_repo::operation_repo`; `tests/edit_stop.rs` the stops inside a rebase (a pick, revert or merge at an `edit` stop, a conflicted `squash` step, a conflicted `reword` with an empty todo, a conflicted `fixup` ending a chain with and without a squash).

Abort and Continue (`src/abort_continue.rs`, plan §2 #88/#89): `Repo::abort(&Operation)` runs git's own abort (`merge --abort`, a squash merge `reset --merge`, `rebase`/`cherry-pick`/`revert`/`am --abort`; a refusal is `GitFailed` with git's stderr), `Repo::continue_operation(&Operation)` git's own continue (`merge --continue`, a squash merge `commit`, `rebase`/`cherry-pick`/`revert`/`am --continue`) with `GIT_EDITOR=:`, giving `GitRun { succeeded, output }` (stdout then stderr; a non-zero exit is not an `Err`). Both build their command with `Repo::command_as_user` (`run.rs` `git_command_as_user`: cwd, `core.quotepath=false`, nothing else; `git_command` is that plus `LC_ALL=C` and the `Access` env) and run it through `run_to_end` (abort through `run_to_success`: `run_to_end` with a non-zero exit as `GitFailed`, the one failure rule `run.rs` `failure` that the deadline runner shares): no deadline (a kill mid-commit leaves `index.lock`), stdin closed, stdout and stderr kept apart (`Finished`), and no `LC_ALL=C`, so hooks see the user's locale; it waits for git itself, then reads the pipes for at most `READER_GRACE` (a hook's background process may hold them open). Every other call keeps `Repo::command`, and all but the checkout's clone and checkout (below) keep `GIT_TIMEOUT`. `tests/abort_continue.rs`: abort per operation gives back status, branch tips and stash list, and a merge's abort drops staged resolutions, a removal, a saved CRLF file and `MERGE_HEAD` but keeps an untracked file; the continue-message tests run through `yamt_conflict_repo::run_ignored_in_child` without `GIT_EDITOR`/`VISUAL`/`EDITOR` and with `core.editor=false`.

The AI's checkout (`src/checkout.rs`, plan §2 #110, #122): `clone_shared_into(into)` (an absolute folder; a partial clone — `extensions.partialClone` or a `remote.<name>.promisor` — refused at once as `Error::PartialClone`; `clone --shared --no-checkout --no-tags --origin origin --config core.longpaths=true`, then HEAD detached and every `refs/heads/*` deleted, so the clone holds no branch or tag of the source; ends with `Repo::with_root`, git resolved once), `remove_remote`, `checkout_detached`, `status_entries` (`status --porcelain=v1 -z --untracked-files=all --no-renames`, `Access::Read`; a rename is a `D ` and an `A ` entry), `head_commit` (`commit_revision` + `oid_line`, as `commit_named`), `branches_and_stash` (one `for-each-ref` of `refs/heads` and `refs/stash`, short names). The clone and the checkout use `Repo::command` + `run_to_success`: slow on a large repository, so no deadline, and they run no user-facing hook, so `LC_ALL=C`. A repository of its own — the clone (`with_root`) and `Repo::discover_from_folder` — leaves `Repo::REPOSITORY_VARIABLES` (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`) out of every run, the clone command included, so an inherited `GIT_DIR` never makes them act on the user's repository; `Repo::discover` keeps them. `tests/checkout.rs`: tags not cloned, `clone.defaultRemoteName` overridden (child process), a detached source, a partial-clone source, a rename's two entries, Windows paths past `MAX_PATH`.
